# Talkie 제품 요구사항 문서

상태: 초안 v0.4
작성일: 2026-10-15
갱신일: 2026-11-14
제품 형태: 반응형 영어 회화 웹서비스

이 문서는 사용자에게 제공할 동작과 제품이 지켜야 할 정책·제약의 기준이다.

## 1. 목적

한국어를 모국어로 사용하는 초중급 학습자가 영어로 실제 상황에 가까운 미션을 수행하고, 자신의 표현을 자연스럽게 개선하며, 배운 내용을 다음 대화에서 재사용하도록 돕는다. 문법 암기보다 말하기·듣기·어휘·문장 구성 능력과 말할 자신감의 향상을 목표로 한다.

## 2. 대상 사용자와 핵심 가치

첫 대상은 일상 및 업무 상황에서 영어를 말하고 싶지만 대화 상대를 구하기 어렵거나 실수를 부담스러워하는 한국어 화자다. 서비스 이용은 만 18세 이상으로 한정하며 가입 시 연령 확인 방식은 구현 전에 정한다 (`DEC-051`). 웹 브라우저에서 미션을 수행하고 개인별 복습으로 이어가는 경험을 제공한다. 미션 횟수로 이용량을 관리하고 실제 과금과 대조한다(DEC-069). 외부 환경으로 중단돼 종료하지 못하면 24시간 재개 기회를 준 뒤 자동 정리한다 (`DEC-024`). IT·클라우드·AWS·AI·개발 등의 관심 주제도 지식 시험이 아닌 영어 표현 연습에 활용한다.

## 3. 제품 원칙

1. 학습자가 직접 말하는 시간이 우선이다. 음성 응답은 짧고, 설명은 필요한 경우에만 제공한다.
2. 기본 대화 언어는 영어다. 이해가 어려우면 쉬운 영어로 먼저 설명하고, 그래도 어렵다면 한국어를 사용한다.
3. 질문은 하나부터 시작하고 현재 응답 부담에 따라 직접 연결된 질문 두 개까지 묶을 수 있다. 난이도는 확장 가능한 단계별 기준을 사용하며 미션 시작 시 적용 평가 기준을 고정한다. 상대처럼 반응하고 의견이나 가상 상황을 더하며 질문만 연속하지 않는다.
4. 목표 충족 시 상대역의 짧은 마지막 대사로 장면을 마무리하고 종료한다. 사용자 명시 종료도 허용한다. 네트워크·브라우저 등 외부 환경으로 연결이 끊겨 종료하지 못한 경우에는 일시 중단으로 두고 24시간 재개 기회를 준다. 그동안 재개하지 않으면 자동 종료하고 저장된 실제 대화로 노트를 생성한다 (`DEC-024`). 미션 이용량과 실전 무진전 종료는 6절을 따른다. 침묵이나 대기 자체를 별도 종료 사유로 삼지는 않는다.
5. 연습에서 교정·다시 말하기를 돕고 실전에서는 교육적 개입을 끈다. 도움 사용은 감점하지 않는다.
6. 학습 노트와 요약은 실제 대화 및 저장된 학습 이력에 근거한다. 확인되지 않은 과거 학습이나 발생하지 않은 오류를 만들지 않는다.
7. 다른 서비스의 구현·콘텐츠·화면을 복제하지 않고, 관찰한 학습 경험을 독립적인 웹 경험으로 설계한다.

### 3.1 요구사항의 구분

- **확정 요구사항**: 서비스 목적·사용자 지시·승인된 결정에서 나온 조건이다. F-01~F-13과 승인된 보안·데이터 보호 원칙을 유지한다. 변경 시 근거와 영향을 검토한다.
- **초기 목표**: 달성하려는 목표이며 설정 근거와 재검토 시점을 명시한다. 측정 결과에 따라 조정한다.
- **검증할 가정**: 확인되지 않은 예상이며 검증 방법과 판단에 필요한 관측 결과를 정의한다. 기술적 가정은 [DESIGN.md](DESIGN.md)에 둔다.
- **미정 항목**: 결정에 필요한 정보와 결정 시점을 명시한다 (11절).

정책과 구현·검증 상태를 구분한다. 확정 요구사항도 수용 기준 검증 전에는 완료가 아니며, 완료 판정은 [TASKS](TASKS.md), 현재 구현·검증 범위는 [PROGRESS](PROGRESS.md)를 따른다.

## 4. 주요 사용자 흐름

여기에는 제품 약속과 지켜야 할 조건만 요약한다. 단계별 흐름과 분기·예외는 [사용자 흐름 설계](design/USER-FLOWS.md)를 따른다.

### 4.1 시작

진행 중 미션이 있으면 기존 미션으로 안내한다. 사용자는 기본 미션·연속 스토리·개인별 AI 추천·직접 지정에서 상황을 선택한다. AI 추천은 관심사·난이도·최근 이력을 참고한 짧은 후보로 제시하고, 선택한 후보만 상세 구성한다. 역할·조건·목표·이용량과 연습/실전 모드를 확인한 뒤 시작한다. 평가 기준은 시작 전에 고정한다(DEC-069).

초기 구현은 직접 제작한 ‘잘못 나온 카페 주문 해결’ 미션 하나로 시작·수행·종료 흐름을 연결하고, AI 추천은 이후 연결한다. 연습을 기본 모드로 제시하며 사용자가 시작 전에 실전을 선택할 수 있다. 시작한 미션의 모드는 재개를 포함해 고정하고, 다른 모드는 새 미션에서 선택한다. 난이도는 초기에는 사용자가 시작 전에 직접 선택한다. 언어 수준은 CEFR을 참고하되 Talkie에서는 A1·A2·B1·B2·C(고급)의 다섯 단계를 사용한다. 단계 구분의 현행 근거는 DEC-084를 따르며 이전 DEC-073을 부분 대체한다. C는 상황에 필요한 의미를 정확하고 자연스럽게 전달하고 필요할 때 말투·설명·표현을 유연하게 조절하는 수준이다. 간단한 상황에서는 짧고 명확한 해결로 충분하며, 정밀한 설명·조율은 실제 조건·이해관계·오해가 있을 때 평가한다. 이는 사용자 선택과 단계별 기대 수준의 기준이며 공인 수준 판정·인증을 제공한다는 뜻은 아니다. 미션의 목표·제약에 따른 복잡도와 구분한다. 구체 설명은 [미션 설계](design/MISSIONS.md#언어-수준별-설명), 세부 평가표는 후속 확정한다(DEC-070).

### 4.2 일반 대화

기존 절 앵커는 유지하며 현행 기본 경험은 미션 수행이다. 상대역은 고정된 조건 안에서 사용자 발화에 반응하고 정보를 공개하며 대안을 조율한다. 복잡한 상황도 하나의 미션으로 수행할 수 있으며 짧은 미션으로 강제 분할하지 않는다. 새 문제를 끝없이 추가하지 않는다. 상황·상대역의 정보와 반응 조건을 시작 전에 구체화해 사용자가 문제 설명·요청·조건 확인과 조율을 수행하도록 한다(DEC-076). 상대역은 사용자에게서 아직 듣지 못한 요구를 미리 해결안으로 완성해 수락만 받고 끝내지 않는다. 이미 충분히 전달한 내용은 반영하며, 목표가 충족되면 최소 발화 수를 채우거나 평가 항목을 관찰하기 위해 인위적으로 대화를 늘리지 않는다. 연습은 막히면 도움을 주고, 실전은 일정 수준 이상 무진전이면 실패로 마무리한다. 무진전의 판정·제외 경계는 아래 4.2.2절을 따르며 운영 임계값은 사례 검증 후 확정한다(DEC-082).

미션은 사전에 허용된 여러 해결 경로를 가질 수 있으며 그중 하나의 완료 조건을 충족하면 성공한다(DEC-081). 모든 경로를 수행하거나 최초 경로를 유지할 필요는 없다. 진행 중 선택을 바꿀 수 있고 최종 합의한 경로로 결과를 판단한다. 선택한 정상 해결 경로 자체를 이유로 감점하거나 평가 만점을 줄이지 않는다. 미션 성공과 수행 근거별 점수·달성 일수 인정은 구분한다.

### 4.2.1 첫 카페 미션의 해결 경로

첫 카페 미션은 다음 두 경로를 처음부터 정상 해결로 허용한다. 직원은 사용자의 문제를 파악한 뒤 구체 요청에 대응하고, 해결 방법을 물으면 선택지를 안내한다. 이미 처리 요청이 명확하면 모든 선택지를 비교하거나 다시 말하도록 강제하지 않는다.

| 경로 | 고정된 처리 조건 | 완료 조건 |
| --- | --- | --- |
| 재제조 | 추가 비용 없이 따뜻한 디카페인 라테로 재제조, 약 5분 대기 | 음료·대기 조건에 사용자가 동의하고 직원이 재제조를 확정 |
| 환불 | 해당 음료 주문 취소·전액 환불, 새 결제·수수료 없음 | 사용자가 취소·환불에 동의하고 직원이 환불 처리를 확정 |

재제조 대기 시간을 듣고 환불로 바꾸는 것도 허용하며, 최종 합의가 확정되면 다른 경로를 추가 수행하지 않고 종료한다. 요청이나 직원의 제안만으로 성공 처리하지 않는다. 약 5분은 역할극의 재제조 대기 조건이며 실제 대화 시간 제한·최소 턴·별도 득점 항목이 아니다. 직원이 환불을 막기 위해 사전에 없는 영수증·수수료·승인자·재고 부족 등의 장애를 만들지 않는다. 모든 결제·환불은 가상 상황이며 실제 결제를 수행하지 않는다. 다른 음료 교환 등 추가 경로는 그 조건과 완료 근거를 구체화한 뒤 확장한다.

### 4.2.2 실전 무진전 종료

진전은 목표 점수 증가와 별도로 판단한다. 새 문제·조건 전달, 관련 질문·답변, 오해 수정, 대안 검토·해결 경로 변경, 구체 제안의 수락을 포함한다. 충분한 짧은 답이나 반복 요청도 맥락에 맞으면 진전으로 인정하며, 상대역이 답하지 않거나 잘못 이해해서 생긴 반복을 사용자 무진전으로 단정하지 않는다.

상대역의 관련 질문·제안에 답할 기회가 있었고 의미를 확인할 수 있는 사용자 응답이 연속으로 진전 없이 반복되는 경우에만 실전 실패 후보로 검토한다. 연속 3회는 합의한 **사례 검증용 후보**이며 운영 종료값이 아니다. 그 전에는 역할 안에서 자연스럽게 재확인하되 정답·교정·튜터 힌트를 제공하지 않는다. 시간·전체 턴 수를 이 기준으로 제한하지 않는다.

진전이 생기면 연속 횟수를 초기화한다. 침묵·오인식 의심·기록 누락·공급자 장애·상대역 조건 위반은 실패 근거에서 제외하며 연속성도 끊는다. 중단 후 재개에는 이전 횟수를 이어 즉시 실패시키지 않는다. 미재생 상대역 질문·빈 전사는 응답 기회나 실패 근거로 세지 않는다.

횟수만으로 실패를 확정하지 않고 관련 발화 근거·제외 사건·미션 완료 여부를 확인한다. 목표 완료가 확인되면 성공을 우선하고 실패 확정 시 상대역의 짧은 마무리 후 종료한다. 연습에는 무진전 자동 실패를 적용하지 않고 기존 도움을 제공한다. 실전 실패에도 고정 벌점·점수 상한을 추가하지 않으며 종료 후 실제 전체 대화로 평가한다. 상황 결과·점수·달성 일수의 분리는 4.5절을 따른다.

### 4.3 교정과 다시 말하기

연습 모드는 즉시 교정·힌트·다시 말하기를 제공하고 사용에 따른 감점이나 점수 상한을 두지 않는다. 실전 모드는 교육적 교정·힌트·다시 말하기를 제공하지 않지만 상대역의 자연스러운 재확인은 허용한다. 두 모드 모두 종료 후 실제 기록으로 교정·피드백을 제공한다. 도움을 포함한 연습 결과와 무도움 실전 수행은 구분해 표시한다. 오인식은 오류로 단정하지 않는다. 앱이 재시도 성공을 강제 차단 조건으로 삼지 않는 기존 경계는 유지한다. 발음·억양은 최종 채점 항목에서 제외하고 연습 모드의 다시 말하기에서 개선 피드백으로 확인한다. 해당 피드백으로 점수·달성 일수에 불이익을 주지 않는다(DEC-072).

### 4.4 종료와 복습

목표 충족 또는 실전 무진전 실패 시 상대역의 짧은 마지막 대사 후 종료한다. 사용자 명시 종료와 중단 후 24시간 자동 종료도 허용한다. 결과는 미션 상태와 최종 달성률·항목별 근거·언어 피드백을 구분해 제공한다. 종료 후 점수가 낮다고 대화를 강제로 재개하지 않는다. 노트는 핵심 교정·복습 중심으로 간결하게 남기며 세부 분량·상세 교정 보관은 후속 확정한다.

### 4.5 평가와 달성 일수

총점은 미션 목표 60점과 회화 품질 40점이다. 미션 채점 항목은 충족/미충족으로 배점을 합산하고 판정 불가를 구분한다. 최종 해결·합의 항목은 준비·정보 확인 항목보다 배점을 높게 둔다. 언어 평가는 문법·어휘와 표현·말의 구성·상호작용의 네 영역으로 구성한다(DEC-072). 상호작용의 대화 흐름은 상대 발화에 대한 반응·재확인·대화 연결을 뜻하며 음성 속도·멈춤을 전사문에서 추정해 채점하지 않는다. 네 영역은 각각 10점으로 총 40점이다(DEC-075). 다섯 수준은 같은 영역 배점을 사용하고 기대 수준을 달리한다. 세부 기준별 배점·부분점수는 4.5.2절을 따른다(DEC-079). 회화 품질은 시작 시 고정한 난이도별 기대 수준으로 평가한다. 쉬운 표현 자체를 감점하거나 어려운 어휘 자체를 가점으로 삼지 않는다. 수준별 세부 평가표는 후속 확정하며, 점수 표시·반올림은 아래 DEC-080 정책을 따른다.

언어 점수는 종료 후 저장이 확인된 전체 대화를 검토해 세부 기준별로 판단하고 영역별로 합산한다(DEC-074). 문장별 점수의 평균·합산으로 산출하지 않으며, 판단에는 실제 사용자 발화 근거를 연결한다. 개별 오류뿐 아니라 반복 양상·의미 전달에 미친 영향·선택 수준에서의 안정성을 보고, 말의 구성과 상호작용은 발화 사이의 연결을 함께 평가한다. 짧지만 충분한 응답을 길이 때문에 감점하지 않는다. 특정 행동의 근거는 마지막 문장뿐 아니라 앞선 전체 대화에서 찾는다. 재확인·수정은 상황에 필요한 대응의 근거이며, 필요하지 않았던 행동을 수행하지 않았다는 이유로 감점하지 않는다(DEC-076). 근거가 부족한 항목은 판정 불가로 구분한다. 판정 불가 항목은 획득 점수와 평가 만점 양쪽에서 제외하고, 나머지 항목의 원래 배점을 유지한다(DEC-078). 평가 만점은 원래 총 만점에서 제외 항목 배점의 합을 뺀 값이며, 달성률은 남은 항목의 획득 점수 합을 평가 만점으로 나눈 비율이다. 목표·언어 영역의 배점을 다시 배분하거나 제외한 점수를 0점·만점으로 대체하지 않는다. 예를 들어 100점 중 10점 항목이 판정 불가이면 90점 만점이며, 72점 획득 시 달성률은 80%이다. 영역별 결과도 해당 영역에서 제외된 배점과 남은 만점을 구분해 표시한다. 모든 항목이 판정 불가여서 평가 만점이 0이면 달성률을 산출하지 않고 해당 미션으로 달성 일수를 인정하지 않는다. 실제 미수행·미충족은 판정 불가로 제외하지 않는다.

결과는 획득 점수/판정 불가 배점을 제외한 평가 만점과 달성률을 함께 표시한다(DEC-080). 획득 점수는 소수 부분점수를 유지하고 불필요한 .0은 생략한다. 달성률은 소수 첫째 자리까지 표시하며 둘째 자리에서 반올림한다. 달성 인정은 표시값이 아닌 반올림 전 실제 비율이 80% 이상인지로 판단한다. 예를 들어 67/84점은 약 79.7619%로 화면에는 79.8%를 표시하고 달성 기준에는 미달한다. 판정 불가 항목과 제외 배점·영역별 남은 만점도 확인할 수 있게 표시한다. 평가 만점이 0이면 점수 비율·달성률을 산출하지 않는 기존 경계를 유지한다.

연습의 첫 시도·힌트·교정·재시도를 전체 대화 맥락에서 함께 평가한다(DEC-077). 사용자가 수정한 발화와 이후 적절한 사용은 개선·안정성의 근거로 인정하고, 처음 틀렸거나 도움받았다는 이유로 정해진 벌점·점수 상한을 두지 않는다. 정답을 한 번 따라 말한 사실만으로 대화 전반의 안정성·숙달을 확정하지 않으며, 마지막 성공으로 앞선 반복 오류를 모두 덮거나 초반 실패로 이후의 올바른 수행을 무시하지 않는다. 첫·마지막·최고 시도만 채택하거나 시도별 점수 평균으로 산출하지 않고 기준별 수행 양상·수정·이후 적용과 반대 근거를 함께 판단한다. AI가 제공한 정답은 맥락이며 실제 사용자 수행을 대신하지 않는다. 점수 확인을 위한 추가 발화·재시도를 강제하지 않는다. 실전의 자연스러운 자가 수정·재확인도 실제 대화의 일부로 평가한다.

최종 달성률 80% 이상인 인정 미션이 하루 하나 이상이면 달성 일수를 인정한다. 실전 실패여도 점수가 기준 이상이면 인정한다. 재개 기한 만료로 자동 종료된 미션은 제외하며, 다른 인정 미션으로 이미 획득한 당일 기록은 취소하지 않는다. 날짜 귀속·누적/연속 표시·소급 집계는 미정이다. 초기 보상은 달성 일수만 제공하며 실전 보상 차등은 추후 후보이다.

### 4.5.1 첫 카페 미션의 목표 배점

첫 카페 미션은 따뜻한 디카페인 라테를 주문했는데 차가운 일반 라테가 나온 상황을 기준으로 다음 항목을 이진 채점한다(DEC-071). 다른 미션은 독립된 성공 조건에 맞춰 항목 수와 배점을 구성하며 이 여섯 항목을 공통으로 강제하지 않는다.

| 항목 | 점수 | 충족 근거 |
| --- | --- | --- |
| 온도가 주문과 다름을 전달 | 5 | 따뜻한 음료를 원했는데 차가운 음료가 나왔다는 차이가 대화에서 확인됨 |
| 카페인 조건이 주문과 다름을 전달 | 5 | 디카페인을 주문했는데 일반 음료가 나왔다는 차이가 확인됨 |
| 원하는 처리 요청 | 10 | 재제조/환불 등 사전에 허용된 처리를 사용자가 요청함 |
| 최종 처리의 온도 조건 해결 | 10 | 최종 제안이 원하는 온도 또는 사전에 허용된 대안 조건을 충족하고 사용자와의 확인이 기록됨 |
| 최종 처리의 카페인 조건 해결 | 10 | 최종 제안이 디카페인 또는 사전에 허용된 대안 조건을 충족하고 사용자와의 확인이 기록됨 |
| 최종 처리에 합의 | 20 | 사용자가 구체적인 허용 처리안을 수락하고, 상대역의 처리 확정까지 확인됨. 제안만 한 상태는 제외 |
| 합계 | 60 | 문제 설명·요청 20점, 최종 해결·합의 40점 |

한 발화로 여러 독립 조건을 충족할 수 있으며 항목마다 별도 발화나 정해진 문장을 요구하지 않는다. 조건 전달과 최종 해결은 구분하고 요청만으로 해결 점수를 주지 않는다. 구체적인 처리 제안에 대한 명확한 수락은 포함된 여러 조건의 확인 근거가 될 수 있다. AI의 일방적 제안이나 맥락 없는 인사·감사만으로 합의를 인정하지 않는다. 문법 오류 자체를 목표 점수에서 중복 감점하지 않되 의미와 합의가 확인되는지는 구분한다. 불명확한 전사·저장 누락·상대역 조건 위반은 사용자 미충족으로 단정하지 않는다. 판정 불가 항목의 제외·달성률 계산은 4.5절을 따른다. 허용 경로·처리 조건은 4.2.1절을 따른다. 주문 취소·전액 환불에 사용자가 동의하고 직원이 처리를 확정하면 온도·카페인 조건 모두의 허용 대안 해결로 인정하고 최종 합의도 인정한다(DEC-081). 환불을 선택했다는 이유로 두 해결 항목을 판정 불가로 제외하지 않는다. 문제 전달·요청 항목은 실제 수행 근거로 별도 판단하며, 예를 들어 온도 불일치만 설명했다면 카페인 불일치 전달을 자동 인정하지 않는다. 경로 변경 전후의 제안·해결을 같은 항목에서 중복 합산하지 않는다.

### 4.5.2 언어 세부 기준과 부분점수

평가 범위는 이번 미션에서 실제 필요했던 수행으로 한정한다(DEC-083). 선택 수준의 정확성·정밀성·상황 적절성은 유지하되, 필요하지 않은 고급 구문·협상·추가 행동을 요구하지 않는다. 쉬운 상황에서도 충분한 근거가 있으면 C 선택자의 충족을 인정할 수 있으며, 폭넓은 능력을 관찰하지 못했다는 이유만으로 이번 수행을 판정 불가로 제외하지 않는다. 서로 다른 수준의 사용자가 같은 점수를 받을 수 있고 결과는 이번 미션 수행 점수이며 종합 수준 인증이 아니다.

문법 안정성은 전체 대화에서 실제 사용한 구조가 필요한 의미 관계를 일관되게 유지했는지 판단한다. 최소 문장 수·고급 구문 개수를 통과 조건으로 두지 않는다. 짧다는 이유만으로 자동 제외하거나 오류가 없다는 이유만으로 충족시키지 않고 요청·설명·응답의 관련 근거와 반대 근거를 함께 확인한다. 단 한 번의 수락만 남은 경우에는 안정성 근거가 부족할 수 있다. 응답 기회와 확인 가능한 수행에서 드러난 어려움은 부분 충족/미충족으로 검토하고, 기록 누락·불명확 전사·실제 기회 부족과 구분한다. 판정 불가의 점수 처리는 4.5절을 따른다.

언어 네 영역은 각각 다음 세 기준으로 구성한다. 다섯 수준은 같은 기준·배점을 사용하고 선택 수준에서 기대하는 수행을 비교한다.

| 영역 | 4점 기준 | 3점 기준 | 3점 기준 |
| --- | --- | --- | --- |
| 문법 | 의미 관계의 정확성 | 문장 구조 | 선택 수준에서의 안정성 |
| 어휘와 표현 | 의도에 맞는 단어 | 자연스러운 단어 조합 | 상황에 적절한 표현 |
| 말의 구성 | 정보 제시 순서 | 이유·대조·조건 연결 | 간결성과 관련성 |
| 상호작용 | 상대 말에 맞는 응답 | 필요한 설명·확인·수정 | 앞선 대화와의 연결 |

세부 기준마다 전체 대화의 수행을 충족·부분 충족·미충족으로 판단하고 각각 해당 배점 전부·절반·0점을 부여한다. 4점 기준의 부분 충족은 2점, 3점 기준은 1.5점이며 항목 합산 시 이 값을 유지한다. 판정 불가는 4.5절에 따라 해당 배점을 만점에서 제외한다. 목표 항목의 이진 채점은 유지한다.

충족은 관찰된 기회에 선택 수준의 기대 수행을 안정적으로 보인 경우다. 부분 충족은 의도가 대체로 전달되지만 반복 오류·불명료함으로 해당 수행이 불안정한 경우이며, 미충족은 확인 가능한 수행과 충분한 관찰 기회에도 어려움이 반복돼 의미 전달·대화 진행에 뚜렷한 지장이 있는 경우다. 사소한 단발 오류로 자동 미충족 판정을 하지 않는다. 같은 오류를 여러 기준에서 자동 중복 감점하지 않으며 각 기준에서 별개의 문제·영향이 확인될 때만 근거를 설명한다. 수준별 구체적인 충족/부분 충족/미충족 사례·관찰 기회 기준은 후속 확정한다. 점수 표시·반올림은 4.5절을 따른다.

## 6. 대화 상태와 예외

계정당 진행 중인 학습 대화는 하나만 허용한다 (`DEC-032`). 재개 가능한 중단 대화도 포함한다. 다른 탭·기기의 중복 연결과 별도 새 대화 시작은 차단하고 기존 대화로 안내한다. 새 대화는 기존 대화를 명시적으로 종료하거나 자동 종료된 뒤 시작한다. 다른 기기 재개는 기존 연결이 중단된 뒤 허용하고 기존 기록 조회는 허용한다.

기본 상태는 미션 준비 → 수행(연습에서 교정/재시도 가능) → 상대역 마무리 → 종료 정리 → 평가·노트 생성이다. 사용자 종료도 정리로 이동한다. 브라우저 이탈·연결 장애는 재개 가능한 중단이며 중단 시각부터 24시간 내 마지막 저장 확정 상태로 재개한다. 재개하면 자동 종료 예약을 취소하고 재중단 시 새 중단 시각을 사용한다. 기한 내 미재개 시 자동 종료하며 미션 차감은 유지하고 해당 미션은 달성 일수에서 제외한다. 정상 침묵·전사 불확실성·장애를 실전 무진전 실패로 바로 취급하지 않는다. 미저장 기록은 복원되지 않을 수 있다.

자동 종료는 저장에 성공한 마지막 확인 턴·실제 재생된 AI 발화·연결된 교정/재시도 기록을 근거로 진행한다. 저장되지 않은 마지막 턴과 미확인·미재생 응답은 요약·학습 근거로 쓰지 않는다. 확인된 사용자 발화가 없으면 빈 학습 노트를 생성하지 않고 세션만 정리한다. 24시간 경계의 재개 요청과 자동 종료는 한쪽만 확정되도록 처리하고, 자동 종료 후 늦게 온 응답은 상태를 되돌리지 못한다. 노트 생성·임시 원문 삭제는 8절의 종료 후 규칙을 따른다.

미션 시작 전 이용 가능 횟수를 확인하고 AI와 사용자 세션 연결 성립 시 차감한다. 연결 시도만으로 차감하지 않는다. 같은 미션의 기한 내 재개는 추가 차감하지 않으며 중복 이벤트·다중 탭으로 이중 차감되지 않아야 한다. 시작한 미션을 계정 잔여량 소진만으로 도중 차단하지 않는다. 연결 성립 신호·직후 장애 환급·장기 연결 보호·재도전 단위는 후속 확정한다. 저장·종료·노트 처리는 이용량과 별도로 보장하며 노트 호출 상한은 유지한다.

AI가 교정 시점·다시 말하기 요청·재시도 결과와 다음 진행을 판단하고, 앱은 진행 상태를 기록·표시·복원한다 (`DEC-010`). 앱은 교육 워크플로를 강제하지 않으며 기록 정합성·중복 방지·명시적 종료·접근 및 비용 통제를 책임진다. 미재생 내용은 전달된 대화나 학습 근거로 취급하지 않고 공급자 맥락과 확인된 재생 범위도 일치해야 한다. 중단·취소 뒤 늦은 응답은 상태를 되돌리지 못한다. 별도 확인 화면 없이 마지막 저장 턴·학습 상태에서 바로 재개한다 (`DEC-031`). 메모리를 잃으면 마지막 저장 성공 시점까지만 복구하며 이후 미저장 기록은 손실될 수 있다 (`DEC-013`). 프롬프트·맥락 조립과 복원 방법은 [음성](design/VOICE.md)·[학습 저장](design/LEARNING-PERSISTENCE.md) 설계를 따른다.

## 7. 주제와 표현 정책

기본 미션은 목표·평가 기준을 사전 설계한다. 개인별 AI 추천은 관심사·난이도·최근 미션을 참고해 후보 상황을 생성하고 선택한 후보만 상세 구성한다. 생성·사용자 지정은 검증된 구조를 우선 활용하고 새 구조는 실행 가능성·중복 없는 채점 항목·허용 대안을 검증한다. 시작 후 기준을 임의 변경하지 않는다. 기술 주제도 지식 정답 시험보다 영어 전달을 연습한다.

추천의 반복 회피·복습 선별은 유효한 최근 6개월 맥락을 사용하되 직접 선택한 미션을 차단하지 않는다. 같은 상황 재도전·의도적 복습은 허용한다. 미션과 관련된 복습 표현 1~2개를 우선 선별하고 무관한 이력 전체를 전달하지 않는다. 최신 유효 수준을 참고하되 난이도 결정 방식은 후속 확정한다. 만료·삭제 기록은 제외하며 노트 보관 기간을 늘리지 않는다. DEC-023의 자유 대화 소재 순환보다 현행 미션 선택을 우선한다(DEC-069).

## 8. 저장 데이터와 학습 노트

DEC-040에 따라 MVP 날짜별 노트는 한국 시간(`Asia/Seoul`)의 대화 종료 날짜에 귀속한다. 자정을 넘긴 대화와 자동 종료도 실제 종료 시각을 사용하고, 노트 생성·재시도가 늦어져도 귀속 날짜를 바꾸지 않는다. 같은 종료 날짜의 세션은 날짜별 노트 하나에 반영한다.

### 저장 실패와 버퍼 유실

대화와 학습 진행 상태는 대화 중 저장하고 정상 종료 시 잔여 기록도 저장한다 (`DEC-013`). 저장 결과를 표시하며 반복 실패·버퍼 상한에도 대화를 정지하지 않는다 (`DEC-031`, `DEC-040`). 실패분은 재시도하고 응답 유실·재전송에도 기록 중복·순서·진행 상태 불일치가 없어야 한다. 주기적 묶음 저장과 재전송 방법은 [학습 저장 설계](design/LEARNING-PERSISTENCE.md#묶음-저장과-두-db-확정)를 따른다.

버퍼 상한에서는 최근 완결 미저장 기록을 우선 유지하고 오래된 단위를 제거한다 (`DEC-047`). 원문·진행 상태·연결된 교정/재시도를 함께 처리하며 이미 저장된 기록은 지우지 않는다. 유실 구간과 가능성을 표시하고 재개·노트에서도 누락을 알린다. 복구 뒤 남은 기록만 재시도하며 빠진 내용을 저장·학습 성공이나 노트 근거로 취급하지 않는다. 무음 폐기·무제한 누적·디스크 우회 저장은 허용하지 않는다. 메모리를 잃으면 마지막 저장 성공 이후의 기록은 손실될 수 있다. 저장·복구 방법과 간격·크기·버퍼 초기값·큰 단위 처리 계약은 [학습 저장 설계](design/LEARNING-PERSISTENCE.md#현재-초기값과-버퍼-유실)에 둔다.

종료 요청 때 잔여 기록 저장이 실패하면 대화는 종료하고 ‘기록 저장 대기’로 표시한다 (`DEC-032`). 메모리가 유지되는 동안 자동 재시도하고 저장 성공 후 확인된 전체 기록으로 노트를 생성한다. 이탈·프로세스 종료로 미저장분을 잃으면 저장된 부분만으로 생성할 수 있음을 안내하며, 확인된 사용자 발화가 없으면 빈 노트를 만들지 않는다. 종료 시점은 최초 종료 요청으로 확정하고 지연 저장·재시도로 원문 최대 24시간 기한을 연장하지 않는다.

### 노트 선별과 생성 결과

종료 선별의 호출·분할 구성과 비용 산정 가정은 [학습 노트 설계](design/LEARNING-NOTE.md#생성검증저장-순서)를 따른다. 이용량과 별도로 종료 노트 호출을 제한하며, 미션 평가와의 호출 구성은 미정이다.

4.4절·6절에 따른 종료 뒤 AI가 앱에 저장된 대화 글과 교정·재시도 기록을 한 번에 검토해 요약·중요 학습 항목·짧은 원문 근거를 선별한다. 앱은 선택된 원문 근거가 실제 기록에 있는지 확인하고 저장한다. 학습 항목은 사용자가 직접 질문한 표현, 반복해서 틀리거나 다시 말하기에 어려움을 보인 표현, 다음 대화에서 다시 활용할 핵심 표현, 대화 중 AI가 추천한 표현을 기준으로 선별한다. AI 추천 표현은 실제 사용자에게 전달된 범위에서 다루며, 추천됐다는 사실을 사용자가 익혔다는 근거로 취급하지 않는다. 항목 수·분량·기준 간 우선순위와 미션 평가 호출 구성·공개 최종 모델은 후속 확정한다([11절](#11-개발-접근과-미결정-사항)). 기존 음성 종료 선별의 기술 계약은 [학습 노트 설계](design/LEARNING-NOTE.md)를 따른다(DEC-064/065).

대화 종료와 노트 완성을 구분하여 종료 후에는 노트를 ‘정리 중’으로 표시하고 사용자는 화면을 떠날 수 있다. 노트 생성 실패는 기존 종료 후 24시간 상한 안에서 자동 재시도하며 MVP에는 사용자 재시도 버튼을 제공하지 않는다. 일부 항목의 원문 근거 검증이 실패하면 해당 항목을 제외하고 검증된 나머지를 저장하며 일부 누락을 표시한다. 유효한 내용이 전혀 없으면 노트 생성 실패로 처리하고, 사용자 발화 자체가 없는 세션은 기존 빈 노트 미생성 규칙을 따른다. 부분 노트의 검증·저장 완료도 원문 즉시 삭제 조건에 해당하며 누락 항목의 추가 생성은 보장하지 않는다. (`DEC-031`).

### 임시 원문의 수명과 백업

전체 대화 글은 임시 저장하고, 추출 후에는 대화 요약·중요 학습 항목·항목별 짧은 원문 근거와 필요한 교정문을 지속 보관하는 방향을 따른다 (`DEC-012`). 전체 대화 글을 계속 보관하는 방식은 채택하지 않는다. 세션 종료 후 요약·중요 학습 항목·원문 근거의 저장 성공을 확인한 뒤 임시 전체 원문을 삭제한다. 추출 또는 저장이 실패하면 재시도를 위해 원문을 임시 유지한다. 종료된 세션의 임시 전체 원문은 명시/자동 종료 시점부터 최대 24시간 유지하며, 요약·학습 항목·원문 근거의 검증과 저장이 완료되면 즉시 삭제한다. 실패 시 그 기한 안에서 재시도하고, 재시도로 기한을 연장하지 않는다. 기한이 지나면 정리 성공 여부와 관계없이 임시 원문을 삭제하므로 미완성 노트의 재생성이 불가능할 수 있다.

외부 환경으로 인한 일시 중단은 DEC-024에 따라 24시간 재개 가능하고 그 뒤 자동 종료한다. 이 24시간은 종료 후 임시 원문 재시도 24시간과 별개이므로 자동 종료와 노트 실패가 이어지면 중단 시점부터 최장 약 48시간 원문이 남을 수 있다.

임시 전체 대화 글은 앱 관리 복원용 백업·스냅샷 대상에서 제외한다 (`DEC-027`). 백업 제외 구성과 장애 복원 한계는 [로컬 운영 설계](design/LOCAL-OPERATIONS.md#백업과-복원-경계)를 따른다. 체험 기록 자동 만료의 백업 처리와 통합 요약의 만료 정보 처리는 후속 합의한다. 재시도·삭제 실패 처리 상세도 별도 합의한다.

### 지속 학습 기록의 보관과 근거

지속 학습 기록(대화 요약·학습 항목·짧은 원문 근거·교정문·날짜별 노트)의 보관 기간은 무료 체험의 경우 각 학습 종료 시점부터 30일, 유료는 기간 제한 없음으로 한다 (`DEC-017`). 무료 기록의 보관 기한 전에 유료로 전환하면 그때 남아 있는 체험 기록도 기간 제한 없이 보관하고, 전환 후 구독이 만료돼도 DEC-018의 기존 유료 기록과 동일하게 유지한다. 유료 이용 중 남긴 지속 학습 기록은 구독 만료만으로 삭제하지 않고 회원 탈퇴 전까지 유지하며 기존 기록의 조회·다운로드를 허용한다 (`DEC-018`). 추가 AI 학습·생성은 별도 이용 권한을 따르고 재구독 시 기존 이력을 이어서 활용한다. MVP의 사용자 조작 삭제는 회원 탈퇴로 한정하고, 탈퇴 시 계정 정보와 연결된 학습 데이터를 모두 삭제한다 (`DEC-019`). 계정을 유지한 세션별 삭제·전체 학습 기록 삭제 기능은 제공하지 않는다. 무료 체험 기록의 30일 만료와 임시 전체 원문 삭제는 별도로 자동 실행한다. 이는 학습 이용량이나 전체 대화 원문의 무제한 보관을 뜻하지 않는다. 만료로 이미 삭제된 체험 기록의 복원은 보장하지 않는다. 탈퇴 백업 삭제는 8.2절을 따른다.

사용자·세션과 연결된 지속 기록에는 직접 질문한 표현·새 표현·다시 말하기 결과·주제 이력·날짜별 노트·다음 복습 항목을 반영한다. 각 요약·학습 항목은 실제 발화 또는 교정 기록의 근거와 연결하며, 전체 원문을 삭제해도 필요한 근거 조각은 함께 조회할 수 있어야 한다.

### 음성과 공급자 데이터 조건

원본 입력·출력 음성은 전송·재생에 필요한 동안만 앱의 휘발성 버퍼에서 처리하고 완료·취소·연결 종료 후 불필요한 버퍼를 해제한다 (`DEC-025`). 앱의 파일·DB·진단 로그·오류 본문·백업에는 원본 음성을 저장하지 않는다. 재연결과 노트 생성은 확인된 전사문·진행 상태를 사용하며 음성 원본은 복구하지 않는다. 임시 전체 전사문은 위 24시간 원칙, 지속 교정 기록은 DEC-017의 요금제별 기간을 따른다.

실제 사용자 연결에는 DEC-025의 공급자 학습 금지·최대 30일 보관을 적용한다. 공급자에 전달되는 음성·전사문과 관련 입력·출력의 대상·기산점·예외·삭제 지원을 계약·설정에서 확인하고, 충족하지 못하면 해당 음성 호출을 시작하지 않는다. 공급자 보관은 앱의 탈퇴 후 24시간 삭제·7일 백업 기한과 별개이며 사용자에게 차이를 고지한다. 공급자 삭제 요청의 구체 방법은 실제 사용자 연결 전에 확정한다. 계정별 접근 제어와 전송·저장 시 보호를 적용한다.

| 적용 범위 | 공급자 데이터 조건 | 허용 범위·제약 |
| --- | --- | --- |
| 실제 사용자·공개 운영 | DEC-025: 모델 학습 금지·보관 최대 30일 | 무료/유료 여부와 무관하게 조건 충족을 확인한 뒤 연결한다. 로컬 시험 예외를 적용하지 않는다. |
| 무료 비공개 로컬 시험 | DEC-056: 공급자 학습 사용·표준 보관 조건 허용 | 개인정보·민감/기밀정보 없는 합성 대화와 개발자 본인 테스트 음성만 사용한다. 다른 사용자 기록·실제 계정 정보·개인 사연은 넣지 않는다. |
| 유료 로컬 후보 실험 | DEC-025 확인을 기본으로 하며 DEC-052의 보관 일수 미확인 후보 유예는 학습 금지 확인과 합성·본인 음성 범위에서 적용 | DEC-056의 무료 시험 예외로 유료 호출 승인을 확대하지 않는다. 후보별 조건·호출 한도는 실험 전에 합의하고 [9.2절의 예산](#92-ai-제공맥락이용량-정책)을 지킨다. |

모든 범위에서 앱의 원본 음성 미저장은 유지한다. 로컬 시험 허용은 실제 사용자 연결·공개 배포 승인이 아니다.

### 일일 노트와 다운로드

학습 맥락은 노트에 함께 저장한다. 노트 상단에는 주제·난이도·복습 표현의 세 가지 맥락을 정리하고, 하단에는 대화 요약·학습 항목·교정과 원문 근거 등 세부 내용을 둔다. 학습 맥락은 노트와 같은 보관·삭제 수명을 따르며 별도 보관으로 기한을 늘리지 않는다. 단일 저장 구조는 [학습 노트 설계](design/LEARNING-NOTE.md#저장-단위와-구성)를 따른다.

일일 Markdown 파일에는 날짜, 주제와 대화 요약, 직접 물어본 표현, 고빈도 표현·구동사·패턴과 예문, 실제 교정과 이유, 유용한 패턴 2~3개, 복습용 플래시카드, 다음 학습 복습을 포함한다. 실제 기록이 부족한 섹션은 빈 항목을 꾸며 채우지 않는다. 사용자는 필요한 날짜별 노트를 하나씩 선택해 Markdown 파일로 개별 다운로드한다 (`DEC-022`). MVP는 여러 노트 일괄 다운로드를 제공하지 않는다. 다운로드 여부는 앱의 기록 보관이나 AI 맥락 선택에 영향을 주지 않는다. ChatGPT 프로젝트 업로드는 선택적 수동 내보내기 안내이며 제품의 주 저장 방식이 아니다.

### 8.1 가입·로그인과 로그인 유지

MVP는 이메일 링크와 Google OAuth/OIDC로 최초 로그인·만료 후 재로그인을 제공하며 다른 소셜 제공자는 포함하지 않는다 (`DEC-020/057`). 같은 앱 계정에 연결한 두 로그인 수단은 동일한 학습 기록을 사용한다. Google 연결은 로그인한 사용자의 명시적 요청으로만 허용하고 이메일 일치만으로 계정을 병합하지 않는다. 같은 이메일의 기존 계정이 있으면 비로그인 Google 로그인을 거부하고 이메일 로그인 후 연결하도록 안내한다. 새 Google 사용자는 제공자가 확인한 이메일로 계정을 만들며 마지막 로그인 수단인 Google 연결은 해제할 수 없다 (`DEC-067`). 구현은 [인증 설계](design/AUTHENTICATION.md), 현재 상태는 [PROGRESS](PROGRESS.md)를 따른다 (`DEC-026`).

| 구분 | 제품 조건 |
| --- | --- |
| 로그인 유지 | 쿠키로 브라우저 재시작에도 유지. 마지막 인증된 이용부터 30일, 유효한 이용 시 갱신. 만료/무효 세션의 자동 연장 금지. 학습 재개·기록 보관 기한과 별개 |
| 로그아웃·탈퇴 | 로그아웃은 해당 세션, 탈퇴는 계정의 모든 세션을 무효화. 탈퇴 전 이메일 또는 연결된 Google 계정으로 다시 본인 확인 |
| 로그인·탈퇴 이메일 링크 | 발급 후 10분·첫 성공 확인 1회. 같은 목적의 재발급은 이전 미사용 링크 무효화. 미리보기/보안 검사는 소비하지 않고 사용자 확인으로 사용. 사용/만료/재발급 오류에는 이유와 새 요청 경로 표시 (`DEC-020/036`) |
| 확인 브라우저 | 실제 링크를 열고 확인한 브라우저에 로그인하며 다른 요청 브라우저는 자동 로그인하지 않음. 대상 이메일 표시·다른 로그인 계정 자동 교체 금지. 탈퇴 재확인과 최종 확정은 원래 세션/브라우저에 귀속 (`DEC-046`) |
| 탈퇴 최종 확인 | 이메일 재확인 성공 후 같은 브라우저에서 10분 안에 확정. 지나면 이메일 재확인부터 다시 시작 (`DEC-036`). Google 재인증도 DEC-067을 따름 |
| 메일 재발송 | 같은 이메일에 30초 간격. 이메일/IP별 횟수 상한은 현재 두지 않으며 메일 서비스 자체 한도와는 별개. 자동 재발송·실패 전용 재요청 UI 없이 기존 요청 화면에서 재요청 |
| 전달 표시 | 요청 접수·메일 시스템 수락·받은편지함 도착을 구분. 실패/전달 불명을 도착 성공으로 표시하지 않음. 실제 서비스·상세 전달 판정/지연·반송 계약은 실제 인증 연결 전 확정 |

인증 경계에서 토큰 추측·재사용·노출, 계정 존재 노출, 세션 탈취·위조, 권한 없는 기록 접근을 검증한다. 인증 저장/처리 방법은 [인증 설계](design/AUTHENTICATION.md)를 따른다.

사용·무효화·만료된 인증 링크/세션 자료와 탈퇴 확인 권한은 효력 종료 후 24시간 안에 삭제한다. 미인증 이메일 요청/발급 제어 자료는 마지막 요청 후 24시간 내 새 요청이 없고 유효 링크도 없으면 삭제한다. 정상 계정·유효 세션은 보존하고 탈퇴 24시간 상한을 우선한다. 진단 로그 7일 수명과 구분하며 로컬 실행 한계는 [로컬 운영](design/LOCAL-OPERATIONS.md)을 따른다.

백업 복원 후에는 기존 세션·미사용 링크·탈퇴 권한을 전부 무효화한 뒤 개방하고 이메일 또는 Google로 재로그인한다 (`DEC-057`). 일반 앱/DB 재시작에는 전체 무효화를 적용하지 않는다. 탈퇴·만료 상태 재적용은 별도 의무이며 인증 무효화만으로 데이터 부활 방지가 끝나지는 않는다.

### 8.2 탈퇴 데이터 일괄 삭제와 백업 기한

회원 탈퇴가 확정되면 즉시 계정 접근을 차단하고 모든 로그인 세션을 무효화한다 (`DEC-021`). 앱 관리 계정 정보·연결 학습 데이터는 정해진 시각의 일괄 작업으로 각 탈퇴 확정 시점부터 24시간 이내에 삭제한다. 대기 중에도 기록 조회·AI 이용·진행 중 작업의 결과 저장을 차단한다. 재시작·실패·재시도로 대상을 잃거나 최초 기한을 연장하지 않아야 한다. 기한 작업의 지속 목록·정시 실행과 재시도 여유를 포함한 실행 계약은 [로컬 운영 설계](design/LOCAL-OPERATIONS.md#기한-작업)를 따른다 (`DEC-028`).

탈퇴 계정의 데이터가 포함된 앱 관리 백업은 탈퇴 확정 시점부터 7일 이내에 해당 데이터를 제거하거나 해당 백업을 만료·폐기한다. 이 기한은 서비스 데이터 삭제 시점부터 다시 계산하지 않는다. 삭제 대기 중 생성된 백업도 같은 기한을 적용한다. 남아 있는 백업은 접근을 제한하고, 복원 시에는 탈퇴·삭제 상태를 다시 적용한 뒤 서비스 접근을 허용하여 계정이나 데이터가 되살아나지 않도록 한다. 이를 충족하는 백업·복원 방식은 기술 선정 시 검증한다. 공급자 측 데이터 보관·삭제 조건은 별도로 확인하며, 이번 정책으로 공급자 측 삭제 완료를 보장하지 않는다.

## 9. 품질 지표와 검증

첫 대화 완료율, 대화당 사용자 발화 시간, 교정 후 다시 말하기 성공률, 다음 대화에서 표현 재사용률, 7일 재방문율을 추적한다. AI 품질은 턴당 질문 수, 임의 종료, 근거 없는 피드백, 과도한 교정, 주제 반복에 대한 평가 시나리오로 검증한다. 목표 수치는 프로토타입과 사용자 테스트의 기준값을 확인한 뒤 정한다.

로컬 개발·AI 후보 실험의 진단 로그는 기록 시각부터 7일 후 자동 삭제한다. 사본·내보내기도 원래 기한을 유지한다(DEC-037). 운영 저장소/기간은 공개 운영 전에 정하며 로컬 저장·정리는 [로컬 운영 설계](design/LOCAL-OPERATIONS.md#로컬-진단-로그)를 따른다(DEC-038).

DEC-040에 따라 로컬 진단 로그는 개발자 본인만 접근하고 앱 내 로그 조회 화면·외부 자동 전송을 제공하지 않는다. 앱 실행에 필요한 로컬 프로세스 접근은 허용한다. 실제 전사문·교정 내용을 별도 평가 파일로 보관하지 않고 합성 사례와 점수·지연·비용·실패 유형 등 내용 없는 평가 결과를 남긴다. 평가 결과의 텍스트 필드에도 실제 발화를 복사하지 않는다. 기존 앱 학습 기록의 보관 정책은 유지한다. 이 결정은 평가 집계의 무기한 보관을 승인하지 않으며, 진단 로그로 남긴 결과는 기존 7일 수명을 따른다.

지연·가용성·비용·복구 목표는 초기 측정과 허용 예산에 근거해 합의한다. 테스트 환경의 장애 실험과 실제 운영 장애는 구분한다. 사용자 발화와 기록을 사용하는 측정·보관 방식은 데이터 정책 합의와 접근 통제 후 적용한다.

초기 목표는 주요 흐름의 기준선 확보와 병목 식별·개선·재검증이다 (`DEC-007`). 성능 향상 자체를 보장하지 않으며 측정 뒤 목표의 적절성을 재검토한다. 지연·처리량·가용성·복구 시간의 수치는 아직 확정하지 않았다. 측정 조건·비교 절차·결과 기록은 [검증 설계](design/ENGINEERING-VALIDATION.md)를 따른다.

### 9.2 AI 제공·맥락·이용량 정책

Talkie가 API를 제공하고 비용을 부담한다. 초기 공급자는 하나로 시작하되 실시간 대화와 교정·요약 모델은 역할에 따라 분리할 수 있다 (`DEC-008`). 공개 경로의 공급자·모델·연결 방식은 선택한 경로의 품질·지연·비용·끼어들기와 기록 정합성 검증 후 합의한다. 모든 후보를 먼저 시험할 필요는 없으며 운영 중 실제 비용·품질·오류를 보고 조정한다(DEC-066). [8절의 공급자 데이터 조건](#provider-data-policy)을 적용하며 로컬 시험을 최종 채택·공개 배포 승인으로 취급하지 않는다. 구현 경계·연결 경로는 [음성 설계](design/VOICE.md), 완료 기준은 [TASKS](TASKS.md#선행-관계)를 따른다.

새 학습마다 새 세션을 만들고 AI에는 현재 대화·확인된 진행 상태·짧은 학습 정보와 관련 복습 기록을 전달한다. 소재 선택은 [7절](#7-주제와-표현-정책)을 따르며 이전 이력 전체를 매번 AI에 전달하지 않는다. 선택한 상황·표현과 필요한 반복 회피 정보만 분량 상한 안에서 제공한다. 이전 학습에서 가져오는 맥락은 주제·시작 난이도·복습 표현이며, 주제와 복습 표현의 조회 기간은 7절을 따른다. 시작 난이도는 최신 유효한 값을 참고하고 학습 공백이 길면 현재 반응에 따라 조절한다. 이 기간 제한을 진행 중인 대화의 재개 기록에 적용하지 않는다. 조립·요약 방식·상한 수치는 [음성 설계](design/VOICE.md#튜터-프롬프트와-컨텍스트-경계), 재개 계약은 [6절](#6-대화-상태와-예외)을 따른다.

대화 연결·기록·인증의 구성은 [DESIGN](DESIGN.md#구성-요소와-데이터-흐름)을 따른다. API 비밀키는 서버에서 관리한다. 첫 운영 배포부터 누구나 가입할 수 있고, 가입 후 정해진 무료 체험량 안에서 학습하는 방향을 채택한다 (`DEC-014`). 무료 체험량·갱신 여부·소진 시 동작과 유료 제공 시점은 미정이다. 계정당 음성 연결은 경로·기기를 합쳐 하나만 허용하고 기존 인증·소유권 통제를 유지한다.

이용 단위는 DEC-069에 따라 연결 시간 이용권에서 미션 횟수로 전환한다. 시작 전 잔여량 확인·연결 성립 차감·동일 미션 재개·만료 처리는 6절을 따른다. 규모가 다른 미션의 차감 단위·가격·포함량·기간/갱신·체험량은 비용 측정 후 확정한다. 평균 시간은 원가 산정 자료이며 고정 종료 시간이 아니다. 주간 실제 과금 대조·공급자 지출 상한/알림·내용 없는 계측·종료 노트의 별도 호출 제한은 유지한다. 기능별 비용을 분리할 수 없으면 추정·미확인으로 표시하고 무료 표본을 유료 원가로 확정하지 않는다. 추가 금액을 청구하는 지갑은 제공하지 않는다.

최초 로컬 AI 후보 비교 전체의 실험 예산은 세금·환율·수수료를 포함해 총 3만 원으로 제한한다 (`DEC-016`). 날짜·실패·재시도로 초기화하지 않는다. 집행액·진행 중 호출의 예약 비용·다음 호출의 최대 비용을 합산해 한도를 넘으면 신규 호출을 막는다. 호출 시간·출력량·재시도 횟수를 제한하고, 최대 비용을 계산할 수 없으면 유료 호출을 시작하지 않는다. 자동 충전·무제한 재시도는 사용하지 않으며 청구 지연·추정 오차를 기록한다. 공급자 데이터 조건은 [8절의 적용 범위](#provider-data-policy)를 따른다. 새 유료 후보 시험의 배분·표본 수·호출 상한은 호출 전에 확정하며 품질은 직접 말하고 들으며 확인한다. 후보 확장 비교는 DEC-066에 따라 공개 선행 조건이 아니다. 부족하면 범위를 줄이거나 추가 예산을 논의한다. 공개 운영비·클라우드 자원 생성은 이번 예산의 승인 범위가 아니다.

### 9.3 전환의 구현 상태와 남은 결정

미션 전환의 계약은 이 PRD를 따르며 기존 자유 대화·교정·시험 시간 보호 코드가 이를 자동 대체하지 않는다. 구현·검증 상태는 [PROGRESS](PROGRESS.md)·[TASKS](TASKS.md), 구현 계약과 미정은 [미션 설계](design/MISSIONS.md)를 따른다(DEC-069).

## 10. 1차 범위 밖

영상 아바타, 세밀한 음소별 발음 점수, 강의 콘텐츠 대량 제작, 학습자 간 소셜 기능, ChatGPT 프로젝트 자동 업로드, 고객 API 키 및 ChatGPT 구독 연결은 첫 버전 범위에서 제외한다.
