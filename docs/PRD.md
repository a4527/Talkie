# Talkie 제품 요구사항 문서

상태: 초안 v0.4
작성일: 2026-10-15
갱신일: 2026-10-29
제품 형태: 반응형 영어 회화 웹서비스

이 문서는 사용자에게 제공할 동작과 제품이 지켜야 할 정책·제약의 기준이다.

## 1. 목적

한국어를 모국어로 사용하는 초중급 학습자가 매일 실제 상황에 가까운 영어 대화를 지속하고, 자신의 표현을 자연스럽게 개선하며, 배운 내용을 다음 대화에서 재사용하도록 돕는다. 문법 암기보다 말하기·듣기·어휘·문장 구성 능력과 말할 자신감의 향상을 목표로 한다.

## 2. 대상 사용자와 핵심 가치

첫 대상은 일상 및 업무 상황에서 영어를 말하고 싶지만 대화 상대를 구하기 어렵거나 실수를 부담스러워하는 한국어 화자다. 서비스 이용은 만 18세 이상으로 한정하며 가입 시 연령 확인 방식은 구현 전에 정한다 (`DEC-051`). 웹 브라우저에서 짧은 회화를 자주 진행하고 개인별 복습으로 이어가는 경험을 제공한다. 세션·이용 기간의 연결 허용 시간을 관리하고 주간 실제 API 과금과 대조해 기준을 조정한다(DEC-062). 외부 환경으로 중단돼 종료하지 못하면 24시간 재개 기회를 준 뒤 자동 정리한다 (`DEC-024`). IT·클라우드·AWS·AI·개발 등의 관심 주제도 지식 시험이 아닌 영어 표현 연습에 활용한다.

## 3. 제품 원칙

1. 학습자가 직접 말하는 시간이 우선이다. 음성 응답은 짧고, 설명은 필요한 경우에만 제공한다.
2. 기본 대화 언어는 영어다. 이해가 어려우면 쉬운 영어로 먼저 설명하고, 그래도 어렵다면 한국어를 사용한다.
3. 질문은 하나부터 시작하고 현재 응답 부담에 따라 직접 연결된 질문 두 개까지 묶을 수 있다. 난이도는 고정 등급 없이 연속적으로 조절한다. 상대처럼 반응하고 의견이나 가상 상황을 더하며 질문만 연속하지 않는다.
4. 기본 종료는 사용자의 명확한 종료 의사에 따른다. 네트워크·브라우저 등 외부 환경으로 연결이 끊겨 종료하지 못한 경우에는 일시 중단으로 두고 24시간 재개 기회를 준다. 그동안 재개하지 않으면 자동 종료하고 저장된 실제 대화로 노트를 생성한다 (`DEC-024`). 연결 허용 시간 한도에 따른 제한·종료의 상세 경계는 구현 전에 정한다(DEC-062). 침묵이나 대기 자체를 별도 종료 사유로 삼지는 않는다.
5. 교정과 새 표현 소개 뒤에는 학습자가 영어로 다시 말해야 다음 대화로 넘어간다.
6. 학습 노트와 요약은 실제 대화 및 저장된 학습 이력에 근거한다. 확인되지 않은 과거 학습이나 발생하지 않은 오류를 만들지 않는다.
7. 다른 서비스의 구현·콘텐츠·화면을 복제하지 않고, 관찰한 학습 경험을 독립적인 웹 경험으로 설계한다.

### 3.1 요구사항의 구분

- **확정 요구사항**: 서비스 목적·사용자 지시·승인된 결정에서 나온 조건이다. 기존 F-01~F-12와 승인된 보안·데이터 보호 원칙을 유지한다. 변경 시 근거와 영향을 검토한다.
- **초기 목표**: 달성하려는 목표이며 설정 근거와 재검토 시점을 명시한다. 측정 결과에 따라 조정한다.
- **검증할 가정**: 확인되지 않은 예상이며 검증 방법과 판단에 필요한 관측 결과를 정의한다. 기술적 가정은 [DESIGN.md](DESIGN.md)에 둔다.
- **미정 항목**: 결정에 필요한 정보와 결정 시점을 명시한다 (11절).

이 구분은 구현 상태와 별개다. 확정 요구사항도 수용 기준을 검증하기 전에는 완료로 표시하지 않는다. 원본 음성의 앱 내 휘발성 처리와 공급자 학습 금지·보관 상한은 DEC-025로 확정했지만 실제 공급자의 충족 여부는 미검증인 것처럼, 정책과 구현·검증 상태를 구분한다.

## 4. 주요 사용자 흐름

여기에는 제품 약속과 지켜야 할 조건만 요약한다. 단계별 흐름과 분기·예외는 [사용자 흐름 설계](design/USER-FLOWS.md)를 따른다.

### 4.1 시작

사용자가 시작 문구나 시작 버튼으로 세션을 연다. [7절의 선택 정책](#7-주제와-표현-정책)에 따라 주제·상황과 복습 표현을 고르고, 짧은 소개와 영어 질문 하나로 시작한다. 기록이 없으면 이전 학습을 아는 척하지 않는다. 상세: [시작 흐름](design/USER-FLOWS.md#1-시작).

### 4.2 일반 대화

학습자의 답변에 먼저 자연스럽게 반응하고 단답에도 대화를 이어간다. 튜터의 의견이나 경험은 **가상**으로 덧붙인다. 난이도는 쉬운 문장에서 시작해 응답에 따라 조금씩 높이며 긴 답변을 강요하지 않는다. 상세: [일반 대화 흐름](design/USER-FLOWS.md#2-일반-대화).

### 4.3 교정과 다시 말하기

MVP는 대화 중 AI가 필요하다고 판단할 때 교정하는 단일 모드로 시작한다 (`DEC-011`). 교정 끄기·종료 후 일괄 교정 옵션은 이후 범위다. 교정은 의미 전달을 막는 오류, 이해 가능한 문법 오류, 어색한 표현 순으로 우선하고, 대화 흐름을 유지하며 가장 유용한 수정 하나를 제시한다. 불확실한 교정은 확인하거나 보류한다. 교정·표현 질문 뒤에는 다시 말하기를 요청하고 성공하면 현재 난이도에 맞는 질문으로 대화를 잇는다. 상세: [교정 흐름](design/USER-FLOWS.md#3-교정과-다시-말하기).

### 4.4 종료와 복습

종료 버튼은 추가 확인 없이 종료하고, 음성 종료 의사는 한 번 확인한 뒤 동의하면 종료한다 (`DEC-040`). 종료하면 앱이 저장한 글을 입력으로 한국어 요약과 종료 피드백(대화 주제·주요 내용, 잘한 점 1~2개, 실제 주요 오류 최대 3개, 핵심 표현, 다음에 쓸 표현)을 제공하고, 중요한 표현 2~3개는 마무리 복습에서 다시 말할 수 있게 한다. 입력·보관 범위와 선별 기준은 8절을 따른다. 상세: [종료 흐름](design/USER-FLOWS.md#4-종료와-복습).

## 6. 대화 상태와 예외

계정당 진행 중인 학습 대화는 하나만 허용한다 (`DEC-032`). 재개 가능한 중단 대화도 포함한다. 다른 탭·기기의 중복 연결과 별도 새 대화 시작은 차단하고 기존 대화로 안내한다. 새 대화는 기존 대화를 명시적으로 종료하거나 자동 종료된 뒤 시작한다. 다른 기기 재개는 기존 연결이 중단된 뒤 허용하고 기존 기록 조회는 허용한다.

기본 상태는 `시작 준비 → 일반 대화 → 다시 말하기 대기 → 일반 대화 → 종료 정리 → 노트 생성`이다. 네트워크나 브라우저 중단은 `일시 중단`으로 이동하고 재개 시 마지막 확인된 턴으로 돌아간다. 기본 종료는 사용자가 명시적으로 요청할 때 `종료 정리`로 이동한다. 예외적으로 외부 환경에 의한 중단이 확인된 시각부터 24시간 동안 재개되지 않으면 앱이 자동 종료·노트 생성으로 이동한다 (`DEC-024`). 기한 전에 재개하면 해당 자동 종료 예약을 취소하고, 다시 외부 환경으로 중단되면 새 중단 시각부터 계산한다. 정상 연결 중에도 연결 허용 시간의 경계에 도달할 수 있으며, 경계 발화·사전 안내·종료 처리는 구현 전에 구체화한다(DEC-062). 음성 인식이 불명확하면 성급히 교정하지 않고 짧게 다시 말해 달라고 요청한다. 정상 연결 중 발화가 없다는 이유만으로 종료하지 않으며, 연결 허용 시간은 계속 계산한다. 외부 환경 중단 시에는 위 재개·자동 종료 규칙을 따른다.

자동 종료는 저장에 성공한 마지막 확인 턴·실제 재생된 AI 발화·연결된 교정/재시도 기록을 근거로 진행한다. 저장되지 않은 마지막 턴과 미확인·미재생 응답은 요약·학습 근거로 쓰지 않는다. 확인된 사용자 발화가 없으면 빈 학습 노트를 생성하지 않고 세션만 정리한다. 24시간 경계의 재개 요청과 자동 종료는 한쪽만 확정되도록 처리하고, 자동 종료 후 늦게 온 응답은 상태를 되돌리지 못한다. 노트 생성·임시 원문 삭제는 8절의 종료 후 규칙을 따른다.

연결 허용 시간이 부족하면 새 유료 음성 연결·AI 대화 요청을 열지 않는다(DEC-062). 이미 확인된 대화 기록의 저장·종료 정리와 24시간 안에 재개한 대화의 기록 처리는 가능해야 한다. 사용자에게 시작 전 이용 가능 상태와 이용 기간을 알리고 경계가 가까워지면 마무리를 안내한다. 정확히 어느 시점에 새 질문을 멈추고 진행 중인 교정/재시도를 어떻게 마칠지는 연결당 상한과 공급자 종료 동작을 검증해 정한다. 종료 노트는 대화 시간과 별도의 호출·재시도 제한을 따르며, 시간 소진만으로 저장된 학습 결과를 버리지 않는다.

AI가 교정 시점·다시 말하기 요청·재시도 결과와 다음 대화 진행을 판단하고 앱은 전달받은 학습 진행 상태를 기록·표시·복원한다 (`DEC-010`). 앱은 교육 워크플로를 강제하지 않으며, 기록 정합성·중복 방지·명시적 종료·접근 및 비용 통제는 계속 책임진다. 프롬프트·선택된 학습자 정보·현재 진행 상태로 AI 판단에 영향을 주고 고정 시나리오 평가로 검증하며 조정한다. MVP 교정 모드는 4.3절, 기록 범위와 저장 방식은 8절을 따른다. 끼어들기 시 생성된 내용과 실제 재생된 범위를 구분하며, 미재생 내용을 전달 완료된 대화나 학습 노트의 근거로 취급하지 않는다. 공급자 측 대화 맥락도 확인된 재생 범위와 맞추도록 검증한다. 중단·취소 후 늦게 도착한 응답은 현재 상태를 되돌리지 못한다. 재연결 시 복구 가능한 마지막 확인 턴과 그에 대응하는 교정 대기 같은 학습 진행 상태를 AI에 전달한다. 별도 재개 확인 화면 없이 저장된 마지막 확인 턴·상태에서 바로 재개한다 (`DEC-031`). 앱 메모리를 잃은 경우 마지막 저장 성공 시점까지만 복구할 수 있으며 이후 미저장 기록은 손실될 수 있다 (`DEC-013`).

## 7. 주제와 표현 정책

일상, 식당·카페·공항·호텔 등 실제 상황, 사회적 대화, 경험, 의견, 가정, 문제 해결, IT 관심사를 순환한다. 경험·비교·이유·선택·가정·역할극 질문을 다양하게 사용한다. 고빈도 구동사, 연결 표현, 리액션, 의견 표현을 현재 대화에 맞게 한두 개씩 소개하고 이후 재사용 기회를 만든다. 기술 주제는 지식을 맞히는 퀴즈가 아니라 생각을 영어로 설명하는 연습으로 만든다.

주제·상황·표현 선택은 `DEC-023`을 따른다. MVP의 주제·상황 중복 회피와 복습 표현 선택은 보관 중이며 접근 가능한 최근 6개월의 학습 맥락을 기준으로 한다. 해당 범위에서 아직 다루지 않은 상황·대화 내용을 우선 선택하고, 범위 밖 상황은 다시 선택할 수 있다. 복습 표현을 다시 연습하면 마지막 연습 시점부터 조회 범위에 다시 포함한다. 6개월은 테스트에서 조정할 초기 기준이며 노트 보관·삭제 기간을 바꾸지 않는다. 이미 만료·삭제된 기록은 제외한다. 같은 주제도 다른 내용이면 허용한다. 예를 들어 식당에서 주문하기·잘못 나온 음식 설명하기·일행과 계산 나누기는 서로 다른 회화 내용으로 다룬다. 다양성은 주제 이름뿐 아니라 상황·역할·대화 목표·질문의 의도와 내용으로 판단하며, 문장이나 고유명사만 바꾼 같은 질문의 불필요한 반복은 피한다.

미경험 후보가 부족하면 가장 오래전에 다룬 상황부터 재사용하되 질문과 전개를 달리한다. 새 표현은 사용 이력을 참고해 덜 다루거나 아직 연습하지 않은 표현을 우선하고, 지난번 어려웠던 표현은 새 상황에 자연스럽게 넣어 복습한다. 의도적 복습·교정 재시도·인식 확인은 불필요한 반복과 구분한다. 무작위 보충도 이 선택 기준을 충족하는 후보에서 수행한다. 후보 구성·질문 이력 표현/저장 형식·유사성 판정 기술·선택 비중과 분량 상한은 구현·평가 전에 구체화한다. 전체 대화 원문 보관을 늘리거나 삭제된 기록을 반복 회피 목적으로 계속 남기는 정책은 채택하지 않는다.

## 8. 저장 데이터와 학습 노트

DEC-040에 따라 MVP 날짜별 노트는 한국 시간(`Asia/Seoul`)의 대화 종료 날짜에 귀속한다. 자정을 넘긴 대화와 자동 종료도 실제 종료 시각을 사용하고, 노트 생성·재시도가 늦어져도 귀속 날짜를 바꾸지 않는다. 같은 종료 날짜의 세션은 날짜별 노트 하나에 반영한다.

### 저장 실패와 버퍼 유실

대화 글과 학습 진행 상태는 주기적으로 묶어 저장하고 정상 종료 시 잔여 기록도 저장한다 (`DEC-013`). 저장 성공·실패를 표시하며, 실패가 지속되거나 미저장 버퍼가 상한에 도달해도 대화를 정지하지 않는다 (`DEC-031`, `DEC-040`). 성공 미확인 기록은 다음 주기에 새 기록과 함께 재시도한다. 응답 유실 뒤 재전송해도 기록이 중복되거나 순서·진행 상태가 어긋나지 않아야 한다.

버퍼 상한에서는 최근 완결 미저장 기록을 우선 유지하고 오래된 단위를 제거한다 (`DEC-047`). 원문·진행 상태·연결된 교정/재시도를 함께 처리하며 이미 저장된 기록은 지우지 않는다. 유실 구간과 가능성을 표시하고 재개·노트에서도 누락을 알린다. 복구 뒤 남은 기록만 재시도하며 빠진 내용을 저장·학습 성공이나 노트 근거로 취급하지 않는다. 무음 폐기·무제한 누적·디스크 우회 저장은 허용하지 않는다. 메모리를 잃으면 마지막 저장 성공 이후의 기록은 손실될 수 있다. 반복 저장 실패를 줄이는 복구·정합성 검증이 필요하며 간격·크기·버퍼 초기값과 남은 큰 단위 처리 계약은 [학습 저장 설계](design/LEARNING-PERSISTENCE.md#현재-초기값과-버퍼-유실)에 둔다.

종료 요청 때 잔여 기록 저장이 실패하면 대화는 종료하고 ‘기록 저장 대기’로 표시한다 (`DEC-032`). 메모리가 유지되는 동안 자동 재시도하고 저장 성공 후 확인된 전체 기록으로 노트를 생성한다. 이탈·프로세스 종료로 미저장분을 잃으면 저장된 부분만으로 생성할 수 있음을 안내하며, 확인된 사용자 발화가 없으면 빈 노트를 만들지 않는다. 종료 시점은 최초 종료 요청으로 확정하고 지연 저장·재시도로 원문 최대 24시간 기한을 연장하지 않는다.

### 노트 선별과 생성 결과

초기 설계·비용 산정은 회화 한 세션 평균 10분을 가정한다. 실제 이용 평균을 측정한 값이나 강제 종료 시간은 아니다. 노트는 저장 구간별 중간 요약 없이 종료 후 저장된 기록을 한 번에 선별한다. 대화 종료 뒤 이용 기간의 연결 허용 시간이 남으면 새 대화를 시작할 수 있다. 연결 시간과 노트 호출의 제한 방향은 DEC-062를 따르며 구체 수치·경계 동작은 후속으로 정한다.

사용자 명시 종료 또는 DEC-024/060에 따른 자동 종료 뒤 AI가 앱에 저장된 대화 글과 교정·재시도 기록을 한 번에 검토해 요약·중요 학습 항목·짧은 원문 근거를 선별한다. 앱은 선택된 원문 근거가 실제 기록에 있는지 확인하고 저장한다. 학습 항목은 사용자가 직접 질문한 표현, 반복해서 틀리거나 다시 말하기에 어려움을 보인 표현, 다음 대화에서 다시 활용할 핵심 표현, 대화 중 AI가 추천한 표현을 기준으로 선별한다. AI 추천 표현은 실제 사용자에게 전달된 범위에서 다루며, 추천됐다는 사실을 사용자가 익혔다는 근거로 취급하지 않는다. 항목 수·분량·기준 간 우선순위와 사용할 모델은 미정이며 사례 평가로 조정한다.

대화 종료와 노트 완성을 구분하여 종료 후에는 노트를 ‘정리 중’으로 표시하고 사용자는 화면을 떠날 수 있다. 노트 생성 실패는 기존 종료 후 24시간 상한 안에서 자동 재시도하며 MVP에는 사용자 재시도 버튼을 제공하지 않는다. 일부 항목의 원문 근거 검증이 실패하면 해당 항목을 제외하고 검증된 나머지를 저장하며 일부 누락을 표시한다. 유효한 내용이 전혀 없으면 노트 생성 실패로 처리하고, 사용자 발화 자체가 없는 세션은 기존 빈 노트 미생성 규칙을 따른다. 부분 노트의 검증·저장 완료도 원문 즉시 삭제 조건에 해당하며 누락 항목의 추가 생성은 보장하지 않는다. (`DEC-031`).

### 임시 원문의 수명과 백업

전체 대화 글은 임시 저장하고, 추출 후에는 대화 요약·중요 학습 항목·항목별 짧은 원문 근거와 필요한 교정문을 지속 보관하는 방향을 따른다 (`DEC-012`). 전체 대화 글을 계속 보관하는 방식은 채택하지 않는다. 세션 종료 후 요약·중요 학습 항목·원문 근거의 저장 성공을 확인한 뒤 임시 전체 원문을 삭제한다. 추출 또는 저장이 실패하면 재시도를 위해 원문을 임시 유지한다. 종료된 세션의 임시 전체 원문은 명시/자동 종료 시점부터 최대 24시간 유지하며, 요약·학습 항목·원문 근거의 검증과 저장이 완료되면 즉시 삭제한다. 실패 시 그 기한 안에서 재시도하고, 재시도로 기한을 연장하지 않는다. 기한이 지나면 정리 성공 여부와 관계없이 임시 원문을 삭제하므로 미완성 노트의 재생성이 불가능할 수 있다.

외부 환경으로 인한 일시 중단은 DEC-024에 따라 24시간 재개 가능하고 그 뒤 자동 종료한다. 이 24시간은 종료 후 임시 원문 재시도 24시간과 별개이므로 자동 종료와 노트 실패가 이어지면 중단 시점부터 최장 약 48시간 원문이 남을 수 있다.

임시 전체 대화 글은 앱 관리 복원용 백업·스냅샷 대상에서 제외한다 (`DEC-027`). 백업 제외 구성과 장애 복원 한계는 [로컬 운영 설계](design/LOCAL-OPERATIONS.md#백업과-복원-경계)에 두고 D-02에서 검증한다. 체험 기록 자동 만료의 백업 처리와 통합 요약의 만료 정보 처리는 후속 합의한다. 재시도·삭제 실패 처리 상세도 별도 합의한다.

### 지속 학습 기록의 보관과 근거

지속 학습 기록(대화 요약·학습 항목·짧은 원문 근거·교정문·날짜별 노트)의 보관 기간은 무료 체험의 경우 각 학습 종료 시점부터 30일, 유료는 기간 제한 없음으로 한다 (`DEC-017`). 무료 기록의 보관 기한 전에 유료로 전환하면 그때 남아 있는 체험 기록도 기간 제한 없이 보관하고, 전환 후 구독이 만료돼도 DEC-018의 기존 유료 기록과 동일하게 유지한다. 유료 이용 중 남긴 지속 학습 기록은 구독 만료만으로 삭제하지 않고 회원 탈퇴 전까지 유지하며 기존 기록의 조회·다운로드를 허용한다 (`DEC-018`). 추가 AI 학습·생성은 별도 이용 권한을 따르고 재구독 시 기존 이력을 이어서 활용한다. MVP의 사용자 조작 삭제는 회원 탈퇴로 한정하고, 탈퇴 시 계정 정보와 연결된 학습 데이터를 모두 삭제한다 (`DEC-019`). 계정을 유지한 세션별 삭제·전체 학습 기록 삭제 기능은 제공하지 않는다. 무료 체험 기록의 30일 만료와 임시 전체 원문 삭제는 별도로 자동 실행한다. 이는 학습 이용량이나 전체 대화 원문의 무제한 보관을 뜻하지 않는다. 만료로 이미 삭제된 체험 기록의 복원은 보장하지 않는다. 탈퇴 백업 삭제는 8.2절을 따른다.

사용자·세션과 연결된 지속 기록에는 직접 질문한 표현·새 표현·다시 말하기 결과·주제 이력·날짜별 노트·다음 복습 항목을 반영한다. 각 요약·학습 항목은 실제 발화 또는 교정 기록의 근거와 연결하며, 전체 원문을 삭제해도 필요한 근거 조각은 함께 조회할 수 있어야 한다.

### 음성과 공급자 데이터 조건

원본 입력·출력 음성은 전송·재생에 필요한 동안만 앱의 휘발성 버퍼에서 처리하고 완료·취소·연결 종료 후 불필요한 버퍼를 해제한다 (`DEC-025`). 앱의 파일·DB·진단 로그·오류 본문·백업에는 원본 음성을 저장하지 않는다. 재연결과 노트 생성은 확인된 전사문·진행 상태를 사용하며 음성 원본은 복구하지 않는다. 임시 전체 전사문은 위 24시간 원칙, 지속 교정 기록은 DEC-017의 요금제별 기간을 따른다.

실제 사용자 연결에는 DEC-025의 공급자 학습 금지·최대 30일 보관을 적용한다. 공급자에 전달되는 음성·전사문과 관련 입력·출력의 대상·기산점·예외·삭제 지원을 계약·설정에서 확인하고, 충족하지 못하면 해당 음성 호출을 시작하지 않는다. 공급자 보관은 앱의 탈퇴 후 24시간 삭제·7일 백업 기한과 별개이며 사용자에게 차이를 고지한다. 공급자 삭제 요청의 구체 방법은 실제 사용자 연결 전에 확정한다. 계정별 접근 제어와 전송·저장 시 보호를 적용한다.

| 적용 범위 | 공급자 데이터 조건 | 허용 범위·제약 |
| --- | --- | --- |
| 실제 사용자·공개 운영 | DEC-025: 모델 학습 금지·보관 최대 30일 | 무료/유료 여부와 무관하게 조건 충족을 확인한 뒤 연결한다. 로컬 시험 예외를 적용하지 않는다. |
| 무료 비공개 로컬 시험 | DEC-056: 공급자 학습 사용·표준 보관 조건 허용 | 개인정보·민감/기밀정보 없는 합성 대화와 개발자 본인 테스트 음성만 사용한다. 다른 사용자 기록·실제 계정 정보·개인 사연은 넣지 않는다. |

### 일일 노트와 다운로드

학습 맥락은 노트에 함께 저장한다. 노트 상단에는 주제·난이도·복습 표현의 세 가지 맥락을 정리하고, 하단에는 대화 요약·학습 항목·교정과 원문 근거 등 세부 내용을 둔다. 노트와 별도의 학습 맥락 저장소를 만들지 않는다.

일일 Markdown 파일에는 날짜, 주제와 대화 요약, 직접 물어본 표현, 고빈도 표현·구동사·패턴과 예문, 실제 교정과 이유, 유용한 패턴 2~3개, 복습용 플래시카드, 다음 학습 복습을 포함한다. 실제 기록이 부족한 섹션은 빈 항목을 꾸며 채우지 않는다. 사용자는 필요한 날짜별 노트를 하나씩 선택해 Markdown 파일로 개별 다운로드한다 (`DEC-022`). MVP는 여러 노트 일괄 다운로드를 제공하지 않는다. 다운로드 여부는 앱의 기록 보관이나 AI 맥락 선택에 영향을 주지 않는다. ChatGPT 프로젝트 업로드는 선택적 수동 내보내기 안내이며 제품의 주 저장 방식이 아니다.

### 8.1 가입·로그인과 로그인 유지

MVP는 이메일 로그인 링크와 Google OAuth/OIDC 로그인을 함께 제공한다 (`DEC-020`, `DEC-057`). 앱이 로그인 링크 발급·검증과 인증 세션 기록·무효화를 직접 구현한다 (`DEC-026`). 메일 전달 서비스는 별도 선정한다. Google 로그인은 제공자 인증을 거친 뒤 앱의 공통 계정·학습 기록·로그인 세션 관리로 연결한다. Google 사용자 식별자와 앱 계정의 연결을 관리하며, 이메일 링크 로그인과 Google 로그인이 같은 앱 계정에 연결된 경우 동일한 학습 기록을 사용한다. 기존 계정 연결·중복 가입·연결 해제와 Google로만 가입한 사용자의 이메일 확보 및 탈퇴 재확인 절차는 구현 전에 합의한다. 이메일 일치만으로 계정을 자동 병합하는 정책은 채택하지 않았다. 다른 소셜 제공자는 이번 범위에 포함하지 않는다. 현재 구현 범위는 [11절](#11-개발-접근과-미결정-사항)과 [인증 설계](design/AUTHENTICATION.md)를 따른다. 로그인 세션은 쿠키로 유지하며 브라우저를 닫았다 열어도 유지한다. 마지막 인증된 이용 시점부터 30일간 유효하고, 인증된 이용 시마다 만료 시점을 갱신한다. 최초 로그인과 세션 만료 후 재로그인은 모두 이메일 링크 또는 Google 로그인을 지원한다. 각 인증 방법은 계정 연결 정책에 따라 해당 앱 계정으로 이어져야 하며 재로그인을 이메일로 한정하지 않는다. 로그아웃 시 해당 로그인 세션을 무효화하고, 회원 탈퇴 시 해당 계정의 모든 로그인 세션을 무효화한다. 회원 탈퇴 실행 전에는 이메일 링크로 다시 본인 확인한다. 이 기간은 로그인 유지 기간이며 학습 세션의 재개 기한이나 기록 보관 기간과 구분한다.

로그인 링크는 발급 시점부터 10분간 유효하고 첫 성공 확인에 한 번만 사용한다 (`DEC-020` 후속). 같은 목적의 새 링크를 요청하면 이전 미사용 링크를 무효화한다. 메일 미리보기·보안 검사만으로 링크를 사용 처리하지 않고 사용자 화면의 확인 동작에서 사용한다. 사용·만료·재발급으로 무효화된 링크에는 이유와 새 링크 요청 경로를 보여준다. 탈퇴 전 이메일 재확인 링크에도 일회성·미리보기 보호를 적용한다. 직접 구현한 인증 경계에서 토큰의 추측·재사용·노출, 계정 존재 노출, 세션 탈취·위조, 권한 없는 기록 접근을 검증한다. DEC-036에 따라 탈퇴 재확인 링크는 발급 후 10분간 유효하고 같은 목적의 새 링크는 이전 미사용 링크를 무효화한다. 이메일 재확인 성공 후에는 해당 브라우저에서 10분 안에 최종 탈퇴 버튼을 눌러 확정하며, 시간이 지나면 이메일 재확인부터 다시 한다. 로그인·탈퇴 인증 메일은 같은 이메일에 30초 간격으로 재발송할 수 있다. 현재 이메일별·접속 IP별 발송 횟수 상한은 두지 않는다. 메일 서비스 자체의 제한을 없앤다는 뜻은 아니다. 실제 메일 발송 서비스와 상세 전달 상태 판정·지연/반송 검증은 실제 인증 연결 전에 확정한다. 인증 상태 저장 방식은 [인증 설계](design/AUTHENTICATION.md)를 따른다. 30일 로그인 유지가 만료되거나 무효화된 세션의 자동 연장을 허용하는 것은 아니다.

DEC-046으로 로그인 링크는 실제 열고 사용자 확인을 마친 브라우저에 로그인한다. 요청을 시작한 다른 브라우저를 자동 로그인시키지 않는다. 확인 화면에 로그인 대상 이메일을 명확히 표시하고 이미 로그인한 다른 계정을 자동 교체하지 않는다. 탈퇴 재확인과 최종 확정은 기존 해당 로그인 세션/브라우저의 연결을 유지한다.

인증 메일은 자동 재발송하지 않는다. 메일 발송 실패 전용 재요청 안내·버튼은 추가하지 않고 사용자가 기존 인증 메일 요청 화면에서 다시 요청할 수 있게 한다. 같은 이메일의 30초 간격과 새 링크 발급 시 이전 미사용 링크 무효화는 유지한다. 요청 접수·메일 시스템 수락·실제 받은편지함 도착을 구분하고 발송 실패나 전달 불명을 도착 성공으로 표시하지 않는다. 만료·사용·재발급된 링크의 기존 오류 이유/새 요청 경로 요구는 유지한다.

사용·무효화·만료된 인증 링크·로그인 세션 행과 탈퇴 확인 권한은 효력 종료 후 24시간 안에 삭제한다. 미인증 이메일 요청/발급 제어 행은 마지막 요청 후 24시간 내 새 요청이 없고 유효 링크가 없으면 함께 삭제한다. 정상 사용자 계정과 유효 로그인 세션은 정리 대상이 아니며 탈퇴 24시간 상한이 우선한다. 로컬 기기가 꺼진 동안 실행을 보장하지 않으며 재실행 시 만료분을 정리한다. 진단 로그 7일 수명과 구분한다.

과거 백업을 복원할 때는 기존 로그인 세션·미사용 인증 링크·탈퇴 확인 권한을 모두 무효화한 뒤 서비스를 개방한다. 사용자는 이메일 링크 또는 Google 로그인으로 다시 로그인한다 (`DEC-057` 후속). 일반 앱/DB 재시작에는 이 전체 무효화를 적용하지 않는다. 탈퇴·기록 만료 상태를 재적용하는 의무는 별도이며 전체 인증 무효화만으로 사용자 데이터 부활 방지가 끝난 것으로 취급하지 않는다.

### 8.2 탈퇴 데이터 일괄 삭제와 백업 기한

회원 탈퇴가 확정되면 즉시 계정 접근을 차단하고 모든 로그인 세션을 무효화한다 (`DEC-021`). 앱 관리 계정 정보·연결 학습 데이터는 정해진 시각의 일괄 작업으로 각 탈퇴 확정 시점부터 24시간 이내에 삭제한다. 대기 중에도 기록 조회·AI 이용·진행 중 작업의 결과 저장을 차단한다. 재시작·실패·재시도로 대상을 잃거나 최초 기한을 연장하지 않아야 한다. 기한 작업의 지속 목록·정시 실행과 재시도 여유를 포함한 실행 계약은 [로컬 운영 설계](design/LOCAL-OPERATIONS.md#기한-작업)를 따른다 (`DEC-028`).

탈퇴 계정의 데이터가 포함된 앱 관리 백업은 탈퇴 확정 시점부터 7일 이내에 해당 데이터를 제거하거나 해당 백업을 만료·폐기한다. 이 기한은 서비스 데이터 삭제 시점부터 다시 계산하지 않는다. 삭제 대기 중 생성된 백업도 같은 기한을 적용한다. 남아 있는 백업은 접근을 제한하고, 복원 시에는 탈퇴·삭제 상태를 다시 적용한 뒤 서비스 접근을 허용하여 계정이나 데이터가 되살아나지 않도록 한다. 이를 충족하는 백업·복원 방식은 기술 선정 시 검증한다. 공급자 측 데이터 보관·삭제 조건은 별도로 확인하며, 이번 정책으로 공급자 측 삭제 완료를 보장하지 않는다.

## 9. 품질 지표와 검증

첫 대화 완료율, 대화당 사용자 발화 시간, 교정 후 다시 말하기 성공률, 다음 대화에서 표현 재사용률, 7일 재방문율을 추적한다. AI 품질은 턴당 질문 수, 임의 종료, 근거 없는 피드백, 과도한 교정, 주제 반복에 대한 평가 시나리오로 검증한다. 목표 수치는 프로토타입과 사용자 테스트의 기준값을 확인한 뒤 정한다.

### 9.1 엔지니어링 품질과 운영 검증

핵심 동작의 정확성·관측 가능성·복구 가능성을 기능과 함께 검증한다. 제품 규칙의 자동 검증과 생성형 AI 품질 평가를 구분한다. 계정별 지속 저장과 기기 간 재개는 제품 요구사항이며 로컬 가짜 공급자 결과로 실제 AI·음성 품질을 판정하지 않는다. 단계별 검증·측정 방법은 [검증 설계](design/ENGINEERING-VALIDATION.md), 개발 순서와 완료 판정은 [TASKS](TASKS.md)를 따른다.

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| O-01 | 아키텍처 선택에 근거를 남긴다. | 핵심 사용자 흐름과 예산·보안·데이터 보호 제약을 정리하고 이를 충족하는 최소 구성부터 검토한다. 대안별 비용·일정·사용자 경험·데이터·운영 영향과 채택 이유, 재검토 조건을 기록한다. 구조 변경에는 측정 결과 또는 요구 변화의 근거를 남기며 필요성 미확인 캐시·고가용성·오토스케일링을 필수로 지정하지 않는다. |
| O-02 | 실패 조건을 포함한 검증을 반복할 수 있다. | 대화 상태 전이·중복 요청·외부 API 실패·계정별 접근·노트 근거를 검증하고 AI 평가 결과를 별도로 남긴다. |
| O-03 | 지연·실패·비용을 관찰할 수 있다. | 응답·끼어들기 중단 지연·끊김·실패율과 공급자가 제공하는 범위의 구성 요소별 지연·비용을 설명할 수 있다. 주요 사용자 동작과 자원·처리/외부 대기를 연결하며 10분 세션·사용자별 월 비용의 실측 또는 조건부 추정 근거를 남긴다. 관측 로그에서 원문 발화·음성·비밀값을 제외한다. |

| O-05 | 배포와 애플리케이션 복구를 검증한다. | CI 검사를 통과한 동일 빌드 결과물을 배포하고 배포 후 기본 동작을 확인한다. 실패한 배포의 이전 버전 복구와 DB 변경 호환성을 검증한다. |
| O-06 | 장애 분석과 데이터 복원을 검증한다. | 운영과 분리한 테스트 환경에서 부하·의존 서비스 실패·배포 실패·백업 복원의 원인과 복구 가능성을 확인한다. 개선·재검증 근거와 해당 시 복구 시간·데이터 손실·재발 방지를 설명할 수 있어야 한다. |

로컬 개발·AI 후보 실험의 진단 로그는 DEC-039에 따라 다음 메타데이터만 기록한다. 각 사건에 해당하는 필드만 남기며 상세 필드명·이벤트 이름은 구현 시 정한다.

| 범위 | 허용 정보 |
| --- | --- |

| 저장 | 성공·실패, 처리 건수, 소요 시간, 재시도 횟수 |

| 인증·메일 | 발송·인증·로그아웃의 성공·실패와 오류 코드 |

대화 내용·전사문·음성·이메일·IP·인증 토큰·쿠키·API 키 및 기타 비밀값·요청/응답 본문은 기록하지 않는다. 외부 오류의 원본 본문도 저장하지 않고 정해진 오류 코드와 민감 내용을 제거한 진단 정보만 남긴다. 추적용 임의 ID는 실제 인증 세션 토큰과 구분한다. 학습 기록은 로그와 별도로 8절의 기록 정책을 따른다. DEC-016의 기존 로그 제한을 유지하고 인증·연결·작업 등 로컬 MVP의 구체 사건 범위를 확정한 것이다.

DEC-037에 따라 로컬 개발·AI 후보 실험의 진단 로그는 각 로그의 기록 시각부터 7일 후 자동 삭제한다. 로컬 로그의 사본·내보내기에도 같은 기한을 적용하며 보관 시각을 새로 계산하지 않는다. 운영 단계의 로그 저장소·보관 기간은 공개 운영 전에 별도로 정한다. 식별자로 기록이 연결될 수 있으므로 로컬 저장 위치·형식은 DEC-038을 따르며 접근 범위와 삭제 실행/검증 방식은 D-02에서 구체화한다.

DEC-040에 따라 로컬 진단 로그는 개발자 본인만 접근하고 앱 내 로그 조회 화면·외부 자동 전송을 제공하지 않는다. 앱 실행에 필요한 로컬 프로세스 접근은 허용한다. 실제 전사문·교정 내용을 별도 평가 파일로 보관하지 않고 합성 사례와 점수·지연·비용·실패 유형 등 내용 없는 평가 결과를 남긴다. 평가 결과의 텍스트 필드에도 실제 발화를 복사하지 않는다. 기존 앱 학습 기록의 보관 정책은 유지한다. 이 결정은 평가 집계의 무기한 보관을 승인하지 않으며, 진단 로그로 남긴 결과는 기존 7일 수명을 따른다.

지연·가용성·비용·복구 목표는 초기 측정과 허용 예산에 근거해 합의한다. 테스트 환경의 장애 실험과 실제 운영 장애는 구분한다. 사용자 발화와 기록을 사용하는 측정·보관 방식은 데이터 정책 합의와 접근 통제 후 적용한다.

초기 목표는 주요 흐름의 기준선 확보와 병목 식별·개선·재검증이다 (`DEC-007`, 2026-10-20 합의). 성능 향상 자체를 보장하지 않으며 측정 뒤 목표의 적절성을 재검토한다. 지연·처리량·가용성·복구 시간의 수치는 아직 확정하지 않았다. 측정 조건·비교 절차·결과 기록은 [검증 설계](design/ENGINEERING-VALIDATION.md)를 따른다.

### 9.2 AI 제공·맥락·이용량 정책

Talkie가 API를 제공하고 비용을 부담한다. 초기 공급자는 하나로 시작하되 실시간 대화와 교정·요약 모델은 역할에 따라 분리할 수 있다 (`DEC-008`). 최종 공급자·모델·연결 경로는 품질·지연·비용·끼어들기와 기록 정합성 검증 후 합의한다. [8절의 공급자 데이터 조건](#provider-data-policy)을 적용하며 로컬 시험을 최종 채택·공개 배포 승인으로 취급하지 않는다. 구현 경계·연결 경로는 [음성 설계](design/VOICE.md), 로컬 통합·후보 비교 순서는 [TASKS](TASKS.md#선행-관계)를 따른다.

새 학습마다 새 세션을 만들고 AI에는 현재 대화·확인된 진행 상태·짧은 학습 정보와 관련 복습 기록을 전달한다. 소재 선택은 [7절](#7-주제와-표현-정책)을 따르며 이전 이력 전체를 매번 AI에 전달하지 않는다. 선택한 상황·표현과 필요한 반복 회피 정보만 분량 상한 안에서 제공한다. 이전 학습에서 가져오는 맥락은 주제·시작 난이도·복습 표현이며, 주제와 복습 표현의 조회 기간은 7절을 따른다. 시작 난이도는 최신 유효한 값을 참고하고 학습 공백이 길면 현재 반응에 따라 조절한다. 이 기간 제한을 진행 중인 대화의 재개 기록에 적용하지 않는다. 선택 기술·요약 방식·상한 수치는 검증하며 정한다. 진행 중 학습의 재연결은 마지막 확인 상태에서 복구한다.

대화별 실시간 연결과 기록을 분리하고 공통 API 인증·결제를 사용한다. API 비밀키는 서버에서 관리한다. 첫 운영 배포부터 누구나 가입할 수 있고, 가입 후 정해진 무료 체험량 안에서 학습하는 방향을 채택한다 (`DEC-014`). 무료 체험량·갱신 여부·소진 시 동작과 유료 제공 시점은 미정이다. Talkie는 요청별 토큰 사용량을 지속 계측·차감하지 않고, 계정과 이용 기간별 **공급자 연결 허용 시간**으로 음성 이용을 관리한다(DEC-062). 새 연결을 허용하기 전에 남은 시간·연결당 상한을 서버에서 확인하고 계정당 음성 연결은 경로·기기를 합쳐 하나만 허용한다(DEC-063). 시간은 학습 세션의 시작/종료 간격이나 사용자가 실제 말한 시간과 구분한다. 웹 브라우저가 관찰한 실제 공급자 연결 시간·대화 수를 서버가 받은 연결 신호와 대조해 사용 시간을 차감하며 발급 최대 시간을 곧바로 사용 시간으로 차감하지 않는다. 연결이 열리지 않은 발급은 사용 시간으로 세지 않고, 종료 보고가 없으면 마지막 서버 확인 뒤 짧은 유예 시간까지만 차감한다. 일시 중단·재연결·중복 발급으로 한도를 우회하거나 이중 차감하지 않아야 한다. 유예 길이·발급 자리 해제·정정과 연결 경계의 마무리 방식은 실제 공급자 동작을 확인해 정한다.

Talkie는 사용자 수·허용 연결 시간·관찰한 연결 사용 시간·대화/문답 수·노트 호출/실패를 내용 없이 집계하고, 매주 공급자의 실제 과금 총액을 이용 활동과 대조해 자체 시간당 운영 기준을 조정한다(DEC-062/063). 계정·기간별 허용/사용 시간과 활성 연결 상태는 학습 대화·노트와 독립적인 계정 연결 이용권 기록으로 관리하고 탈퇴 때 함께 삭제한다(DEC-063). 학습 기록의 만료·삭제로 남은 이용 시간이 바뀌지 않아야 한다. Live, 분리형 Gemini 텍스트/TTS, Soniox STT, 종료 노트의 비용은 공급자 보고에서 구분되는 범위만 실제액으로 표시하고, 구분되지 않는 앱 기능별 금액은 추정·미확인으로 표시한다. 주간 평균은 개별 세션 비용이나 향후 비용을 보장하지 않으며, 무료 등급 비용 0을 유료 비용 기준으로 사용하지 않는다. 연결 시간·동시성·발급 횟수와 노트 호출/재시도를 제한하고 공급자 계정/프로젝트 지출 상한·알림을 검증한다. 사용자는 시작 전에 이용 가능 상태와 이용 기간·허용 시간의 변동 가능성을 보고, 경계에 가까워지면 마무리 안내를 받는다. 기간 시간 소진 시 새 유료 음성 연결은 막되 이미 확인된 기록의 저장·종료 정리와 기존 24시간 재개 범위의 기록 처리는 허용한다. 종료 노트는 음성 연결 시간과 별도로 제한하고 부족/실패를 알린다. 구체 시간·연결당 상한·기간/갱신·체험량·노트 호출 수·주간 비용 허용 편차·공급자 지출 상한과 마무리 동작은 측정과 후속 합의로 정한다. 이용량 제한이 있는 요금제를 지향하되 가격·포함량은 비용 측정 후 확정한다. 사용자에게 추가 금액을 청구하는 지갑은 제공하지 않는다.

최초 로컬 AI 후보 비교 전체의 실험 예산은 세금·환율·수수료를 포함해 총 3만 원으로 제한한다 (`DEC-016`). 날짜·실패·재시도로 초기화하지 않는다. 집행액·진행 중 호출의 예약 비용·다음 호출의 최대 비용을 합산해 한도를 넘으면 신규 호출을 막는다. 호출 시간·출력량·재시도 횟수를 제한하고, 최대 비용을 계산할 수 없으면 유료 호출을 시작하지 않는다. 자동 충전·무제한 재시도는 사용하지 않으며 청구 지연·추정 오차를 기록한다. 공급자 데이터 조건은 [8절의 적용 범위](#provider-data-policy)를 따른다. 유료 호출의 후보별 배분·표본 수·호출 상한은 호출 전에 확정하며 성능 기준은 DEC-054대로 직접 청취 뒤 정한다. 부족하면 범위를 줄이거나 추가 예산을 논의한다. 공개 운영비·클라우드 자원 생성은 이번 예산의 승인 범위가 아니다.

## 10. 1차 범위 밖

영상 아바타, 세밀한 음소별 발음 점수, 강의 콘텐츠 대량 제작, 학습자 간 소셜 기능, ChatGPT 프로젝트 자동 업로드, 고객 API 키 및 ChatGPT 구독 연결은 첫 버전 범위에서 제외한다.

## 11. 개발 접근과 미결정 사항

로컬 MVP의 현재 범위와 실제 운영 전에 필요한 결정을 구분한다. 단계별 개발 순서·의존성은 [TASKS](TASKS.md#선행-관계), 선택 근거는 [DECISIONS](DECISIONS.md), 구현·검증 상태는 [PROGRESS](PROGRESS.md)를 따른다. 외부 자료에는 관찰·추정·미확인을 구분하고 출처와 한계를 남긴다.

| 범위 | 이미 확정한 방향 | 남은 결정·검증과 시점 |
| --- | --- | --- |
| 로컬 MVP · 앱·인증·저장 | 한 앱의 로컬 구성, 앱 직접 이메일 인증·지속/임시 PostgreSQL 분리·로컬 합성 메일과 기한 작업 방향은 DEC-015/026/028/033~045로 확정. 링크·세션·탈퇴 재확인·발송 간격의 제품 조건은 8.1절 | 로컬 구성과 초기값은 [상세 설계](DESIGN.md#상세-설계)를 기준으로 확인한다. 실제 timer 실행·장기 실패·전체 경쟁/복원 검증은 해당 TASK에서 완료 판정 |
