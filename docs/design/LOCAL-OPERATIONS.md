# 로컬 구성·기한 작업·로그

갱신일: 2026-10-28. 합성 데이터의 로컬 실행 구성과 남은 운영 검증을 관리한다. 설치·명령은 [README](../../README.md#로컬-인증저장-시험), 데이터 모델은 [DATABASE](DATABASE.md), 제품 보관·삭제 기한은 [PRD](../PRD.md#8-저장-데이터와-학습-노트)를 따른다.

## 로컬 실행 구성

지속·임시 PostgreSQL은 Docker Compose의 별도 인스턴스·볼륨·연결로 구성한다(DEC-041). 앱은 루프백 origin·SMTP와 합성 이메일만 허용한다. 로컬 Mailpit 메일함은 메모리 기반·로컬 한정이며 외부 전달·영속 볼륨·본문 로그·백업 복사를 사용하지 않고 시험 종료 시 폐기한다(DEC-042). 실제 메일 서비스와 운영 호스팅·지역·DB 권한 분리는 후속이다.

웹 서버와 기한 작업 명령은 분리하며 Linux 사용자 systemd timer 템플릿을 둔다(DEC-043). 사용자 서비스 수명·로그아웃·절전·재부팅·누락 보완은 실제 검증 대상이고 기기가 꺼진 동안 삭제 기한 준수를 보장하지 않는다. 로그인 없이 상시 실행할 호스트 설정과 운영 실행 플랫폼은 미정이다.

## 기한 작업

자동 종료·노트 재시도·탈퇴 삭제의 대상·최초 기한·상태는 지속 작업 목록에 저장하고 웹 프로세스와 분리한 정시 실행에서 처리한다(DEC-028). 실행 주기는 처리 시간과 실패 재시도 여유를 포함해 제품 기한을 만족해야 한다.

[maintenance.ts](../../app/src/server/maintenance.ts)는 DB의 계정·학습·작업 상태를 확인해 연결 만료 감지·자동 종료·노트 정리·원문 삭제·체험 노트 만료·탈퇴 자료 삭제와 인증 행 정리를 처리한다. 한 계정의 실패가 다른 계정 처리를 막지 않도록 나누며 저장 목록의 존재만으로 모든 작업의 운영 기한 준수를 보장하지 않는다. `scheduled_jobs`의 현행 종류·제약은 [DATABASE](DATABASE.md#저장소와-스키마-경계)를 따른다.

원문/노트 처리의 트랜잭션 순서·재시도·삭제 후 저장 차단은 [학습 저장](LEARNING-PERSISTENCE.md)에 둔다. 최초 기한을 재시도로 늘리지 않으며 기한·중복 실행·재시작·재개/탈퇴/저장과의 경쟁을 검증해야 한다. 운영 실행 주기·알림·대량 처리·전체 장애 기한 검증은 남는다.

인증 행 정리는 효력 종료 23시간부터 수행하는 현재 초기값으로 24시간 상한 전 재시도 여유를 둔다. 통합 탈퇴 권한의 소비/만료 시각을 독립 정리하고 유효 로그인 자체는 유지한다. 발급 제어 행 정리도 이메일 잠금과 재검사를 사용한다. 만료된 인증의 사용 차단과 실제 행 삭제를 구분한다.

## 백업과 복원 경계

임시 원문 볼륨은 앱 복원용 DB 백업·외부 WAL 아카이브·호스트/볼륨 스냅샷에서 제외한다(DEC-034). 별도 서버/VM까지 요구하지 않는다. 일반 재시작 복구의 로컬 데이터/WAL과 외부 복원용 아카이브를 구분하며 실제 백업·복원 시험에서 원문 부활이 없는지 확인한다. 디스크 손실 시 임시 원문은 복구하지 못하고 DELETE를 물리 흔적 즉시 제거로 해석하지 않는다. 노트 완료·최초 기한·재시도와 삭제 경쟁의 계약은 [학습 저장](LEARNING-PERSISTENCE.md#원문-삭제와-수명-경계), 이 선택의 이유·대안은 [ADR-034](../adr/034-ISOLATED-POSTGRESQL-TEMPORARY-TRANSCRIPTS.md)에 둔다.

백업 시험은 합성 데이터의 지속 DB 내보내기·복원·전체 인증 무효화부터 수행하고 사본은 시험 종료 시 폐기한다(DEC-044). 실제 사용자 데이터 보관 전에는 백업 생성/폐기 주기·보호·복구 목표와 삭제 상태 재적용을 확정·검증해야 한다. 실제 사용자 계정의 무백업 운영 승인이 아니다. 탈퇴 후 복원 시 접근 허용 전 삭제 상태 재적용·백업 수명 검증은 남는다.

## 로컬 진단 로그

승인된 로컬 로그 구성은 DEC-038의 프로젝트 루트 `.local/logs/` 날짜별 JSONL이며 PostgreSQL과 분리한다. `.local/`은 Git 추적에서 제외한다. 서버 로거·정리는 구현 시 연결하고 [PRD 9.1의 수명·접근·수집 제한](../PRD.md#91-엔지니어링-품질과-운영-검증)을 적용한다. 실행 중 주기적 정리와 시작 시 만료분 정리로 기록별 기한을 지키며 날짜별 파일 회전으로 만료를 늦추지 않는다. 기기 종료 중에는 실행되지 않으므로 재실행 시 만료분을 정리한다. 운영 저장소와 로컬 정리 실행 간격·세부 필드/이벤트 이름은 후속이다.

현재 제품용 JSONL 로거와 자동 정리는 미구현이다. B-00 메모리 측정은 요청 ID·상태 전이·결과·대기 시간만 최근 100개 유지하고 원문/오류 본문·콘솔·파일 로그를 남기지 않는다. 독립 평가 하니스의 기록은 [하니스 README](../../harness/voice-eval/README.md#기록과-로그)를 따른다.

학습 저장 경로와 진단 로거를 분리하고 허용 필드만 출력하는 경계에서 요청/응답·외부 오류 객체 전체 직렬화를 막아야 한다. 실제 발화·교정의 별도 평가 사본 미생성 등 제품 제약은 위 PRD를 따르며, 구현·검증의 완료 상태는 [TASKS](../TASKS.md)를 따른다.
