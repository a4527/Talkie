# 첫 학습 흐름 설계

작성일: 2026-10-16. 작업: `D-01`, `B-00`. 제품 기준은 [PRD](../PRD.md)의 `F-01~F-05`, `F-09~F-10`, 6절이다. 개발 순서는 `DEC-006`, 검증 방식은 `DEC-007`을 따른다.

기준선·실험 절차는 [검증 설계](ENGINEERING-VALIDATION.md)를 따른다. 학습 상태 책임은 DEC-010의 AI 진행 + 앱 기록, MVP 교정 모드는 DEC-011을 따른다. 제품의 기록 범위·보관·삭제 정책은 [PRD 8절](../PRD.md#8-저장-데이터와-학습-노트), 저장·복원 구현과 현재 초기값은 [학습 저장 설계](LEARNING-PERSISTENCE.md)를 기준으로 한다. B-00의 실행 중 메모리 기록은 실제 저장소의 복원·보관·삭제 정책 검증을 대체하지 않는다.

실제 제품의 중단·종료 예외는 [PRD 6절](../PRD.md#6-대화-상태와-예외), 선택 이유는 [ADR-024](../adr/024-AUTO-CLOSE-INTERRUPTED-SESSION-AFTER-ONE-DAY.md)를 따른다. 실제 계정별 저장·종료 작업은 B-02/B-05/B-06 범위이며 아래 B-00 완료 기준에 자동 작업이나 브라우저 종료 후 복원을 추가하지 않는다.

## 구현 범위

B-00은 로컬에서 가짜 학습 시나리오와 텍스트 입력으로 전체 흐름을 확인하는 프로토타입이다. 가짜 응답은 학습 품질을 평가하는 실제 AI로 취급하지 않는다. 임시 기록은 현재 실행 중인 세션에서만 사용하며 영구 저장·인증·기기 간 재개 완료로 표시하지 않는다. 실제 AI는 B-09, 음성은 B-02, 계정별 저장은 B-01/B-05에서 추가한다. 이후 실시간 음성 방향은 `DEC-008`과 PRD 6·9.2절을 따른다. 아래 텍스트 프로토타입의 응답 대기 중 중복 전송 방지는 음성 끼어들기를 막는 규칙으로 확장하지 않는다.

첫 로컬 구현의 프레임워크는 [ADR-015](../adr/015-NEXTJS-TYPESCRIPT-LOCAL-PROTOTYPE.md)의 Next.js + TypeScript 한 프로젝트를 따른다. 화면·학습 처리·가짜 AI 연결을 최소한으로 구분하고 세부 모듈 경계는 구현하며 조정한다. 아래 설계는 B-00의 화면 동작과 상태 규칙을 정의한다. 실제 음성 경로 검증은 DEC-030, 실제 종료 작업 방향은 DEC-028을 따르며 실행 플랫폼·클라우드는 미정이다.

## 화면과 주요 조작

| 화면 | 내용과 조작 | 이동 조건 |
| --- | --- | --- |
| 시작 | 로컬 데모 안내, 짧은 주제 소개, 대화 시작 | 시작하면 첫 질문을 한 번 표시 |
| 대화 | 대화 기록, 답변 입력, 보내기, 세션 종료 | 교정이 필요하면 다시 말하기 상태로 전환 |
| 다시 말하기 | 원문·우선 교정 하나·짧은 설명, 다시 답변하기 | 재시도 성공 후 대화로 복귀; 실패하면 재시도 유지 |
| 일시 중단 | 확인된 대화 기록, 중단 이유, 이어서 하기 | 사용자가 재개하면 중단 전 상태로 복귀 |
| 종료 정리 | 종료된 대화의 피드백과 기록에 연결된 노트, Markdown 다운로드 | 노트 실패 시 생성만 재시도; 대화를 자동 재개하지 않음 |

모바일에서는 기록과 입력을 세로로 배치한다. 입력·종료·재개를 키보드로 조작할 수 있고, 처리 중·실패 상태는 글로도 안내한다. 응답 대기 중 답변의 중복 전송을 막되 명시적 종료 의사는 받을 수 있다.

## 대화 상태

아래 학습 상태는 공급자가 전달한 진행 결과를 앱이 기록·표시하는 상태다. 교정 시점·재시도 성공/실패·다음 대화 진행은 AI의 책임이며, B-00에서는 가짜 공급자가 그 결과를 반환한다. 앱은 학습자의 답변을 자체 판정하거나 성공 전 다음 대화를 강제로 차단하지 않는다. 중복·종료·실패·복원 같은 실행 상태는 앱이 관리한다.

| 현재 상태 | 사건 | 다음 상태와 규칙 |
| --- | --- | --- |
| 시작 준비 | 시작 | 응답 대기 → 일반 대화. 동일 시작 사건으로 세션을 중복 생성하지 않음 |
| 일반 대화 | 답변 제출 | 응답 대기. 빈 입력은 전송하지 않음 |
| 응답 대기 | 일반 응답 확인 | 일반 대화. 반응과 질문 하나를 표시 |
| 응답 대기 | 교정 응답 확인 | 다시 말하기 대기. 원문과 교정 기록을 연결 |
| 다시 말하기 대기 | 재시도 제출 | 응답 대기. 공급자가 알린 성공은 일반 대화, 실패는 다시 말하기 대기로 기록 |
| 일반 대화·응답 대기·다시 말하기 대기 | 연결 실패·사용자 중단 | 일시 중단. 돌아갈 상태와 마지막 확인 턴을 보존 |
| 일시 중단 | 재개 | 확인된 상태로 복귀. 미확인 요청의 처리는 같은 요청 ID로 재확인하거나 재시도 |
| 종료 전 상태 | 명시적 종료 | 종료 정리. 지연 도착한 대화 응답으로 종료 상태를 되돌리지 않음 |
| 종료 정리 | 노트 생성 성공 | 노트 표시·다운로드 가능 |
| 종료 정리 | 노트 생성 실패 | 종료 상태 유지. 노트 생성만 재시도 |

단답·침묵·잘못된 재시도로 자동 종료하지 않는다. 세션 중단과 종료를 다른 사건으로 처리한다. 프로토타입에서 브라우저 새로고침으로 메모리가 사라지는 한계는 안내하고, 이를 영구 재개 기능의 검증으로 사용하지 않는다.

## 데이터와 책임 경계

개념상 최소 항목은 `sessionId`, `turnId`, `requestId`, 현재 상태, 마지막 확인 턴, 발화 기록, 교정의 원문·재시도 연결, 종료 상태, 노트다. 이 목록은 DB 제품이나 보관 정책을 확정하지 않는다.

- 화면은 입력과 상태를 표시하고 공급자의 진행 결과를 반영하는 기록 규칙과 실행 상태 전이는 화면 밖에서 검증할 수 있게 둔다.
- 응답 공급자의 입출력과 실패를 한 경계에서 처리한다. 가짜 공급자와 실제 공급자가 공유할 학습 결과·실패 계약을 정의한다. 실시간 공급자에는 스트리밍·취소·재생 범위 확인 사건이 추가되므로 단일 텍스트 응답 계약만으로 음성을 완료 처리하지 않는다.
- 같은 요청 ID의 재전송·늦은 응답으로 발화·교정·노트가 중복 추가되지 않아야 한다. 종료된 세션의 이전 응답은 상태를 변경하지 못한다.
- 요약은 확인된 발화와 교정 기록만 참조한다. 학습 항목과 필요한 짧은 원문 근거·교정문의 연결을 가짜 데이터로 확인한다 (`DEC-012`). 확인된 사용자 발화가 없으면 빈 노트를 만들지 않는다 (`F-09`). 발화는 있으나 교정이 없으면 오류를 꾸미지 않고 해당 내용이 없음을 표시한다.
- 가짜 공급자는 준비한 시나리오를 재생한다. 임의 입력에 대한 실제 언어 평가가 가능한 것처럼 성공률을 보고하지 않는다. 실제 AI에서는 교정 시점·재시도 판정·규칙 준수를 고정 시나리오로 평가하고 프롬프트·전달 맥락을 조정한다.

## B-00 완료 기준

| 검증 | 기대 결과 | 연결 요구사항 |
| --- | --- | --- |
| 시작부터 노트까지 정상 흐름 | 대화·교정·재시도·종료·다운로드를 로컬에서 직접 수행 | `F-02`, `F-04`, `F-05`, `F-09`의 초기 흐름 |
| 교정 실패와 성공 | 가짜 공급자의 실패/성공 결과를 기록·표시; 실제 AI의 판정 품질은 별도 평가 | `F-05` |
| 단답·빈 입력·대기 | 자동 종료하지 않으며 빈 입력을 전송하지 않음 | `F-02` |
| 중복·지연 응답 | 기록 중복 없음; 종료 후 늦은 응답이 대화를 재개하지 않음 | `O-02` |
| 실패 후 재개 | 마지막 확인 턴과 교정 대기 상태를 유지 | `F-01`의 로컬 상태 검증 |
| 종료·노트 실패 | 종료 유지, 노트만 재시도. 확인된 사용자 발화가 없으면 노트를 생성하지 않음 | `F-09` |
| 노트 내용 | 실제 입력·확인된 교정에만 연결; 빈 기록의 내용을 꾸미지 않음 | `F-09` |
| 측정과 로그 | 요청 ID·상태 전이·응답 대기 시간을 측정하고 원문·비밀값을 로그에서 제외 | `O-03`의 초기 측정 |
| 조작과 표시 | 모바일·PC 화면 크기와 키보드 조작 확인 | `F-01`의 초기 화면 검증 |

앱의 진행 상태 기록·실행 상태 전이·중복·종료 후 응답·복원·노트 근거는 자동 테스트로 확인한다. 교정·재시도에 대한 AI 판단은 실제 연결 후 시나리오 평가로 구분한다. 화면 흐름과 Markdown 다운로드는 브라우저에서 확인한다. 가짜 공급자의 지연과 비용은 실제 AI 측정과 구분한다. 프로토타입 통과로 음성·로그인·영구 저장·일일 노트 통합 요구사항을 완료 처리하지 않는다.

## 이후 검증으로 이어지는 항목

실제 AI 연결 후 같은 실패 시나리오를 외부 응답 계약에 적용한다. 음성을 연결하면 PRD의 실시간 끼어들기·재생/생성 취소·사용자 발화 전환·재생 범위와 기록 동기화를 검증한다. 응답·중단 지연을 측정하고 인식·모델·합성 지연은 공급자가 제공하는 범위에서 구분한다. 계정별 저장 단계에서 마지막 확인 턴의 영구 저장, 접근 제어, 날짜별 여러 세션 통합을 추가한다. 공개 사용 전 데이터 정책과 삭제·접근 제어를 검증한다.
