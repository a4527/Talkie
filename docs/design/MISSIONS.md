# 미션 구성·평가·이용량 설계

갱신일: 2026-11-15. 승인·미구현 설계의 진입점이다. 제품 약속·배점·일수 기준은 [PRD 4~7절](../PRD.md#4-주요-사용자-흐름), 이유와 대체 관계는 [DEC-069](../adr/069-MISSION-CENTERED-LEARNING.md)·[DEC-070](../DECISIONS.md#dec-070)을 따른다. 정확한 스키마·도구 필드는 미확정이다.

## 생성과 확정

추천은 간단한 후보만 생성하고 선택된 후보에 상세 구성을 수행한다. 직접 제작은 검증된 미션·평가표를 사용하며 변형은 바뀐 조건의 영향을 검증한다. 사용자 지정·신규 생성은 기존 구조를 우선 활용한다. 검증은 형식·배점 합계뿐 아니라 목표 실행 가능성·독립된 채점 근거·대안 해결을 다룬다.

미션 정의에는 역할·공개/비공개 정보·제약·목표·채점 항목·배점·허용 대안·완료 조건과 버전을 둔다. 화면용 큰 목표와 내부 이진 채점 항목을 분리한다. 진행 상태는 근거 발화와 연결하고 상대의 제안과 사용자의 수락을 구분한다. 하나의 복잡한 미션에 여러 목표를 유지하며 강제 분할하지 않는다. DEC-081에 따라 허용 해결 경로별 조건·완료 근거를 고정 정의에 연결하고, 하나의 경로 완료를 전체 성공으로 판단한다. 여러 경로를 모두 수행해야 하는 누적 목표와 혼동하지 않는다. 경로 선택·변경과 최종 합의의 근거를 구분하고 종료 시 확정된 경로를 사용한다. 정확한 타입/API·저장 계약은 후속이다.

## 난이도와 모드

초기 선택 방식·기본 모드·진행 중 변경 제한은 [PRD 4.1절](../PRD.md#41-시작)을 따른다. 시작 요청에서 선택한 모드와 난이도를 검증해 미션에 귀속하고, 재개 시 화면의 새 선택값이 아닌 저장된 값을 사용한다. 기존 미션이 있으면 새 선택으로 덮어쓰지 않는다. 실전 변경을 위해 진행 중 미션을 자동 종료하거나 별도 진행 미션을 만들지 않는다. 구체 API/DB 계약과 이관 방식은 후속 설계 대상이다.

난이도는 순서와 분리된 ID·표시명·정렬 순서·대화 설정·언어 평가표·버전으로 관리한다. 시작 시 적용 버전을 고정하고 결과에도 연결한다. 단계 추가·기준 변경으로 과거 결과를 소급 재해석하지 않는다. 참고 수준은 DEC-073/084와 [PRD 4.1절](../PRD.md#41-시작)을 따르며 수준별 세부 평가 예시·향후 자동 수준 추정은 미정이다.

실시간 AI 하나가 상대역·미션 상태와 연습 모드의 튜터 판단을 구조화해 전달하고 종료 후 별도 호출로 평가하는 구성을 우선 검증한다. 실전에는 교육적 교정 지시·도구를 제외한다. 매 턴 별도 심판이나 다른 모델 도입은 채택하지 않았다. 최종 평가와 노트 선별은 별도 종료 호출로 동시에 요청하고 실패한 쪽만 다시 시도한다(DEC-087). 결합은 품질·비용 측정 후 다시 검토할 수 있다.

## 상대역의 정보와 반응 조건

DEC-076의 제품 경계는 [PRD 4.2절](../PRD.md#42-일반-대화)을 따른다. 미션 상세화에서 사용자에게 주는 상황·상대역이 처음 아는 사실·사용자에게 들어야 아는 사실·제공 가능한 처리·반응/종료 조건을 구분한다. 같은 AI가 전체 설정을 보더라도 상대역은 아직 전달받지 않은 사용자 의도를 이미 안다고 연기하지 않도록 역할 지식 경계를 둔다. 연습 도움을 위한 튜터 지식과 상대역 지식을 구별한다.

상대역의 반응은 누적 대화와 확인된 상태를 사용한다. 이미 받은 정보는 재사용하고, 모호하거나 빠진 조건만 자연스럽게 확인한다. 사용자가 여러 조건과 요청을 한 번에 충분히 말했다면 단계를 건너뛰어 처리할 수 있다. 고정 대본 순서·최소 턴 수·고의 오해·허용되지 않은 새 장애를 완료 조건으로 두지 않는다. 사용자 수락 전에 상대역이 해결을 확정하거나 인사만으로 완료하지 않는지 확인한다.

평가 입력은 저장 확정된 전체 대화이며 마지막 문장의 정보량으로 근거 부족을 판정하지 않는다. 재확인·수정은 상황 대응의 예시로 사용하고 필수 행동 체크리스트로 만들지 않는다. 세부 기준별 판단에는 앞선 발화와 반대 근거를 함께 연결한다. 상대역의 과도한 정보 선제 제공·이미 전달한 조건의 재질문·목표 충족 전 조기 종료·해결 후 불필요한 연장을 고정 사례로 검증한다. 카페의 처리 조건·경로별 완료는 DEC-081의 [PRD 4.2.1절](../PRD.md#421-첫-카페-미션의-해결-경로)을 따른다. 직원은 다른 직원이 원래 주문을 받았으므로 사용자가 음료를 들고 왔다는 사실만 처음 알고, 컵 표시와 사용자가 전달한 원래 주문·문제·원하는 처리를 대화 중 누적한다. 인사는 문제 설명을 받을 수 있게 시작하고 원래 주문·불일치·해결을 미리 완성하지 않는다. 상대역은 최종 선택한 경로를 확정한 뒤 마무리하며 실제 프롬프트/상태 계약과 AI 품질은 후속이다.

## 언어 수준별 설명

다섯 단계 A1·A2·B1·B2·C(고급)의 선택과 기대 범위는 [PRD 4.1절](../PRD.md#41-시작)·DEC-084를 따른다. [유럽평의회 종합 척도](https://www.coe.int/en/web/common-european-framework-reference-languages/table-1-cefr-3.3-common-reference-levels-global-scale)를 참고한 Talkie용 설명이며 아래 사례는 앱의 수준 설명을 돕기 위한 자체 구체화다. 공인 시험 평가표와 동등한 판정 기준은 아니다.

| 수준 | 사용자가 선택할 때 참고할 설명 | 대화에서 기대하는 모습의 예 |
| --- | --- | --- |
| A1 | 기본 단어·짧은 표현으로 원하는 것을 말한다. 상대가 천천히 명확하게 말하고 반복하거나 풀어 말하면 간단히 주고받을 수 있다. | 주문 종류나 원하는 온도를 짧게 답하고, 못 알아들었을 때 다시 말해 달라고 요청한다. 짧다는 이유로 불충분하다고 보지 않는다. |
| A2 | 익숙한 일상 상황에서 단순한 정보를 주고받고 기본적인 요청·설명을 한다. 긴 설명보다는 직접적인 질문과 답이 편하다. | 주문과 다른 점을 간단한 문장으로 알리고 교환을 요청한다. 명확한 처리 제안에 답한다. |
| B1 | 익숙한 상황을 연결된 문장으로 설명하고 의견·계획에 간단한 이유를 붙인다. 예상과 다른 일에도 설명하거나 확인하며 대응한다. | 무엇을 주문했고 무엇이 나왔는지 설명하고, 원하는 처리와 이유를 전달한다. 필요한 조건을 다시 확인한다. |
| B2 | 비교적 복잡한 내용을 자세히 설명하고 관점·대안의 장단점을 주고받는다. 상대 반응에 맞춰 설명을 보충한다. | 대안이 여러 개면 차이와 선호를 설명하고 처리 조건을 조율한다. 쉬운 해결을 불필요하게 복잡하게 말할 필요는 없다. |
| C(고급) | 상황에 필요한 의미를 정확하고 자연스럽게 전달하고, 필요할 때 표현·말투·설명을 유연하게 조절한다. | 간단한 주문 문제는 간결하게 해결한다. 실제 조건 충돌·오해가 있을 때 정밀한 설명과 조율을 관찰하며 이를 위해 새 장애를 만들지 않는다. |

같은 미션의 역할 조건·목표·배점은 수준 선택 때문에 임의 변경하지 않는다. 실제 필요한 언어의 정확성·구성·상호작용을 해당 수준의 기대와 비교한다. 단순한 미션에서 C의 모든 능력을 관찰할 수 있다고 보지 않으며, 한 미션 점수로 종합 수준을 인증하지 않는다. 단계별 실제 채점 예시와 관찰 기회 처리·검증 사례는 미구현/미정이다. 연습/실전의 도움 범위는 별도 정책을 따른다.

## 첫 연결 범위와 구현 순서

첫 미션의 상황은 잘못 나온 카페 주문 해결이다. 주문 설명·변경 요청·대안 합의를 검증 대상으로 삼는다. 기존 [카페 사례](../proposals/MISSION-CENTERED-LEARNING-PLAN.md#사례-1--짧은-상황-잘못-나온-카페-주문-해결)는 검토 자료이며, 목표 배점과 기본 상황은 후속 DEC-071로 [PRD 4.5.1절](../PRD.md#451-첫-카페-미션의-목표-배점)에 확정했다. 해결 경로·처리 조건은 후속 DEC-081로 [PRD 4.2.1절](../PRD.md#421-첫-카페-미션의-해결-경로)에 확정했다. 수준별 세부 평가 사례·실제 연결은 후속이다.

1. 난이도별 기대 수준과 카페 미션의 조건·완료 근거·평가표를 구체화하고 합의한다. 평가표가 없는 단계로 시작하거나 임의 기본값으로 대체하지 않는다.
2. 직접 제작 미션의 선택·조건 확인과 모드/난이도 선택을 연결한다. 미정인 AI 추천을 사용 가능한 기능으로 표시하지 않는다.
3. 서버에서 미션·모드·난이도·평가표 버전을 시작 시 고정하고 기존 저장·재개·계정 격리에 연결한다. 기존 자유 대화 세션을 근거 없이 카페 미션으로 변환하지 않는다.
4. 상대역 수행·연습/실전 개입 분리·종료와 결과/기존 노트 연결을 확인하고 두 음성 경로에 적용한다. 미정인 점수·일수·횟수 정책을 로컬 시험값으로 확정하지 않는다.

현재 앱의 `Talk` 화면과 `start` API는 자유 대화용이며 이 흐름을 구현하지 않았다. 다음 논의 초안은 [초기 미션 상세 검토안](../proposals/FIRST-MISSION-DETAILS.md)에 둔다.

## 최소 연결 계약

승인(2026-11-15, DEC-086~089). 정의 레지스트리·시작 API·세션 고정은 [정의](../../app/src/mission/definitions.ts)·[학습 서비스](../../app/src/server/learning.ts)·[마이그레이션](../../app/drizzle/records/0005_mission_sessions.sql), 진행 상태의 저장·병합·재개는 [진행 상태](../../app/src/mission/progress.ts)로 구현하고 DB 시험을 통과했다(2026-11-15 worklog). 진행 상태를 만드는 실시간 도구·클라이언트 창 경계·종료 처리·결과 저장과 미션 선택 화면은 미구현이다. 위 2~4단계의 최소 계약이며 비교·대안은 [검토안](../proposals/FIRST-MISSION-MINIMUM-CONTRACT.md)에 둔다. 테이블·필드·도구 이름은 가칭이며 구현 때 코드와 이 절을 함께 확정한다. 횟수 차감·일수 날짜/소급·무진전 운영 임계값·수준별 세부 평가표는 이 계약에 포함하지 않는다.

**정의(DEC-086):** 카페 미션의 정의(역할·공개/비공개 정보·처리 조건·경로·목표 항목·배점)와 평가표를 코드의 불변 객체로 두고 정의 버전·평가표 버전을 붙인다. 바꿀 때는 새 버전을 추가하며 기존 버전을 지우지 않는다. 시작 시 서버가 존재·배점 합계(목표 60·언어 40)를 검증하고, 재개·평가는 저장된 버전으로 정의를 찾는다. AI 추천/생성 미션의 DB 정의는 F-06 때 설계한다.

**시작 API:** `POST /api/learn`의 `start`에 `mission: {missionId, missionMode: practice|real, languageLevel: A1|A2|B1|B2|C}`를 추가하고 기존 `scenario` 요청은 유지한다. 둘을 함께 보내면 거부한다. 진행 미션이 있으면 요청값을 무시하고 저장값으로 재개하며, 진행 대화가 구형 자유 대화면 `LEARNING_MODE_CONFLICT`로 기존 대화 종료를 안내한다. 응답의 `mission`에는 상황·역할·화면 목표·모드·수준만 담고 상대역 비공개 정보·채점 항목은 보내지 않는다. 횟수 확인·차감은 B-10 전까지 호출하지 않는다.

**세션 고정:** 지속 DB에 `learning_sessions`와 1:1인 `learning_session_missions`를 두고 `(learning_session_id, user_id)` 복합 FK cascade로 소유자를 맞춘다. 미션 ID·정의/평가표 버전·모드·수준은 생성 후 바꾸지 않고, 종료 시 종료 사유(`goal_completed`·`no_progress_failed`·`user_ended`·`resume_expired`)와 최종 경로만 한 번 기록한다. 학습 세션과 같은 트랜잭션에서 만들며 미션 행이 없는 기존 세션은 구형 자유 대화로 남긴다. 음성/텍스트 구분은 기존 `demo_scenario`를 따른다.

**진행 상태:** 저장 스냅샷에 선택 필드 `missionProgress`(경로 사건 `proposed`·`user_accepted`·`staff_confirmed`·`route_changed`와 근거 턴 ID, 무진전 연속 후보 수와 근거)를 추가해 대화와 같은 저장 순번으로 확정한다. 재개 응답에서 무진전 연속 수는 0으로 돌려준다. 빈 진행은 직렬화하지 않아 구형 저장 JSON·해시 호환을 유지한다. 원문과 함께 삭제된다. 구현: `route_changed`의 경로는 바뀐 뒤 경로다. 저장 시 근거 턴은 같은 스냅샷에 있어야 하고 수락은 사용자 턴, 직원 확정은 상대역 턴이어야 한다(순서·재생 완료 확인은 실시간 검증기 몫). 미션 세션에서만 받고 경로는 고정 정의에 있어야 한다. 경로 사건은 교정처럼 사건 ID로 누적하고 확정된 사건은 바꿀 수 없으며, 무진전 연속 수는 최신 저장값을 따른다. 경로 ID는 상대역 비공개 정보가 아니므로 브라우저 스냅샷에 포함된다.

**실시간 도구:** 같은 실시간 AI가 교정 도구와 별도로 미션 상태 도구를 호출해 경로 사건·목표 완료·무진전 후보를 근거 턴과 함께 보고한다. 앱은 경로가 정의에 있는지, 수락 근거가 확정된 사용자 발화인지, 직원 확정이 수락 뒤 재생 완료된 상대역 턴인지 확인하고 한 경로의 세 사건이 모두 있을 때만 마무리 대사 뒤 종료한다. 무진전은 실전에서만 받으며 제외 사건 뒤 연속성을 끊고 목표 완료를 우선한다. 실전에는 교정 도구를 넣지 않는다. 임계값은 설정값이며 3은 시험값이다. 두 음성 경로가 같은 검증기를 쓴다.

**종료 처리(DEC-087·089):** 기존 종료 노트 작업을 확장해 확정된 같은 원문으로 평가 호출과 기존 노트 추출을 동시에 요청한다. 평가 호출은 (고정 정의·평가표·수준 설명, 턴 ID가 있는 전체 대화·교정/재시도·누락 표시·최종 경로를 입력, 목표 6항목 `met|unmet|undeterminable`·언어 12기준 `met|partial|unmet|undeterminable`의 판정·근거 턴·반대 근거·짧은 사유를 출력, 모델 총점은 받지 않음)이며 응답은 앱이 검증·합산한다. 평가와 노트는 각각의 상태로 따로 확정하고, 다음 실행에서는 미확정인 쪽만 다시 호출한다. 확정된 결과는 다른 쪽 실패로 되돌리지 않는다. 호출 중 새 저장 순번이 확정되면 기존 노트 규칙처럼 이전 원문의 결과를 버린다. 마지막으로 확정하는 쪽이 세션 행을 잠근 상태에서 두 상태를 다시 읽어 원문 삭제를 진행한다. 근거 턴이 실제 사용자 턴이 아니거나 기준이 빠지거나 중복되면 그 평가 시도를 실패로 보고 다시 호출한다. 점수는 반점 정수로 합산하고 80% 판정은 `earned × 10 ≥ max × 8`로 비교한다. 평가와 노트가 모두 확정(또는 사용자 발화 없음으로 생략)된 뒤 원문을 삭제한다. 종료 후 24시간 기한 안에 평가를 확정하지 못하면 `unavailable`로 기록한다. 입력이 노트 추출 상한을 넘는 장문의 분할 평가는 후속이며 그때까지 평가 실패로 처리한다.

**결과 저장(DEC-088):** 결과 집계(정의/평가표 버전·모드·수준·종료 사유·최종 경로·영역별/전체 획득과 평가 만점의 반점 정수·달성 여부·종료 시각·평가 상태)는 회원 탈퇴 전까지 보관하고, 기준별 판정·사유·짧은 근거는 노트와 같은 만료 시각을 가진 별도 행에 둔다. 집계에는 사용자 발화 원문을 넣지 않는다. 기존 만료 작업은 노트와 함께 상세 행만 삭제한다. `GET /api/learn`의 세션 항목에 미션 정보와 평가 상태·점수 원값을 추가하고 표시 문자열·반올림은 화면에서 DEC-080 규칙으로 만든다.

## 기록·평가·결과

평가의 단위·배점·재시도 반영·제외·표시/달성 정책은 [PRD 4.5절](../PRD.md#45-평가와-달성-일수), 관찰 범위와 부분점수는 [4.5.2절](../PRD.md#452-언어-세부-기준과-부분점수)을 따른다(DEC-072/074~080/083/084). 이 절은 그 정책을 입력·근거·상태·합산에 연결하는 설계다.

평가 입력은 고정 미션·모드·수준/평가표 버전, 저장 확정된 전체 대화·교정/재시도와 누락 정보다. 교정 대상·첫 시도·도움·사용자 수정·이후 적용의 근거를 연결한다. AI 발화는 맥락으로 구분하고 사용자 수행·도움 제공·재생 범위를 혼동하지 않는다. 장문 분할·병합·호출 수는 후속 계약이며 전체 대화 평가가 단일 API 호출을 뜻하지 않는다.

AI의 기준별 판정 후보에는 관련 사용자 발화와 반대 근거·제외 사유, 해결 경로와 최종 합의를 연결한다. 앱은 소유권·근거 존재·저장/재생 확정·중복·늦은 응답을 검증하고 고정 평가표의 원래 배점에 판정을 매핑해 점수/유효 만점을 합산한다. 모델 총점을 그대로 저장 근거로 삼지 않는다. 존재 검증은 의미적 정확성을 보장하지 않으므로 [고정 합성 사례](../proposals/FIRST-MISSION-EVALUATION-CASES.md)와 TASKS B-12에서 판정·합산 경계를 확인한다. 사례별 등급 후보는 아직 승인/실제 AI 검증 전이다.

경로별 처리 제안·사용자 수락·직원 확정, 경로 변경 전후 근거를 미션 정의에 연결한다. 카페의 경로 계약은 [PRD 4.2.1절](../PRD.md#421-첫-카페-미션의-해결-경로), 배점 연결은 [4.5.1절](../PRD.md#451-첫-카페-미션의-목표-배점)을 따른다(DEC-081). 같은 최종 조건을 경로별로 중복 합산하지 않는 검증과 성공/점수 분리를 유지한다.

미션 진행과 교정 상태는 같은 세션의 별도 상태로 둔다. 상황 결과·최종 점수·일수 인정도 분리하고, 무진전은 아래 구조화 판정 경로로 연결한다. 표시값과 달성 판정은 원래 점수/유효 만점에서 각각 계산하며 표시 문자열을 집계 입력으로 쓰지 않는다. 반점 단위를 정수화한 비교 등으로 비율 경계의 부동소수점 오차를 방지한다. 최종 저장/API 표현·원자적 확정·일수 날짜/소급은 후속이다.

언어 영역과 발음 피드백 범위는 DEC-072·PRD를 따른다. 연습 재시도의 발음·억양 확인에는 실제 음성 근거가 필요하며 전사문으로 대신 판정하지 않는다. 기존 원본 음성 미저장·휘발성 처리와 연습/실전 경계를 유지한다. 사용 포트의 평가 지원·검증 불가 시 표시·피드백 필드·음성 해제 시점은 연결 전에 구체화하고, 발음 성공을 필수 통과 조건으로 추가하지 않는다.

## 무진전 판정과 사례 검증

제품 판정·초기화·제외 규칙은 [PRD 4.2.2절](../PRD.md#422-실전-무진전-종료)을 따른다. 같은 실시간 AI가 무진전 후보와 이유·관련 발화 근거를 구조화해 제안하고 앱이 모드·연속 근거·제외 사건·완료 상태를 검증한다. 매 턴 별도 심판 호출은 도입하지 않는다. 구조 검증은 의미 판단의 정확성을 보장하지 않으므로 아래 고정 사례로 대조한다. 정확한 도구 필드·원자적 상태 확정·저장/재개 경쟁·마지막 대사 재생 실패 처리는 후속 API/DB·음성 계약에서 구체화한다.

연속 3회는 검증용 후보이고 공개 운영값은 미정이다. A1·A2·B1·B2·C 각각에서 짧은 답·반복 요청·무관한 답·인식 불확실성을 대조하고, 오판한 발화와 이유를 기록해 임계값 확정 전에 논의한다. 실제 공급자 호출 계획·표본 수·비용 승인을 이 문서 갱신으로 확대하지 않는다.

| 사례 | 기대하는 확인 결과 |
| --- | --- |
| 온도 설명→카페인 문제 보충→재제조 요청 | 각각 진전. 최소 턴을 채우지 않고 합의로 진행 |
| 대기 시간 질문→5분 안내→환불 요청 | 정보 확인·경로 변경 모두 진전 |
| 구체 제안에 “Yes, please.”→직원 처리 확정 | 짧은 수락을 진전으로 인정하고 성공 종료 |
| 서로 다른 자연스러운 재확인에도 같은 무관한 응답 3회 | 실패 후보. 실제 근거·제외 사건·완료 여부 검토 필요 |
| 무관한 답 2회→관련 조건 설명 | 카운터 초기화. 누적 3회 방식으로 실패시키지 않음 |
| 무관한 답 2회→오인식 의심/연결 중단→무관한 답 1회 | 이전 2회와 합쳐 실패시키지 않음 |
| 직원이 이미 받은 정보를 반복 질문해 사용자가 같은 답을 반복 | 상대역 오류로 분리하고 사용자 실패 근거에서 제외 |
| 침묵·전사 빈 문자열·재생되지 않은 질문 | 횟수에 포함하지 않음. 침묵 종료를 새로 도입하지 않음 |

위 사례는 합성 입력의 기대 결과이며 실행 결과가 아니다. 실제 AI 일관성·비용·지연 검증은 미수행이다. 당일 결과는 worklog에 기록하고 B-03 완료 근거와 구분한다.

## 연결과 횟수

서버는 새 미션 시작의 잔여량·계정의 진행 세션·연결 상태를 원자적으로 확인한다. 연결 성립 시 차감은 미션 식별자와 중복 방지 키로 한 번만 확정하고, 같은 미션 재개는 새 차감을 만들지 않는다. 공급자별 연결 성립의 서버 검증 신호·실패 복구·환급 예외·발급 자리 수명·규모별 단위는 구현 전 구체화한다. 계정당 진행 대화·활성 음성 연결 하나의 경계는 유지한다.

이용권 상태는 학습 기록 수명과 분리해 관리하고 탈퇴 정리와 연결한다. 구체 테이블·보존·복원 계약은 미정이다. 기존 시간 이용권은 새로 구현하지 않으며 시험 시간 보호를 운영 횟수 차감으로 오인하지 않는다. 비용 관찰용 연결 시간은 수집할 수 있지만 사용자 잔여량 차감 단위와 구분한다.

중단·24시간 재개·확정 저장 복원은 [학습 저장](LEARNING-PERSISTENCE.md)을 재사용한다. 종료 사유·평가 결과·기준 버전을 저장해 재개 만료 제외와 기존 당일 달성 유지에 사용한다. 날짜 귀속·일수 집계의 보존/소급 방식은 미정이다.

## 맥락·노트와 검증

공통 규칙·고정 미션·선택 사용자 설정·관련 복습·확인된 최근 상태를 상한 안에서 전달한다. 사용자 지정과 노트는 지시가 아닌 데이터로 분리하고 만료·삭제·다른 사용자 정보는 제외한다. 현재 조회/입력 상한과 공급자 포트는 [음성 설계](VOICE.md)를 따른다.

노트는 실제 근거를 선별하는 기존 종료 경로를 재사용하며 필수 내용의 변경·상세 교정 보관·분량은 후속 결정한다. 기존 노트 형식·조회·다운로드의 호환을 유지한다. 평가 결과 보관과 원문 삭제의 관계를 명시하고 삭제된 전체 원문의 재생성을 약속하지 않는다.

검증은 자동 상태/차감/권한/경계 경쟁 테스트와 목표 판정·언어 품질·수준별 일관성·무진전 종료의 AI 사례 평가를 구분한다. 미션별 시간 분포·호출·비용을 측정하고 실제 시험 결과는 worklog에 기록한다. 구현 작업과 완료 판정은 [TASKS](../TASKS.md)를 따른다.
