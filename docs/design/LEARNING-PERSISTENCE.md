# 학습 저장·복원 설계

갱신일: 2026-10-29. `/learn`의 가짜 AI·합성 대화와 `/voice`의 비공개 저장 학습이 같은 저장/재개 계약을 사용한다. 음성 확인 범위는 [VOICE](VOICE.md#생성재생전사-범위)를 따른다. 사용자 동작·보관 기한은 [PRD 6·8절](../PRD.md#6-대화-상태와-예외)을 따르며 데이터 모델은 [DATABASE](DATABASE.md)와 연결한다.

구현: [클라이언트 저장](../../app/src/app/learn/page.tsx), [학습 상태](../../app/src/learning/session.ts), [저장/노트 서비스](../../app/src/server/learning.ts), [원문 수명](../../app/src/server/db/transcripts-lifecycle.ts), [기한 작업](../../app/src/server/maintenance.ts).

## 확인된 기록과 연결 소유

시작·답변마다 요청 ID를 부여하고 응답 확인 시 사용자/공급자 턴과 교정·재시도를 함께 기록한다. 중단 중 도착한 응답은 확인 턴으로 추가하지 않고 재개 시 같은 요청 ID로 재확인한다. 종료 후 지연 응답은 무시한다. 노트는 확인된 발화·전달된 교정·연결된 재시도만 사용한다. 생성 내용과 실제 재생 범위는 [음성 설계](VOICE.md)에서 구분한다.

계정당 진행 대화 하나(재개 가능한 중단 포함)와 활성 연결 하나를 허용한다. 다른 탭/기기의 중복 시작·연결을 차단하되 조회는 허용하고 기존 연결 중단 후 재개할 수 있다. API의 `learningSessionId`와 연결 소유 비밀값 `learningConnectionToken`은 로그인 자격과 별개다. 서버는 인증·소유자와 연결 해시·유효 창을 확인한다. 진행 대화 유일성은 DB 조건부 고유 인덱스로도 보호한다.

## 묶음 저장과 두 DB 확정

1. 대화·진행 상태를 메모리 창에 모으고 정기 저장 또는 정상 종료 시 남은 분량을 전송한다. 사용자에게 저장 성공·실패를 표시하며 실패만으로 대화를 정지하지 않는다.
2. 계정→학습 행을 잠근 뒤 연결과 최초 기한을 확인한다. 임시 상태 행도 잠그고 존재·미삭제·기한 내 상태를 검사한다. 저장 요청이 없는 상태 행을 다시 생성하지 않는다.
3. 임시 DB에 `save_sequence_number`와 snapshot·해시를 커밋한다. 같은 순번/내용은 중복 없이 확인하고 다른 내용은 거절한다. 순번은 지속 DB 확정 위치와 다음 위치 범위로 제한한다.
4. 지속 DB의 `confirmed_save_sequence_number`를 갱신한 뒤 저장 성공을 알린다. 두 DB의 동시 커밋은 보장하지 않는다. 응답 유실·중간 실패는 같은 순번/내용으로 재확인한다.
5. 복원은 확정 위치 이하의 임시 snapshot을 순서대로 합쳐 확인된 턴·상태를 복구한다. 임시 DB에만 커밋된 미확정 저장은 재개/노트 근거로 사용하지 않는다. 확정 위치의 원문이 없으면 만들어 채우지 않고 오류로 처리한다.

초기 0번 저장·이전 해시와 JSON 키 호환성은 [DB 저장 형식](DATABASE.md#저장-json과-이관-호환성)을 따른다. 클라이언트 창이 줄어도 이미 저장한 과거 턴은 지우지 않는다. 종료·탈퇴·삭제와 쓰기가 경쟁하면 계정/상태 잠금과 유효성 재검사로 늦은 저장을 차단한다.

## 현재 초기값과 버퍼 유실

| 항목 | 로컬 구현 초기값 |
| --- | --- |
| 정기 저장 / 연결 확인 / 연결 유효 창 | 5초 / 15초 / 45초 |
| 클라이언트 메모리 창 | 직렬화 128 KiB·200턴, 입력 6,000자 |
| 서버 snapshot 검증 상한 | 직렬화 256 KiB·500턴, 턴 텍스트 12,000자 |

클라이언트 초기값과 서버 거부 상한은 서로 다른 경계다. 측정으로 조정할 대상이며 운영 성능 목표가 아니다. 원문/상태의 요청 단위를 함께 잘라 최근 완결 창을 유지하고 오래된 미저장 단위 유실은 `hasConversationGaps`로 표시한다. 남은 단위는 복구 후 재시도하고 재개·노트에서 누락을 알린다. 메모리 손실 시 마지막 저장 이후 발화·상태는 잃을 수 있다.

무제한 누적·원문 디스크 우회 저장을 전제하지 않는다. 큰 단일 단위·저장 중 제거/응답·실제 연결 강제 종료와 장기 장애의 전체 경쟁 검증은 남는다. 유실 위험 수용의 이유는 [ADR-031](../adr/031-SAVE-RETRIES-AND-NOTE-OUTCOMES.md), 상한에서의 선택은 [ADR-047](../adr/047-RETAIN-RECENT-UNSAVED-RECORDS-AT-BUFFER-LIMIT.md)에 둔다.

## 종료·재개·노트

정상 종료 요청에서 최초 서버 종료 시각과 원문 삭제 기한을 확정한다. 잔여 저장 실패 시 대화는 종료하고 기록 저장 대기로 표시한다. 메모리 소유자는 최초 기한 안에서 연결 확인·재전송할 수 있으며 실패·재시도로 기한을 늘리지 않는다. 메모리 소실 후 연결 확인이 끝나면 작업 실행기가 마지막 확정 저장분으로 정리한다. 빈 발화는 빈 노트 없이 정리한다.

외부 중단은 재개 가능 상태와 종료를 구분하고, 재개가 확정되면 자동 종료 대상에서 빠진다. 중단 기한 뒤 자동 종료한 상태는 늦은 응답·재개로 되돌리지 않는다. 중단 후 재개 기한과 종료 후 원문 기한은 별도다. 현재 실행기의 중단 감지·자동 종료/재시도는 [로컬 기한 작업](LOCAL-OPERATIONS.md#기한-작업)을 따른다.

현재 가짜 노트는 최근 사용자 발화 최대 세 개에서 각 160자 이내 근거만 남긴다. 비공개 음성 노트도 최근 사용자 근거 일부와 실제 재생/근거 검증을 통과한 최근 교정·재시도 일부를 모으며 추가 공급자 호출은 하지 않는다. 실제 AI 선별·전체 P0 노트 형식을 대체하지 않는다. 한국 종료 날짜를 집계 키로 사용하며 생성 시각과 구분한다. 체험 기록 수명만 연결했고 유료 전환·만료 백업 처리는 미구현이다.

승인된 최종 흐름은 AI가 저장된 대화·교정·재시도를 검토해 항목/근거를 선별하고 앱이 근거 존재를 검증하는 방식이다. 부분 노트·자동 재시도·화면 이탈·선별 품질과 항목 분량의 최종 계약은 [PRD 8절](../PRD.md#8-저장-데이터와-학습-노트)·[ADR-031](../adr/031-SAVE-RETRIES-AND-NOTE-OUTCOMES.md)·해당 TASK를 따른다. 가짜 흐름의 사용자 노트 재시도를 최종 제품의 재시도 UI로 해석하지 않는다.

노트 단일 저장의 상단 세 맥락·하단 세부 형식, 검증과 읽기 계약은 [학습 노트 설계](LEARNING-NOTE.md)를 따른다. 음성 시험 노트의 새 형식 생성/읽기는 구현했으며 전체 AI 종료 추출은 남는다.

## 원문 삭제와 수명 경계

지속 DB의 `learning_sessions.transcript_delete_deadline_at`이 최초 종료 기준의 기한이고 임시 상태의 같은 열은 마지막 저장 때 동기화한 보조값이다. 노트·근거의 지속 커밋 후 별도 트랜잭션에서 임시 원문을 삭제한다. 기한 만료 시 결과 정리 실패 여부와 관계없이 원문을 정리한다.

원문 삭제는 임시 상태 행을 잠그고 자식 저장 행 전체 삭제와 `source_deleted_at`·사유 갱신을 같은 임시 DB 트랜잭션에서 수행한다. 실패 시 함께 되돌리고 재시도 시 완료 시각을 바꾸지 않는다. 삭제 완료 상태는 저장을 거절하고 상태가 없으면 완료 시각을 지어내지 않는다. 정상 삭제 후 상태 이력은 남고 탈퇴/고아 정리에서는 상태도 지운다. 이력 필드 의미와 손실 한계는 [DATABASE](DATABASE.md#시각권한원문-이력)를 따른다.

## 검증 범위와 미정 사항

합성 데이터의 저장·재전송·부분 커밋·복원·삭제·브라우저 검증 근거는 [2026-10-23](../worklogs/2026-10-23.md), [2026-10-25](../worklogs/2026-10-25.md), [2026-10-27](../worklogs/2026-10-27.md)에 둔다. 실제 공급자의 구조화 교정/재시도 품질·전체 AI 노트 선별·대규모/장기 장애·운영 기한 준수·유료 기록 전환·실제 삭제 상태의 백업 복원 적용은 남는다. 임시 DB만 커밋된 상태에서 메모리를 잃은 재개의 복구 공백을 문서 분리로 해결한 것으로 표시하지 않는다. D-02/B-01/B-05/B-06의 완료 판정은 [TASKS](../TASKS.md)를 따른다.
