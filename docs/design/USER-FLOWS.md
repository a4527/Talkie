# 사용자 흐름 설계

작성일: 2026-10-29. 제품 기준은 [PRD 4절](../PRD.md#4-주요-사용자-흐름)·[6절](../PRD.md#6-대화-상태와-예외)이고, 이 문서는 그 약속이 사용자 눈에 어떤 순서로 나타나는지를 단계별로 풀어 쓴다. 요구사항·정책 조건을 새로 정하지 않으며, 조건이 필요하면 PRD·DEC 링크로 연결한다.

순서도는 흐름이 확정된 뒤 추가한다. 지금은 글 목록으로만 적는다.

## 범위와 읽는 법

- 대상은 실제 제품의 학습 흐름이다. B-00 가짜 AI 프로토타입의 화면·상태·검증은 [FIRST-LEARNING-FLOW](FIRST-LEARNING-FLOW.md)를 따른다.
- 각 흐름은 **시작 조건 → 단계 → 분기·예외 → 관련 항목** 순서로 적는다. 관련 항목은 요구사항 ID(F-*)와 작업 ID(B-*)다.
- 표기: **현재 구현**은 로컬 시험으로 확인된 범위, **승인·미구현**은 결정됐지만 구현 전, **미정**은 합의 전이다. 구현 상태의 기준은 [TASKS](../TASKS.md)·[PROGRESS](../PROGRESS.md)이며 이 문서는 구현 완료를 뜻하지 않는다.

## 1. 시작

- 시작 조건: 로그인한 사용자가 `영어 회화 시작`, `오늘 대화 시작`, `Let's start today's conversation.` 또는 시작 버튼으로 세션을 연다.
- 단계:
  1. 계정에 진행 중이거나 재개 가능한 대화가 있는지 확인한다. 있으면 새 대화를 시작하지 않고 기존 대화로 안내한다(→ [5. 중단·재개](#5-중단재개자동-종료)).
  2. [PRD 7절의 선택 정책](../PRD.md#7-주제와-표현-정책)에 따라 주제·상황과 복습 표현을 고른다.
  3. 짧은 소개와 영어 질문 하나로 시작한다.
- 분기·예외:
  - 저장된 기록이 없으면 이전 학습을 아는 척하지 않고 복습 표현을 꾸며내지 않는다.

## 2. 일반 대화

- 시작 조건: 시작 흐름이 끝나 대화가 진행 중이다.
- 단계(턴 반복):
  1. 학습자의 답변에 먼저 자연스럽게 반응한다. 필요하면 튜터의 의견이나 **가상** 경험을 덧붙인다.
  2. 질문 하나부터 시작하고 현재 응답 부담에 따라 직접 연결된 질문 두 개까지 묶는다. 난이도는 고정 단계 없이 연속적으로 조절하며 어려워하면 질문을 나눈다.
  3. 한 주제가 충분히 진행되면 관련 주제로 확장하거나 새 주제로 전환한다.
  4. 난이도는 쉬운 문장에서 시작해 응답에 따라 조금씩 높인다. 한 문장에서 2~3문장으로 확장하도록 유도하되 긴 답변을 강요하지 않는다.
- 분기·예외:
  - 단답이어도 대화를 이어간다.
  - 정상 연결 중에는 사용자 종료 또는 연결 허용 시간 경계에 따른 종료 전까지 피드백 화면으로 넘어가지 않는다(DEC-062).
  - 교정이 필요하면 [3. 교정](#3-교정과-다시-말하기)으로 이동했다가 돌아온다.

## 3. 교정과 다시 말하기

- 시작 조건: 대화 중 AI가 교정이 필요하다고 판단했거나, 학습자가 한국어로 말하거나 표현을 물었다. MVP는 이 단일 모드이며 교정 끄기·종료 후 일괄 교정은 이후 범위다(DEC-011).
- 단계:
  1. 대화 흐름을 유지한 뒤 중요한 오류를 고른다. 우선순위는 의미 전달을 막는 오류, 이해 가능한 문법 오류, 직역투·반복적·교과서적 표현 순이다.
  2. 현재 맥락에서 가장 유용한 수정 또는 대체 표현 하나를 제시한다. 설명은 짧은 한국어로 할 수 있다.
  3. 표현을 물은 경우 자연스러운 영어 표현을 제시하고 다시 말하도록 요청한다.
  4. 학습자가 다시 말한다.
  5. 올바르게 말하면 짧게 반응하고 현재 난이도에 맞는 질문으로 대화를 잇는다(→ 일반 대화).
- 분기·예외:
  - 음성 오인식이나 교정 근거가 불확실하면 확인하거나 보류한다.
  - 재시도가 틀리면 짧게 고치고 다시 요청한다.
  - 진행 판단(교정 시점·재시도 요청·성공/실패)은 AI가 하고 앱은 그 결과와 진행 상태를 기록·복원한다(DEC-010).

## 4. 종료와 복습

- 시작 조건: 사용자가 종료를 요청하거나 연결 허용 시간 경계에 따른 종료가 확정된다(DEC-062, 승인·미구현).
- 종료 방식:
  - 시간 경계에 따른 종료가 확정되면 아래 노트 정리로 이어진다. 남은 허용 시간이 부족하면 새 유료 음성 연결을 열지 않으며 사전 안내·경계 발화의 세부 순서는 구현 전에 구체화한다.
  - 종료 버튼은 추가 확인 없이 종료한다(DEC-040).
  - 음성으로 종료 의사를 말하면 짧게 한 번 확인하고 사용자가 동의한 뒤 종료한다. 확인 대기만으로 종료를 확정하지 않는다.
- 단계:
  1. 영어 대화를 마친다.
  2. 앱이 저장한 글을 입력으로 한국어로 요약한다. 입력·보관 범위와 학습 항목 선별 기준은 [PRD 8절](../PRD.md#8-저장-데이터와-학습-노트)을 따른다.
  3. 종료 피드백을 제시한다: 대화 주제와 주요 내용, 구체적으로 잘한 점 1~2개, 실제 발생한 주요 오류 최대 3개(3개 미만이면 있는 것만), 실제로 배운 핵심 표현, 다음에 다시 사용할 표현.
  4. 중요한 표현 2~3개는 마무리 복습에서 다시 말할 수 있게 한다.
  5. 일일 Markdown 노트를 만들고 다운로드할 수 있다(F-10).
- 분기·예외:
  - 발화가 확인되지 않은 세션과 저장 실패·부분 노트의 처리는 [PRD 8절](../PRD.md#8-저장-데이터와-학습-노트)과 [학습 저장](LEARNING-PERSISTENCE.md)을 따른다.

## 5. 중단·재개·자동 종료

- 시작 조건: 네트워크·브라우저 등 외부 환경으로 대화가 끊겼거나, 같은 계정에서 다른 탭·기기가 접속했다.
- 단계:
  1. 상태는 `일시 중단`으로 이동한다.
  2. 사용자가 돌아오면 마지막으로 확인된 턴에서 재개한다.
  3. 중단 후 24시간 안에 돌아오지 않으면 자동으로 종료하고 노트를 생성한다(DEC-024).
- 분기·예외:
  - 계정당 진행 중인 대화는 하나만 허용한다. 다른 탭·기기의 중복 연결과 새 대화 시작은 차단하고 기존 대화로 안내한다(DEC-032).
  - 자동 종료는 저장된 마지막 확인 턴·실제 재생된 AI 발화·연결된 교정/재시도 기록만 근거로 쓴다. 저장되지 않은 마지막 턴과 미확인·미재생 응답은 쓰지 않는다.
  - 정확한 상태 전이와 종료 저장 경계는 [PRD 6절](../PRD.md#6-대화-상태와-예외)·[학습 저장](LEARNING-PERSISTENCE.md)을 따른다.

## 이 문서에 쓰지 않는 것

- 정책 수치·보관 기한·비용은 PRD, 선택 이유는 [DECISIONS](../DECISIONS.md), 저장·API·음성 계약은 각 상세 설계에 둔다.
- 날짜별 구현·검증 결과는 worklog에 둔다.
