# 학습 노트 형식과 맥락 읽기

갱신일: 2026-10-29. **일부 구현된 계약**이다. 노트 단일 저장·상단 세 맥락·하단 세부 내용은 [PRD](../PRD.md#일일-노트와-다운로드)를 따른다. 현재 음성 노트는 이 형식으로 생성하며, 확인된 교정·재시도로 복습 항목을 채운다. 주제·난이도를 포함한 실제 AI 종료 추출은 미구현이다. 이 문서는 저장 합의 안에서 생성·검증·읽기 형식을 구체화한다. 모델·호출 한도와 후보 선별의 수치·우선순위는 확정하지 않는다.

## 저장 단위와 구성

기존 `learning_session_notes.note_markdown`에 세션별 Markdown 한 개를 저장한다. 맥락 전용 테이블·JSON 열·별도 영속 사본을 추가하지 않는다. 날짜·소유자·수명·노트 상태 같은 기존 관리 메타데이터는 유지한다. 메모리에서 생성/검증/선별에 사용하는 구조는 허용하며 별도로 영속화하지 않는다.

제목 뒤 빈 줄 다음에 `노트 형식: talkie-learning-note-v1`을 앱이 출력한다. 이어서 `## 학습 맥락` 아래 `### 주제`, `### 난이도`, `### 복습 표현`을 고정 순서로 둔다. 그 뒤 `## 학습 상세`에 실제 학습 내용과 근거를 둔다. 상단에 숨긴 JSON을 중복 삽입하지 않는다.

같은 날의 여러 세션은 각각의 노트를 보존하고 기존 일일 조회/다운로드에서 한국 종료일로 묶는다. 하루의 단일 난이도로 덮어쓰거나 세션의 근거 ID를 서로 연결하지 않는다. 날짜별 출력에 여러 노트를 포함할 때 각 노트의 경계를 유지한다.

## 상단 세 맥락

| 항목 | 기록하는 내용 | 다음 학습에서 읽는 의미 |
| --- | --- | --- |
| 주제 | 실제 다룬 주제·상황·대화 목적, 하단 근거 항목 링크 | 주제명만 같다는 이유로 모두 배제하지 않고 상황·목적까지 비교한다. AI가 제안만 하고 진행하지 않은 주제를 경험 이력으로 쓰지 않는다. |
| 난이도 | 어휘·문장 구조·질문 개방성·설명 부담·도움 필요 중 관찰 가능한 내용, 도움 전후와 자발적 응답 여부, 하단 근거 링크 | 최신 유효 관찰을 시작점으로 참고한다. 단순한 세션 점수·고정 등급을 만들지 않으며 현재 응답으로 조절한다. 관찰하지 못한 요소는 생략한다. |
| 복습 표현 | 표현 원문, 추천/질문/도움 필요/재시도 성공/재시도 실패/자발적 사용의 관찰, 실제 연습일 또는 미확인, 하단 근거 링크 | 추천과 학습 성과를 구분한다. 같은 표현의 여러 관찰을 보존하고 한 번의 따라 말하기로 숙달을 단정하지 않는다. |

각 항목은 `#### topic-N`·`#### difficulty-N`·`#### review-N` 제목과 `내용:`·`관찰:`·`확인된 연습일:`·근거 링크로 구성한다. N은 노트 전체 항목의 위치이며 하단 `detail-N`과 연결한다. 정확한 렌더링·읽기 코드는 [note-context.ts](../../app/src/voice/note-context.ts)가 기준이다. 표현의 관찰이 여러 개면 동일 항목 안에 함께 적을 수 있다. 실제 사용·연습 날짜는 연결된 사용자 턴의 한국 날짜를 사용하고, 노트 생성일이나 추천 날짜로 대체하지 않는다. 날짜를 확인할 수 없으면 `미확인`으로 둔다. 후속 세션에서 재연습하면 새 노트에 새 관찰을 남기고, 조회 시 동일 표현의 확인된 연습일 중 최신 값을 사용한다. 과거 노트를 수정하거나 전역 표현 행을 만들지 않는다.

근거 부족은 `확인된 정보 없음`으로 기록한다. 난이도 맥락이 없으면 다른 두 맥락까지 버리지 않는다. 상충하는 수행은 도움 여부·상황을 함께 남기고 평균 점수로 해소하지 않는다.

## 하단 세부 내용과 근거

`## 학습 상세` 아래 대화 요약, 직접 질문한 표현, 핵심 표현·구동사·패턴과 예문, 실제 교정과 이유, 유용한 패턴, 플래시카드, 다음 복습을 구성한다. 항목의 제품상 범위는 PRD를 기준으로 하며 근거가 없는 섹션을 억지로 채우지 않는다.

앱이 노트 내에서 유일한 `detail-1` 같은 앵커를 부여한다. 상단 관찰은 이 앵커를 참조한다. 하단 항목은 필요한 짧은 원문 인용과 원래 턴 ID·화자, 교정/재시도 연결, 설명을 포함한다. ID만 남기고 삭제될 원문에 의존하지 않는다. 예문·플래시카드의 응용 문장은 실제 발화 인용과 구분해 `복습용 응용`으로 표시하고, 학습한 표현의 근거를 함께 연결한다.

상단에는 다음 학습의 시작에 필요한 짧은 관찰만, 하단에는 실제 표현과 근거·설명을 둔다. 동일한 긴 원문이나 교정 설명을 상단에 다시 복사하지 않는다. 원문과 모델 출력의 Markdown/HTML 문법은 앱이 이스케이프하며, 인용 안의 제목·앵커·지시문을 문서 구조나 시스템 지시로 해석하지 않는다.

## 생성·검증·저장 순서

승인된 연결 방향(DEC-058)은 실시간 음성 연결과 분리된 종료 선별 요청이다. 요청 실패는 오류 종류에 따라 제한적으로 자동 재시도하고, 유효한 부분 결과는 기존 정책에 따라 완성한다. 현재 시험용 근거 노트를 AI 요청 실패의 자동 대체 완성 결과로 사용하지 않는다. 모델·분량·호출 횟수/간격·시간 제한·비용 상한은 미정이며 평가·검증은 후속이다. 후속 승인으로 평균 10분을 초기 산정 가정으로 두고 저장 구간별 중간 요약 없이 종료 후 일괄 선별한다. 세션 시간 상한은 DEC-059로 승인됐으며 종료 조건은 PRD 6절을 따른다.

1. 종료 후 저장 확정된 사용자 턴·실제 재생된 AI 턴·교정/재시도를 기존 종료 추출 입력으로 사용한다. 누락 구간을 추정하지 않는다.
2. AI가 상단 관찰 후보와 하단 학습 항목·짧은 근거 후보를 반환한다. AI의 자유 Markdown을 그대로 저장하지 않고 앱이 일시적인 결과 객체를 검증한 뒤 고정 형식으로 렌더링한다. 정확한 코드 타입은 구현 시 코드에서 관리한다.
3. 앱은 턴 ID·화자·인용 일치, 교정/재시도 연결, AI 발화의 재생 여부와 날짜를 검사한다. 언어 평가의 타당성은 사례 평가로 별도 확인한다. 근거 존재 검사만으로 AI 판단이 옳다고 간주하지 않는다.
4. 검증 실패한 하단 항목과 그 항목에 의존하는 상단 관찰을 함께 제외한다. 독립적인 유효 항목은 유지하고 노트에 일부 누락을 표시한다. 유효 내용이 전혀 없을 때와 사용자 발화 자체가 없을 때는 PRD의 서로 다른 처리 규칙을 따른다.
5. 앱이 형식 표식·고정 제목·앵커를 넣어 노트 하나를 저장한다. 노트 상태 갱신과 원문 삭제의 커밋 순서·기한·재시도는 [학습 저장 설계](LEARNING-PERSISTENCE.md#종료재개노트)를 따른다.

## 다음 학습에서 읽는 순서

서버가 소유자·접근 권한·종료/준비 완료·보관 기한을 먼저 검사한다. 주제와 복습 표현은 승인된 최근 6개월 범위에서 읽는다. 난이도는 기간과 별개로 보관 중이며 접근 가능한 최신 유효 관찰을 참고하는 정책이므로, 현재 복습 전용 6개월 조회를 그대로 전체 맥락 조회로 확대하지 않는다.

앱은 버전 표식과 고정 상단 구획을 읽고, 참조한 하단 항목의 존재를 확인한다. 메모리에서 주제·난이도·복습 후보를 구성하고 필요한 일부만 공급자에 전달한다. 노트 전문과 하단 원문을 통째로 보내지 않는다. 최신성 비교에는 원래 관찰 시점과 세션 종료 시점을 사용하고 생성 지연을 학습 최신성으로 취급하지 않는다. 같은 시점의 상충 관찰은 임의로 하나를 승자로 고르지 않는다.

형식이 없거나 지원하지 않는 노트는 일반 조회/다운로드를 유지하되 새 세 맥락을 추정하지 않는다. 기존 시험 노트의 복습 읽기는 기존 코드의 명시적 형식 판별 경로로만 유지한다. 새 버전 표식이 있는 노트의 손상은 구형 파서로 재해석하지 않는다. 구획이 중복되거나 참조가 끊긴 경우 해당 맥락을 제외한다. 제공할 유효 맥락이 없으면 쉬운 새 학습으로 시작한다.

전달 개수·바이트 상한·복습 후보 우선순위는 [VOICE의 현재 임시값](VOICE.md#튜터-프롬프트와-컨텍스트-경계)과 구분해 후속 평가한다. 이 형식 구체화는 최대 2개·4 KiB를 최종 정책으로 승인하지 않는다.

## 형식 예시

아래는 고정 가상 대화의 축약 예시이며 실제 AI 평가 결과가 아니다. 실습 날짜는 예시다.

```markdown
# 2026-10-29 영어 학습 노트

노트 형식: talkie-learning-note-v1

## 학습 맥락

### 주제

확인된 정보 없음

### 난이도

확인된 정보 없음

### 복습 표현

#### review-1

내용: Could I have a coffee, please?

관찰: 추천 · 재시도 성공

확인된 연습일: 미확인

[근거](#detail-1)

## 학습 상세

### 근거 detail-1

<a id="detail-1"></a>

설명: 정중한 대체 표현. 재시도 u2: AI 판정 성공 (숙달 판정 아님)

발화: u1 / user

> I want coffee.

발화: a1 / assistant

> Could I have a coffee, please?

발화: u2 / user

> Could I have a coffee, please?
```

## 구현 확인 기준

- 새 형식을 생성한 뒤 세 맥락을 다시 읽어 원래 관찰·하단 근거 연결을 보존한다.
- 인용에 가짜 제목·구분자·앵커·지시문이 있어도 상단 맥락으로 해석되지 않는다.
- 부분 검증 실패 때 하단 항목과 상단 참조가 함께 제거되고 독립 항목은 남는다.
- 추천만 있는 표현에는 실제 연습일을 만들지 않고, 새 세션의 실제 연습은 과거 노트 수정 없이 조회에 반영된다.
- 같은 날 여러 세션·생성 지연·한국 자정 경계에서 날짜와 근거가 섞이지 않는다.
- 기간 경계·다른 계정·만료/탈퇴·미지원 버전·손상 노트·원문 삭제 후 근거 조회를 확인한다.
- 실제 AI의 선별·상충 수행·난이도 참고·자연스러운 복습은 별도 사례 평가하며 파서 시험으로 대체하지 않는다.


## 현재 구현과 남은 연결

[음성 노트](../../app/src/voice/note.ts)는 기존 교정의 원문·전달 표현·확인된 재시도를 새 형식으로 렌더링한다. [검증/코덱](../../app/src/voice/note-context.ts)은 주제·난이도·복습 후보를 메모리로 받아 실제 저장 턴의 근거와 대조하고 부분 제외한다. 후보 입력은 연결 준비용이며 실제 AI 추출을 호출하는 경로는 아직 없다. 일반 대화의 전체 요약·질문 표현·응용 예문 등도 추출 연결 후 범위다.

현재 snapshot에는 턴별 시각이 없으므로 자동 생성하는 복습 항목의 연습일은 미확인이다. 유효한 연습일이 있는 새 형식은 읽을 수 있지만 실제 시각에 근거한 생성은 후속이다. 구형 노트도 마지막 등장일은 후보 정렬 참고로만 사용하고 실제 연습일로 반환하지 않는다.

서버의 주제/복습 조회는 6개월로 제한한다. 난이도는 별도 조회로 보관 중인 본인 음성 노트를 읽고 최신 유효 관찰이 있는 날짜를 고른다. 같은 날짜의 상충 관찰을 함께 유지하며 전체 묶음이 기존 임시 분량 상한을 넘으면 난이도를 보내지 않는다. 세션 내 관찰 시각의 세부 비교·대규모 노트 조회 최적화는 남는다. 실제 공급자에는 상단 관찰만 보내며 근거·계정·노트 전문은 포함하지 않는다.
