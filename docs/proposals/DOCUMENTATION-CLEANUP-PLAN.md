## 공통 경계

- 앞선 C 통합·평가 후보와 미커밋 변경을 보존한다. 앱 기능·DB/실제 데이터·공급자 호출·배포·커밋은 변경하지 않는다.
- PRD의 사용자 동작·배점/반올림·권한·비용/보관/삭제 제약은 유지한다. 이전 시간 이용권의 이력을 지우거나 코드가 승인 계약을 자동 대체하게 하지 않는다.

- 각 단계 수정 전에 작업 트리 Markdown 사본·해시와 미커밋 diff를 저장소 밖에 저장한다. 수정 후 그 기준선 대비 증분을 검토하고 앞선 변경의 보존을 확인한다. 1단계 기준선은 `/tmp/talkie-doc-cleanup-baseline-20261114`이며 임시 사본의 장기 보존은 보장하지 않는다.
- 각 단계: 계획 구체화 → Claude Opus 5.5 읽기 전용 검토 → 지적 반영/계획 보완 → 수정 → 해당 범위 검사. 검토가 불가능하면 적용을 진행하지 않고 원인을 보고한다. Claude가 수정에 참여하도록 별도 지시하지 않는다.

### 수정 범위와 방법

1. PRD 노트 선별 문단의 ‘모델 미정’을 기존 음성 종료 선별과 미션 후속 범위로 구별한다. DEC-064/065 링크와 미정인 미션 평가 호출 구성·공개 경로 최종 모델만 설명하며 모델명·수치를 새로 싣지 않는다.
2. DATABASE의 시간제 승인·미구현 표를 현행 미션 확장 안내/링크로 바꾸고, Google 스키마 부재 설명을 실제 매핑 경계에 맞춘다. 새 테이블/스키마를 설계하거나 과거 DEC-063을 삭제하지 않는다.
3. API·LEARNING-PERSISTENCE·VOICE의 음성 노트 설명을 코드와 승인 범위에 맞춘다. Google 정리 대상은 DATABASE·API·DESIGN·PROGRESS이다. API의 미션 미구현과 실제 장기 연결 보호·품질 미완료는 유지한다.
4. DESIGN은 현재 음성 포트/어댑터와 부분 구현을 설명하고 화면 경로는 USER-FLOWS 화면 지도에 연결한다. 실행 포트나 실행 절차는 복사하지 않는다. README의 B-00 안내만 /try로 맞추고 기존 제목 앵커와 가짜 노트 범위를 유지한다.
5. PROGRESS의 현재 표·다음 작업에서 폐기된 시간제·이미 구현된 음성 추출·Google 연결 정책/부분 구현을 미정으로 다시 제시하는 문구를 바로잡는다. 실제 OAuth·음성 종료 E2E·교육 품질 미검증은 유지하고 전체 구조 축약은 3단계에 수행한다.
6. 제안서/색인은 당시 대본·선택 이유·미승인 후보를 보존하고 현행 안내에 DEC-064/065/069 및 설계/검증 링크를 추가한다. 당시 설명 전체를 소급 재작성하지 않는다.
7. API·LEARNING-NOTE·TASKS V-05·ENGINEERING-VALIDATION에 남은 시간제 문구도 포함한다. 사용자 차감은 횟수, 연결 시간은 비용 관찰 지표로 구별하며 주간 대조·노트 호출 보호는 유지한다. 새 측정값·지표를 정의하지 않는다. 이번에 내용이 바뀌는 현행 문서의 갱신일도 맞추고 과거 작성일은 유지한다.

Claude 검토의 M1~M7은 위 초안보다 우선한다. DEC-065의 승인 수치·평가 한도/통과 기준·실측 전/사용자 조정 원문은 DECISIONS에 보존하고 현행 설계에는 복사하지 않는다. DEC-064도 승인 이유·필수 기준·상위 모델 재합의·역사적 대체를 보존하며 목록의 중복 요약만 본문 링크로 줄인다.
