점검일: 2026-11-14. **점검 결과와 정리 제안이며 정책 변경·정리 적용 완료를 뜻하지 않는다.** 기준은 [AGENTS](../../AGENTS.md#document-ownership)다. 사용자 요청에 따라 PRD 분량뿐 아니라 문서 책임·중복·상태·결정·근거·파일 구조·커밋 검사 환경을 확인했다.

## 결론과 범위

부분 준수다. 파일 배치·명명·로컬 문서 링크·대부분의 승인/미승인 구분은 갖춰져 있지만, 현행 상태의 충돌과 책임 혼재가 있다. 링크가 있어도 같은 계약을 양쪽에 상세히 쓰거나 오래된 상태를 계속 현행으로 읽게 하는 문제가 남는다.

- 구조 검사: `docs/**/*.md`와 루트 AGENTS·README·CLAUDE 97개, Markdown 인라인 링크 896개의 로컬 경로·대상 Markdown 앵커를 검사했다. 파일명은 날짜형 worklog 예외를 포함해 대문자 원칙과 대조했다. 코드 블록·자동 생성 문서까지 정식 Markdown 파서로 해석한 검사는 아니며, 외부 URL의 응답은 검사하지 않았다.
- 내용 대조: PRD·TASKS·PROGRESS·DESIGN·상세 설계 11개·DECISIONS·README·TROUBLESHOOTING을 중심으로 확인하고 제안서의 현재/과거 안내·ADR의 상태/후속 관계·worklog 연결을 대조했다. 모든 과거 작업의 실제 승인 대화·실험 원본·커밋 당시 실행 결과를 재현한 감사는 아니다.
- 코드 표본: Google 매핑 스키마·종료 노트 추출 연결·루트 화면을 확인해 구체적인 문서 모순을 대조했다. 전체 앱 동작·보안·DB 상태의 검증은 아니다.
- 기준 시점은 점검 시작 시의 작업 트리다. 같은 날 앞서 수정한 C 통합 문서와 중복 감점 추천도 포함한다. 과거 C1/C2·시간제 기록 자체를 일괄 위반으로 세지 않았다.

## 확인한 문제

### A01 · 높음 · 대체된 시간 이용권이 현재 남은 일로 유지됨

- 근거: [PROGRESS](../PROGRESS.md)의 43~49행과 현재 작업 표 B-10(75행)은 DEC-062/063의 시간 이용권·별도 이용권 테이블을 앞으로 구현할 일로 적고 있다. 반면 [TASKS B-10](../TASKS.md)은 DEC-069가 시간 이용권을 대체했다고 명시한다. [DATABASE](../design/DATABASE.md) 5·16행도 시간 이용권을 승인·미구현 현행 설계로 소개하며, 머리말의 미션 전환 안내와 충돌한다.
- 영향: 다음 구현자가 폐기된 차감 방식을 구현할 수 있다. 단순히 옛 날짜가 남은 문제가 아니라 ‘현재 작업 상태’와 ‘승인·미구현’이라는 현행 안내의 모순이다.
- 정리: 미션 횟수 계약을 기준으로 PROGRESS의 현재/다음 작업과 DB의 현행 확장 범위를 맞춘다. 옛 시간제 비교·승인 근거는 기존 ADR·worklog에 보존하고 대체 링크를 둔다. 새 차감 정책을 이 점검으로 정하지 않는다.

### A02 · 높음 · 노트 모델·호출·구현 여부가 문서마다 다름

- 근거: [PRD](../PRD.md) 181행은 선별 모델을 미정으로 적는다. [PROGRESS](../PROGRESS.md) 51행은 실제 추출 호출·코드 반영이 없다고 적으면서 55행과 B-06에는 구현·평가했다고 적는다. [LEARNING-PERSISTENCE](../design/LEARNING-PERSISTENCE.md) 43행은 음성 노트에 추가 공급자 호출이 없다고 설명한다. [VOICE](../design/VOICE.md) 64행은 실제 AI 추출을 후속으로 둔다. [제안서 머리말](LEARNING-NOTE-EXTRACTION.md)과 [색인](INDEX.md)도 모델·호출 한도가 미정인 상태로 안내한다.
- 대조: DEC-064/065는 모델 방향·초기 한도를 승인했다. [LEARNING-NOTE](../design/LEARNING-NOTE.md)는 별도 종료 추출 연결을 설명하며 [learning.ts](../../app/src/server/learning.ts)의 `extractVoiceNote`와 [maintenance.ts](../../app/src/server/maintenance.ts)의 호출이 존재한다. [11월 2일 기록](../worklogs/2026-11-02.md#b-06-종료-노트-안전성품질-보완)에 실제 합성 평가 조건이 남아 있다.
- 정리: 기존 자유 대화용 종료 추출의 승인/부분 구현, 미션 최종 평가·노트 계약의 미정, 실제 교육 품질의 미검증을 구별한다. 기존 연결 구현을 전체 품질 완료로 올리거나, 미션 계약 미정이라는 이유로 기존 구현을 없었던 것으로 설명하지 않는다.

### A03 · 중간 · 현재 설계·소개에 이전 화면과 Google 상태가 남음

- 근거: [DESIGN](../DESIGN.md) 13~15행은 `/`를 B-00으로 소개하고 Google 로그인을 남은 구현으로 적는다. [README](../../README.md) 17행도 루트에서 시나리오를 고르도록 안내한다. 현재 [루트 화면](../../app/src/app/page.tsx)은 랜딩이며 [사용자 흐름의 화면 지도](../design/USER-FLOWS.md#앱-화면-지도)는 `/try`·`/talk`를 설명한다. [DATABASE](../design/DATABASE.md) 5행은 Google 매핑이 없다고 적지만 같은 문서 23행과 [스키마](../../app/src/server/db/records-schema.ts)의 `googleIdentities`는 존재한다. [API](../design/API.md) 85행은 Google 계정 연결 정책을 미정으로 적지만 DEC-067과 인증 설계에 합의·부분 구현이 있다.
- 정리: ‘전환 전 구현’은 미션 전환 전의 현행 자유 대화 앱으로 설명하고, 그보다 이전 데모 경로와 혼동하지 않는다. 오래된 화면 사용법은 README에서 현행 실행 경로로 맞추며 실제 Google 클라이언트 미검증은 유지한다.

### A04 · 중간 · PRD에 구현 수단·기술적 가정이 섞임

- 근거: [PRD](../PRD.md) 45행의 수준 정의를 데이터로 관리한다는 설명, 157행의 프롬프트/상태 전달과 공급자 맥락 동기화 방법, 179행의 평균 10분 산정 가정·일괄 선별 구성, 217행의 별도 맥락 저장소 금지, 223행의 앱 직접 인증 구현·쿠키 수단, 307행의 PostgreSQL/합성 메일/timer 구성 등이 제품 약속과 함께 들어 있다.
- 정리: 사용자에게 보이는 수준·재개·기록 일치·노트 구성·로그인 유지와 데이터 보호 제약은 PRD에 남긴다. 이를 보장하는 프롬프트 입력 구성·저장 구조·인증 구현·운영 구성·산정 가정은 각각 미션/음성·학습 노트·인증·로컬 운영 설계로 옮기고, 선택 이유는 DEC/ADR에 연결한다. 한 문단 전체를 기계적으로 옮기지 않고 문장 안의 제품 조건과 수단을 나눈다.

### A05 · 중간 · 링크와 함께 정책 상세도 재서술됨

- 근거: [미션 설계](../design/MISSIONS.md#기록평가결과) 54~62행은 PRD 4.5절의 전체 대화 평가·부분점수·판정 불가 제외·배점 유지·환불 동등 처리·표시와 달성 판정을 길게 다시 설명한다. [TASKS B-12](../TASKS.md)는 같은 정책을 다수 열거해 수용 기준과 명세의 경계가 흐려졌다. 방금 정리한 C 기대 설명도 PRD와 미션 설계 사이에 반복된다.
- 정리: 정책 원문은 PRD에 남기고 미션 설계에는 버전 고정·근거 연결·앱 합산·저장/API 경계 등 구현 협력만 남긴다. TASKS에는 확인할 경계 조합과 해당 정책/평가 사례 링크를 둔다. 짧은 요약·독립된 구현 설명·테스트 경계는 허용하며 같은 단어가 있다는 이유로 중복으로 세지 않는다.

### A06 · 중간 · PRD·설계·PROGRESS가 날짜별 검증 기록까지 맡음

- 근거: [PRD 9.3](../PRD.md#93-전환의-구현-상태와-남은-결정)은 구현 상태를 관리하고, 11절의 Google 항목에는 가짜 신원 서버 시험/실제 클라이언트 미검증 상태가 들어 있다. [VOICE](../design/VOICE.md) 72행은 10월 30일 사용액과 사용자 시험 보고를 다시 적는다. [PROGRESS](../PROGRESS.md)에는 ‘오늘’ 사용액·과거 여러 다음 작업·이미 뒤집힌 구현 설명이 누적돼 현재 상태를 빠르게 식별하기 어렵다.
- 정리: PRD에는 제공 조건·미정 결정과 결정 시점을 남기고 구현/검증은 TASKS·PROGRESS로 연결한다. 설계에는 현재 구현의 경계와 관련 근거 링크만 둔다. PROGRESS는 현재 단계·다음 작업·남은 한계 위주로 줄이고 날짜별 실험 조건/금액은 worklog로 연결한다. 과거 worklog를 현행처럼 다시 쓰지 않는다.

### A07 · 중간 · 짧은 결정의 상세 계약 관리가 남아 있음

- 근거: [DECISIONS](../DECISIONS.md)에는 DEC-064/065가 짧은 요약(107~108행)과 별도 상세 본문(333~345행)으로 중복돼 있다. DEC-065는 구간 문자 수·토큰·재시도·시간·동시성 수치를 열거하고, DEC-036~039도 상세 인증/로그 계약을 관리한다. 자체 기록 규칙은 짧은 결정에 결론·핵심 이유·링크만 남기도록 정한다.
- 정리: 현행 호출 수치·보호 방법은 학습 노트/음성 설계에서 관리하고 결정에는 채택 범위·이유·초기값이라는 성격·기준 링크만 남긴다. 중요한 절충을 이해하는 데 필요한 핵심 조건은 보존한다. 분량만 보고 ADR을 새로 만들지 않으며 기존 동의·위험 수용·ID·앵커·대체 관계를 잃지 않는다.

### A08 · 낮음 · 갱신일과 과거/현재 표시가 혼재함

- 근거: PRD와 DESIGN의 갱신일은 10월 29일, PROGRESS의 ‘마지막 갱신’은 11월 2일인데 이후 미션·평가·C 통합이 반영돼 있다. 제안서 색인의 점검일도 10월 28일이다. [ADR-055](../adr/055-GEMINI-LIVE-FIRST-E2E-AND-VOICE-PORT.md)는 최초 Accepted와 후속 변경 설명을 함께 두지만 결정 목록은 Partially Superseded로 표시한다. 후속 근거는 있으므로 승인 누락으로 단정하지 않는다.
- 정리: 현행 파일의 날짜 안내를 맞추거나 갱신일을 단일 관리한다. ADR은 결정 당시 상태를 보존하되 현재 상태/대체 범위를 명확하게 한 번 표시한다. 오래된 작성일·당시 승인 상태 자체는 위반이 아니다.

### A09 · 중간 · 커밋 검사 파일은 있으나 현재 환경에서 자동 실행이 보장되지 않음

- 관찰: `git config --show-origin --get core.hooksPath`에 설정이 없고 기본 `.git/hooks/pre-commit`도 없다. `.githooks/pre-commit`은 존재·실행 가능하지만 Git 자동 훅으로 연결돼 있지 않다. README는 설정 명령을 안내한다.
- 관찰: 프로젝트 `.tools/gitleaks`는 없고 PATH의 `/usr/local/bin/gitleaks`는 8.18.2다. 저장소 훅의 `gitleaks git --pre-commit --staged --redact .`와 같은 `git` 하위 명령을 실행하면 `unknown command`로 실패한다. CI는 별도로 8.30.1을 지정한다.
- 별도 검사: `python3 scripts/check_secrets.py --tracked` 통과. 설치 버전에 맞는 `gitleaks detect --source . --redact --no-banner --no-color`로 Git 이력 28커밋 검사, 탐지 0건. 이는 현재 저장소 훅 통과·미커밋 파일 전체 검사·비밀값 부재의 증명이 아니다. 과거 커밋 당시 훅이 실행됐는지도 현재 환경만으로 판단할 수 없다.
- 정리: 명시된 버전과 로컬 훅 경로를 맞춘 뒤 실제 스테이징 diff·민감 파일명·Gitleaks 검사를 확인해야 한다. 이번 점검에서는 Git 설정·설치·스테이징·커밋을 변경하지 않았다.

## PRD에 남겨야 하는 상세

분량을 줄이려고 제품 계약을 설계 문서로 옮기면 책임 원칙을 다시 위반한다. 다음은 상세하더라도 PRD가 기준이다.

| 내용 | 판단 |
| --- | --- |
| 목표 60/언어 40, 세부 배점, 부분점수, 판정 불가, 반올림과 80% 인정 | 사용자가 받는 평가 결과의 계약. 계산용 자료형·검증/저장 방법만 설계 |
| 카페의 허용 경로·처리 조건·완료 기준·환불 동등 처리 | 첫 제공 미션의 고정 제품 조건. 실행 프롬프트·상태 필드·실행 대본은 설계/사례 |
| 연습/실전 도움·무진전 판정/제외·짧은 수행 인정 | 사용자 동작과 평가 공정성. 사례 대본과 생성 검증 방법은 별도 |
| 로그인 30일·인증 10분·발송 30초·보관/삭제 기한 | 수명·권한·비용과 데이터 보호 약속. 열/잠금/트랜잭션/timer는 설계 |
| 로그에 담을 수 있는 정보·금지 정보·접근자·수명 | 데이터 수집 정책이므로 PRD에 유지 가능. JSONL 위치·파일 회전·필드명은 설계 |
| 실험 총예산·유료 호출 전 차단 조건·실제 사용자 데이터 제외 | 승인된 비용/데이터 제약. 예약 장부의 타입과 집행 알고리즘은 설계 |

## 정리 순서 제안

1. 현행 충돌 A01~A03부터 해결한다. 코드가 있다는 이유만으로 승인 계약을 바꾸지 않고 결정·worklog·구현을 대조한다.
2. PRD를 제품 약속·정책·목표·미정 결정으로 정리한다. 같은 문단의 기술 수단·구현 상태를 해당 설계/PROGRESS로 이관하고 기존 앵커를 유지한다.
3. 미션 설계·TASKS·DECISIONS의 반복 명세를 기준 링크와 각 문서의 고유 책임으로 줄인다. PROGRESS는 현재 작업·근거·다음 작업으로 재구성한다.
4. 변경한 파일과 직접 연결된 기준만 다시 대조하고 링크·ID·수용 기준·상태·이관한 계약의 누락을 검사한다. 문서가 짧아진 정도를 완료 기준으로 삼지 않는다.

정책을 보존하는 정리와 명확한 후속 상태 연결은 기존 결정 안의 문서 작업이다. 중요한 계약의 실제 충돌이 남거나 요구사항을 바꿔야 할 때에만 AGENTS의 논의 절차를 적용한다. 이번 요청은 점검이므로 이관·정책/설계 수정·훅 설정 변경은 적용하지 않았다.
