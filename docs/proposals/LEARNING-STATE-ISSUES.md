# 학습 상태 관리 쟁점

작성일: 2026-10-16. 마지막 갱신: 2026-10-21. 상태: B안 채택 (DEC-010), MVP 모드 채택 (DEC-011), 기록 범위 방향 채택 (DEC-012), 주기적 묶음 저장 채택 (DEC-013), 간격·저장 기술·실패 처리 상세 미정. 보관·재개 기한의 현재 기준은 PRD 8절과 DEC-017~028을 따른다. 관련: `DEC-002`, `DEC-003`, `DEC-008`, PRD 6·8·9.2절, `D-01`, `D-02`, `D-03`, `B-00`.

이 문서는 학습 상태를 앱과 AI 중 누가 어떻게 관리할지에 관한 쟁점·선택지와 사용자 답변을 정리한다. 채택된 결정을 대체하지 않는다. 결정은 사용자와 합의한 뒤 `DECISIONS.md`에 기록한다.

## 배경

`DEC-008`은 "앱이 학습 상태를 관리하고 AI가 대화·교정을 맡는다"고 정했다. 논의 시작 당시 [PRD](../PRD.md) 6절과 [첫 학습 흐름 설계](../design/FIRST-LEARNING-FLOW.md)는 `일반 대화 → 다시 말하기 대기 → 일반 대화`처럼 세션 안의 진행 상태도 앱이 상태 전이로 관리하는 것으로 기술했다. 현재 책임 기준은 DEC-010에 맞춰 갱신했다.

논의 중 다음 관점이 제기됐다. 대화를 시작할 때 앱이 학습 상태를 바탕으로 컨텍스트를 전달하고, AI는 세션 안의 대화만 다루며, 세션이 끝나면 그 내용을 앱에 전달한다. 이 관점과 현재 문서의 기술 사이에서 "학습 상태"의 범위가 정리되지 않았다.

## 학습 상태의 층

| 층 | 내용 | 현재 문서의 기술 |
| --- | --- | --- |
| L1. 세션 사이의 누적 상태 | 익힌 표현, 반복 오류, 주제 이력, 복습 항목 | 계정별 저장소에 보관 (`DEC-002`, PRD 8절) |
| L2. 세션 중 대화 기록 | 전사문, 실제 재생 범위, 턴 순서 | 저장 대상으로 명시 (PRD 6·8절). 앱 기록 방향 채택. 전체 대화는 임시 보관 (DEC-012). 종료 후 추출 결과 저장 성공 확인 뒤 전체 원문 삭제, 실패 시 재시도용 유지. 주기적 묶음 저장 (DEC-013), 간격은 미정. 종료 후 최대 24시간 내 재시도하며 성공 즉시 또는 기한 경과 시 원문 삭제 |
| L3. 세션 중 학습 진행 | 교정 발생, 다시 말하기 대기, 재시도 성공·실패 | AI 판단 + 앱 기록·복원 (DEC-010, PRD 6절) |
| L4. 세션 종료 결과 | 종료 피드백, 노트, 다음 복습 항목 | 실제 대화·교정 기록에 근거 (원칙 6, `F-09`). 앱이 임시 저장한 글을 입력으로 요약·항목·짧은 원문 근거를 남김 (DEC-012). 종료 후 AI가 저장된 대화·교정·재시도 기록을 한 번에 검토해 선별. 선별 기준은 PRD 8절 참조. 모델·항목 수·분량·우선순위는 미정 |

## L3 선택지

- **A. AI 전담**: 교정·다시 말하기 규칙을 프롬프트로 지시하고, 앱은 세션 중에 관여하지 않는다.
- **B. AI 진행 + 앱 기록**: AI가 대화를 진행하고 교정·재시도 결과를 이벤트(예: 도구 호출)로 앱에 알린다. 앱은 기록·표시하되 흐름을 강제하지 않는다.
- **C. 앱 전담**: 앱이 상태 머신으로 턴마다 AI 출력을 분류하고, 다시 말하기 대기 중에는 AI에 지시를 넣어 흐름을 강제한다.

## 측면별 쟁점

아래는 채택 전 대안 비교다. 현재 B안을 채택했으며 문서 변경도 반영했다. "추정"으로 표시한 항목은 실제 공급자 테스트로 확인하지 않은 내용이다.

| 측면 | A | B | C |
| --- | --- | --- | --- |
| 대화 자연스러움·지연 | 세션 중 앱 개입 없음 | 이벤트 호출이 발화 흐름이나 지연에 영향을 줄 수 있음 (추정) | 턴별 판단·지시 주입에 따른 지연 가능 (추정) |
| `F-05` 다시 말하기 보장 | 프롬프트 준수에 의존 | 프롬프트 준수에 의존하며 준수 여부를 기록으로 확인 | 앱이 강제 |
| 대화 중 화면 표시 | 교정·재시도 상태를 세션 중에 알 수 없음 | 이벤트 기반 표시 가능 | 상태 기반 표시 가능 |
| 노트 근거 (`F-09`, `V-02`) | 별도 근거 확보 방식 필요 | 이벤트와 전사문 대조 가능 | 앱 상태 기록과 연결 |
| 품질 지표 (PRD 9절) | 종료 후 추출로 산출 | 세션 중 기록과 종료 후 추출 | 세션 중 상태 기록 |
| 끊김 후 재개 (PRD 6절) | 전사문으로 복원 | 마지막 이벤트로 진행 상태 복원 | 앱 상태로 복원 |
| 실시간 음성·끼어들기 (`DEC-008`) | 세션 중 앱 상태와 엇갈릴 여지 없음 | 끼어들기 시 이벤트와 재생 범위의 정합성 확인 필요 | 끼어들기 시 앱 상태와 AI 맥락의 정합성 확인 필요 |
| 테스트 (`O-02`) | 대부분 AI 시나리오 평가 | 앱 기록·중복·재개는 자동 테스트, AI 행동은 시나리오 평가 | 상태 전이는 자동 테스트, 출력 분류 정확도는 별도 평가 |
| 구현 범위 | 프롬프트·종료 처리 | 이벤트 계약·기록·표시 | 상태 머신·분류·지시 주입 |
| 비용 | 추가 호출 없음 | 이벤트 처리분 | 턴별 분류 호출 시 증가 |
| 공급자 교체 | 프롬프트 이전 | 앱이 정의한 이벤트 계약 이전 | 앱 로직은 유지, 분류·주입 방식 이전 |
| 현재 문서와의 차이 | PRD 6절·설계·`B-00`·`B-03`·`B-04` 수정 필요 | PRD 6절·`F-05` 수용 기준·설계 수정 필요 | 현재 기술과 가까움 |

## 층과 무관하게 정해야 할 쟁점

- **L2 기록 주체와 시점**: 세션 내용을 종료 시 한 번에 받으면 브라우저 종료·네트워크 끊김·비용 한도·공급자 세션 시간 제한으로 세션이 끝나지 못했을 때 그 내용을 잃는다. 이는 연결 중단을 재개 가능한 상태로 다루는 원칙 4·PRD 6절과 관련된다. 세션 중 지속 저장은 이 위험을 줄이는 대신 저장 빈도와 데이터 처리량이 늘어난다.
- **L4 생성 입력**: AI가 세션 기억으로 작성한 요약을 받는 방식과, 저장된 전사문에서 별도 처리로 교정·표현을 추출하는 방식이 있다. 전자는 단순하지만 일어나지 않은 오류·표현이 들어갈 수 있고, 후자는 항목별 근거 연결이 가능하지만 종료 후 처리 시간과 비용이 추가된다.
- **재생되지 않은 발화**: 끼어들기로 재생되지 않은 AI 발화를 학습 근거에서 빼는 처리(PRD 6절, `B-05`, `V-02`)가 L2·L4 방식에 따라 달라진다.
- **음성 오인식**: 전사문이 틀리면 L4 결과도 틀린다. 불확실한 인식·교정의 확인·보류(`F-04`)를 세션 중과 종료 후 중 어디서 적용할지 정해야 한다.
- **데이터 정책**: 전사문을 세션 중에 저장하면 `D-02`의 보관 기간·삭제 범위·공급자 보관 조건이 첫 구현 단계부터 적용 대상이 된다.

## 결정에 필요한 질문

1. 대화 중 화면에 교정이나 다시 말하기 요청을 표시해야 하는가?
2. `F-05`의 다시 말하기는 앱이 강제해야 하는가, AI가 수행하고 결과를 기록하면 되는가?
3. 종료 피드백과 노트는 무엇을 입력으로 만드는가?
4. 끊김 후 재개 시 대화 기록만 이어지면 되는가, 교정 대기 같은 진행 상태까지 복원해야 하는가?
5. 세션 중 대화 기록을 앱이 언제·얼마나 자주 저장하는가?

## 2026-10-21 사용자 답변과 남은 범위

아래는 최초 답변과 후속 합의를 구분한 기록이다. 후속 논의에서 B안을 명시적으로 채택했다. 이유·대안·영향은 [ADR-010](../adr/010-AI-LED-LEARNING-APP-RECORDS.md)을 기준으로 하며, MVP 모드는 후속 [DEC-011](../DECISIONS.md#dec-011)로 확정했고 기록 범위는 [ADR-012](../adr/012-TEMPORARY-TRANSCRIPTS-AND-LEARNING-EVIDENCE.md)로 방향을 정했다. 후속 합의로 종료 후 요약·항목·근거 저장 성공 확인 뒤 전체 원문을 삭제하고 실패 시 재시도용으로 유지한다. 주기적 묶음 저장은 DEC-013으로 합의했고, 선별 기준은 후속 합의로 PRD 8절에 정리했다. 임시 원문은 종료 후 최대 24시간 유지하고 성공 즉시 또는 기한 경과 시 삭제하기로 합의했다. 재시도로 기한을 연장하지 않는다. 간격·묶음 크기·재시도/삭제 실패 상세·임시 저장 기술과 선별 항목 수·분량·우선순위·모델은 미정으로 유지한다.

| 질문 | 사용자 답변 | 남은 범위 |
| --- | --- | --- |
| 1. 교정·다시 말하기 표시 | 교정·다시 말하기를 옵션으로 제공한다. 후보는 교정 끄기, 대화 중 AI가 필요하다고 판단할 때 교정, 학습 종료 후 한 번에 교정할 점 표시의 약 세 가지다. MVP에서는 그중 하나를 선택한다. | 후속 합의로 MVP는 대화 중 AI 판단 교정 단일 모드를 채택했다 (DEC-011). 교정 끄기·종료 후 일괄 교정 모드 선택은 이후 범위다. 화면·다시 말하기 예외의 세부 동작은 남아 있다. |
| 2. 다시 말하기 강제 주체 | 사용자는 1번으로 함께 답했다고 보았다. | 후속 논의에서 AI가 요청·판정하고 앱이 기록·복원하는 B안을 채택했다 (DEC-010). 모드별 세부 동작은 미정이다. |
| 3. 종료 피드백·노트 입력 | 앱이 저장한 글을 입력으로 사용한다. AI가 중간중간 중요하다고 판단한 부분만 저장할지, 전부 저장한 뒤 중요한 부분을 선별할지는 더 고민한다. | 후속 합의로 전체 대화 글은 임시 보관하고 요약·중요 학습 항목·필요한 짧은 원문 근거와 교정문을 지속 보관한다 (DEC-012). 후속 합의로 종료 후 요약·항목·근거 저장 성공을 확인한 뒤 임시 전체 원문을 삭제하고 실패 시 재시도용으로 유지한다. 후속 합의로 종료 후 AI가 저장된 대화·교정·재시도 기록을 한 번에 검토해 선별하고 앱은 원문 근거의 실제 기록 존재를 확인한다. 후속 합의한 네 가지 선별 기준은 PRD 8절을 따른다. 임시 원문은 종료 후 최대 24시간 내 재시도하며 성공 즉시 또는 기한 경과 시 삭제한다. 항목 수·분량·우선순위·모델과 재시도/삭제 실패 상세는 미정이다. L2 기록과 L3 복원 요구를 함께 고려한다. |
| 4. 끊김 후 재개 | 대화 기록뿐 아니라 교정 대기 같은 진행 상태까지 복원해야 한다. | 복원 요구는 확인됐다. AI 판단 결과를 앱이 기록하고 재개 시 전달하는 B안으로 책임을 정했다. 상태 전달 형식·저장 시점 등 구현 상세는 미정이다. |
| 5. 기록 저장 시점·빈도 | 최초 답변에서는 더 고민한다고 했다. | 기록 범위는 DEC-012, 저장은 DEC-013의 주기적 묶음 저장으로 정했다. 정상 종료 시 남은 기록을 저장하고 메모리 손실 시 마지막 저장 이후 기록 손실은 허용한다. 구체 간격·묶음 크기는 검증 후 조정하며 종료 후 임시 원문은 최대 24시간 내 재시도하며 성공 즉시 또는 기한 경과 시 삭제하고 재시도로 기한을 연장하지 않는다. 재시도/삭제 실패 상세·임시 저장 기술은 미정이다. 중단 세션은 후속 DEC-024의 외부 환경 중단 후 24시간 재개·자동 종료를 따른다. |

후속 DEC-015로 B-00의 실행 중 세션 메모리 범위를 확정했다. DEC-027/028로 임시 전체 원문의 앱 복원용 백업 제외·지속 작업 목록과 정시 실행을 정했으며 구체 저장·실행 플랫폼은 미정이다. 아래 일반 쟁점은 최초 논의 당시 비교이며 현재 합의가 있는 항목을 다시 미결정으로 취급하지 않는다.

### 다음 논의에서 구분할 사항

- **교정 모드와 책임 주체**: 언제 교정할지는 제품 옵션이고, 누가 진행 상태를 판단·기록·제어할지는 구현 책임이다. 한쪽 선택만으로 다른 쪽을 확정하지 않는다.
- **기록과 진행 상태**: 전체 대화의 임시 저장과 별도로 교정 대기를 복원할 진행 상태를 기록해야 한다. 원문 정리 시점과 복원 요구의 정합성을 확인한다. 전체 대화의 지속 보관을 채택한 것은 아니다.
- **기존 요구사항과의 충돌**: 교정 끄기·종료 후 교정은 현재 원칙 5·F-04/F-05·PRD 6절과 첫 학습 흐름의 필수 교정·재시도 경로에 영향을 준다. MVP는 대화 중 AI 판단 교정으로 확정해 기존 교정·재시도 경로를 유지한다. 이후 모드를 추가할 때 해당 요구사항과 완료 기준의 영향을 함께 논의한다.
