# API 사용량 한도와 사용자 안내 검토안

후속: 사용자가 비용이 높다고 판단해 [절감 대안 전반](VOICE-COST-REDUCTION.md)을 검토했다. 아래 $1.25/$38.10/$76.20는 승인된 한도가 아니며, 압축/분리형 검증 전 상품 한도로 채택하지 않는다.

작성일: 2026-10-30. 상태: 구조 동의 후 수치·표시 방식 논의 중. 사용자는 세션/구독 기간 한도와 노트 예산 분리 구조에 동의했고, 15분씩 하루 1~2회를 기준으로 구체 계산을 요청했다. 아래 모델 후보·수치는 미승인이다. DEC-059의 시간 상한 변경도 아직 확정하지 않는다.

## 현재 구현과 기존 합의

- 현재 로컬 음성 모델은 [gemini-live-setup.ts](../../app/src/voice/gemini-live-setup.ts)의 `models/gemini-3.8-live`다. 무료 비공개 시험이며 아래 유료 단가 환산은 실제 지출이 아니다. 현재 setup에 명시적 맥락 압축 설정이 없고 어댑터에 사용량 집계가 없어 실측 근거는 없다.
- [DEC-058](../DECISIONS.md#dec-058--별도-종료-선별-요청과-제한적-재시도)과 [노트 설계](../design/LEARNING-NOTE.md#생성검증저장-순서)에 따라 노트는 Live와 분리된 종료 LLM 요청으로 만든다. 구체 모델·재시도 수치 등은 미정이다. Live의 남은 토큰으로 노트를 생성한다는 뜻이 아니다.

## 공식 관찰과 계산 조건

2026-10-30 [Google 가격표](https://ai.google.dev/gemini-api/docs/pricing) 확인: Gemini 3.8 Live의 100만 토큰당 입력 텍스트 $0.75·음성 $3, 출력 텍스트 $4.50·음성 $12. [공식 사용 안내](https://ai.google.dev/gemini-api/docs/live-api/best-practices)는 음성 약 25토큰/초, 턴마다 이전 맥락을 포함한 재과금과 전사 텍스트의 추가 출력 과금을 설명한다. 따라서 음성 분당 요금만 곱한 값은 세션 전체 비용 추정으로 충분하지 않다.

합성 산정 가정: 연결 15분 동안 마이크 900초 전송(22,500토큰), AI 음성 총 360초(9,000토큰), 시스템/초기 맥락 2,000텍스트 토큰, 전사 총 3,000출력 텍스트 토큰. N번 문답에 음성과 발화량을 균등 분배하고 압축·재연결은 없다고 가정한다. 과거 AI 출력 음성도 다음 턴부터 입력 맥락에 포함한다. 도구 교환/내부 추론·실제 무음 처리·초기 맥락 차이는 계산에 완전히 반영하지 못한다.

계산식(USD): `3/1,000,000 × [22,500×(N+1)/2 + 9,000×(N-1)/2] + 12/1,000,000×9,000 + 0.75/1,000,000×2,000×N + 4.50/1,000,000×3,000`.

| 15분 동안 문답 수 | Live 추정 비용 |
| --- | --- |
| 10회 | $0.63 |
| 20회 | $1.12 |
| 30회 | $1.60 |

실측 평균이나 상한 보장값이 아니다. 짧은 문답이 많은 튜터 특성상 턴 수가 핵심 변수다. 실제 공급자 사용량과 청구 대조가 필요하다. 맥락 압축은 비용을 줄일 가능성이 있지만 기억/교육 품질 영향과 실제 절감량은 미확인이며 채택하지 않았다.

## 초기 한도 제안

| 항목 | 제안 | 의미 |
| --- | --- | --- |
| 세션 Live | $1.25 상당 | 20문답 기준 약 $1.12와 여유분. 15분 보장이 아니며 문답이 많으면 더 일찍 소진 |
| 세션 노트 | $0.02 별도 예약 | Live 종료 뒤의 텍스트 LLM 요청과 제한적 재시도용. 마무리 음성 예산은 Live 쪽에 따로 확보해야 함 |
| 하루 1회 수준 구독 | 30일 환산 Live $37.50 + 노트 $0.60 | 합계 $38.10 상당. 판매 가격이나 실제 평균 원가가 아니라 한도 배정 시나리오 |
| 하루 2회 수준 구독 | 30일 환산 Live $75 + 노트 $1.20 | 합계 $76.20 상당. 동일 조건의 두 배 |

구독 실제 갱신 주기·일일 강제 한도·이월 여부는 별도 합의한다. 우선 기간 총량 안에서 날짜별 사용을 유연하게 하는 쪽을 제안한다. 위 월액은 API 예산만이며 세금·환율·결제 수수료·서버·이익은 포함하지 않는다. 저가 구독을 목표로 한다면 이 구조 그대로 확정하기 전에 맥락 압축이나 다른 음성 경로의 비용/품질 검증이 필요하다.

노트 모델의 계산용 후보는 Gemini 3.5 Flash-Lite다(선정 아님). 위 가격표의 Standard 입력 $0.30/100만·출력 $2.50/100만 기준, 입력 12,000·출력 2,000토큰이면 $0.0086, 같은 최대 크기 두 요청이면 $0.0172다. 출력에는 추론 과금분도 포함해 예산을 관리해야 한다. 따라서 $0.02를 초기 예약 제안으로 둔다. 12,000토큰이 실제 15분 원문에 충분한지·품질은 미확인이며 초과 원문을 조용히 자르는 정책은 채택하지 않는다. 이 계산으로 재시도 횟수나 기존 기한 내 재시도 정책을 확정하지 않는다.

## 사용자에게 보여줄 것

토큰·달러·백분율 대신 대화 중에는 경과 시간과 마무리 단계만 표시하는 안을 추천한다. 내부 예산이 마무리 예약분 경계에 접근하면 ‘이번 연습을 마무리할게요’로 전환하고, 마지막 답변과 종료를 위한 제한된 사용량을 남긴다. 몇 분/몇 문답이 남았다고 보장하지 않는다. 마무리 예약분의 구체 크기는 응답 한도와 실측으로 정해야 한다.

시작 화면에는 ‘보통 15분 안팎으로 연습해요’와 기간 잔여량을 현재 평균 세션 소비량으로 환산한 ‘약 N회 분량’을 표시하는 대안을 제안한다. 이는 시작할 수 있는 확정 횟수가 아니며 사용 방식에 따라 달라진다는 설명·갱신일을 함께 둔다. 실측 전에는 남은 횟수를 계산하지 않고 플랜의 목표 이용량만 설명한다. ‘매일 1회’처럼 고정 횟수를 보장하려면 서비스가 비용 변동을 부담하는 별도 상품 정책이 필요하다.

## 남은 검증과 영향

사용량의 종류별 단가 가중 합으로 서버 예산을 관리하는 방향이며 사용자에게 금액을 청구하는 지갑 기능은 제안하지 않는다. 브라우저 직접 연결에서 사용자 보고만 신뢰하지 않고 한도를 집행할 수 있는지 확인해야 한다. 불가능하면 중계 등 경로 변경을 논의한다. 최종 공급자 적합성·유료 호출/공개 연결 승인은 이 계산으로 확대하지 않는다.

실제 15분·서로 다른 문답 수에서 종류별 과금 토큰/청구, 전사·도구·재연결·무음·마무리 비용을 대조해야 한다. 구독 총량 차감·노트 예약/정산·동시 요청·지연 보고의 초과 오차도 검증 대상이다. 사용자는 시간 예측이 어려워지고 운영에는 사용량 원장과 예약/정산이 추가되는 절충이 있다. 이번에는 문서·공식 자료 확인과 산술 계산만 수행하며 공급자 호출·추가 E2E는 수행하지 않았다.
