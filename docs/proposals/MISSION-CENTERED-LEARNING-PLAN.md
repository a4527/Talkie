# 미션 중심 영어 학습 전환 계획

작성일: 2026-11-03

## 문서의 범위와 상태

2026-11-03 논의·사례·초안의 보존 문서다. 합의된 정책은 [PRD](../PRD.md#4-주요-사용자-흐름), 이유·대체 관계는 [DEC-069](../adr/069-MISSION-CENTERED-LEARNING.md), 구현 계약은 [미션 설계](../design/MISSIONS.md), 작업 기준은 [TASKS](../TASKS.md)로 이관했다. 아래 선행 3단계 판정·초안 배점·‘아직 PRD를 변경하지 않았다’ 등의 표현은 논의 당시 기록이며 현행 상태가 아니다. 이후 변경은 기준 문서에서 관리하고 이 문서의 과거 예시를 자동 갱신하지 않는다. 남은 미정은 미션 설계에서 관리한다.

## 합의한 방향

- 자유 대화 중심에서 영어로 상황을 해결하는 미션 중심으로 전환한다. 실제 예정된 대화를 입력하면 리허설로 활용한다.
- 기존 인증, 음성 포트와 분리형 STT→LLM→TTS, 학습 저장·재개, 노트 조회·다운로드 구조를 재사용한다. 인증과 학습 데이터의 경계도 유지한다.
- 직접 설계한 기본 미션·연속 스토리, 개인별 AI 변형·생성, 사용자 지정 미션을 공통 구조로 처리한다.
- 복잡한 상황을 강제로 짧은 미션으로 나누지 않는다. 하나의 상황 안에 여러 목표를 두고 연속 수행할 수 있게 한다.
- 이용량은 미션 단위로 안내하는 방향으로 검토한다. 시작한 미션을 잔여 이용량 소진 때문에 중간에 끊지 않는 경험을 지향한다.
- 즉시 교정·다시 말하기는 연습 시 켜고 실전 시 끌 수 있게 한다. 두 방식 모두 종료 후 근거 기반 피드백을 제공한다.
- 노트와 다음 대화 맥락을 더 간결하게 만든다. 초기에는 달성 일수만 제공한다. 가상 재화·성장·꾸미기·경품 등 보상은 후속 검토로 남긴다.

## 현재 구현에서 재사용할 부분

현재 코드의 확인 범위에 근거한 계획이며 기능 완료를 의미하지 않는다.

| 영역 | 현재 진입점 | 전환 시 처리 |
| --- | --- | --- |
| 시작·학습 화면 | `app/src/app/home/page.tsx`, `app/src/app/talk/page.tsx`, `app/src/components/use-voice-learning.ts` | 미션 선택·사전 확인·목표 표시·결과 연결 |
| 공통 튜터 지시 | `app/src/voice/tutor-prompt.ts` | 역할 수행과 목표 판정을 위한 공통 규칙 및 미션 데이터 구성 |
| 음성 연결 | `app/src/voice/port.ts`, `app/src/voice/adapters/` | Live·분리형에 동일한 미션 계약 전달 |
| 저장·종료 | `app/src/server/learning.ts`, `app/src/learning/types.ts` | 미션 정의·진행·결과를 기존 세션과 연결 |
| 과거 학습 맥락 | `app/src/voice/prior-learning.ts` | 미션 관련성을 우선하는 선별로 조정 |
| 노트 | `app/src/voice/note-extraction.ts`, `app/src/voice/note-context.ts` | 간결한 결과와 핵심 교정·복습 연결 |

현재도 전체 과거 노트를 공급자에게 전달하지 않는다. 이전 학습 맥락은 최대 4 KiB, 재개용 현재 대화는 최근 최대 20턴·20 KiB로 제한된다. 서버의 노트 조회·선별 비용과 공급자 입력 크기는 별도로 측정한다. 미션 전환 자체가 절감을 보장하지는 않는다. 관련 기준: [음성 설계](../design/VOICE.md), [학습 저장](../design/LEARNING-PERSISTENCE.md).

## 사용자 흐름

1. 추천 미션·연속 스토리·직접 만들기 중 선택한다.
2. 상황, 역할, 원하는 결과, 예상 규모와 이용량을 확인한다. 사용자 지정 상황이 모호하면 필요한 조건만 확인한다.
3. 연습 또는 실전을 선택하고 시작한다. 사용자에게 알릴 목표와 상대만 아는 조건을 구분한다.
4. 하나의 상황 안에서 목표를 수행한다. 복잡한 상황도 강제로 화면을 끊거나 새 미션으로 나누지 않는다.
5. 목표 달성 또는 사용자 마무리 요청에 따라 결과로 이동한다. 장애는 재개 가능한 중단으로 구분한다.
6. 상황 해결 결과와 영어 피드백을 별도로 확인하고, 노트·재도전으로 연결한다.

## 미션의 생성과 추천

제작 방식과 추천 방식을 분리한다. 직접 만든 미션도 개인별로 추천하고, AI 생성 미션도 연속 스토리로 연결할 수 있다.

- 기본 미션은 목표·판정·난이도 검증의 기준 사례로 직접 설계한다.
- AI는 검증된 협상·문제 해결·정보 확인 등의 구조 안에서 소재와 조건을 변형하거나 새 상황을 생성한다.
- 사용자 지정은 입력한 상황을 존중하고, 실행 가능한 목표와 조건을 제안해 시작 전에 확인받는다.
- 추천은 수준·명시적 선호·최근 수행 이력을 참고하되 같은 유형의 무의미한 반복을 줄인다. 직접 선택한 미션은 추천의 미경험 우선 규칙으로 차단하지 않는다.
- 공통 출발 상황과 개인별 변형을 함께 제공하면 서로 해결 방법을 비교할 수 있다. 공유·소셜 기능 자체는 이번 구현 범위로 확정하지 않는다.
- 연속 스토리는 소수 에피소드로 먼저 검증한다. 이전 선택의 후속 영향과 에피소드별 완료 조건을 명시하며 무제한 분기는 초기 범위로 잡지 않는다.

### 추천 생성과 미션 확정 절차

후속 합의: AI가 사용자의 관심사·난이도·최근 미션 이력을 참고해 주제와 상황 후보를 그때 생성한다. 후보 단계에서는 간단한 상황만 제시하고 모든 후보의 상세 미션·평가표를 미리 생성하지 않는다. 사용자가 선택한 후보에 대해서만 역할·조건·목표·채점 항목·배점을 구성하고 검증한 뒤 시작 전에 고정한다.

직접 제작한 미션은 검증된 평가 기준을 미리 둔다. AI 변형은 기존 미션 구조와 평가 기준을 재사용하되 조건 변경의 영향을 확인한다. AI 생성·사용자 지정은 가능한 경우 검증된 구조에 연결하고, 새로운 구조는 기준을 생성해 검증한다. 이 검증은 배점 합계·필드 검증뿐 아니라 목표의 실행 가능성과 근거 판정 가능성에 대한 사례 평가를 포함해야 하며 모든 자동 생성의 품질을 보장한다고 해석하지 않는다.

채점 항목은 관찰 가능한 결과 하나를 다루고 동일 행동을 중복 채점하지 않는다. 해당 상황에 필요한 항목만 포함하고 허용된 대안 해결을 반영한다. 상대가 먼저 알려준 사실은 사용자가 같은 질문을 반복해야만 인정하는 식으로 평가하지 않는다. 구체적인 이해 확인 근거는 항목별로 정의한다. 시작 후 AI가 항목이나 배점을 임의 변경하지 않는다.

## 가장 먼저 설계할 목표와 완료 기준

목표는 특정 문장·발화량이 아니라 대화를 통해 만든 상태로 정의한다. 목표 달성과 미션 종료는 구분하며, 해결하지 못해도 결과를 확인할 수 있어야 한다.

| 항목 | 정의 |
| --- | --- |
| 시작 문제 | 사용자가 해결할 구체적인 문제 |
| 역할·정보 | 양측이 아는 사실과 대화로 알아낼 정보 |
| 목표 | 전달·확인·요청·합의 등 관찰 가능한 결과 |
| 상대의 제약 | 가능한 제안·양보 범위·불가능한 요청 |
| 대안 | 원래 목표가 불가능할 때 인정할 다른 해결 |
| 완료 근거 | 실제 확인된 발화로 판단할 조건 |
| 종료 | 달성·부분 달성·미해결 및 사용자 종료·중단의 구분 |

예: 예약 누락 호텔 미션은 예약 증빙 설명, 이용 가능한 객실과 비용 확인, 최종 선택 확인을 목표로 둔다. 객실이 없다면 대체 숙소 안내에 합의하는 경로를 허용할 수 있다. 특정 정답 문장을 요구하지 않으며, 문법 오류만으로 실패시키지 않는다. 면접 미션에서 실제 채용 여부처럼 관찰할 수 없는 결과를 목표로 삼지 않는다.

시작 시 핵심 조건과 버전을 고정한다. AI가 사용자를 쉽게 성공시키려고 조건을 바꾸거나 새 문제를 끝없이 추가하지 못하도록 한다. AI는 판정과 근거를 제안하고 앱은 형식·근거 연결·중복·소유권을 검증한다. 검증만으로 교육적 판정의 정확성이 보장되지는 않으므로 별도 사례 평가가 필요하다.

## 대표 미션과 판정 사례 초안

아래는 첫 논의를 위한 설계 사례이며 확정된 제품 정책이나 실제 AI 평가 결과가 아니다. 시간·턴 수는 아직 지정하지 않는다. 목표의 수가 같아도 실제 소요 시간이 같다고 가정하지 않는다.

### 사례 1 · 짧은 상황: 잘못 나온 카페 주문 해결

- 사용자에게 보이는 상황: 따뜻한 디카페인 라테를 주문했는데 차가운 일반 라테가 나왔다. 주문한 음료로 교환하고 싶다.
- 상대역: 카페 직원. 주문 내역을 확인할 수 있으며 무료 재제조가 가능하다. 의도적으로 잘못을 숨기거나 새 비용을 만들지 않는다.
- 목표 A: 주문과 다른 점 및 원하는 변경을 전달한다.
- 목표 B: 상대가 제시한 처리 내용을 이해하고 최종 선택을 확인한다.
- 허용 경로: 정확한 재제조를 요청하거나 사용자가 받아들일 수 있는 대안을 합의한다. 취소·환불은 사전에 허용한 조건에서만 대안으로 인정한다.

| 결과 | 대화에서 확인되는 근거 | 판정 이유 |
| --- | --- | --- |
| 달성 | 사용자가 따뜻한 디카페인을 요청 → 직원이 무료 재제조 제안 → 사용자가 해당 제안 수락 | A·B 충족 |
| 부분 달성 | 사용자가 문제를 전달하고 직원이 교환을 제안했지만 사용자가 선택하지 않고 종료 | A만 충족 |
| 미해결 | 음료가 마음에 들지 않는다는 말만 하고 어떤 문제·처리를 원하는지 확인되지 않은 채 종료 | A·B 미충족 |
| 판정 보류 | 디카페인 요청의 전사가 불명확하고 재확인도 이루어지지 않음 | 미충족으로 단정할 근거 부족 |

짧은 “Yes, please”도 바로 앞 제안이 하나이고 명확하다면 선택 확인으로 인정하는 안이다. 특정 완성 문장을 다시 말하게 해야만 달성되는 구조로 만들지 않는다. 직원이 원하는 음료를 묻고 사용자가 답한 경우도 전달로 인정하며, 자발적 설명 능력 평가는 별도 언어 피드백에서 다룬다.

### 사례 2 · 복잡한 상황: 고객과 납기 변경 협상

- 사용자에게 보이는 상황: 최종 납기를 6월 12일에서 19일로 변경해야 한다. 핵심 기능은 12일 시연 가능하고, 사전에 승인된 범위에서 진행 보고를 약속할 수 있다.
- 상대만 아는 조건: 고객은 15일 내부 보고 때문에 12일 시연과 19일 최종 납기, 중간 진행 보고가 보장되면 변경을 수락할 수 있다. 해당 사정은 질문이나 제안에 맞춰 대화에서 공개한다.
- 목표 A: 지연 이유와 새 일정 제안을 전달한다.
- 목표 B: 고객의 우려를 파악하고 허용된 범위의 대응책을 제시한다.
- 목표 C: 최종 납기·중간 제공물·후속 행동을 상호 확인한다.
- 제한: AI가 고객의 보고 일정을 없애거나 사용자에게 없는 인력·할인 권한을 만들어 타결하지 않는다. 사용자가 제약 밖 약속을 해도 자동 성공으로 판정하지 않는다.

| 결과 | 대화에서 확인되는 근거 | 판정 이유 |
| --- | --- | --- |
| 달성 | 우려 확인 후 12일 핵심 시연·19일 최종 제공·중간 보고를 제안하고 양측이 조건을 확인 | A·B·C 충족 |
| 부분 달성 | 이유·우려·대안을 논의했지만 고객이 내부 확인을 요청하고 후속 연락만 합의 | 협상 진전은 있으나 최종 변경 합의 없음 |
| 미해결 | 지연만 통보하고 고객 우려에 대응하지 않은 채 종료 | 합의와 대응이 확보되지 않음 |
| 판정 보류 | 고객의 수락 음성이 중단되어 실제 전달 여부가 불명확 | 생성된 수락만으로 확정하지 않음 |

하나의 미션 안에서 연속 진행한다. 목표를 개별 유료 미션으로 강제 분할하지 않는다. 최종 계약이 불가능한 경우에도 우려 확인·후속 약속 같은 유효한 대응은 인정하되, 원래 목표 달성과 혼동하지 않는다. 다른 타결 조건을 허용하려면 시작 전 미션 정의에 포함한다.

### 사례 3 · 사용자 지정: 내 프로젝트 영어 면접 리허설

- 입력 예: “내일 백엔드 면접에서 내 프로젝트를 설명하고 질문을 받고 싶어.”
- 시작 전 확인: 프로젝트의 목적·본인 역할·핵심 선택과 이유·실제 결과를 간단히 받는다. 비밀 자료 입력을 요구하지 않는다. 미제공 사실은 만들지 않고 대화에서 묻는다.
- 제안 목표 A: 프로젝트 목적과 본인 기여를 구분해 설명한다.
- 제안 목표 B: 기술 선택에 관한 꼬리 질문에 이유와 절충을 설명한다.
- 제안 목표 C: 결과 또는 배운 점을 설명한다. 측정 수치가 없으면 한계와 정성적 결과도 허용한다.
- 상대역: 면접관. 전달이 부족하면 자연스럽게 구체화를 요청한다. 영어 실력이 아니라 기술 지식 정답만으로 미션을 평가하지 않는다.
- 실제 채용·합격·면접관 만족 여부는 완료 기준으로 사용하지 않는다. 시작 전에 사용자가 목표 범위를 확인한다.

| 결과 | 대화에서 확인되는 근거 | 판정 이유 |
| --- | --- | --- |
| 달성 | 목적·본인 기여, 선택 이유와 절충, 결과나 배운 점이 질문·답변으로 확인됨 | A·B·C 충족 |
| 부분 달성 | 프로젝트와 역할은 설명했지만 선택 이유나 결과를 설명하지 못하고 종료 | 일부 목표만 충족 |
| 미해결 | 인사·일반 소개만 수행하고 프로젝트 관련 설명 없이 종료 | 목표 관련 근거 없음 |
| 판정 보류 | 프로젝트 설명의 핵심 구간이 저장되지 않음 | 기록 부족으로 수행을 단정하지 않음 |

기술적 진위 검증이나 실제 면접 합격 예측은 제공한다고 약속하지 않는다. 사용자가 특정 목표를 원하지 않으면 시작 전에 수정하고, 진행 중 판정 편의를 위해 목표를 몰래 바꾸지 않는다.

### 사례에서 도출한 공통 판정안

- 문법·발음 점수와 상황 목표 달성은 분리한다. 뜻이 전달되면 목표는 달성될 수 있고 언어 개선점은 별도로 남긴다.

- 실시간 상대역과 모드별 튜터 판단은 한 AI의 구조화 출력, 종료 평가는 별도 호출을 우선안으로 두되 동시 판단 품질·지연·비용은 후속 검증한다. 매 턴 별도 심판 AI는 현재 채택하지 않는다.

## 목표별 배점과 최종 달성률

2026-11-03 후속 합의: 목표마다 배점을 나누고 문법·단어·문장 선택·자연스러움·의미 전달의 명확성을 포함한 최종 달성률을 표시한다. 최종 달성률 80% 이상인 미션이 있는 날을 달성 일수로 인정한다. 후속 합의로 아래 60/40 배점을 초기 기준으로 사용한다. 채점 항목별 근거 기준은 미션별로 구체화한다. 앞선 사례의 범주 판정은 근거 설명에 활용하고 최종 결과 표시는 백분율 중심으로 수정한다.

### 초기 배점

최종 달성률을 상황 목표 60점과 회화 품질 40점으로 구성한다. 목표별 점수 합계는 60점으로 고정하고 핵심 목표에 더 높은 배점을 둔다. 채점 단위는 대화 근거로 충족 여부를 확인할 수 있는 최소 항목으로 나눈다. 각 항목은 충족 시 해당 배점 전부, 미충족 시 0점으로 평가하며 일괄적인 부분 점수는 사용하지 않는다. 전사 오류·기록 누락은 미충족으로 단정하지 않고 판정 보류로 구분한다. 화면의 큰 목표 아래 여러 채점 항목을 둘 수 있다.

| 평가 영역 | 초안 배점 | 평가 내용 |
| --- | --- | --- |
| 상황 목표 | 60 | 필요한 정보 파악·요청·대안 조율·조건 확인 등 미션별 목표 |
| 의미 전달의 명확성 | 15 | 상대가 의도를 추측해야 하는 정도, 조건·이유·관계의 분명함 |
| 문법 | 10 | 발화의 정확성, 오류가 이해에 미치는 영향 |
| 단어·표현 선택 | 10 | 의도·상황·상대에 적절하고 정확한 표현 |
| 문장 구성·자연스러움 | 5 | 정보 연결과 대화에 맞는 문장 구성 |

쉬운 단어라도 완전하고 명확하며 적절한 문장이면 높은 점수를 받을 수 있다. 어려운 어휘를 많이 쓰는 것 자체를 보상하지 않는다. 단어 나열로 의도를 짐작하게 만든 경우에는 상황 목표가 일부 충족되어도 회화 품질에서 차이가 나도록 한다. 동일 오류를 여러 항목에서 기계적으로 중복 감점하지 않도록 평가 예시를 만든다. 음성 인식 불확실성을 사용자 문법 오류로 단정하지 않는다.

예: 상황 목표 45/60, 명확성 10/15, 문법 6/10, 표현 6/10, 자연스러움 3/5이면 최종 70%로 표시한다. 목표별 점수와 회화 품질을 함께 보여주어 같은 70%라도 부족한 부분을 알 수 있게 한다. 이는 계산 예시이며 실제 평가 결과가 아니다.

미정: 판정 보류의 점수 처리·난이도별 구체 기대 수준·정보 부족 시 평가 보류·반올림. 전체 달성률 80%와 상황 해결 완료는 같은 의미가 아니다. 상황 목표를 모두 충족해도 영어 품질에 따라 100%가 아닐 수 있고, 80%를 넘겨도 해결되지 않은 목표는 남을 수 있다. 80% 판정은 표시 반올림 전 점수에 적용하는 안을 검토한다.

### 난이도별 회화 품질 평가

상황 목표 60점과 회화 품질 40점의 배점은 유지한다. 회화 품질의 기대 수준을 시작 시 확정한 사용자 난이도에 맞춰 적용하는 방향으로 설계한다. 난이도 이름만 전달하지 않고 명확성·문법·표현·문장 구성 각각에 대한 수준별 평가표와 예시를 함께 전달한다. 구체적인 수준 구분과 평가표는 아직 미확정이다.

초보자는 짧고 기본적인 표현이라도 분명하고 상황에 적절하면 높은 점수를 받을 수 있다. 상위 수준은 필요한 뉘앙스·조건·이유를 정확하고 자연스럽게 연결하는지를 더 요구한다. 모든 수준에서 어려운 단어 사용 자체를 가점으로 삼지 않으며, 의미를 바꾸거나 중요한 조건을 누락한 문제는 초보자에게도 피드백한다. 동일한 단순 답변을 고급이라는 이유만으로 감점하지 않고, 해당 상황에서 필요한 표현의 정밀도와 구성으로 평가한다.

난이도·평가표 버전을 미션 시작 시 고정하고 결과에도 표시한다. 수행 중 난이도가 조정되어도 평가 기준을 몰래 바꾸지 않는다. 서로 다른 난이도의 같은 점수를 동일한 절대 능력으로 해석하거나 직접 순위화하지 않는다. 향후 비교 평가에서는 동일 발화를 수준별 평가표에 적용해 점수 차이와 근거가 납득되는지 확인한다.

난이도 컨텍스트는 평가 기준 전달 수단이며 점수 일관성을 보장하지 않는다. 기준 예시·고정 사례 평가·결과 검증을 함께 사용한다. 연습 도움·재시도는 감점하지 않는다. 난이도별 실제 AI 평가 품질은 후속 검증한다.

### 확장 가능한 난이도 구조

후속 합의: 초급·중급·고급 3단계를 코드에 고정하지 않고 난이도 정의와 평가표를 데이터로 관리한다. 초기 단계 수·이름·세부 기준은 아직 확정하지 않는다.

- 각 단계에 순서와 분리된 고유 ID, 표시 이름, 정렬 순서, 대화 난도 설정, 언어 평가 기준, 버전을 둔다.
- 대화 난도 설정은 어휘·문장 길이·질문 복잡도·도움 정도를 다루고, 평가 기준은 명확성·문법·표현·문장 구성의 기대 수준과 예시를 다룬다. 연습/실전 모드와의 결합 규칙은 후속 구체화한다.
- 미션 목표와 60/40 배점 구조를 난이도 정의와 분리한다. 새 단계를 추가할 때 단계별 평가 사례와 미션 실행 가능성을 검증하되 모든 미션을 단계마다 복제하는 구조는 피한다.
- 미션 시작 시 적용한 단계 ID와 평가표 버전을 고정하고 결과에도 연결한다. 이후 단계 추가·이름 변경·기준 개정이 과거 결과의 의미를 소급 변경하지 않게 한다.
- 기준 변경의 버전 이력과 과거 결과 표시 방식을 설계한다. 사용자의 최초 수준 선택·자동 추정·변경 추천 방식은 아직 확정하지 않는다.

단계 수를 늘리는 것과 실제 평가 해상도를 높이는 것은 다르다. 인접 단계의 기대 수준 차이를 AI가 일관되게 적용하는지 고정 사례로 검증한 뒤 세분화한다. 현재 작업은 구조 방향의 계획 반영이며 코드·스키마 구현은 포함하지 않는다.

숙소 미션의 객실·비용·접근성·제휴 이동 가능 조건은 생성 시 모순 없이 고정한다. 사용자가 조건에 맞는 다른 대안을 제시하면 미션의 제약 안에서 검토한다. 면접 미션에 문제 대응 목표를 추가할 때는 시작 전 사용자 확인과 관련 사실 확인을 거친다. 같은 핵심 내용을 자연스럽게 한 번에 전달하면 여러 목표를 함께 충족할 수 있으며 불필요한 질문을 강제하지 않는다.

### 종료 표현 정리

앞선 ‘역할상 마무리’는 상대역 인물의 짧은 마지막 대사로 장면을 끝낸다는 뜻이다. 예를 들어 직원이 확정된 객실과 입실 절차를 안내하거나 고객이 변경 일정을 확인한 뒤 인사한다. 앱이 임의로 추가 합의를 만들어내는 단계가 아니며 새 문제를 추가하지 않는다. 대화 종료를 최종 100% 획득과 동일시하지 않는다. 후속 합의: 미션 목표가 충족되면 상대역의 짧은 마무리 대사 후 종료한다. 최종 언어 평가는 종료 후 수행하므로 80% 미달을 이유로 대화를 자동 연장하지 않는다. 미해결 상태의 종료·중단 경계는 후속 결정한다.

## 달성 일수

사용자가 미션 학습을 이어온 일수를 확인할 수 있게 한다. 초기 범위는 달성 일수 표시만 포함하며 가상 재화·경험치·성장·꾸미기·경품은 포함하지 않는다.

인정 기준은 최종 달성률 80% 이상으로 합의했다. 하루에 해당 미션이 하나 이상 있으면 하루로 집계한다. 누적/연속 표시 방식, 날짜 기준과 중단 후 재개의 귀속은 구현 전에 정한다. 하루 여러 미션을 수행해도 일수는 중복 증가하지 않도록 하며 기존 기록의 소급 반영 여부도 명시한다. 현재 노트의 한국 시간 종료일 정책과 혼동하지 않도록 별도 정의한다.

## 긴 미션과 이용량

복잡한 미션은 내부 목표를 여러 개 두되 하나의 경험으로 진행·저장·재개한다. 분할은 선택지이며 필수가 아니다.

미션 수 기반 안내를 위해 시작 전에 이용 가능 여부를 확인하고 AI와 사용자 세션의 연결이 성립할 때 미션 횟수를 차감한다. 종료 시 차감을 확정하는 선행 제안은 이 후속 합의로 대체한다. 평균 시간은 원가 추정에 쓰며 보장 시간이나 강제 종료 시각으로 해석하지 않는다. 서로 다른 규모를 모두 동일한 1회로 볼지, 일반·확장 또는 사전 안내한 단위로 구분할지는 비용 측정 후 결정한다.

미정 사항: 연결 성립의 공급자별 확인 신호와 차감의 원자적 처리, 연결 직후 공급자 장애의 환급 예외, 새 재도전·동시 시작의 처리, 비정상 장기 연결 보호, 시작 전 이용량 확보의 만료·해제. 정상 미션 중 잔여량 소진으로 차단하지 않는 경험과 비용 상한을 함께 설계해야 한다. 기존 연결 시간 정책을 즉시 제거하지 않는다.

## 연습·실전과 컨텍스트

연습은 즉시 교정·다시 말하기를 켜고, 실전은 이를 끈다. 실전에서도 상대역의 자연스러운 재확인은 가능하다. 목표·판정 기준은 동일하게 유지하되 힌트 사용 등 수행 조건을 결과에 구분해 표시하는 안을 검토한다. 진행 중 모드 전환 허용 여부와 기본 모드는 미정이다.

컨텍스트는 공통 학습 규칙, 미션 정의, 명시적인 사용자 선호·수준, 관련 복습 표현, 현재 목표 상태와 확인된 최근 대화로 구성한다. 추정 성격을 새로 저장하지 않는다. 사용자 입력과 노트는 지시문이 아닌 데이터로 분리한다. 만료·삭제 기록 제외와 사용자 간 격리를 유지한다.

### 연습 도움과 점수·실전 보상

후속 합의: 연습 중 힌트·교정·다시 말하기 사용은 점수 감점이나 달성률 상한의 사유로 삼지 않는다. 같은 목표·난이도 평가 기준을 적용하며 연습에서도 최종 달성률 80% 이상이면 달성 일수 기준을 충족한다. 도움을 받았다는 이유로 이를 제외하지 않는다.

모드와 도움 사용 여부는 점수와 별도로 구분해 결과를 해석한다. 연습 점수는 도움을 포함한 수행 결과이며 무도움 실전 능력과 동일한 증거로 해석하지 않는다. 교정 후 다시 말한 발화를 어떤 근거로 평가할지, 여러 시도의 반영 범위는 후속 평가 규칙에서 구체화한다. AI가 제안한 표현만 있고 사용자가 실제 발화하지 않았다면 사용자 수행 근거로 대신 쓰지 않는다.

사용자는 향후 실전 선택에 별도 또는 더 큰 보상을 제공하는 방향을 제안했다. 이는 후속 보상 후보로 남기며 종류·차등 규모·지급 조건은 확정하지 않는다. 초기 제공 범위는 달성 일수만 유지한다. 실전 점수를 보상 목적으로 가산하지 않으며 추후 보상 정책과 평가 점수를 분리한다. 진행 중 모드 변경 허용 여부와 실전 인정 조건은 후속 결정한다.

### 진전 없는 실전의 종료

후속 합의: 연습은 막히면 힌트·교정·다시 말하기로 도움을 제공하며 진행한다. 실전은 일정 수준 이상 대화 진전이 없으면 미션 실패로 처리하고, 상대역의 짧은 마무리 대사 후 결과로 이동한다. 실패를 이유로 종료 피드백이나 확인된 학습 기록을 버리지 않는다.

구체적인 임계값은 아직 확정하지 않는다. 단순히 새 채점 항목이 충족되지 않았다는 이유만으로 진전 없음으로 판정하지 않는 안을 제안한다. 이유 설명·상대 질문에 응답·새 대안 제시·오해 해소·조건 조율은 목표가 아직 완료되지 않아도 진전일 수 있다. 동일 요청·거절만 반복되고 새로운 정보나 대응이 없는 경우를 대표적인 무진전 후보로 둔다.

모든 미션에 동일한 턴 수를 적용할지, 복잡도별 임계값을 둘지, 안내나 마지막 확인을 제공할지는 후속 결정한다. 침묵·전사 불확실성·연결 장애는 무진전 횟수와 구분하는 안을 검토한다. 단일 짧은 답변만으로 실패시키거나, 상대역 AI가 조건을 어겨 진전을 막은 상황을 사용자 실패로 단정하지 않도록 사례 평가한다.

후속 합의: 실전 실패 여부와 별개로 최종 달성률 80% 이상이면 달성 일수를 인정한다. 실패 시 점수를 0점으로 만들거나 80% 미만으로 제한하지 않는다. 미션 목표 60점 안에서 최종 해결·합의에 해당하는 핵심 항목의 배점을 준비·정보 확인 항목보다 높게 두는 방향으로 조정한다. 구체적인 미션별 배점은 후속 작성한다. 조기 종료 시 점수가 낮을 가능성은 있으나 자동 보장되지는 않으므로 평가 사례로 확인한다.

## 간결한 노트와 종료 피드백

기존 종료 일괄 선별을 재사용해 임시 원문에서 근거 있는 교정을 추출한다. 결과 화면은 상황 해결 결과와 언어 피드백을 구분한다. 저장 노트는 미션·결과 한 줄, 핵심 개선 표현 최대 3개, 다음 복습 표현 1~2개 정도를 초안으로 검토한다. 이는 확정 상한이 아니다.

상세 교정의 보관·재조회 여부와 노트 필수 섹션 변경은 후속 결정한다. 임시 원문이 삭제된 뒤 상세 교정 전체를 다시 볼 수 있다고 약속하지 않는다. 기존 자유 대화 노트의 조회·다운로드 호환성과 원문 수명·탈퇴 삭제·백업 경계는 유지한다.

## 기준 문서 반영 계획

구현 전에 제품 약속은 [PRD](../PRD.md), 구현 계약은 [설계](../DESIGN.md) 및 관련 상세 문서에 반영한다. 미션 전환의 후속 결정은 기존 결정을 역사적으로 다시 쓰지 않고 대체 범위와 근거를 연결한다.

- 대화 진행·AI 판단: ADR-003·DEC-010, PRD 4~6절과 F-02~F-07.
- 소재·복습: DEC-023, PRD 7절과 F-11.
- 종료·이용량: DEC-040·DEC-062 및 관련 발급·소진 결정.
- 노트: PRD 8절·F-09, DEC-058·DEC-064·DEC-065 및 관련 설계.
- 작업: [TASKS](../TASKS.md)의 B-03・B-07・B-08・B-09・B-10과 첫 학습 흐름 관련 수용 기준을 영향 범위만 조정한다. B-08은 노트 탐색과 역할극 책임을 분리 검토한다.

PROGRESS·CHANGELOG는 실제 반영 범위에 맞춰 요약하고 날짜별 검증은 worklog에 둔다. 이 계획서 작성만으로 현행 요구사항·완료 상태·가격·미션 수를 변경하지 않는다.

## 중도 이탈·연결 중단의 기존 정책 재사용

기존 [PRD 6절](../PRD.md#6-대화-상태와-예외)과 [ADR-024](../adr/024-AUTO-CLOSE-INTERRUPTED-SESSION-AFTER-ONE-DAY.md)에 따라, 종료 요청 없이 브라우저를 닫거나 연결이 끊어지면 재개 가능한 중단으로 다룬다. 고의 이탈과 장애를 추정해 사용자 실패로 구분하지 않는다. 24시간 안에 재개하면 마지막 저장 확정 기록·상태에서 이어가고 자동 종료 예약을 취소한다. 다시 중단되면 새 중단 시각을 기준으로 한다.

24시간 동안 재개되지 않으면 자동 종료하고 저장된 확인 기록으로 노트를 생성한다. 확정된 사용자 발화가 없으면 빈 노트를 만들지 않는다. 명시적 종료는 즉시 종료 정리로 이동한다. 마지막 저장 이후의 미저장 발화는 복원되지 않을 수 있다.

미션 전환에서도 이 중단·재개 경계를 재사용한다. 진행 중 이탈을 실전 무진전 실패와 동일시하지 않는다.

### 연결 시 차감과 재개 만료

후속 합의:

- AI와 사용자 세션의 연결이 성립하면 미션 횟수를 차감한다. 후보 추천·미션 구성·연결 시도만으로는 차감하지 않는다.
- 같은 미션을 기존 재개 기한 안에 이어가는 것은 추가 미션 차감 없이 처리한다. 연결 재시도·중복 이벤트로 같은 미션을 중복 차감하지 않게 한다.
- 중단 후 24시간 동안 재개하지 않으면 미션은 자동 종료하고 이미 차감한 횟수는 복구하지 않는다.
- 재개 기한 만료로 자동 종료된 미션은 달성 일수에서 제외한다. 이는 정상 종료 결과의 80% 기준에 대한 명시적 예외다. 미완료 점수가 80%를 넘더라도 인정하지 않는다.
- 위 제외는 해당 만료 미션에만 적용한다. 당일 다른 미션이 최종 달성률 80% 이상으로 인정 조건을 충족했다면 이미 획득한 하루의 달성 기록은 유지한다. 이후 다른 미션의 실패·중단·만료로 그날의 달성을 취소하지 않는다.
- 확인된 기록의 정리·노트 생성은 기존 정책을 유지한다. 노트를 남기는 것과 달성 일수 인정은 별개다.

공급자별 연결 성립 신호, 연결 직후 장애의 환급 예외, 만료 전 사용자 명시 종료 시 평가 범위, 일수 날짜 귀속은 후속 구체화한다. 새 재도전의 단위와 과금 규모도 아직 확정하지 않는다. 연결 성립과 서버 차감을 일치시키는 구현·검증이 필요하며 현재 구현 완료를 의미하지 않는다.
