# 음성 비용 절감 선택지와 비교

후속: 조사 이후 Soniox STT → Gemini 텍스트 → Gemini TTS 분리형이 Gemini Live와 함께 로컬 `/voice`의 비공개 선택 경로로 통합됐다([현재 설계](../design/VOICE.md#분리형-비공개-시험-경로)). 아래 ‘후보’·‘미구현’ 표현과 비용 표는 조사 당시 제안이며 현재 구현·실측 원가를 뜻하지 않는다. 분리형 짧은 사용자 시험의 Soniox STT 사용액 외 전체 청구액은 미확인이다. 현행 이용 제한은 DEC-062의 연결 허용 시간·주간 실제 과금 대조를 따르며 아래 토큰 산술을 사용자 차감 방식으로 쓰지 않는다.

작성일: 2026-10-30. 상태: 조사·미승인 제안. 사용자 요청은 비용을 낮출 수 있는 방법 전반의 검토다. 공급자/모델·중계 서버·제품 동작·데이터 정책을 새로 채택하지 않는다. 실제 API 호출·추가 E2E·지출은 없다.

## 결론과 기존 추정의 범위

가장 큰 구조적 절감 후보는 음성 인식(STT) → 작은 텍스트 LLM → 음성 합성(TTS)의 분리형이다. 음성 이력을 텍스트로 바꿔 다음 턴에 전달하면 비싼 음성 맥락 재과금을 피한다. 기존 후보 구성에 포함된 방향이며 제품 적용/구체 모델은 미확정이다. 구현 부담이 작은 비교군은 Gemini Live의 짧은 맥락 창이다. 두 방식 모두 한국인 억양 영어·한국어 혼용·불완전 발화·끼어들기 품질과 비용 실측이 필요하다.

[앞선 비용 산정](API-USAGE-BUDGET.md)의 약 $1.12/15분은 압축 없는 20문답 가정이다. 현재 서비스의 실측 평균·피할 수 없는 최저 비용이 아니다. $38.10/$76.20도 제안한 한도의 30일 배정액이지 실측 원가가 아니다. 기존 [평가 계획](AI-CANDIDATE-EVALUATION-PLAN.md)의 Gemini ‘최대 $0.023/분’은 맥락 재과금을 빠뜨렸으므로 상한 근거로 쓰지 않는다. 역사적 표는 보존하고 본 비교로 보완한다.

## 계산 조건과 공식 근거

모든 추정은 15분 연결·AI 음성 6분·20문답을 기준으로 한다. 분리형 텍스트 LLM의 세션 누적 입력 60,000·출력 3,000토큰, 별도 노트 입력 12,000·출력 2,000토큰을 가정한다. 텍스트 이력도 매 턴 재전달될 때 비용을 합산한다. 공통 LLM은 계산용 Gemini 3.5 Flash-Lite Standard($0.30/$2.50, 100만 입력/출력 토큰당)로 $0.0255, 노트 $0.0086이다. 노트 재시도는 표에 포함하지 않는다.

2026-10-30 공식 자료 관찰:

- [Gemini 가격표](https://ai.google.dev/gemini-api/docs/pricing): Flash-Lite TTS Standard는 2026-12-31까지 음성 출력 $6/100만·텍스트 입력 $0.50/100만, 2027-01-01부터 각각 $12/$1. 25음성 토큰/초 기준 6분과 입력 2,000토큰은 현재 $0.055, 인상 후 $0.110이다. 할인 종료를 무시한 장기 원가를 제시하지 않는다.
- [Live 비용 안내](https://ai.google.dev/gemini-api/docs/live-api/best-practices#pricing-and-billing)와 [세션 관리](https://ai.google.dev/gemini-api/docs/live-api/session-management): 이전 맥락을 턴마다 과금하며 압축/슬라이딩 창으로 제한할 수 있다. 설정만으로 기존 전체 맥락의 무료 보존을 보장하지 않는다.
- [Soniox 가격표](https://soniox.com/pricing): 광고 환산 $0.12/시간과 별도로 실시간 입력 음성 $2/100만·출력 텍스트 $4/100만을 표기한다. 참고량 30,000입력 음성 토큰/시간·15,000출력 텍스트 토큰/발화시간을 합산한다. 15분 연속 입력 $0.015 + 15분 모두 발화한다고 보수적으로 잡은 전사 $0.015 = $0.030이나, 광고 환산과 세부 토큰 합산 기준이 일치하지 않는다. 비교표에는 **광고 기준 $0.030에 전사 $0.015를 추가한 $0.045**를 보수적 예산으로 사용한다. 실제 요율/토큰 수를 청구와 대조해야 하며 정밀 견적으로 취급하지 않는다. TTS는 6분 생성 기준 음성 약 3,000토큰과 텍스트 1,500토큰으로 $0.0705다.
- [Groq Whisper 가격](https://console.groq.com/docs/model/whisper-large-v3-turbo)과 [STT 제한](https://console.groq.com/docs/speech-to-text): $0.04/시간, 요청당 최소 과금 10초. 파일 요청 방식으로 문장 종료 후 보내는 대안이다. 20요청의 최소 합은 200초이며 비교표는 발화/최소 과금/분할 여유를 합쳐 600초 청구($0.0067)를 가정한다. 실시간 부분 전사와 동등한 방식이 아니다.
- [Google Cloud TTS 가격](https://cloud.google.com/text-to-speech/pricing): Standard/WaveNet $4/100만 문자. 영어 900문자/분 가정의 6분(5,400문자)은 $0.0216. 무료 할당량은 비용 계산에서 제외한다. 해당 음성의 품질·한국어 혼용은 청취 전 미확인이다.
- [OpenAI 공식 가격](https://developers.openai.com/api/docs/pricing): Realtime mini 음성 입력 $10·캐시 입력 $0.30·출력 $20/100만 토큰. 일반 Realtime보다 저렴하지만 Gemini와 토큰 정의가 달라 단가 숫자만 비교할 수 없다. 캐시 적중률·오디오 토큰량·한국어 품질을 확인하기 전 최저가로 추천하지 않는다. OpenAI Docs 스킬로 공식 문서를 확인했다.

## 절감 방법 전체 분류

텍스트 LLM 자체도 더 줄일 수 있다. 위 Gemini 공식 가격표의 2.5 Flash-Lite Standard($0.10/$0.40)로 같은 60,000입력·3,000출력을 처리하면 $0.0072다. 3.5 모델 가정의 $0.0255보다 $0.0183 절감된다. 같은 저가 모델의 노트 산술은 $0.002다. 둘 다 바꾸면 문장 단위 Groq + Cloud 저가 음성 조합은 약 $0.0375/세션까지 계산되지만 교정/노트 품질 동등성을 확인한 결과가 아니다. 따라서 약 $0.04는 달성된 원가가 아닌 품질 절충 후보의 계산값이다.

| 대량 할인·약정·적합 리전 | 단가 인하 가능 | 사용량/계약과 데이터 지역/지연을 확인한 뒤. 무료 크레딧·할인 종료를 장기 원가에 넣지 않음 |
| 일일/월별 한도·유휴 차단·중복 호출 방지 | 예산 초과/악용 차단 | 15분 동일 품질의 단위 원가를 낮추는 방법과 구분. 평균 이용률이 낮을 것이라는 기대만으로 손실을 감수하지 않음 |

현재 코드 관찰: Gemini setup에 명시적 압축 설정이 없고 오디오 캡처는 연속 전송 경로다. 어댑터는 전사·도구·재생을 처리하지만 공급자 usageMetadata 집계는 없다. 임의로 사용량 수치를 구현하거나 현재 청구를 단정하지 않는다.

## 로컬·자체 호스팅까지 고려한 경우

- 브라우저/기기 STT·TTS·작은 LLM: API 호출을 줄이지만 모델 다운로드·메모리·배터리·기기별 속도 차이·한영 전환과 상업 배포 조건을 확인해야 한다. [whisper.cpp](https://github.com/ggml-org/whisper.cpp)는 WASM 등 로컬 경로를 제공한다. 가능한 경로와 모바일에서 적합한 품질/지연은 별개다.
- [SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)은 브라우저 지원이 제한적이고 일부 브라우저에서는 서버로 보낸다. 무료·오프라인·보관 조건 충족을 한 번에 보장하는 대안으로 쓰지 않는다. [SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)는 기기의 사용 가능한 음성에 의존한다.
- 자체 서버 STT/TTS/LLM: 외부 API 대신 CPU/GPU·유휴 서버·동시 처리·장애/업데이트 비용을 부담한다. [Piper](https://github.com/OHF-Voice/piper1-gpl) 같은 후보는 엔진과 음성별 라이선스를 각각 확인해야 한다. 특정 모델의 상업 이용·한국어 품질을 이 문서로 승인하지 않는다.
- 손익분기식은 `월 추가 고정 운영비 / (API 세션 비용 − 자체 실행 세션 변동비)`다. 예를 들어 가정상 월 $100의 추가 서버가 있고 순절감이 세션당 $0.05면 월 2,000세션부터 서버비만 상쇄한다. 이는 시장 서버 견적이 아니고 개발/운영 인건비·피크 여유분을 제외한 산술 예시다. 작은 MVP에서 자체 GPU가 자동으로 싼 것은 아니다.
- 하이브리드: 기기 TTS 또는 STT 한 요소부터 옮기고 실패 시 서버 대안을 사용한다. 모든 요소를 한 번에 로컬화하는 것보다 품질 문제를 분리하기 쉽지만 이중 경로 유지비가 생긴다.

## 제안하는 선택과 검증 순서

1. **기존 Live를 비교 기준으로 보존**하고 종류별/턴별 사용량을 내용 없는 메타데이터로 계측할 준비를 한다. 비용식이 실제 사용량/청구와 맞는지 확인하지 않고 상한을 상품 약속으로 확정하지 않는다.
2. **Live 압축 비교군과 저가 분리형을 비교**한다. 분리형 첫 후보는 실시간 STT + 작은 LLM + 저렴한 TTS이며, 더 싼 문장 단위 STT는 지연 절충 후보로 둔다. 순수 API 목표를 우선 세션 $0.10 안팎으로 제안하되 노트·재시도와 2027년 가격을 포함해 실측 후 판단한다. 이는 채택된 예산이 아니다.
3. 같은 한국어 혼용·한국인 억양·교정/재시도·끼어들기 사례로 인식/교육 품질과 발화 종료→첫 소리 지연·실패율·취소 후 낭비를 측정한다. 음성 맥락을 버리더라도 현재 교정/재시도 상태·실제 재생 근거는 보존해야 한다.
4. 결과가 목표에 못 미치면 Cloud 저가 음성/기기 TTS, 문장 단위 STT 순으로 절충을 비교한다. 상위 모델은 어려운 턴만 검토하고 자체 호스팅은 실제 이용량이 생긴 뒤 손익분기로 판단한다.

분리형에는 중계·STT/LLM/TTS 스트리밍·발화 종료 감지·취소 전파·재생 근거 동기화가 추가되어 일정/운영 부담이 증가한다. API 비용 절감률만 보고 개발 기간을 정하지 않는다. 한국어 지원 표는 인식/설명 품질을 보장하지 않는다. 공급자별 학습·보관/삭제·지역 조건은 기존 PRD/DEC-025와 대조해야 하며, 가격 조사만으로 실제 사용자에게 보낼 수 있다고 판정하지 않는다. 사용자 요청으로 보류된 추가 E2E·새 유료 호출은 이번 조사에서 수행하지 않았다.
