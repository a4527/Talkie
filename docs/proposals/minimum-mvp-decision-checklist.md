# 최소 MVP 구현을 위한 결정 점검표

점검일: 2026-10-23. 상태: 현행 요구사항 대조 결과·미결정 목록. 새 정책·기술 채택이 아니다.

사용자의 요청은 최소 MVP 구현에 필요한 결정의 누락 없는 정리다. 기준은 [PRD](../../PRD.md), [TASKS](../../TASKS.md), [현재 설계](../../design.md), [결정 목록](../../DECISIONS.md), [첫 흐름](../design/first-learning-flow.md), [검증 설계](../design/engineering-validation.md), [기존 논의 진행표](mvp-preimplementation-decisions.md) 및 DEC-031이다. 과거 제안의 ‘미정’은 후속 결정과 대조했다. 아래 ID는 이 점검표의 식별자이며 새 TASK나 DEC가 아니다.

## 범위와 읽는 방법

2026-10-23 후속: D-02의 [인증·저장 상세 설계 초안](authentication-storage-design.md)에 데이터 모델·동시성·두 DB 저장 경계와 다섯 기술 선택을 정리했다. 1A·3A·4A·5A는 DEC-041~044, 2B는 Drizzle ORM·Drizzle Kit으로 DEC-045에 채택했다. 상세 계약·구현/검증은 남는다. 아래 점검 항목의 완료나 실제 사용자 데이터 보관 승인을 뜻하지 않는다.

- **첫 구현 B-00**: 가짜 AI·텍스트·실행 중 메모리만 사용한다. D-01/D-04/DEC-015로 착수 조건이 충족됐다. 추가 사용자 결정은 현재 없다. 패키지 버전·실행 명령·화면 세부·내부 모듈·테스트 도구 등의 기존 결정 안에서의 구현 선택과 설치·빌드 검증은 남아 있다.
- **로컬 실제 기능 MVP**: 실제 음성 대화·앱 직접 이메일 인증·계정별 저장·재개·종료/부분 노트·개별 다운로드·기한 작업을 연결하는 기존 진행표의 범위다. 아래 L01~L50은 이 단계의 남은 결정·설계·검증 항목이다. 이 전체를 B-00 착수 조건으로 올리지 않는다.
- **공개 운영과 유료 제공**: 아래 P01~P10. 로컬 실제 기능의 착수 조건은 아니지만 기존 P0/O 요구사항에서 삭제한 것이 아니다. 프로젝트 전체 완료와 로컬 기능 완료를 구분한다.
- **제품/영향 큰 기술**은 사용자와 대안·영향·이유를 합의한다. **구현 상세**는 승인 범위에서 에이전트가 설계·검증하며, 큰 영향이나 기존 결정과의 충돌이 발견되면 논의한다. **검증**은 사용자가 선택만 해서 완료할 수 없으며 실제 근거가 필요하다.
- 표의 ‘남음’은 전부를 지금 동시에 선택하라는 뜻이 아니다. 최초 사용·관련 기능 통합·공개 전 등 명시한 시점까지 정한다. 구현 초기값과 실측 후 확정할 목표를 구분한다.

로컬 구현 후속: 합성 인증·두 DB 저장/재개·가짜 노트와 시험을 시작했다. 현재 구현/검증과 남은 수용 기준은 [design](../../design.md#로컬-인증저장-구현-현황)과 [worklog](../worklogs/2026-10-23.md#체크포인트-push-후-로컬-인증저장-구현)를 따른다. 아래 L 항목 전체 완료나 실제 사용자/운영 승인으로 취급하지 않는다.

## 지금 확정할 필요가 없는 것

MSA·헥사고날 등 구조 명칭, 필요성 미확인 별도 큐/캐시/고가용성/오토스케일링, 실측 없는 최종 성능 수치, 실제 음성 비교 전 최종 공급자, 공개 전 결제/유료 가격을 B-00 선행 조건으로 만들지 않는다. P1 역할극·고급 노트/표현 탐색·복습 확장은 현행 TASKS 우선순위를 따르며, P0 노트 필수 섹션과 소재 다양성 요구를 함께 제거하지 않는다.

## 진행 순서와 한계

B-00은 즉시 착수 가능하다. 실제 기능 준비는 인증/저장 기술(L02~L10), 저장/종료 실패와 데이터 수명 경계(L11~L20), AI 호출 전 적합성·실험 조건(L21~L25)을 먼저 구체화한다. 정책·단가 확인→승인된 조건으로 비교→최종 선택(L26~L30) 순서를 유지한다. 학습/노트/비용/검증(L31~L50)은 각 기능 전에 결정한다. 사용자 선택이 필요한 항목만 대안·영향을 준비해 다섯 개씩 논의하고 구현 상세는 설계와 검증으로 처리한다.

현재 문서에 명시된 미정 항목과 수용 기준에서 필요한 경계 조건을 대조한 목록이다. 새 공급자 제약·실험 결과로 추가 문제가 드러나면 이 점검표를 보완한다. 이 목록 작성으로 D-02/D-03이나 기능 작업을 완료 처리하지 않으며, 정책 적합성·가격을 새로 확인하거나 호출한 것도 아니다. 기존 제안서 전체의 과거 미정 표현을 재작성하지 않고 현재 상태를 이 점검표와 후속 결정으로 판별한다.

### 임시 원문: Redis와 DB 저장·삭제 비교 후속

2026-10-23. 사용자는 1A(PostgreSQL)를 재확인하고 임시 원문의 Redis/DB 적합성을 질문했다. 임시 저장은 미채택이다. 기존 제안의 Redis C는 영속화 없는 구성으로, 영속화한 Redis와 구분한다.

- 관찰: [Redis 영속성](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/)은 RDB/AOF/영속화 없음과 fsync 정책별 손실 범위를 설명한다. 영속화 없음은 Redis 재시작 시 원문 유실, AOF는 디스크 원문·재작성·복원 잔존 처리를 추가한다. [EXPIRE](https://redis.io/docs/latest/commands/expire/)는 TTL과 능동/수동 만료를 제공하나 물리 메모리/디스크 즉시 덮어쓰기 보장이 아니다. [메모리 관리](https://redis.io/docs/latest/operate/oss_and_stack/management/optimization/memory-optimization/)의 noeviction은 메모리 한도에서 새 쓰기 오류를 반환하므로 대화 원문을 캐시처럼 임의 축출하지 않도록 별도 설계가 필요하다.
- 관찰: [PostgreSQL vacuum](https://www.postgresql.org/docs/current/routine-vacuuming.html)은 DELETE가 옛 행 버전을 즉시 물리 제거하지 않음을 설명한다. [백업/WAL](https://www.postgresql.org/docs/current/continuous-archiving.html)은 전체 클러스터 복원 범위다. DB DELETE나 Redis TTL 어느 것도 저장 매체·백업 사본 즉시 완전 삭제의 근거로 삼지 않는다.
- 판단: Talkie의 원문은 중단 재개·노트 재시도의 유일한 근거이므로 재생성 가능한 캐시와 다르다. 삭제 예정이라는 이유만으로 휘발성 Redis가 더 적합하지 않다. 현재는 백업 경계를 분리한 PostgreSQL 저장·삭제 쪽 추천을 유지한다. TTL 편의만으로 Redis 운영·영속화·메모리/만료·두 저장소 정합성 부담을 추가할 근거는 약하다. 다만 실제 성능·비용은 미측정이며 분리 PostgreSQL도 운영 복잡성과 잔존 관리가 있다.
- 공통: 성공 시 즉시 삭제·종료 후 최초 24시간 상한과 중단 후 별도 24시간을 구분한다. 모든 저장마다 TTL을 24시간으로 재설정해 기한을 늘리지 않는다. 만료·재개·자동 종료/노트 생성 경쟁을 설계하고 기한 작업은 DEC-028의 지속 목록에 유지한다. 접근 차단과 물리 잔존/백업 경계를 구분해 검증한다.

임시 원문 후속 합의: 사용자가 DB 저장·삭제 추천에 동의해 DEC-034를 채택했다. L07의 기술 방향과 첫 묶음 2A는 확정이며 백업 제외·삭제/복원·저장소 간 실패 검증은 남는다. 앞의 미채택 표현은 동의 전 당시 상태이며 3번 인증 상태 저장은 여전히 미정이다.

인증 저장 후속 합의: 3A는 DEC-035로 채택했다. 사용자·노트와 같은 지속 PostgreSQL DB의 별도 테이블을 사용하고 측정된 부하/운영 필요에 따라 분리를 재논의한다. 첫 묶음의 다섯 선택은 모두 확정됐으며 상세 설계·구현·검증은 남는다. 앞의 인증 저장 미정 표현은 동의 전 당시 상태다.

## DEC-040 후속 합의

L25의 로그 접근은 개발자 본인만·외부 자동 전송/앱 조회 화면 없음으로 확정했다. 실제 전사문·교정의 별도 평가 사본을 만들지 않으며 합성 사례·내용 없는 평가 결과를 사용한다. L12는 장기 실패/버퍼 상한을 이유로 대화를 정지하지 않고 기존 실패 표시·누적 재시도를 유지한다. 상한 수치와 미저장 기록 유지/포기 규칙은 남는다. L36은 버튼 즉시 종료·음성 한 번 확인, L38은 한국 시간 실제 종료일 귀속·지연 생성에도 날짜 유지로 확정했다. 상세 병합·동시성·실제 검증은 남으며 해당 L 항목 전체 완료는 아니다. 기준은 PRD와 ADR-040이며 앞의 미정 표현은 후속 합의 전 상태다.
