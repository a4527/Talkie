# 로컬 실제 기능 MVP의 사전 결정 진행표

작성일: 2026-10-21. 상태: 오늘 논의 마감, 남은 상세는 후속 논의. 이 문서는 제안과 논의 순서를 관리하며 채택된 결정을 대체하지 않는다. 현재 상태는 아래 진행표, 채택 근거는 DECISIONS와 ADR을 따른다. 뒤의 제안·질문·미정 표현은 각 절의 후속 합의 전 당시 기록이며 자동으로 현재의 결정 요청이 되지 않는다. 남은 결정은 MVP에 필요한 항목을 다섯 개씩 묶어 제시한다.

## 합의한 진행 범위

사용자는 로컬 실제 음성·인증·저장·학습 노트 구현 전 결정을 다루고, 실측이 필요한 항목은 정책과 측정 조건을 먼저 정하는 진행 방식에 동의했다. 공개 무료 체험 상세·유료 요금제·클라우드·지역·배포 구성은 후속 논의다. 이는 DEC-014의 공개 가입 방향이나 MVP 전체 요구사항을 취소하는 결정이 아니다.

Next.js + TypeScript(DEC-015), AI 판단과 앱 기록 책임(DEC-010), 대화 중 교정(DEC-011), 기록 범위와 임시 원문 최대 24시간/성공 즉시 삭제(DEC-012), 주기적 묶음 저장(DEC-013)을 유지한다. 현재 B-00은 기존 승인 범위에서 착수할 수 있다. 아래 논의 완료를 B-00의 새 선행 조건으로 추가하지 않는다.

## 1순위 제안: 실험 예산과 데이터

아래는 논의 당시 대안이다. 사용자는 3만 원과 추천 데이터·로그·집행 규칙에 동의했다 (DEC-016). 현재 기준은 PRD, 이유는 ADR-016을 따른다. 금액은 공급자 요금이나 실험 완료 비용 추정이 아니다. 공급자 처리 조건과 세부 실험 조건은 호출 전에 확정한다.

| 대안 | 유료 AI 실험 총한도 | 장점 | 단점·일정 영향 |
| --- | --- | --- | --- |
| A | 1만 원 | 지출을 작게 제한 | 시나리오·반복 수를 줄이거나 조기에 비교를 중단할 수 있음 |
| B · 추천 | 3만 원 | 초기 비교를 진행하면서 총지출을 제한하는 출발점 | 충분한 반복 가능 여부는 후보 단가와 호출량 계산 후 확인 필요 |
| C | 5만 원 | 같은 단가에서 반복·추가 사례에 배분할 여유 | 비교가 개선된다는 보장은 없으며 최대 지출이 증가 |

제안 집행 규칙:

- 최초 후보 비교 라운드 전체에 총한도를 적용한다. 날짜나 실패·재시도로 예산을 초기화하지 않는다. 공개 운영비·클라우드 자원 생성은 포함하거나 승인하지 않는다.
- 세금·환율·수수료를 포함한 원화 지출을 기준으로 계획한다. 확인 가능한 단가로 다음 실험의 상한을 계산할 수 없으면 유료 호출을 시작하지 않는다.
- 호출 시간·출력량·재시도 횟수를 제한하고, 이미 집행한 금액과 진행 중 호출의 예약 비용 및 다음 호출의 최대 비용이 한도를 넘으면 신규 호출을 막는다. 공급자 청구 지연과 앱 추정 오차는 별도로 기록한다. 자동 충전과 무제한 재시도는 사용하지 않는다.
- 후보별 배분과 표본 수는 3순위에서 단가를 확인한 뒤 예산 안에서 정한다. 부족하면 범위 축소 또는 추가 예산 논의로 돌아간다.

데이터 대안:

- 추천: 합성 대화 + 개발자가 테스트용으로 직접 말한 음성만 사용한다. 다른 사용자의 기록·실제 계정 정보·개인 사연을 넣지 않는다. 음성은 인식·지연·끼어들기 확인에 필요하지만 실제 목소리가 공급자에 전달된다는 영향이 있다. 해당 공급자 처리 조건을 2~3순위에서 확인한 뒤 사용한다.
- 대안: 합성 텍스트·합성 음성만 사용한다. 개발자 목소리의 외부 전달을 줄일 수 있지만 자연 발화 인식 품질 평가는 후속 단계로 남는다. 합성 음성 생성도 비용·처리 조건 확인 대상이다.
- 공통 제안: 앱은 원본 음성을 파일·DB에 저장하지 않고 처리 중 버퍼만 사용한다. 로그는 요청 ID·상태·시간·사용량 중심으로 남기며 원문·음성·비밀값을 제외한다. 전사문·평가 결과의 저장과 삭제 기간은 2순위에서 결정한다. 공급자 측 보관은 앱 정책과 별도로 확인한다.

## 측정 항목과 완료 판정

- AI 비교: 같은 시나리오로 끼어들기·생성/재생 중단·기록 동기화·한국어 이해·교정·요약·지연·10분 세션 비용을 평가한다. 수치 통과 기준·표본 수·최대 호출량을 실험 전에 합의한다. 통과 후보가 없으면 실제 AI 통합을 보류한다.
- 저장·복원: 정상 흐름, 연결 중단, 중복 저장, 늦은 응답, 미저장 기록 손실, 요약·저장·삭제 실패와 기한 경과를 확인한다. 계정 간 접근 차단과 노트 근거 연결도 검증한다.
- 실측 전 선택에는 초기값·근거·미검증 가정·통과 기준·재검토 시점을 남긴다. 후보 테스트 없이 D-03을 완료 처리하지 않는다. 로컬 실험을 클라우드 적합성·동시 사용자 수·가용성 검증으로 확대 해석하지 않는다.
- 합의된 정책은 PRD, 구조·계약은 design, 중요한 선택 이유는 ADR에 먼저 기록한다. TASKS 완료 기준·PROGRESS·사용자에게 의미 있는 CHANGELOG·당일 worklog를 직접 영향 범위에서 맞춘다.

## 현재 남은 논의

2026-10-23 후속: 지속 DB 엔진은 DEC-033으로 PostgreSQL 채택. 임시 원문은 DEC-034의 별도 PostgreSQL 인스턴스·볼륨을 채택했다. 인증 상태 저장 방식과 데이터 모델·실패/복원·백업 제외 검증은 남는다.

전체 미결정·구현 상세·검증의 최신 대조 목록은 [최소 MVP 결정 점검표](minimum-mvp-decision-checklist.md)를 따른다. B-00, 로컬 실제 기능, 공개 운영의 결정 시점을 구분한다.

2026-10-23 후속: 저장·재개·노트의 다섯 논의는 DEC-031/ADR-031로 구체화했다. 1번은 기존 A/B 대신 사용자 제안인 저장 상태 표시·대화 계속·다음 주기 실패 분량 포함 재시도를 채택했고 나머지는 `2A 3B 4A 5A`다. 버퍼 상한·장기 실패·종료 시 저장 실패·재시도 수치는 미정이다.

예산·기록 수명·로그인·탈퇴·중단·음성 정책과 DEC-026~030의 다섯 선택을 합의했다. 남은 범위는 실제 메일/세션/임시 저장·정시 실행 기술과 데이터 계약·실패/복원 처리, 탈퇴 재확인·발송 제한·로그 접근/보관, AI 비교의 평가 조건·맥락 분량이다. 발화 파생 평가 자료의 지속 보관은 전제하지 않는다. 공급자 후보의 실제 계약·가격·품질·비용과 최종 공급자/경로는 D-03에서 확인·합의한다. 공개 체험·과금·운영 선택은 해당 단계 전에 논의한다.

## 임시 음성과 공급자 보관 조건 논의 기록

확인일: 2026-10-21. 상태: **B안 채택 · DEC-025**. 아래 대안과 당시 제안은 판단 근거이며 현재 요구사항은 PRD 8절, 이유는 ADR-025를 따른다. DEC-008의 원본 음성 기본 장기 미보관과 DEC-016의 로컬 실험 앱 파일·DB 미저장 및 제한된 테스트 데이터는 이미 합의했다. PRD 8절의 학습 전사문 보관과 앱 관리 백업 기한은 음성 원본이나 공급자 측 데이터에 자동 적용되지 않는다. 실제 공급자·모델·연결 방식은 D-03에서 비교한다.

앱 측 공통 제안: 로컬 실험과 실제 제품 모두 마이크 입력·AI 출력 음성은 전송·재생에 필요한 동안만 클라이언트/서버의 휘발성 버퍼에서 처리한다. 완료·취소·연결 종료 후 불필요한 버퍼를 해제하고 파일·DB·진단 로그·오류 본문·백업에 원본 음성을 넣지 않는다. 재연결과 노트 생성은 확인된 전사문·진행 상태를 사용하며 음성 원본을 복구하지 않는다. 버퍼 해제가 이미 공급자에게 전송된 데이터나 브라우저/운영체제의 통제 밖 임시 처리까지 삭제한다는 뜻은 아니다. 실제 연결에서 버퍼 생존 범위와 중단·오류 경로를 검증한다.

| 공급자 보관 대안 | 사용자 경험·데이터 | 비용·일정·운영 영향 |
| --- | --- | --- |
| A · 공급자도 원본 음성·전사문을 처리 후 보관하지 않는 조건만 허용 | 외부 잔존을 가장 줄임 | 이 조건을 제공하는 실시간 음성 후보가 있는지 미확인이다. 후보·지역·기능·가격 제약으로 연결이나 출시가 늦어질 수 있다. |
| B · 추천: 모델 학습에 사용하지 않고, 공급자 보관은 최대 30일로 제한 | 품질·남용 조사에 쓰이는 제한적 보관은 허용하되 앱 삭제 이후에도 공급자에 데이터가 남을 수 있음을 사용자에게 알린다 | 30일 상한을 계약·설정으로 확인하고, 처리 목적·접근 주체·삭제 시점·하위 처리자·지역·탈퇴 요청 시 삭제 지원 여부를 기록해야 한다. 후보가 충족하지 못하면 A 또는 재논의로 돌아간다. 실제 지원 여부·가격은 미확인이다. |
| C · 공급자 표준 보관 조건 수용, 상한은 후보 선정 후 결정 | 후보 선택 폭이 넓을 수 있으나 사용자에게 데이터 수명을 명확히 설명하기 어렵다 | 제품 정책과 공급자 조건의 차이를 뒤늦게 발견할 위험이 크다. 후보 선정 전 외부 제공 기준이 불명확하다. |

추천안 B의 30일은 **Talkie가 제안하는 상한이지 공급자의 확인된 정책이 아니다**. 호출 전 공식 계약·개발자 문서·설정에서 음성과 전사문 각각의 학습 사용, 보관 시작/종료, 예외, 삭제 가능 여부를 확인한다. 실험은 DEC-016의 합성 대화·개발자 본인 음성으로 제한하고, 조건이 충족되지 않으면 유료 음성 호출을 시작하지 않는다. 공개 사용자 음성을 받기 전에는 실제 선택 후보의 조건, 계정 탈퇴 시 앱의 24시간/7일 기한과 공급자 잔존 범위의 차이, 사용자 고지와 접근 통제를 다시 검증한다. 이 제안은 공급자 측 탈퇴 데이터의 7일 삭제를 보장하지 않는다.

학습 허용의 경제적 효과 확인 (2026-10-21, 후보 채택 아님): [OpenAI의 API 데이터 공유 안내](https://help.openai.com/en/articles/10306912-sharing-feedback-evaluation-and-fine-tuning-data-and-api-inputs-and-outputs-with-openai)는 일부 적격 조직이 입력·출력 공유 시 특정 모델에서 일일 무료 토큰을 받을 수 있다고 밝힌다. 적격 여부는 계정 설정에서 확인해야 하며, 안내된 대상 목록만으로 Talkie의 실시간 음성 트래픽 할인은 확인되지 않는다. [Gemini API 가격 안내](https://ai.google.dev/gemini-api/docs/pricing)는 무료 티어에서 콘텐츠를 제품 개선에 사용하고 유료 티어에서는 사용하지 않는다고 구분한다. 무료 티어는 모델·사용량 범위가 제한되며 유료 티어에는 더 높은 한도와 기능이 있다. 반대로 [Anthropic API의 상업용 데이터 안내](https://privacy.claude.com/en/articles/7996885-how-do-you-use-personal-data-in-model-training)는 기본적으로 대화를 모델 학습에 쓰지 않는다고 설명한다. 따라서 학습 허용이 모든 공급자의 API 단가 인하나 실시간 음성 후보 증가를 뜻하지는 않는다. 무료 티어·공유 혜택은 후보·모델·음성 기능·계정 자격별로 확인해야 한다. 사용자 음성을 학습에 제공하면 이후 삭제·탈퇴 정책과 별도로 되돌리기 어려운 데이터 사용이 생길 수 있어, 비용 이득이 실제로 확인되기 전에는 기본 정책에 넣지 않는 것이 추천이다.

사용자는 앱 측 공통 제안과 B안을 선택했다. 공급자 측 모델 학습 금지·최대 30일 보관은 정책 상한이며 실제 후보가 이를 지원한다고 확인한 것은 아니다. 로그 접근·보관 기간, 전사문·평가 결과의 별도 실험 수명, 백업의 체험 만료·임시 원문 처리, 인증/삭제 작업 상세는 후속 D-02 논의로 남긴다.

## 이메일 로그인 링크 수명과 재사용 논의 기록

상태: **10분안 채택 · DEC-020 후속**. 아래 대안은 당시 비교 기록이며 현재 기준은 PRD 8.1절과 ADR-020 후속을 따른다. DEC-020은 이메일 링크 가입·로그인과 마지막 인증된 이용 후 30일 쿠키 세션을 합의했다. 여기서 정하는 짧은 링크 수명은 로그인 상태 30일과 별개다. 인증·메일 공급자와 세션 저장 기술은 이 제안으로 선정하지 않는다.

| 대안 | 사용자 경험 | 데이터·보안·운영 및 일정 영향 |
| --- | --- | --- |
| A · 채택: 링크 발급 후 10분 | 메일을 바로 열면 충분하고 유출 링크의 유효 시간이 짧음 | 메일 전달 지연이나 기기 전환 시 만료·재발송이 늘 수 있음 |
| B · 당시 추천: 링크 발급 후 15분 | 짧은 수명을 유지하면서 메일 확인 시간을 조금 더 줌 | 경계 시각·시계 차이와 지연 메일의 만료 안내, 재발송 흐름을 검증해야 함 |
| C · 링크 발급 후 30분 | 늦게 도착한 메일을 사용할 여지가 큼 | 유출·공유된 미사용 링크가 더 오래 유효함 |

공통 제안: 링크는 **첫 성공 확인에 한 번만** 쓰고, 새 링크를 요청하면 같은 목적의 이전 미사용 링크를 무효화한다. 메일 서비스의 링크 미리보기·보안 검사만으로 토큰을 소모하지 않도록 사용자 화면의 확인 동작에서 사용 처리한다. 사용 후·만료 후·재발송 후 다시 열린 링크에는 유효하지 않음을 설명하고 새 링크 요청을 제공한다. 발송 남용과 계정 존재 노출을 제한하되 구체 발송 횟수·간격은 메일 공급자 조건과 테스트에 맞춰 정한다. 탈퇴 전 이메일 재확인 링크에도 같은 일회성·미리보기 보호를 적용하되 재확인 후 삭제 확정까지 허용할 시간은 별도로 논의한다.

사용자는 15분 추천 대신 10분을 선택했고 공통 제안의 일회성·최신 링크만 유효·미리보기 보호를 함께 채택했다. 10분은 메일 전달 시간 실측값이 아니며 실제 전달 지연·만료율과 재발송 흐름을 검증한다. 탈퇴 재확인 링크 수명과 재확인 후 확정 허용 시간, 발송 제한 수치는 다음 논의에 남긴다.

## 보류한 세부값 제안: 인증·진단·실험 자료·탈퇴 작업

상태: **미채택·현재 결정 요청 철회**. 사용자가 남은 결정을 다섯 개씩 묶어 요청해 아래 수치를 제시했으나, MVP 최소 범위 질문을 받고 작업 선행 조건과 구현 단계에서 정할 운영값을 섞어 물은 것으로 확인했다. 다음 표는 당시 비교 기록이며 지금 선택할 항목이 아니다. 실제 메일 지연·공급자 요금·운영 부하를 측정하지 않았고 PRD·DEC·TASK의 확정 요구로 옮기지 않았다.

공통 경계: 1번의 재확인 완료는 탈퇴 자체가 아니며 최종 확인 동작이 있어야 DEC-021의 삭제 기한이 시작된다. 2번의 제한 정보는 인증 처리용으로만 사용하고 진단 로그에 이메일을 남기지 않는다. 3번의 로그와 4번의 발화 파생 평가 자료는 별도 저장·접근·삭제 대상으로 다룬다. 5번의 주기를 정해도 백업 내 탈퇴 데이터는 최초 탈퇴 후 7일, 앱 관리 데이터는 24시간 이내라는 기존 기한이 유지되며 자동 준수는 검증해야 한다. 실패한 삭제를 다음 정시 작업에 재시도하되 기한을 연장하지 않는다.

범위 재정리: B-00의 로컬 가짜 AI·가짜 데이터 흐름에는 위 다섯 수치가 필요하지 않다. 실제 공개 가입과 탈퇴 기능에는 재확인·발송 남용 방지·24시간 이내 일괄 삭제가 필요하지만, 1·2·5번의 정확한 수치·주기는 인증/메일/작업 기술을 고를 때 기존 기한을 충족하도록 정하고 검증한다. 3번은 DEC-016의 실제 AI 후보 실험 로그를 지속 보관하기 전에 접근 범위·기한을 정해야 하지만, B-00의 가짜 데이터 흐름에는 아직 필요하지 않다. 4번의 발화 파생 평가 자료는 저장을 전제할 필요가 없다. DEC-012의 임시 전체 원문 24시간과 DEC-025의 원본 음성 미저장을 유지하면서 합성 사례·발화 내용 없는 집계 결과로 후보 검증을 시작할 수 있다. 위 숫자들은 새로운 MVP 선행 결정이 아니며 필요해질 때 근거와 함께 다시 제안한다. 다른 남은 정책·공급자 검증은 관련 기능을 연결하기 전에 다룬다.

## 실제 기능 연동을 위한 다섯 결정 제안

확인일: 2026-10-21. 상태: **사용자 선택 `1C 2A 3A 4C 5C`로 다섯 항목 채택** (`DEC-026`~`DEC-030`). 현재 결정은 각 ADR을 따른다. 이번 묶음은 B-00의 선행 조건이 아니다. 1~3은 B-01/B-05의 실제 인증·저장·종료 작업을 구현하기 전의 설계 방향, 4~5는 D-03 후보 실험의 범위를 정한다. 4의 최종 공급자와 5의 최종 연결 경로는 실측·정책 확인 뒤에만 채택한다. 표의 추천은 기술·가격·실험 적합성 검증을 대신하지 않는다.

## 보관 기간 후속 합의

사용자가 무료 체험 1개월·유료 기간 제한 없는 지속 학습 기록 보관을 명시해 DEC-017로 채택했다. 위 조사 당시 미정 표현과 과거 후보는 당시 상태다. 현재 요구사항은 PRD 8절, 이유는 ADR-017을 따른다. 기산점·구독 종료/하향·유예·백업·통합 요약 만료 처리는 아직 합의 전이다.

## 구독 만료 후 기록 보존 재검토

2026-10-21 사용자는 구독 종료 후에도 정보가 남는 것이 일반적이지 않은지 질문했다. 직전 30일 후 초과 기록 삭제는 미승인 제안이며 철회한다. DEC-017의 종료 후 처리 미정 상태는 유지한다.

관찰: [Speak 구독 취소 안내](https://help.speak.com/en/articles/5355569-how-can-i-cancel-the-subscription)는 자동 갱신 해제와 만료일까지 이용을 설명하고, [계정 삭제 안내](https://help.speak.com/en/articles/5358745-how-do-i-delete-my-speak-account)는 별도 절차와 복구 불가를 안내한다. 이 두 안내만으로 만료 후 모든 학습 기록의 무기한 보존을 확인할 수는 없다. [Babbel 취소 안내](https://support.babbel.com/hc/en-us/articles/205600298-Canceling-a-subscription)도 자동 갱신 취소와 잔여 기간 접근을 설명한다. 공개된 이 안내들만으로 업계 전체 보관 기간을 일반화하지 않는다.

수정 제안: 유료 이용 중 남긴 지속 학습 기록은 구독 만료만으로 삭제하지 않고 사용자 삭제/탈퇴 전까지 유지하며, 추가 AI 학습·생성 권한은 구독과 별도로 통제한다. 재구독 시 기존 이력을 이어받도록 한다. 기존 노트의 만료 후 조회·다운로드 허용 여부도 함께 합의한다. 무료 체험만 이용한 기록 1개월 원칙은 유지하되 체험 중 생성 기록의 업그레이드 적용·기산점은 후속 결정이다. 이는 재방문 사용자 경험을 보호하지만 휴면 사용자의 저장·백업 비용이 누적된다. 아직 채택하지 않았다.

## 구독 만료 처리 후속 합의

사용자는 위 수정안에 “그렇게 하자”라고 동의했다. DEC-018로 기존 유료 기록의 만료 후 유지·조회·다운로드·재구독 시 이력 활용과 AI 이용 권한 분리를 확정했다. 현재 기준은 PRD 8절, 근거는 ADR-018을 따른다. 무료 체험 기산점·기존 체험 기록의 유료 전환 적용·삭제/백업·통합 요약 정책은 미정이다. 위 미채택 표현은 후속 동의 전 당시 상태다.

## 무료 기록의 기산점·전환 후속 합의

사용자가 “그러자”라고 동의해 DEC-017 후속으로 각 학습 종료 시점부터 30일 보관·기한 전 유료 전환 시 남은 체험 기록의 기간 제한 없는 보존을 확정했다. 구독 만료 후에도 전환한 기록을 유지한다. 위 미정 표현은 후속 합의 전 상태이며 현재 요구는 PRD 8절, 이유는 ADR-017 후속을 따른다. 다음 논의는 인증·사용자 삭제/탈퇴 범위·내보내기·중단 세션 재개 기한·백업·공급자 처리 조건이다.

## MVP 삭제 기능 범위 합의

세션별·전체 학습 기록 삭제·회원 탈퇴 제안에 사용자가 회원 탈퇴만 제공하도록 명시했다. DEC-019로 탈퇴 시 계정·연결 학습 데이터 전체 삭제, 세션별·계정 유지형 전체 기록 삭제 제외를 채택했다. 탈퇴하지 않은 유료 보존 기록과 체험 30일 만료/유료 전환의 기존 합의를 유지한다. 삭제 처리 기한·백업·공급자 처리 상세는 미정이다.

## 이메일 로그인과 로그인 유지 합의

사용자가 이메일 링크를 선택하고 매번 메일을 열지 않도록 로그인 상태를 오래 유지하자고 제안했다. 마지막 이용 후 30일·이용 시 갱신·브라우저 재시작 후 유지·로그아웃/탈퇴 시 무효화·탈퇴 전 이메일 재확인안에 “그러자”라고 동의해 DEC-020으로 채택했다. 현재 정책은 PRD 8.1절, 이유와 검증 범위는 ADR-020을 따른다. 인증·메일·세션 구현 기술과 링크 상세는 실제 인증 연결 전에 확정한다. 다음은 탈퇴 처리 기한과 백업 삭제이며, 이어서 내보내기·중단 세션 재개 기한·실험 기록/로그 수명·공급자 처리 조건을 논의한다. 위 인증 미정 표현은 후속 합의 전 상태다.

## 탈퇴 일괄 삭제와 백업 기한 합의

사용자가 탈퇴 즉시 차단·24시간 이내 삭제를 유지하면서 정해진 시각에 모아서 삭제하고 백업은 1주일의 기한을 주도록 명시해 DEC-021로 채택했다. 기준은 PRD 8.2절, 이유·대안·운영 영향은 ADR-021을 따른다. 두 기한 모두 탈퇴 확정 시점부터 계산하며 실패·재시도로 연장하지 않는다. 구체 실행 시각과 재시도/복원 기술은 삭제 기능 구현 전에 정한다. 위 백업/삭제 기한 미정 표현은 당시 상태이며 현재 탈퇴 정책은 이 후속 합의를 따른다. 체험 만료·임시 원문 삭제의 백업 처리와 공급자 보관 조건은 별도 논의다. 다음은 기록 내보내기 범위다.

## 노트 개별 다운로드 합의

사용자가 필요한 노트를 하나씩 선택해 개별 다운로드하도록 명시해 DEC-022로 기록했다. 현재 요구사항은 PRD F-12·8절, 이유는 DECISIONS의 작은 결정 DEC-022를 따른다. AI 참고 기록의 저장·맥락 선택 방식은 기존 DEC-008/012를 유지하며 이번 결정은 사용자 파일 다운로드 범위만 정한다. 다음 정책 논의는 중단 학습 세션의 재개 기한이다.

## AI 컨텍스트 선택에 대한 사용자 제안

2026-10-21 사용자는 다양한 주제를 이야기하기 위해 최근에 하지 않은 주제·최근에 하지 않은 표현·지난번 어려웠던 표현을 넣고 나머지는 무작위로 보충하는 방식을 제안했다. 구체 규칙은 논의 중이며 새 Accepted 결정으로 기록하지 않는다. 기존 DEC-008의 앱 저장 이력에서 일부만 선택해 맥락으로 전달하는 범위 안에서 검토한다.

제안하는 해석:

- 주제·표현의 최근 사용 이력을 보고 최근에 다루지 않은 후보를 선택한다. 이력이 없는 첫 학습도 후보에서 선택할 수 있다.
- 지난 학습에서 어려움을 보인 표현은 복습 대상으로 구분한다. 최근에 나왔더라도 복습할 수 있어야 하므로 새 표현의 반복 회피 규칙을 일괄 적용하지 않는다.
- 나머지는 주제·표현 후보에서 무작위로 보충한다. 사용하지 않은 후보를 고르는 기준과 중복 회피를 무작위 보충에도 적용한다. 과거 기록 전체를 임의로 붙이는 방식이 아니다.
- 현재 대화와 재개 시 확인된 진행 상태는 기존 합의대로 유지한다. 무작위 학습 소재와 진행 상태를 구분한다.

대안과 영향: 전체 무작위는 선택 규칙이 간단하지만 최근 내용 반복과 복습 누락이 생길 수 있다. 최근 회피·어려운 표현 복습·무작위 보충 조합은 다양성과 복습을 함께 다루지만 최근 사용 시점·어려움의 근거·후보 중복을 관리하고 선택 품질을 검증해야 한다. 이 영향은 설계 판단이며 효과를 실측한 결과가 아니다. 분량 상한을 유지하고 선택 규칙 자체에 별도 AI 호출을 필수로 추가하지 않는다. 구체 선택 기술·비용은 미확정이다.

남은 합의: 최근의 기준(예: 최근 3회 학습 또는 최근 7일), 어려움 판정과 해소 조건, 항목별 개수·비중·컨텍스트 분량 상한, 후보 부족 시 처리와 무작위 재현/평가 방법. 최근 3회는 학습 빈도와 무관하게 직전 학습의 반복을 피하는 초기안이며 최근 7일은 달력 기준으로 단순하나 이용 빈도에 따라 제외 범위가 달라진다. 두 수치는 미승인 예시다. 이번 논의로 주제 선정의 기술·수치 또는 어려운 표현을 숙달한 것으로 간주하는 기준을 확정하지 않는다.

## 상황·질문 다양성 후속 합의

사용자는 최근 3회 기준이 좁다며 최대한 다양한 상황을 목표로 했다. 보관 중인 접근 가능한 이력 전체에서 미경험 상황을 우선하고 후보가 부족하면 오래된 상황을 다른 질문으로 재활용하는 안에 “그러자”라고 동의했다. 같은 주제라도 내용이 달라지면 허용하고, 이전 AI 학습에서 질문이 완전히 똑같이 나왔던 불편을 추가로 제시했다. DEC-023으로 상황·목표·질문 내용의 다양성과 불필요한 동일 질문 반복 회피를 확정했다. 기존 제안의 최근 3회·7일 수치는 채택하지 않는다. 현재 기준은 PRD 4.1·5·7·9.2절, 이유·대안·한계는 ADR-023이다. 실제 유사 질문 판정 기술·후보 표현·컨텍스트 분량 및 AI 평가 결과는 미정이다. 위 제안 절의 ‘논의 중’과 최근 기준 예시는 후속 합의 이전 상태다.

## 다음 논의 제안: 중단 학습 세션의 재개 기한

상태: 당시 미채택 제안. 현재 재개·자동 종료 정책은 후속 DEC-024를 따른다. DEC-010/012/013과 PRD 6절은 중단을 명시적 종료와 구분하고 마지막 저장 성공 턴·진행 상태에서 재개하도록 한다. 종료된 세션의 임시 전체 원문 24시간 상한을 중단 세션에 그대로 적용하는 합의는 아직 없다. 아래의 기한은 음성 연결 유지 시간이 아니라 저장된 학습 대화를 다시 이어갈 수 있는 기간이다.

| 대안 | 사용자 경험 | 데이터·비용·운영 영향 |
| --- | --- | --- |
| 중단 후 24시간 | 다음 날 이어가기까지만 보장 | 중단 데이터 노출·저장 기간이 짧지만 주말 등 공백 뒤 대화를 잃을 수 있음 |
| 중단 후 7일 · 추천 | 며칠 뒤 재개할 여유 | 기간 동안 전체 대화 글·진행 상태를 저장하고 만료 정리 작업·실패 검증이 필요 |
| 중단 후 30일 | 오래 쉬고 돌아와도 이어가기 쉬움 | 전체 원문·진행 상태의 임시 보관 기간과 저장·백업·접근 통제 부담이 커짐 |

추천안의 추가 동의가 필요한 처리: 마지막으로 중단된 시점부터 7일 이내에는 확인된 마지막 저장 턴과 해당 학습 상태에서 재개한다. 7일이 지나면 해당 중단 세션은 재개 불가로 안내하고 임시 대화 원문·진행 상태를 삭제한다. 이를 명시적 종료나 노트 생성 성공으로 표시하지 않으며, 미완성 세션의 노트가 없을 수 있음을 사전에 안내한다. 저장된 턴/상태의 범위와 재개 기한을 알리고 만료 전 선택지는 구현 시 정한다. 종료 세션의 24시간 규칙과 회원 탈퇴 기한은 그대로다. 7일은 사용자 사용 간격·저장 비용의 실측값이 아닌 초기 정책 제안이다.

남은 상세: 재개 기산점과 중단 반복/실제 재개 시 갱신, 만료 직전의 동시 재개/삭제, 무료 체험 보관 만료와 백업 처리, 만료 알림 여부. 정책 동의 전 PRD·DEC에 채택된 것으로 기록하지 않는다.

## 중단 세션 재개 기간별 텍스트 저장비 예시

확인일: 2026-10-21. 다음은 계산을 위한 가정이며 실제 사용자 규모·전사문 크기 측정이나 공급자 채택이 아니다. 매일 새 중단 세션 1,000개가 생기고 한 건의 복원용 대화 글·진행 상태가 100 kB이며 DB 인덱스·여유 공간을 포함해 3배인 300 kB를 차지한다고 가정한다. 매일 같은 유입이 지속되어 보관 기한에 도달한 정상 상태이며 완료·재개로 조기 삭제되는 비율은 0으로 잡는다. 원본 음성은 저장하지 않는다. 기존 비용 추정서의 100 kB/세션은 **지속 학습 기록**의 가정이므로 여기의 중단 전사문 100 kB는 별도의 미측정 예시다.

| 재개 기한 | 동시에 남아 있는 중단 세션 | 가정한 DB 용량 | 1일 대비 추가 용량 |
| --- | ---: | ---: | ---: |
| 24시간 | 1,000개 | 0.3 GB | — |
| 7일 | 7,000개 | 2.1 GB | 1.8 GB |
| 30일 | 30,000개 | 9 GB | 8.7 GB |

[Supabase 공식 가격표](https://supabase.com/pricing)는 Pro 프로젝트당 8 GB 포함 후 초과 디스크 $0.125/GB, 기본료 월 $25와 매일 백업 7일 보관을 표시한다. 이미 포함 용량을 모두 사용해 추가분 전부가 초과 과금된다면 1일→7일의 순수 DB 추가분은 월 약 $0.225, 1일→30일은 약 $1.09다. 포함 용량이 남으면 같은 가정에서 추가 청구가 0일 수 있다. [Neon 공식 가격표](https://neon.com/pricing)의 Launch 저장 $0.35/GB·월을 단순 적용하면 각각 약 $0.63·$3.05/월이다. 2026-10-21 확인 가격이며 실제 청구 단위·최소 할당·백업/변경 이력·컴퓨트는 별도다.

이 수치는 저장 공간의 **증가분**만 계산한다. 사용자 수·중단 비율·세션 길이·전사문 크기가 10배면 용량 비용도 대략 10배가 될 수 있다. 실행 중 연결·복원 요청·백업·실패 정리·기한 검증·데이터 접근 통제의 비용/운영 부담은 계산하지 않았다. 기한이 길수록 복원 대상을 더 오래 보관해야 하는 사용자 데이터 영향도 있다. 실제 DB·백업 선택 전에 중단 세션의 건수·바이트·조기 재개/종료 비율을 측정해 다시 산정한다. 이 예시로 7일 정책을 채택하거나 백업 삭제 적합성을 검증한 것은 아니다.

## 중단 후 1일 자동 종료·노트 생성 제안

상태: 제안 당시 논의 중이었으며, 외부 환경 중단에 한정한 예외로 후속 DEC-024에 채택됐다. 사용자는 오래 뒤에는 이전 대화가 기억나지 않아 새 대화를 시작하는 편이 좋다며 “세션종료 1일로 제한을 두고 종료시에 자동으로 내용 정리”하자고 제안했다. 위 7일 재개 추천은 이 사용자 제안으로 재검토한다. 기존 PRD 원칙 3.4·6절과 DEC-003은 명시적 종료 전 임의 종료 금지 및 중단≠종료를 채택했으므로, 자동 종료는 해당 범위의 변경이다. 사용자와 자동 종료의 정확한 기준·노트 실패 동작까지 합의한 뒤에만 PRD·DEC/ADR·설계·작업 기준을 변경한다.

| 대안 | 사용자 경험 | 비용·일정·데이터·운영 영향 |
| --- | --- | --- |
| 7일 재개, 자동 종료 없음 · 이전 제안 | 며칠 뒤 이어갈 수 있으나 맥락을 잊고 돌아올 수 있음 | 중단 원문·상태를 오래 보관, 자동 노트 호출 없음, 기간 만료 시 노트 손실 가능 |
| 중단 후 24시간에 재개만 만료, 자동 노트 없음 | 짧은 보관이나 미완성 대화는 학습 결과로 남지 않음 | 노트 비용은 줄지만 사용자 발화·교정을 잃을 수 있음 |
| 중단 후 24시간에 자동 종료·정리 · 사용자 제안 | 다음에는 새 대화를 시작하고 이전 대화의 노트를 볼 수 있음 | 중단 데이터 보관은 짧아지지만 버려진 세션에도 AI 정리 호출·실패 재시도와 일괄 종료 작업이 필요 |

구체 승인 후보: 연결 중단이 확인된 시점부터 24시간 동안 재개할 수 있고, 그 전에 재개하면 중단 타이머를 취소한다. 24시간이 지나면 앱이 자동 종료 상태로 전환하여 마지막 저장 성공 턴·확인된 재생 범위·교정/재시도 기록만 사용해 요약·학습 항목·근거를 만든다. 사용자가 명시적으로 종료했을 때와 같은 근거 검증·저장 성공 확인을 적용한다. 미확인 응답과 미재생 발화는 제외한다. 확인된 사용자 발화가 하나도 없으면 꾸며낸 요약을 생성하지 않고 빈 세션으로 정리한다. 자동 종료 이후 늦게 도착한 응답·재개 요청은 해당 대화를 되살리지 않으며 다음 학습은 새 세션으로 시작한다. 종료 후 노트 생성 실패 시 기존 DEC-012의 종료 시점부터 최대 24시간 재시도용 원문 보관과 기한 만료 삭제를 적용한다. 즉 중단부터 최장 약 48시간 원문이 남을 수 있다. 성공 시 즉시 삭제한다.

남은 승인/구현 상세: 중단을 감지하는 신호와 시간의 기산, 24시간 경계의 재개/종료 경쟁 처리, 저장되지 않은 마지막 턴 손실 안내, 노트 생성에 필요한 최소 기록, 자동 종료·정리 작업의 실행 기술·재시도/중복/실패 알림, 체험 사용량·학습 기록 30일 기산점, 공급자 처리·백업 정합성. 자동 정리에 따른 AI 비용은 중단 빈도와 실제 요약 단가를 측정하기 전까지 추정할 수 없다. 기존 3만 원은 로컬 후보 비교 예산이며 자동 운영 호출 비용 승인으로 해석하지 않는다.

## 중단 후 자동 종료의 후속 합의

사용자는 명시적 종료가 기본이며 외부 환경으로 종료하지 못한 경우에 한정해 24시간 자동 종료·노트 생성으로 확장한다고 명시했다. DEC-024/ADR-024에 채택했고 현재 정책은 PRD 3·6·8절을 따른다. 위 7일 재개 추천과 24시간 자동 종료 제안의 ‘미채택’ 표현은 승인 전 당시 상태다. 24시간 내 재개가 확정되면 자동 종료 예약을 취소한다. 종료 후 노트/원문 정리의 별도 24시간 상한과 미저장 기록 손실 가능성은 유지한다. 실제 자동 종료 작업 방향은 후속 DEC-028의 지속 작업 목록·정시 실행이며 플랫폼·실패 처리·중단 빈도에 따른 AI 비용은 미정이다. B-00 메모리 프로토타입 완료를 이 정책 구현으로 간주하지 않는다.

2026-10-23 후속: 인증 토큰·세션 저장은 DEC-035의 같은 지속 PostgreSQL DB로 확정했다. 실제 부하/운영 필요를 확인해 분리를 재논의하며 인증 상세·메일 서비스·구현 검증은 남는다.

2026-10-23 후속: DEC-040으로 로그 본인 접근·발화 평가 사본 미저장·장기 저장 실패에도 대화 지속·한국 시간 종료일 노트·음성 종료 확인을 합의했다. 버퍼 상한/미저장 기록 유지·포기와 실제 검증은 남는다. 최신 범위는 최소 MVP 점검표 후속 절을 따른다.
