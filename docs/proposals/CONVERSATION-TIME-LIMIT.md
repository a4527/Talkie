# 한 대화 15분 종료 경계 검토안

작성일: 2026-10-30. 상태: 철회된 검토안. DEC-060이 15분 강제 종료를 토큰 사용량 한도로 대체했고, DEC-062가 이후 연결 허용 시간 이용권을 채택했다. 아래 고정 15분 종료의 다섯 항목은 당시 미승인 제안으로만 보존하며 현재 구현 기준이 아니다.

기준은 [ADR-059](../adr/059-SHORT-CONVERSATIONS-AND-SESSION-LIMIT.md)와 [사용자 흐름](../design/USER-FLOWS.md#4-종료와-복습)이다. 평균 10분은 산정 가정이며, 중단 후 24시간 재개 기한·종료 후 저장/노트 기한은 별개로 유지한다.

## 합의할 다섯 항목

| 항목 | 추천안 | 대안과 영향 |
| --- | --- | --- |
| 1. 시간 집계 | 연결 준비가 끝나 대화 가능한 시점부터 연결 중 경과 시간을 누적한다. 사용자 생각 시간·침묵·AI 응답 대기를 포함하며, 외부 중단 중에는 멈추고 재개 시 남은 시간을 이어 쓴다. | 최초 시작부터 벽시계 15분은 단순하지만 긴 중단 뒤 24시간 내 재개할 기회를 사실상 없앤다. 실제 발화 시간만 합산하면 공정해 보이지만 감지 오차가 있고 긴 연결과 비용을 제한하기 어렵다. 추천안도 공급자 대기 시간이 연습 시간을 줄이는 절충이 있다. |
| 2. 사전 안내 | 화면에 남은 시간을 표시하고, 1분 남았을 때 화면으로 한 번 안내한다. AI에도 남은 시간을 전달해 새 주제보다 마무리를 유도하되 종료 집행은 앱이 맡는다. | 음성 안내는 눈을 보지 않아도 알 수 있지만 사용자 발화를 방해하고 호출/재생이 늘 수 있다. 안내 없이 종료하면 구현은 작지만 갑작스러운 중단이 된다. AI의 마무리 발화를 보장된 동작으로 간주하지 않는다. |
| 3. 한도 순간 발화 | 15분 도달 시 새 입력·생성·재생을 중단하고 종료한다. 추가 대화 유예는 두지 않는다. 이미 확인된 완결 단위만 기존 저장 절차로 넘기고, 경계에서 미완결인 발화는 학습 근거로 쓰지 않는다. | 현재 발화나 재시도를 끝내도록 기다리면 자연스럽지만 최대 15분을 넘길 수 있고 종료 지연 상한을 새로 정해야 한다. 즉시 종료는 마지막 문장/교정이 끊기거나 미완결 내용이 노트에 빠질 수 있다. 미재생 응답·미확인 재시도는 성공으로 기록하지 않는다. |
| 4. 종료 뒤 경험 | ‘15분 대화를 마쳤어요’와 기존 저장/노트 상태를 표시하고 사용자가 새 대화를 시작하도록 한다. 자동으로 새 대화를 열지 않는다. 정리 중에도 기존 진행 대화 하나 제약과 저장 경계를 만족하면 새 대화를 시작할 수 있게 한다. | 노트 완료까지 새 시작을 막으면 상태는 단순하지만 실패/재시도 동안 연습을 못 한다. 새 대화에는 준비된 유효 노트만 사용하므로 직전 노트가 아직 없을 수 있다. 시간 종료 뒤 별도 음성 복습으로 한도를 늘리지 않으며 기존 종료 복습 흐름과의 세부 조정은 승인 후 기준 문서에 명시한다. |
| 5. 재접속·경쟁 | 남은 시간은 서버가 관리하고 새로고침·탭/기기 변경·재연결로 초기화하지 않는다. 한도 종료와 수동 종료가 겹쳐도 종료는 한 번만 확정한다. 늦은 응답은 기존 종료 상태를 되돌리거나 노트 근거를 추가하지 못한다. | 브라우저 타이머만 쓰면 간단하지만 새로고침/백그라운드 지연으로 우회된다. 서버 집계에는 연결 생존 확인과 재시작 복구가 필요하다. 갑작스러운 단절을 서버가 인지하기 전까지의 시간 오차와 생존 확인 간격은 구현 설계에서 명시하고 검증해야 한다. |

## 구현 전후 확인 범위

승인 후 제품 동작은 PRD에 먼저 반영하고, 서버 시간 집계·중단 감지·동시 종료의 구현 계약을 관련 설계에 구체화한다. 현재 데이터 구조로 누적 시간을 보존할 수 있는지 확인한 뒤 필요한 이관과 재시작 복구를 설계한다. 이 제안은 DB 필드·하트비트 간격·단절 허용 오차를 확정하지 않는다.

검증은 가짜 시계/공급자로 시작·14분 안내·15분 경계, 중단/재개 누적, 새로고침과 서버 재시작, 수동 종료 경쟁, 경계 미완결/미재생 제외와 늦은 응답 차단을 확인하는 방향이다. 새 대화와 이전 노트 정리의 격리도 확인한다. 사용자가 보류한 추가 E2E와 실제 공급자 호출은 이번 문서 작성에 포함하지 않았다.

비용은 연결 중 15분을 관리해도 반복 새 시작·별도 노트 요청 때문에 일일 상한을 보장하지 않는다. 일정에는 서버 시간 보존·연결 상태 동기화·종료 경쟁 처리가 추가된다. 새 개인 정보나 별도 학습 맥락 저장은 제안하지 않지만 시간 집계 데이터가 필요하므로 보관·삭제 경계를 설계에서 확인한다. 외부 자료나 실측에 근거한 성능/비용 주장은 없으며 위 영향은 구현 전 예상이다.
