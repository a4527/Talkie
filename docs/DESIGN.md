# Talkie 현재 설계

갱신일: 2026-10-29. 전체 구조·구성 요소의 경계·핵심 데이터 흐름과 기술적 가정의 진입점이다. API·DB·인증·저장·음성·로컬 운영의 상세 계약은 아래 문서로 연결한다.

## 현재 구현과 구조의 확정 범위

첫 로컬 구현은 Next.js + TypeScript 한 프로젝트이며 코드·설정·의존성·산출물은 `app/`에 모은다(DEC-015). 반응형 웹·계정별 학습 기록·서비스 부담 AI·서버 비밀값 관리 방향을 유지한다. 화면·학습 상태·공급자 경계를 구분하되 특정 모듈형 모놀리스·헥사고날·MSA 전체 구조를 확정한 것은 아니다. 별도 서버·운영 배포·최종 공급자/모델/연결 경로는 미채택이다.

| 흐름 | 현재 구현 | 남은 범위 |
| --- | --- | --- |
| `/` B-00 | 가짜 AI 텍스트 대화→교정→재시도→종료→노트/다운로드. 브라우저 메모리에서 실행 | 서버 저장·실제 AI/음성 없이 새로고침하면 기록 소실 |
| `/account`, `/learn` | 합성 이메일 링크·로그인/탈퇴 재확인, 계정별 두 DB 저장·재개·가짜 노트 | 실제 메일·Google 로그인·실제 AI 선별·유료 기록 전환·운영 검증 |
| `/voice` | 로컬 로그인 후 Gemini Live 직접 연결. 메모리 시험과 계정별 전사/교정 저장·재개·근거 노트 연결 | 실제 공급자의 구조화 교정 품질·전체 AI 노트 선별·미재생 맥락 동기화 검증 |

이 표는 구현 경계의 요약이며 전체 수용 기준 통과를 뜻하지 않는다. 실행과 검증 명령은 [README](../README.md), 상세 근거는 [PROGRESS의 연결 기록](PROGRESS.md)을 따른다.

## 구성 요소와 데이터 흐름

| 구성 요소 | 책임·경계 | 코드 진입점 |
| --- | --- | --- |
| 화면·브라우저 장치 | 입력·상태·재생·다운로드와 로컬 연결 수명 관리 | `app/src/app/`, `app/src/components/` |
| 학습 상태·가짜 공급자·노트 | 요청 ID·확인 턴·교정/재시도·근거 검증. 텍스트 공급자 계약은 음성 스트리밍 계약을 대체하지 않음 | `app/src/learning/` |
| 서버 경계 | 인증·소유자·입력 검증, 저장·기한 작업·단기 음성 자격 발급. DB 접근은 server-only | `app/src/server/`, `app/src/app/api/` |
| 지속 기록·임시 원문 | 계정/노트/인증/작업과 전체 원문의 수명을 별도 PostgreSQL 인스턴스·볼륨으로 분리 | `app/src/server/db/` |
| 음성 포트·공급자 어댑터 | 공통 연결/전사/중단 사건으로 공급자 메시지를 변환하고 장치 처리와 분리 | `app/src/voice/` |
| 독립 평가 하니스 | 제품 앱과 별도인 공급자 비교·예산 장부·내용 없는 평가 기록 | [harness/voice-eval](../harness/voice-eval/README.md) |

승인된 학습 흐름은 접근 가능한 이력에서 짧은 맥락 선택 → AI의 진행/교정 판단 → 앱의 전달·재생 확인과 상태 기록 → 주기적 저장 → 종료 후 근거 검증·노트 저장 → 임시 원문 삭제다. AI의 교육 판단과 앱의 기록·중복·늦은 응답·소유권 통제를 구분한다. 소재 선택·이력 제공 범위는 [PRD 7·9.2절](PRD.md#7-주제와-표현-정책)을 따른다. 현재 텍스트 데모와 음성 저장 학습은 화면/공급자를 구분하고 같은 저장·재개 계약을 사용한다. 통합·검증 상태는 [PROGRESS](PROGRESS.md)를 따른다.

## 기술적 가정·제약과 변경 조건

보안·데이터 보호·예산 제약의 기준은 PRD 8·9.1·9.2·11절이다. 최소 구성부터 측정하며 캐시·고가용성·오토스케일링을 학습을 위한 필수 구성으로 추가하지 않는다. 구조를 바꾸려면 관측 근거 또는 요구 변화, 대안별 비용·일정·사용자 경험·데이터·운영 영향을 검토한다.

| 검증할 가정 | 검증 방법·재검토 조건 |
| --- | --- |
| 최소 구성이 초기 요구와 부하를 감당할 수 있다. | 정상 기준선과 단계별 부하 실험으로 확인한다. 사용자 지연·오류 또는 제약 위반이 나타나면 원인을 좁혀 구성 변경 검토 |
| 외부 AI 대기가 대화 지연의 주요 부분일 수 있다. | 사용자 지연·앱 처리·외부 호출 대기를 비교. 관측되지 않은 공급자 내부 시간을 추정치로 확정하지 않음 |
| 부하 증가 시 앱 자원이나 처리 대기가 지연에 영향을 줄 수 있다. | 동일 시나리오에서 부하를 변경해 지연·오류·자원·대기를 대조 |
| 제한된 맥락이 비용·지연을 줄이며 필요한 복습 정보를 유지할 수 있다. | 합성 이력 규모·맥락 크기를 달리해 지연·비용·정보 누락을 함께 평가 |

로컬 합성 검증·별도 DB 실험은 해당 worklog를 따르며 실제 운영 성능·성능 개선·전체 장애 대응 검증 완료를 뜻하지 않는다. 수치 목표·운영 후보의 결정 시점은 PRD 11절을 따른다.


## 상세 설계와 변경 관리

설계 변경은 해당 상세 문서의 계약을 먼저 갱신하고 이 진입점의 요약·연결을 맞춘다. 승인된 미구현 설계·현재 구현·미정 사항을 구분한다. 제품 정책 변경은 PRD, 중요한 선택의 변경·대체는 [DECISIONS의 기록·변경 규칙](DECISIONS.md#기록변경-규칙)을 따른다. 기존 ADR의 결정 당시 이유와 제안서의 과거 후보는 현재 구현에 맞춰 다시 쓰지 않는다.
