# Talkie 트러블슈팅

## 기록 기준

다음에 같은 문제를 더 빨리 해결하는 데 도움이 되는 사례를 남긴다. 아래 중 하나라도 해당하면 기록한다.

| 대상 | 판단 기준 |
| --- | --- |
| 원인 규명에 시간이 든 문제 | 여러 가설을 확인하거나 코드·로그·환경을 추적한 경우 |
| 재발 가능한 문제 | 재시작·배포·환경 변경·동시 요청 등에서 다시 발생할 수 있는 경우 |
| 설계·운영을 바꾼 문제 | 저장 구조·설정·권한·배포·복구 절차를 수정하게 된 경우 |
| 영향이 큰 문제 | 데이터 유실·잘못된 삭제·접근 권한·서비스 중단과 관련된 경우. 금방 해결해도 기록 |

단순 오타, 바로 해결된 문법 오류, 반복 가치 없는 일회성 실패는 제외한다. 같은 문제의 재발은 기존 사례에 발생일·달라진 조건·결과를 보충한다. 시간만으로 기계적으로 선별하지 않는다.

## 작성 방법

- 사례는 이 문서에 날짜와 제목을 붙여 간략히 기록한다. 날짜별 worklog에는 사례 링크와 그날의 작업 결과만 남긴다.
- 원인을 찾는 데 사용한 주요 가설·확인 근거를 포함하되 모든 시도와 로그를 나열하지 않는다. 확인된 사실·추정·미확인을 구분하며 미해결이면 원인 미확인과 다음 확인 항목을 적는다.
- 발생 환경을 로컬 개발·시험 중 의도적 장애·실제 운영으로 구분한다. 검증 조건과 한계를 남기고 비밀값·이메일·대화 원문은 복사하지 않는다.
- 설계나 결정이 바뀌면 해당 기준 문서를 갱신하고 사례에서는 링크로 연결한다.

최소 양식:

```markdown
### YYYY-MM-DD · 문제 제목

- 증상·발생 조건: 환경과 관찰한 현상.
- 원인과 근거: 주요 가설을 확인하거나 배제한 증거. 추정이면 명시.
- 해결: 적용한 수정 또는 임시 조치.
- 재검증: 확인 방법·결과·한계.
- 재발 방지·남은 과제: 예방 조치와 미해결 사항.
```

## 사례

### 2026-10-24 · 원문 미저장과 자동 삭제를 구분할 수 없음

- 증상·발생 조건: 로컬 데모에서 사용자가 원문 DB가 비어 있다고 보고했고, `erase_at`을 삭제 완료 시각으로 해석했다. 실제 운영 장애가 아니다.
- 원인과 근거: 코드 확인 결과 `erase_at`은 삭제 기한이며 노트 저장 후 원문 행과 버전은 삭제된다. 생성·삭제 완료 이력이 없어 과거 미저장과 정상 삭제를 구분할 수 없었다. 해당 과거 원문이 실제 저장·삭제됐는지는 미확인이다.
- 해결: 기한을 `transcript_delete_deadline_at`으로 바꾸고 원문 DB에 내용 없는 생성·첫 저장·삭제 완료 시각/사유 이력을 추가했다. 계약은 [design](DESIGN.md)의 원문 수명 확인, 결정은 [DEC-048](DECISIONS.md#dec-048)을 따른다.
- 재검증: 별도 시험 DB에서 원문 삭제 후 이력 보존과 이력 기록 실패 시 삭제 취소·재시도를 확인했다. 결과와 적용 환경은 [당일 검증 기록](worklogs/2026-10-24.md#검증과-적용)을 따른다.
- 재발 방지·남은 과제: 기한과 완료 시각을 구분하고 첫 저장 여부를 남긴다. 변경 전 삭제 이력은 복원하지 않으며 SQL 삭제 기록은 물리 소거 증거가 아니다.
