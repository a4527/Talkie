# Talkie 트러블슈팅

## 기록 기준

다음에 같은 문제를 더 빨리 해결하는 데 도움이 되는 사례를 남긴다. 아래 중 하나라도 해당하면 기록한다.

| 대상 | 판단 기준 |
| --- | --- |
| 원인 규명에 시간이 든 문제 | 여러 가설을 확인하거나 코드·로그·환경을 추적한 경우 |
| 재발 가능한 문제 | 재시작·배포·환경 변경·동시 요청 등에서 다시 발생할 수 있는 경우 |
| 설계·운영을 바꾼 문제 | 저장 구조·설정·권한·배포·복구 절차를 수정하게 된 경우 |
| 영향이 큰 문제 | 데이터 유실·잘못된 삭제·접근 권한·서비스 중단과 관련된 경우. 금방 해결해도 기록 |

단순 오타, 바로 해결된 문법 오류, 반복 가치 없는 일회성 실패는 제외한다. 같은 문제의 재발은 기존 사례에 발생일·달라진 조건·결과를 보충한다. 시간만으로 기계적으로 선별하지 않는다.

## 작성 방법

- 사례는 이 문서에 날짜와 제목을 붙여 간략히 기록한다. 날짜별 worklog에는 사례 링크와 그날의 작업 결과만 남긴다.
- 원인을 찾는 데 사용한 주요 가설·확인 근거를 포함하되 모든 시도와 로그를 나열하지 않는다. 확인된 사실·추정·미확인을 구분하며 미해결이면 원인 미확인과 다음 확인 항목을 적는다.
- 발생 환경을 로컬 개발·시험 중 의도적 장애·실제 운영으로 구분한다. 검증 조건과 한계를 남기고 비밀값·이메일·대화 원문은 복사하지 않는다.
- 설계나 결정이 바뀌면 해당 기준 문서를 갱신하고 사례에서는 링크로 연결한다.

최소 양식:

```markdown
### YYYY-MM-DD · 문제 제목

- 증상·발생 조건: 환경과 관찰한 현상.
- 원인과 근거: 주요 가설을 확인하거나 배제한 증거. 추정이면 명시.
- 해결: 적용한 수정 또는 임시 조치.
- 재검증: 확인 방법·결과·한계.
- 재발 방지·남은 과제: 예방 조치와 미해결 사항.
```

## 사례

### 2026-10-24 · 원문 미저장과 자동 삭제를 구분할 수 없음

- 증상·발생 조건: 로컬 데모에서 사용자가 원문 DB가 비어 있다고 보고했고, `erase_at`을 삭제 완료 시각으로 해석했다. 실제 운영 장애가 아니다.
- 원인과 근거: 코드 확인 결과 `erase_at`은 삭제 기한이며 노트 저장 후 원문 행과 버전은 삭제된다. 생성·삭제 완료 이력이 없어 과거 미저장과 정상 삭제를 구분할 수 없었다. 해당 과거 원문이 실제 저장·삭제됐는지는 미확인이다.
- 해결: 기한을 `transcript_delete_deadline_at`으로 바꾸고 원문 DB에 내용 없는 생성·첫 저장·삭제 완료 시각/사유 이력을 추가했다. 계약은 [design](DESIGN.md)의 원문 수명 확인, 결정은 [DEC-048](DECISIONS.md#dec-048)을 따른다.
- 재검증: 별도 시험 DB에서 원문 삭제 후 이력 보존과 이력 기록 실패 시 삭제 취소·재시도를 확인했다. 결과와 적용 환경은 [당일 검증 기록](worklogs/2026-10-24.md#검증과-적용)을 따른다.
- 재발 방지·남은 과제: 기한과 완료 시각을 구분하고 첫 저장 여부를 남긴다. 변경 전 삭제 이력은 복원하지 않으며 SQL 삭제 기록은 물리 소거 증거가 아니다.

### 2026-10-29 · 합성 음성 시험은 연결되지만 응답하지 않음

- 증상·발생 조건: 로컬 비공개 시험의 고정 `espeak-ng` 음성을 전송했으나 전사·음성 응답이 없었다. 실제 운영 장애나 사용자 마이크 장애로 판정하지 않는다.
- 원인과 근거: 텍스트 입력은 정상 응답했으며 같은 PCM은 교정 도구 유무·앞뒤 무음 추가와 관계없이 자동 발화 감지에서 처리되지 않았다. 자동 감지를 끄고 시작/끝을 명시하자 전사와 음성 응답을 받았다. 이 합성 입력의 자동 감지 누락을 확인했으며 감지기 내부 판단 이유는 미확인이다. 장치를 사용하지 않으므로 OS 볼륨 믹서는 이 시험 경로에 관여하지 않는다.
- 해결: 합성 시험에서만 토큰 제약/연결 설정을 동일하게 바꾸고 명시적 발화 신호를 사용한다. 앱의 실제 마이크 자동 감지 설정은 유지한다. 시험 경계는 [음성 설계](design/VOICE.md#학습저장-통합과-실험-통제)를 따른다.
- 재검증·남은 과제: [대조 시험과 재검증](worklogs/2026-10-29.md#합성-음성-실패-원인-조사와-수정)에 조건/결과를 기록했다. 이 조치는 실제 마이크/VAD 품질의 검증이 아니며 전체 교정/재시도 품질을 보장하지 않는다.

### 2026-10-29 · 도구만 완료된 단계가 교정과 실제 답변의 연결을 끊음

- 증상·발생 조건: 실제 Gemini 합성 시험에서 학습 도구 뒤에 음성/전사 없이 `turnComplete`가 도착하고, 그 뒤에 실제 답변이 이어졌다. 로컬 앱/시험 어댑터가 조기 답변 완료를 내보내 교정 근거가 실제 출력과 연결되지 않았다.
- 원인과 근거: 도구 수신만으로 만든 출력 ID를 출력이 있는 턴으로 취급하고 완료 때 입력/출력 ID를 비웠다. 해당 순서를 회귀 테스트로 재현해 기존 구현의 실패를 확인했다. 이는 일반적인 연결 실패나 근거 문장의 언어 판단 문제가 아니다.
- 해결: 실제 출력이 시작됐는지 구분해 도구만 완료된 단계는 대기하고, 뒤따르는 실제 답변에 근거를 연결한다. 중간에 중단되면 대기 근거를 버린다. 원문 일치·재생 완료·교정 표현 근거 검사는 유지한다.
- 재검증·남은 과제: 자동 회귀 테스트와 PC/모바일 가짜 공급자 시험을 통과했고 실제 공급자의 교정 기록도 확인했다([검증 조건](worklogs/2026-10-29.md#합성-음성-실패-원인-조사와-수정)). 실제 재시도 판정 도구 누락은 별도 미해결이며 전체 AI 품질 완료로 보지 않는다.

- 재시도 도구 누락 후속: 기존 프롬프트는 매 발화 호출 지시만 있고 재시도 판정/상태 전환의 구체 조건이 부족했다. 이를 명시한 뒤 고정 합성 1회에서 성공 기록을 확인했다([후속 검증](worklogs/2026-10-29.md#재시도-판정-프롬프트-보완)). 모든 발화에서 준수하거나 누락 원인이 프롬프트 하나뿐이라고 단정하지 않는다.

### 2026-11-18 · 저장 중 DB 연결 종료로 Node 프로세스 종료

- 증상·발생 조건: 격리 DB에서 원문 트랜잭션이 행 잠금을 기다리도록 한 뒤 사용 중인 지속 DB 연결을 종료하자 로컬 Node 프로세스가 종료됐다.
- 원인과 근거: 풀의 오류 수신은 유휴 연결을 처리한다. 요청이 사용 중인 `pg` 연결이 쿼리 사이에 끊기면 연결 객체의 오류 이벤트에 수신기가 없어 프로세스까지 종료됐다.
- 해결: 두 풀에서 연결 객체의 오류 이벤트도 처리한다. 실패한 요청은 기존 오류 경로로 돌아가고 드라이버 오류 본문은 기록하지 않는다. [DB 연결 처리](../app/src/server/db/index.ts)
- 재검증: 같은 장애로 최초 저장만 실패하고, 같은 순번·본문을 같은 프로세스에서 다시 저장했다. 두 풀의 사용 중 연결 종료를 서버 시험에 추가했다. [검증 기록](worklogs/2026-11-18.md#격리-db-복구와-시간-경계)

### 2026-11-19 · 브라우저 시험이 실행마다 번갈아 전부 실패

- 증상·발생 조건: 로컬 개발. 코딩 에이전트가 `npm run test:e2e`를 실행하면 한 번은 대부분의 사례가 약 1초 만에 실패(`ERR_EMPTY_RESPONSE`, 화면 요소 없음)하고 다음 실행은 통과하는 일이 반복됐다. 처음에는 dev 서버 첫 컴파일 지연으로 추정했다.
- 원인과 근거: 실패 회차의 webServer 출력에 Next 16.4.2의 보안 권고와 함께 명령을 멈췄다는 안내가 있었다. Next는 `experimental.agentUpgrade`(기본 `security`)가 켜진 상태에서 에이전트 실행을 감지하면 첫 `next dev`를 멈추고 `.next/cache`에 재시도 영수증을 남긴다. 다음 실행은 영수증으로 계속되고, 그 다음 실행은 영수증이 소모돼 다시 멈춰 결과가 번갈아 나왔다. 설치된 `node_modules/next/dist/lib/upgrade/nudge.js`와 [공식 설정 문서](../app/node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/agentUpgrade.md)로 확인했다. 권고 2건(GHSA-mfr8-8qww-v76h, GHSA-vc7v-qv4w-wrv8, moderate)은 `'use cache'`·`unstable_cache` 사용 시에만 해당하며 이 앱은 두 기능을 쓰지 않는다.
- 해결: 사용자 선택에 따라 Next를 16.4.6 패치 버전으로 올렸다. 알림만 끄는 `agentUpgrade: false`는 이후 보안 권고도 감추므로 택하지 않았다.
- 재검증: `npm audit` 0건, 전체 브라우저 시험 3회 연속 32개 통과·4개 skip. [검증 기록](worklogs/2026-11-19.md#next-패치-업그레이드와-브라우저-시험-안정화)
- 재발 방지·남은 과제: 새 보안 권고가 나오면 같은 증상이 다시 생긴다. 시험이 번갈아 실패하면 webServer 출력에서 업그레이드 안내부터 확인한다.
