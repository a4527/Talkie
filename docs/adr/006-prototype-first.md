# ADR-006 · DEC-006 · REA를 제외하고 첫 학습 흐름부터 구현

이 문서는 2026-10-20에 기존 결정 원문을 ADR로 옮긴 기록이다. 결정일·승인 근거·당시 비교 범위는 유지했다. 기존에 기록되지 않은 대안이나 실측 결과를 소급해 추가하지 않는다. 현재 구조는 [design.md](../../design.md), 상태와 대체 관계는 [결정 목록](../../DECISIONS.md)을 참고한다.

- 결정일: 2026-10-16
- 상태: Accepted
- 동의 근거: 사용자가 REA를 빼고 바이브 코딩으로 시작하는 변경 계획을 요청하고, 단계별 제안 후 `진행해줘`라고 명시함
- 배경: 기존 순서는 경쟁 서비스 조사와 실행 대상 확보가 구현보다 앞서 있었다. 사용자는 빠른 기능 구현과 클라우드 엔지니어링 역량을 보여주는 프로젝트를 원한다.
- 검토한 대안과 장단점: 조사 후 구현은 비교 근거가 풍부하지만 시작이 늦어진다. 전체 기능을 한 번에 구현하면 빠르게 보일 수 있지만 실패 원인 분리와 검증이 어렵다. 작은 학습 흐름부터 구현하면 사용 가능한 결과와 측정 근거를 빠르게 얻지만 이후 통합·설계 보완이 필요하다.
- 결정: REA를 프로젝트 작업에서 제외한다. 경쟁 서비스 조사를 구현의 선행 조건에서 해제하고, 가짜 데이터·가짜 AI 응답으로 텍스트 학습 흐름을 먼저 연결한 뒤 실제 AI와 음성을 추가한다. 외부 자료를 참고할 때 관찰·추정·미확인 구분과 출처 기록은 유지한다.
- 채택 이유: 분석 대상 준비 없이 시작하면서 애플리케이션 동작과 외부 서비스 문제를 단계적으로 검증할 수 있다.
- 영향: 기존 R-01~R-03을 취소하고 로컬 프로토타입 작업을 추가한다. 초기 API 비용을 피하고 구현 피드백을 앞당긴다. 프로토타입의 임시 데이터는 계정별 영구 저장 요구사항을 대체하지 않는다. 구체적인 프레임워크·AI 공급자·데이터 정책은 별도 합의한다.
- 대체 관계: [DEC-004 / ADR-004](004-research-evidence.md)를 대체
