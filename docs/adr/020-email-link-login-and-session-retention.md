# ADR-020 · DEC-020 · 이메일 링크 로그인과 마지막 이용 후 30일 로그인 유지

- 결정일: 2026-10-21
- 상태: Accepted
- 동의 근거: 사용자가 “이메일 로그인 링크로하고 캐시?를 길게 가져가면 되지않을까 매번 열면 귀찮은까”라고 요청했다. 로그인 세션을 쿠키로 유지하고 마지막 이용 후 30일·이용 시 갱신·브라우저 재시작 후 유지·로그아웃/탈퇴 시 무효화·탈퇴 전 이메일 재확인안을 제시하자 “그러자”라고 동의했다.
- 배경·확정 제약: DEC-014의 공개 가입과 DEC-019의 회원 탈퇴를 지원하면서 반복적인 이메일 확인의 불편을 줄인다. 학습 세션·기록 보관 수명과 인증 세션 수명을 구분한다.
- 대안: 이메일 링크는 비밀번호 관리 기능을 줄이지만 메일 발송 설정·비용·전달 실패 대응과 메일함을 여는 절차가 필요하다. 이메일·비밀번호는 익숙하지만 이메일 확인·비밀번호 재설정·계정 보호의 구현·검증 범위를 늘린다. Google 로그인만 제공하면 해당 계정 사용자는 간편하지만 Google 계정이 필수이고 외부 로그인 설정이 필요하다. 매번 이메일 링크를 요구하면 반복 확인 부담이 있고, 정해진 날짜에 일괄 만료하는 방식은 꾸준히 이용해도 재로그인이 필요하다. 마지막 이용 기준 갱신은 이 불편을 줄이지만 장기간 로그인 상태가 지속될 수 있다.
- 결정: MVP 가입·로그인은 이메일 링크로 한다. 로그인 세션은 쿠키로 유지하며 마지막 인증된 이용 후 30일간 유효하고 인증된 이용 시 갱신한다. 브라우저를 닫았다 열어도 유지한다. 로그아웃은 해당 로그인 세션을, 탈퇴는 계정의 모든 로그인 세션을 무효화한다. 탈퇴 실행 전 이메일 링크로 다시 본인 확인한다. 현재 요구사항은 [PRD 8.1절](../../PRD.md#81-가입로그인과-로그인-유지)을 따른다.
- 이유: 사용자는 이메일 로그인을 선택하면서 매번 메일을 열어야 하는 불편을 줄이길 원했다. 마지막 이용 기준으로 로그인 유지 기간을 갱신하고 탈퇴는 별도 재확인하도록 합의했다.
- 영향·비용·일정·데이터·운영: 인증 서비스와 메일 발송 설정·전달 실패 대응, 세션 만료·갱신·무효화와 계정별 접근 차단의 구현·검증이 필요하다. 로그인 세션을 장기간 유지하므로 공유 기기에서 로그인 상태가 남을 수 있다. 이메일·인증 세션 데이터가 필요하며 구체 저장 방식·메일 서비스·요금은 아직 선정하거나 측정하지 않았다. 메일 지연 시 로그인·탈퇴 재확인이 지연될 수 있다.
- 검증 범위: 만료 전 인증된 이용의 기한 갱신, 30일 경계에서 만료 세션 갱신 거부, 브라우저 재시작 후 유지, 로그아웃한 세션의 재사용 거부, 탈퇴 전 재확인과 탈퇴 후 모든 세션의 접근 차단, 다른 계정 기록 접근 차단을 확인한다. 구현과 실측은 아직 없다.
- 남은 상세: 인증·메일 공급자, 세션 저장 기술, 로그인 링크 유효기간·일회성 처리·발송 제한, 탈퇴 재확인 유효 범위와 구체 갱신 방식은 실제 인증 연결 전에 확정한다. 중단 학습 세션 재개 기한·탈퇴 데이터 삭제 기한·백업 삭제는 별도 합의한다.
- 재검토 조건: 메일 전달·로그인 사용성 문제, 공급자의 세션 정책 제약, 장기 로그인 유지의 접근 통제 문제가 확인되면 대안과 영향을 논의한다.
- 대체 관계: DEC-014의 미정 가입·로그인 방식과 DEC-019의 탈퇴 본인 확인·로그인 세션 무효화 범위를 구체화한다. 기존 기록 보관·삭제 범위를 변경하지 않는다.

## 후속 합의

미정으로 남긴 탈퇴 데이터 삭제 일정·백업 기한은 DEC-021로 구체화했다. 이 시점에는 인증·메일·세션 기술과 로그인 링크 상세가 미정이었다. [ADR-021](021-scheduled-account-deletion-and-backup-deadlines.md)을 참고한다.

2026-10-21 로그인 링크 후속 합의: 10·15·30분 대안에서 10분은 미사용 링크의 유효 시간을 짧게 하지만 메일 지연·기기 전환 시 재발송이 늘 수 있고, 30분은 늦은 메일에 여유를 주지만 유출 링크의 유효 시간이 길어진다. 15분 추천을 받은 사용자가 “10분으로 진행하자”라고 명시했다. 로그인 링크는 발급 시점부터 10분, 첫 성공 확인에 한 번만 유효하다. 같은 목적의 새 링크를 요청하면 이전 미사용 링크를 무효화한다. 메일 미리보기·보안 검사가 토큰을 소모하지 않게 사용자 확인 동작에서 처리하며, 만료·사용·재발급으로 무효화된 링크에는 새 요청 경로를 제공한다. 탈퇴 전 재확인 링크도 일회성·미리보기 보호를 적용하되 링크 수명과 재확인 후 삭제 확정 허용 시간은 미정이다. 이는 30일 로그인 쿠키 수명과 별개다. 발송 제한 수치·메일/인증 기술·전달 지연의 실측은 남아 있으며 실패·중복·경계 시각을 B-01에서 검증한다.

## 후속 상태 연결 (2026-10-21)

인증 구현 책임은 후속 [ADR-026](026-app-managed-email-link-authentication.md)에서 앱 직접 링크·세션 관리로 정했다. 메일 전송 서비스·세션 저장 기술·발송 제한·탈퇴 재확인 수명은 미정이다.
