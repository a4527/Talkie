# ADR-026 · DEC-026 · 앱이 직접 관리하는 이메일 링크 인증

- 결정일: 2026-10-21
- 상태: Accepted
- 동의 근거: 관리형 인증(A), 앱의 인증 라이브러리·메일·세션 조합(B), 앱의 토큰·세션 직접 구현(C)을 비교한 뒤 사용자가 `1-c`를 선택했다.
- 배경: DEC-020은 로그인 링크 10분·일회성·최신 링크만 유효·미리보기 보호와 마지막 인증된 이용 후 30일 세션 갱신, 로그아웃·탈퇴 시 무효화를 요구한다. 구현 주체는 미정이었다.
- 대안: A는 구현과 보안 운영 부담이 작지만 공급자 기능·요금과 즉시 무효화 가능성을 확인해야 한다. B는 일부 통제를 앱에 두되 라이브러리 유지보수와 메일·세션 통합이 필요하다. C는 기존 규칙을 앱이 직접 통제하지만 구현·보안 검증·운영 부담이 가장 크다.
- 결정과 이유: C를 채택한다. 앱 서버가 링크의 발급·검증·무효화 및 로그인 세션의 기록·갱신·폐기를 직접 담당한다. 외부 메일 전송 서비스 이용까지 배제하는 결정은 아니다. 선택 이유 중 확인 가능한 것은 승인된 링크·세션 규칙을 앱 구현으로 통제한다는 점이며, 사용자의 추가 동기는 추정하지 않는다.
- 영향: 인증용 저장 구조와 비밀 토큰 보호, 동시 요청·재사용·만료·계정 탈퇴 경계 검증이 필요해 B-01과 D-02의 일정·유지보수 부담이 커진다. 메일 전달 비용·지연은 별도로 남는다. 10분 만료·30일 세션 유지라는 사용자 동작은 바뀌지 않는다. 다른 계정 접근과 토큰 노출은 보안 위험이다.
- 검증: 토큰 원문을 저장·로그하지 않고 재생 공격, 최신 링크 무효화, 메일 미리보기, 시계 경계, 세션 갱신/로그아웃/탈퇴 직후 차단, 다른 계정 접근을 검증한다. 발송 제한·탈퇴 재확인 링크 수명·메일 업체·DB는 D-02에서 정한다. 구현과 테스트는 아직 없다.
- 재검토 조건: 요구한 보안·운영 수준을 직접 구현으로 달성하기 어렵거나 검증 비용이 과도하면 A/B를 다시 비교한다.
- 연결: [DEC-020](020-email-link-login-and-session-retention.md), PRD 8.1절, D-02/B-01.
