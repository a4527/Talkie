# ADR-046 · DEC-046 · 이메일 인증 사용성과 수명·복원 경계

- 결정일: 2026-10-23
- 상태: Accepted
- 동의 근거: 사용자가 후속 다섯 정책에 “다 A로” 동의했다. 다만 메일 실패의 별도 재요청 흐름은 불필요하고 사용자가 메일이 오지 않으면 다시 요청할 것이라고 명시했다. 이 수정을 2A에 우선 적용한다.
- 기준: 현재 동작·기한은 [PRD 8.1절](../../PRD.md#81-가입로그인과-로그인-유지), 저장/동시성 상세는 [design](../../design.md#로그인-상태-저장)을 따른다.

## 배경과 선택

DEC-020/026/035/036의 앱 직접 이메일 링크·지속 PostgreSQL 인증은 확정됐지만 로그인할 브라우저, 메일 실패 후 동작, 인증 행의 실제 정리 수명, 과거 백업 복원 뒤 인증의 처리는 미정이었다. 보안·인증 데이터 수명과 사용자의 재로그인 약속을 구체화하므로 ADR로 남긴다.

| 항목 | 채택한 선택·이유 | 대안·절충 |
| --- | --- | --- |
| 로그인 브라우저 | 링크를 실제 열고 확인한 브라우저에 로그인. 요청 기기와 달라도 사용 가능 | 요청 브라우저 한정은 연결 증명 관리가 필요하고 메일 앱의 다른 브라우저로 열면 돌아가야 한다. 채택안은 대상 이메일의 명확한 확인·유도 로그인/계정 자동 교체 방지 검증이 필요하다. |
| 메일 실패 | 자동 재발송과 실패 전용 재요청 안내/버튼을 추가하지 않고 기존 요청 화면을 이용 | 메모리 유지 중 1회 자동 재전송은 일시 장애를 감출 수 있으나 중복 메일·횟수/상태 관리가 늘어난다. 사용자는 메일이 오지 않으면 스스로 다시 요청할 것으로 판단했다. 실패를 성공으로 표시하거나 기존 무효 링크의 새 요청 경로를 제거하는 결정은 아니다. |
| 인증용 행 정리 | 효력이 끝난 인증 자료를 24시간 내 정리 | 7일은 진단 여유 대신 이메일/인증 메타데이터 보관을 늘린다. 정상 계정·유효 세션 보존과 사용 차단/실제 행 삭제를 구분한다. |
| 백업 복원 | 과거 백업 복원 후 인증 자료를 전부 무효화하고 재로그인 | 인증 유지에는 백업보다 최신인 소비/로그아웃/무효화 이력의 별도 내구성·수명·복원 정합성 관리가 필요하다. 채택안은 이 복잡성을 줄이지만 복원 뒤 사용자 재로그인이 필요하다. 일반 재시작은 제외한다. |

## 영향·한계·검증

추가 외부 메일 비용/자동 호출을 만들지 않고 인증 정리 작업·복원 개방 절차·확인 화면 검증이 추가된다. 실제 비용·일정·성능은 미측정이다. 메일 도착이 지연되면 사용자는 기존 요청 화면에서 다시 요청해야 하며 새 발급은 기존 링크를 무효화한다. 요청/수락/실제 전달 상태를 혼동하지 않는다.

현재 24시간 행 삭제는 서비스 DB의 인증 자료 정리 계약이며 앱 관리 백업의 구체 대상·폐기/보호는 기존 D-02의 남은 백업 설계와 함께 검증한다. 탈퇴/체험 만료의 데이터 재적용은 인증 전체 무효화와 별개다. 로컬 기기 종료 중 실행을 보장하지 않으며 재시작 후 정리를 검증한다. 메일 원문·토큰 원문을 추가 보관하는 결정은 아니다.

링크를 연 브라우저만 인증되는지, 다른 계정이 자동 교체되지 않는지, 미리보기 미소비, 메일 실패/전달 불명에서 자동 재전송·실패 전용 재요청 UI가 없는지, 기존 요청/무효 링크 경로와 30초/10분 제한, 효력 종료·24시간·동시 재요청/정리 경계, 정상 재시작의 인증 유지와 과거 복원의 전체 무효화를 시험한다. 아직 구현·메일 전달·삭제/복원 시험은 없다.

- 재검토 조건: 유도 로그인·브라우저 전환 혼동, 메일 미도착 사용성, 정리 기한 준수, 복원 후 재로그인 부담에 문제가 관측되면 대안을 재논의한다.
- 대체 관계: DEC-020/026/035/036의 미정 사용성·수명/복원 범위를 구체화한다. 일반 이용의 30일 로그인 유지와 기존 탈퇴/백업 정책은 유지한다.
- 연결: D-02, B-01/B-05, [논의 원안](../proposals/authentication-storage-design.md#다음-다섯-선택-인증-사용성과-실패-처리).
