# ADR-015 · DEC-015 · 첫 로컬 구현의 Next.js와 TypeScript

- 결정일: 2026-10-21
- 상태: Accepted
- 동의 근거: Next.js + TypeScript 한 프로젝트에서 로컬 가짜 AI 학습 흐름을 구현하고 화면·학습 처리·가짜 AI 연결을 최소한으로 구분하며, 세부 모듈 경계와 실행·배포 구조는 검증 후 판단하는 범위를 제안했다. 사용자는 “그래 근거도 정리하고있지?”라고 답해 동의하고 근거 기록을 요청했다.
- 배경·확정 제약·측정 근거: DEC-006의 첫 학습 흐름 구현, DEC-007의 단계별 검증, DEC-010의 AI 판단과 앱 기록·복원 책임을 유지한다. 사용자는 다양한 아키텍처에서 적합한 구성을 선택하는 과정을 중시한다. 구현 전 기술·요금으로 후보를 좁히고 공통 앱의 필요한 부분을 후보 환경에서 실행해 비교하는 방향에 동의했다. 실제 앱 성능·비용·배포·복구 측정은 아직 없다.
- 검토한 대안과 장단점: [최소 스택 비교안](../proposals/initial-stack.md)의 A는 Next.js + TypeScript 한 프로젝트로 화면과 HTTP API를 연결하며 실행·계약 구성을 줄일 수 있다. B는 React/Vite + Node.js API로 화면·API 독립 배포에 유리하지만 실행·빌드·통신 구성이 추가된다. C는 React/Vite + FastAPI로 Python 처리를 활용할 수 있지만 두 언어·런타임·계약 관리가 필요하다. 이 일정·운영 평가는 추정이며 실측 우위가 아니다. 현재 독립 배포 또는 Python 전용 처리의 필수 요구는 확인되지 않았다.
- 결정: 첫 구현은 Next.js + TypeScript 한 프로젝트로 진행한다. 로컬 가짜 데이터·가짜 AI 응답으로 시작→대화→교정→다시 말하기→종료→노트 흐름을 연결한다. 화면·학습 처리·가짜 AI 연결의 역할을 구분하고 세부 모듈 경계는 구현하며 조정한다. B-00 임시 기록은 첫 학습 흐름 설계의 실행 중 세션 메모리 범위로 한정한다. Next.js를 제품 전체의 유일한 실행 환경으로 확정하지 않는다.
- 이유: 첫 학습 흐름을 한 언어·한 프로젝트에서 검증하면서 이후 음성·저장·작업 실행의 선택 근거를 확보하기 위한 최소 선택이다. 책임 구분은 이후 변경의 영향 범위를 줄이려는 방향이며, 서비스 분리 비용이 없어지는 것은 아니다. 프레임워크 선택만으로 낮은 비용·높은 성능을 보장하지 않는다.
- 영향·단점: D-04의 비교·명시적 동의·근거 기록 기준을 충족한다. B-00은 구현·검증 전이며 완료 처리하지 않는다. 서버/브라우저 경계를 지켜 비밀값·데이터 접근 처리를 서버에 두어야 한다. Next.js의 실행 모델과 배포 환경 제약을 학습·검증해야 한다. DB·인증·공급자·모델·음성 경로·작업 실행·클라우드·예산은 별도 결정이다. 요약·재시도·삭제를 단순한 요청 후 콜백만으로 보장했다고 간주하지 않는다. 실제 저장·삭제·복원 정책과 공개 서비스 접근·비용 통제 요구는 유지한다.
- 검증하지 못한 가정: 의존성 설치·빌드·실시간 연결·서버 측 한도 집행·종료 작업 지속성·동시 사용·운영비·가용성은 미검증이다. 버전은 호환성 확인 후 잠금 파일로 고정한다. 모듈형 모놀리스·헥사고날·MSA 등의 아키텍처 이름과 세부 경계는 채택하지 않았다. 단일 서버 운영 및 중단 허용 범위도 미합의다.
- 재검토 조건: 화면 배포와 음성 세션의 독립 운영, 장시간 연결, 별도 작업 실행·확장, 여러 클라이언트의 API 공유 또는 Python 전용 처리 필요가 확인되면 필요한 부분부터 실행·배포 분리를 비교한다. 기존 기록·복원·보관 요구를 만족하지 못하거나 측정상 병목·비용 문제가 있으면 재검토한다.
- 대체 관계: DEC-006·DEC-007의 개발 접근을 구체화하며 기존 결정을 대체하지 않는다. 현재 구조는 design.md, 제품 요구는 PRD, 작업 완료 기준은 TASKS와 첫 학습 흐름 설계를 따른다.

## 공식 자료와 한계

- [Next.js의 백엔드 기능](https://nextjs.org/docs/app/guides/backend-for-frontend): HTTP 엔드포인트·데이터 접근을 지원하지만 모든 백엔드 요구의 대체를 보장하지 않는다.
- [Next.js 배포](https://nextjs.org/docs/app/getting-started/deploying): Node.js 서버·Docker 실행을 지원한다. 정적 내보내기는 기능이 제한되며 다른 플랫폼의 어댑터 지원 범위는 별도 확인한다.
- [after](https://nextjs.org/docs/app/api-reference/functions/after): 응답 후 작업 실행 기능이다. 이 기능만으로 재시작 후 재시도·기한 삭제가 보장된다는 근거는 없다.
- 위 자료는 2026-10-21 논의에서 확인했다. 프로젝트에서 실행하거나 측정한 결과와 구분한다.
