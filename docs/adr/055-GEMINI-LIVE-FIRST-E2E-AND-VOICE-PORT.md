# ADR-055 · DEC-055 · Gemini Live 우선 E2E와 음성 포트·어댑터

- 결정일: 2026-10-27
- 상태: Accepted
- 동의 근거: 사용자가 Gemini Live로 앱 E2E를 먼저 연결한 뒤 모델을 비교하고, 한 앱 안의 음성 포트·공급자 어댑터로 구현하며 필요 시 음성 구현을 별도 서버로 옮기는 방향에 “그래 그렇게 진행하자”라고 동의했다. 당시 합의 기록은 [2026-10-27 worklog](../worklogs/2026-10-27.md#합의--gemini-live-우선-통합과-음성-경계)를 따른다.
- 배경·이유: 초기 연결 준비와 운영 복잡성을 줄이면서 앱의 전체 학습 흐름을 먼저 연결하려는 선택이다. 공급자 구현을 포트 뒤에 두어 후속 모델 비교와 교체에 대비한다.
- 결정: Gemini Live로 로컬 E2E를 먼저 연결하고 모델 비교는 그 뒤에 수행한다. 초기 음성 처리는 한 앱의 포트·공급자 어댑터로 분리하며 필요 시 별도 서버로 옮기는 방향이다. 최종 모델 선택·공개 배포·MSA·별도 서버 채택을 뜻하지 않는다.
- 대안·절충: 기존의 비교 선행 순서를 유지하면 모델 비교 뒤에 앱 통합을 시작하지만 로컬 E2E 착수도 그만큼 뒤로 간다. 이번 선택은 통합을 앞당기는 대신 최종 비교·선택을 후속으로 남긴다. 포트가 있어도 분리형으로 전환할 때 STT·LLM·TTS 연결과 중단 처리는 추가 구현해야 한다. 초기 한 앱 구성은 운영 복잡성을 줄이지만 별도 서버가 필요한지는 후속 검증과 논의에 남는다.
- 미검증·재검토: 포트 분리만으로 공급자 교체나 전체 학습 흐름의 완성을 보장하지 않는다. 실제 확장·장시간 연결·실행 환경 필요가 관측되면 서버 분리를 재논의한다. 구조와 미통합 경계는 [음성 설계](../design/VOICE.md), 작업 순서·완료 판정은 [TASKS](../TASKS.md#선행-관계), 실제 검증 상태는 [PROGRESS](../PROGRESS.md)를 따른다. 비용·일정 절감의 정량 효과는 이 결정에서 확인하지 않았다.
- 대체 관계: DEC-053/054의 비교 선행 순서와 D-03 완료 후 B-09 착수 조건을 이 로컬 통합에 한해 대체한다. 후보 비교·최종 선택 자체는 유지한다. 공급자 데이터 조건과 시험 예외는 별도 결정인 DEC-025/052/056 및 [PRD](../PRD.md#provider-data-policy)를 따른다.

2026-10-28 문서 책임 정리의 후속으로 DECISIONS 본문을 이관했다. 결정일·상태·승인 범위의 변경은 아니다.
