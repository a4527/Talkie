# ADR-013 · DEC-013 · 대화와 학습 진행 상태의 주기적 묶음 저장

- 결정일: 2026-10-21
- 상태: Accepted
- 동의 근거: 매 발화·상태 변화마다 저장소에 쓰는 대신 앱 메모리에 모아 주기적으로 묶어 저장하고, 갑작스러운 종료 시 마지막 저장 이후 기록을 잃을 수 있다는 대안을 논의했다. 사용자가 “주기적으로 묶고 간격은 나중에 조절해보자”라고 동의했다.
- 배경·확정 제약: DEC-010의 앱 기록·복원과 DEC-012의 임시 원문 보관 방향은 확정됐지만 저장 빈도는 미정이었다. 사용자는 잦은 저장을 우려했다.
- 검토한 대안과 장단점: 매 발화·학습 상태 변화마다 저장하면 미저장 구간은 작지만 저장 요청이 잦다. 종료 시 한 번 저장하면 요청은 적지만 비정상 종료 때 세션 전체를 잃을 수 있다. 주기적으로 묶으면 요청 빈도를 줄일 수 있으나 마지막 저장 이후 기록은 손실될 수 있다. 실제 비용·성능 차이는 미측정이다.
- 결정: 대화 글과 학습 진행 상태 변화는 앱 메모리에 모으고 저장소에 주기적으로 묶어서 저장한다. 정상 종료 시 남은 기록을 저장한다. 저장 간격·묶음 크기와 세부 트리거는 검증하면서 조정하며 수치는 미확정이다. 논의 예시인 3턴·30초를 채택한 것은 아니다.
- 이유: 저장 요청 빈도와 재개 가능한 기록의 최신성 사이에서 절충하고 측정으로 간격을 정하기 위해서다.
- 영향·단점: 갑작스러운 종료나 메모리 손실 시 마지막 저장 성공 이후 발화·진행 상태를 잃을 수 있다. 이때 저장된 마지막 확인 턴과 그에 대응하는 진행 상태로 복원한다. 비용·일정에는 버퍼·묶음 처리·종료 시 저장과 실패·재시도 검증이 추가된다. 실제 저장량·비용·지연은 미측정이다. 앱이 열려 있는 동안의 연결 중단과 메모리 손실은 구분한다. 배치 주기는 보관 기간과 별개이며 로그에 원문을 남길 근거가 아니다.
- 검증: 저장 요청 수·지연·미저장 구간을 측정하고 발화와 진행 상태의 정합성, 저장 실패·재전송·중복·순서, 정상 종료 시 남은 기록 저장, 비정상 종료 후 마지막 저장 상태 복원을 확인한다. DEC-012의 요약·항목·근거 저장 성공 확인 전 전체 원문 삭제 금지는 유지한다.
- 연결 문서·작업: PRD 6·8·11절, design.md, B-05·V-01/V-05/V-06 및 첫 학습 흐름. B-00의 메모리 테스트를 실제 저장소 복원 검증으로 취급하지 않는다.
- 미확정 범위: 저장 간격·묶음 크기·트리거, 저장 실패 재시도 상세·버퍼 상한, 임시 원문 보관 상한·기간 초과 처리와 공급자 보관 조건. 실제 사용자 데이터 연결에는 D-02 정책과 접근 통제가 선행한다.
- 검증하지 못한 가정: 선택할 저장 간격에서 요청 빈도와 기록 손실 위험이 허용 가능한지 미확인이다.
- 재검토 조건: 저장 지연·실패·복원 불일치 또는 허용하기 어려운 미저장 손실이 나타나면 주기·묶음 크기·저장 방식 조정을 검토한다. 손실 허용 원칙 변경은 다시 논의한다.
- 대체 관계: DEC-010·DEC-012의 미정 저장 빈도와 복원 범위를 구체화한다. 기존 결정을 대체하지 않는다.
