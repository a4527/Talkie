# ADR-047 · DEC-047 · 미저장 버퍼 상한에서 최근 완결 기록 우선

- 결정일: 2026-10-23
- 상태: Accepted
- 동의 근거: 사용자가 후속 다섯 정책에 “다 A로” 동의했다. 메일 재요청에만 수정을 명시했으며 버퍼 초과의 최근 기록 유지·오래된 미저장 기록 제거는 제안 A대로 채택한다.
- 기준: 제품 동작은 [PRD 8절](../PRD.md#8-저장-데이터와-학습-노트), 구현 계약은 [design](../design/LEARNING-PERSISTENCE.md)을 따른다.

## 배경·대안·이유

DEC-031/040은 저장 장애에도 대화 지속·실패 표시·누적 재시도를 정했지만 유한 메모리 상한에서 무엇을 유지/포기할지는 미정이었다. 대화를 멈추거나 무제한 누적하는 안은 기존 합의와 맞지 않는다. 새 원문 디스크 보관은 기존 데이터 경계를 넓히므로 이번 선택에 포함하지 않는다.

최근의 완결 기록 단위를 유지하고 오래된 미저장 단위를 제거하는 A와, 먼저 쌓인 단위를 유지하고 새 단위 편입을 생략하는 B를 비교했다. A는 최근 대화·재개 맥락을 우선하고 B는 장애 초반 내용을 우선한다. 사용자는 A를 선택했다. 유실은 복구할 수 없고 기록 보관의 핵심 절충이므로 ADR로 남긴다. 학습 효과나 장애 빈도의 실측에 따른 선택은 아니다.

## 영향과 검증

원문·진행 상태·연결된 교정/재시도를 완결 단위로 함께 처리하며, 보존되지 않은 부분을 근거로 재시도 성공이나 학습 성공을 만들지 않는다. 기존 DB 저장분은 이 정책으로 삭제하지 않는다. 유실 범위 표시·구간 순서·대응 상태·노트/재개 누락 안내와 버퍼 크기/큰 단위 처리의 설계·시험이 추가된다. 음성 대화는 계속하고 남은 미저장 기록은 복구 뒤 재시도한다. 메모리 상한·실제 유실량·지연/비용은 미측정이다.

구체 상한 수치와 단일 기록이 상한보다 큰 경우, 제거 대상이 저장 진행 중일 때의 응답 처리, 구간 간 단절/근거 연결·재개 상태를 구현 전 명세한다. 잘못 연결된 상태나 빈 노트를 만들지 않고 연속 저장 성공으로 표시하지 않는지 검증한다. 종료 잔여 저장 대기와 최초 종료 후 원문 삭제 기한은 유지한다. 아직 구현·부하/장애·복구 시험은 없다.

- 재검토 조건: 빈번한 상한 도달이나 중요한 학습 기록 유실이 관측되면 상한·저장 복구·보존 우선순위를 재논의한다.
- 대체 관계: DEC-031/040의 상한 도달 시 유지/포기 미정 계약을 구체화한다. 나머지 누적 재시도·대화 지속·근거/삭제 정책은 유지한다.
