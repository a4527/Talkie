# ADR-007 · DEC-007 · 기능 구현과 엔지니어링 검증을 함께 진행

이 문서는 2026-10-20에 기존 결정 원문을 ADR로 옮긴 기록이다. 결정일·승인 근거·당시 비교 범위는 유지했다. 기존에 기록되지 않은 대안이나 실측 결과를 소급해 추가하지 않는다. 현재 구조는 [design.md](../../design.md), 상태와 대체 관계는 [결정 목록](../../DECISIONS.md)을 참고한다.

- 결정일: 2026-10-16
- 상태: Accepted
- 동의 근거: 아키텍처·테스트·트러블슈팅·검증·운영·배포를 프로젝트에 녹이는 계획을 제안한 뒤 사용자가 `진행해줘`라고 명시함
- 배경: 서비스 기능뿐 아니라 선택의 근거와 운영 결과를 클라우드 엔지니어의 작업 증거로 보여줄 필요가 있다.
- 검토한 대안과 장단점: 기능 완성 후 운영을 추가하면 첫 화면 구현은 빠르지만 초기 측정과 비교 근거가 부족하다. 처음부터 운영 구성을 모두 만들면 재현성은 갖추지만 예산과 실제 부하가 정해지기 전에 복잡성과 비용이 커진다. 기능별 테스트·최소 측정부터 시작해 배포·복구를 단계적으로 추가하면 개발 속도와 근거 확보를 함께 유지할 수 있다.
- 결정: 핵심 테스트와 최소 측정을 초기 구현에 포함하고, 아키텍처 비교·IaC·CI/CD·관측·권한·비용 통제·장애 실험·복구 검증을 단계별 완료 기준으로 관리한다. 실제 측정으로 개선 전후를 비교한다.
- 채택 이유: 동작하는 서비스, 선택 이유, 실패 분석과 복구 근거를 연결할 수 있다.
- 영향: 기능 외 검증 작업 시간이 추가된다. 클라우드 비용은 예산·지역·운영 후보 비교 후 산정한다. 사용자 데이터가 포함된 측정은 데이터 정책과 접근 통제를 전제로 한다. 특정 클라우드·배포 구조·IaC 도구나 수치 목표를 이 결정으로 확정하지 않는다.
- 대체 관계: 없음
