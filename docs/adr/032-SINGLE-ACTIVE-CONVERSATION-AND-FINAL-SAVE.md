# ADR-032 · DEC-032 · 계정당 진행 대화 하나와 종료 시 기록 저장 대기

- 결정일: 2026-10-23
- 상태: Accepted
- 동의 근거: 사용자가 첫 기술/정책 묶음에서 “4A 5A로 하자”라고 명시했다. DB 관련 1~3은 선택하지 않고 PostgreSQL 추천 이유를 질문했으므로 미정이다.
- 배경: 동시 기기/탭의 기록 충돌과 종료 직전 잔여 저장 실패 처리가 미정이었다.
- 대안: 동시 학습은 하나만 허용(A), 새 연결의 기존 연결 인계(B), 여러 대화 허용(C)을 비교했다. A는 충돌·중복 비용과 구현 범위를 줄이지만 중단 대화를 종료하기 전 새 학습을 시작할 수 없다. B/C는 전환·병행이 편하지만 연결 인계·늦은 응답·동시 비용·기록 처리 범위가 늘어난다. 종료 시 저장 실패는 저장 대기와 재시도(A), 마지막 저장분으로 즉시 부분 노트(B)를 비교했다. A는 복구 가능한 발화를 보존할 기회를 주지만 노트 대기가 늘고 메모리 손실 위험은 남는다.
- 결정: 계정당 진행 대화 하나만 허용하며 재개 가능한 중단 대화도 포함한다. 중복 연결·새 대화는 기존 대화로 안내하고 명시/자동 종료 뒤 새 대화를 시작한다. 다른 기기 재개는 기존 연결 중단 후 허용하며 기록 조회는 허용한다. 종료 시 잔여 저장 실패는 대화 종료와 기록 저장 대기를 분리하고 메모리가 살아 있는 동안 자동 재시도한다. 성공 후 확인 기록으로 노트를 만든다. 미저장분을 잃으면 저장분만으로 생성 가능성을 알리고 확인된 사용자 발화가 없으면 빈 노트를 만들지 않는다.
- 기한: 최초 종료 요청이 종료 시점이며 지연 저장·재시도로 종료 후 24시간 원문 상한을 연장하지 않는다. DEC-031의 노트 자동 재시도·근거 검증된 부분 노트와 구분한다.
- 영향: 학습 전환의 제약과 노트 대기 안내가 추가된다. 활성 대화/연결의 동시 확정 방지·재개 경쟁·종료 후 늦은 저장·기한 경계·메모리 손실을 검증해야 한다. 비용·사용성은 미측정이다. 브라우저 종료 뒤 미저장 기록 보존을 보장하지 않는다.
- 미확정: DB/임시 저장/인증 상태 저장 기술(이번 묶음 1~3), 저장 주기·버퍼 상한·장기 실패 대응·재시도 수치. 운영 중 연결 중단 감지·동시 처리 계약은 구현 설계/검증 대상이다.
- 검증: 여러 탭/기기의 새 시작·중복 연결 차단과 기록 조회, 기존 연결 중단 후 재개, 중단 대화 종료 뒤 새 시작, 종료 잔여 저장 실패→복구, 메모리 손실→저장분 노트, 빈 발화, 종료 기한 연장 금지를 확인한다.
- 대체 관계: DEC-013/024/031의 미정 경계 구체화. 기존 결정을 대체하지 않는다.
- 연결: PRD 6·8절, B-02/B-05/B-06/B-09, DESIGN.md.
