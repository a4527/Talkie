# ADR-005 · DEC-005 · 현재 상태와 날짜별 작업 기록을 분리

이 문서는 2026-10-20에 기존 결정 원문을 ADR로 옮긴 기록이다. 여러 작업 문서의 역할과 대안 비교를 포함하므로 ADR에 보존했다. 결정일·승인 근거·당시 내용은 유지했다. 현재 문서 역할은 [design.md](../../design.md), 상태는 [결정 목록](../../DECISIONS.md)을 참고한다.

- 결정일: 2026-10-15
- 상태: Accepted
- 동의 근거: 2026-10-15 대화에서 대안과 영향을 제시한 뒤 사용자가 `동의해`라고 명시함
- 배경: 그날의 변경을 중심으로 문서 간 정합성을 확인하면서도 작업마다 필요한 문서만 읽어야 한다.
- 검토한 대안과 장단점: 기존 루트 파일만 유지하면 단순하지만 날짜별 기록이 누적된다. TASK와 PROGRESS를 모두 날짜별로 나누면 기록은 분명하지만 작업의 최신 상태가 흩어진다. 단일 TASK·현재 상태 PROGRESS·날짜별 worklog의 혼합 방식은 최신 상태를 찾기 쉽고 일일 근거를 보존하지만 기록 파일이 하나 늘어난다.
- 결정: `TASKS.md`는 단일 작업 목록, `PROGRESS.md`는 현재 상태 요약으로 유지한다. 작업한 날짜마다 `docs/worklogs/YYYY-MM-DD.md`에 결과·검증·남은 불일치를 기록한다. 그날 바뀐 파일과 관련 문서에 대해 마감 정합성 점검을 수행한다.
- 채택 이유: 작업 상태의 기준을 하나로 유지하면서 과거 작업과 문서 점검 근거를 날짜별로 찾을 수 있다.
- 영향: 문서 작업 과정과 파일 구조가 바뀐다. 제품 기능이나 사용자 데이터에는 영향이 없고 작업일마다 짧은 점검·기록 시간이 추가된다.
- 대체 관계: 없음
