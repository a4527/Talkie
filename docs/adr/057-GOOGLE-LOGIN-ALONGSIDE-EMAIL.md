# ADR-057 · DEC-057 · 이메일 링크와 Google 로그인 병행

- 결정일: 2026-10-28
- 상태: Accepted
- 동의 근거: 사용자가 이메일 인증과 OAuth를 모두 사용하고 싶다고 명시했고, 제공자별 인증 이후 공통 계정·기록·세션을 관리하는 설명에 “그러자”, “구현은 하지말고 관련 문서내용만 구글 oAuth 내용으로 최신화”라고 요청했다.
- 배경·이유: 이메일 링크를 유지하면서 Google 소셜 로그인을 프로젝트에서 경험하려는 요청이다.
- 결정: 이메일 링크와 Google OAuth/OIDC 로그인을 함께 제공한다. 제공자 인증 이후 앱 계정·학습 기록·로그인 세션 관리는 공통으로 처리한다. 이번 변경은 문서에 한정한다.
- 대안·영향: 이메일만 유지하면 추가 개발은 줄지만 요청한 소셜 로그인 경험을 제공하지 못한다. Google로 대체하면 이메일 로그인 선택지가 사라진다. 병행하면 로그인 선택권이 늘고 공통 계정/세션 처리를 재사용하지만 Google 앱 설정·콜백/토큰 검증·계정 연결과 장애 대응의 개발 및 운영 부담이 추가된다. 비용·일정은 미측정이다. Google 사용자 식별자와 앱 계정 연결 데이터가 필요하며 저장 상세는 미정이다.
- 미확정: 계정 연결·중복 가입·연결 해제, Google 전용 가입자의 이메일 확보·탈퇴 재확인, 라이브러리·DB 스키마·요청/콜백 보안 상세·동의 범위·키 관리·운영 설정은 구현 전에 정한다. 이메일 일치 자동 병합은 승인하지 않았다. 다른 제공자 추가와 결제 정책은 이번 결정 범위가 아니다.
- 검증·재검토: Google 로그인은 미구현·미검증이다. B-01에서 정상/취소/실패·응답 검증·계정 분리·동일 계정 기록 접근·세션 무효화를 확인한다. 계정 연결의 보안·사용성 문제가 확인되면 재논의한다.
- 대체 관계: DEC-020의 이메일 단독 로그인 범위만 확대한다. DEC-026의 앱 직접 이메일 링크·세션 관리, 기존 세션 수명·로그아웃/탈퇴 무효화 정책은 유지한다.
- 외부 근거: [Google OpenID Connect 공식 문서](https://developers.google.com/identity/openid-connect/openid-connect). 2026-10-28 대화 중 확인한 관찰은 Google이 OAuth 2.0 기반 OIDC와 인가 코드 흐름을 지원한다는 점이다. 실제 프로젝트 설정·응답·운영 적합성은 미확인이다.

## 로그인·재로그인 후속 합의 (2026-10-28)

- 동의 근거: 문서 검토에서 재로그인의 이메일 한정을 지적한 뒤 사용자가 “로그인과 재로그인모두 이메일이든 google이든 지원해”라고 명시했다.
- 결정·범위: 최초 로그인뿐 아니라 세션 만료·과거 백업 복원 후 재로그인에도 이메일 링크 또는 Google 로그인을 지원한다. 선택한 인증 방법과 앱 계정의 연결은 기존 계정 연결 설계에서 보장하며 이메일 일치 자동 병합을 승인한 것은 아니다.
- 영향·연결: 재로그인을 이메일로 한정하는 안내를 없애고 두 경로에서 새 앱 세션 발급·기록 접근·기존 세션 무효화를 검증한다. 계정 연결·Google 전용 가입자의 탈퇴 재확인 상세는 여전히 미정이다. 현행 요구사항은 [PRD 8.1](../PRD.md#81-가입로그인과-로그인-유지), 구현·완료 판정은 [D-02/B-01](../TASKS.md)을 따른다.
- 대체 관계: DEC-020과 DEC-046의 재로그인 방법을 이메일로 한정하는 범위만 확대한다. 과거 인증 전체 무효화·일반 재시작의 로그인 유지·기존 세션 수명은 유지한다. 문서 승인으로 Google 구현 완료를 뜻하지 않는다.
