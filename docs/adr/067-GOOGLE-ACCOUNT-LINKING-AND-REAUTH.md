# ADR-067 · DEC-067 · Google 계정의 명시적 연결과 탈퇴 재인증

- 결정일: 2026-11-02
- 상태: Accepted
- 동의 근거: 로컬 앱 데모에 Google 로그인을 포함하기로 한 뒤 DEC-057의 미확정 항목을 질문했다. 사용자가 계정 연결 “명시적 연결만”, Google 전용 가입자의 탈퇴 재확인 “Google 재인증”, 구현 방식 “openid-client 라이브러리”를 선택했다. 연결과 재인증은 추천안이었고 라이브러리는 추천안(직접 구현) 대신 대안을 골랐다.
- 배경·이유: DEC-057은 이메일 링크와 Google 병행을 승인했지만 계정 연결·중복 가입·연결 해제, Google 전용 가입자의 탈퇴 재확인, 라이브러리를 구현 전 합의로 남겼다. 로컬 데모의 메일은 `.test` 주소만 Mailpit으로 보내므로 실제 Gmail 주소로 탈퇴 확인 메일을 보낼 수 없다.
- 결정:
  - 같은 이메일의 기존 계정이 있으면 비로그인 Google 로그인으로 자동 병합하지 않고 거부한다. 로그인한 상태에서 계정 화면의 “Google 계정 연결”로만 연결한다. 연결되지 않은 새 Google 사용자는 Google이 확인한 이메일(`email_verified`)로 새 계정을 만든다.
  - Google 연결 해제는 그 계정이 현재 메일 경로로 이메일 로그인을 할 수 있을 때만 허용한다. Google로만 로그인할 수 있는 계정의 마지막 로그인 수단은 제거하지 않는다.
  - Google이 연결된 계정의 탈퇴 재확인은 연결된 Google 계정으로 다시 인증해 같은 사용자 식별자(`sub`)를 확인하는 방식으로 할 수 있다. 성공 시 이메일 링크와 같은 10분 탈퇴 권한을 현재 로그인 세션에 부여한다.
  - OIDC 인가 코드·PKCE·state/nonce 검증은 `openid-client`를 사용한다. 앱 계정·세션 발급과 무효화는 DEC-026의 앱 직접 관리를 유지한다.
- 대안·절충: 검증된 이메일 일치 시 자동 연결은 편하지만 DEC-057이 승인하지 않은 병합이고 이메일 소유 변경 시 계정 탈취 위험이 있다. 제공자별 별도 계정은 단순하지만 같은 사람이 이메일과 Google을 함께 쓸 수 없다. 탈퇴를 확인 문구 입력만으로 하면 구현이 쉽지만 본인 재확인 수준이 기존 정책보다 약하다. 라이브러리 없이 직접 구현하면 의존성은 없지만 OIDC 검증 실수의 위험이 커진다.
- 미검증·재검토: Google의 discovery는 `auth_time`·`prompt=login`을 제공하지 않는다(2026-11-02 discovery 문서 관찰). 재인증은 계정 선택(`prompt=select_account`)과 새 인가 코드 교환으로 확인하며, 브라우저에 Google 세션이 남아 있으면 비밀번호 재입력을 강제하지 못한다. 실제 Google OAuth 클라이언트로의 정상·취소·실패 흐름은 아직 시험하지 않았다. 공개 운영의 동의 화면·검수·키 관리와 실제 메일 공급자 도입 시 Google 전용 계정의 메일 재확인 허용 여부는 재검토한다.
- 대체 관계: DEC-057의 미확정 항목 중 계정 연결·연결 해제·Google 전용 가입자 탈퇴 재확인·라이브러리를 확정한다. 이메일 일치 자동 병합 미승인과 DEC-026의 앱 직접 세션 관리는 유지한다.
