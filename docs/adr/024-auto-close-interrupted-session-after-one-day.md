# ADR-024 · DEC-024 · 외부 환경으로 중단된 세션의 24시간 후 자동 종료

- 결정일: 2026-10-21
- 상태: Accepted
- 동의 근거: 사용자가 오래 뒤에는 이전 대화를 기억하지 못해 새로 진행하는 편이 낫다며 1일 자동 종료·정리를 제안했다. 기존 명시적 종료 원칙과의 충돌, 중단 후 24시간 내 재개·자동 종료·저장된 기록으로 노트 생성·실패 시 종료 후 최대 24시간 원문 재시도안을 제시하자 “사용자가 명시적으로 종료하는게 기본인데 외부 환경으로 인해 종료하지 않은경우는 24시간 자동 종료, 노트 생성으로 확장”이라고 범위를 명시해 동의했다.
- 배경·기존 제약: DEC-003과 PRD 원칙 3.4·6절은 사용자가 명시적으로 종료할 때까지 세션을 임의 종료하지 않도록 했다. DEC-010은 마지막 저장 상태에서 재개하고 저장된 글로 종료 노트를 만들도록 했다. DEC-012는 종료 후 임시 전체 원문을 저장 성공 시 즉시, 실패 시 종료 시점부터 최대 24시간 안에 삭제한다. DEC-013의 묶음 저장은 마지막 미저장 턴의 손실 가능성을 남긴다.
- 검토한 대안: (1) 명시 종료만 유지하고 중단 재개 기간을 길게 두면 예전 대화를 이어갈 수 있지만 사용자가 맥락을 잊고 전체 원문·상태를 오래 보관한다. (2) 중단 24시간 후 재개만 만료하고 노트를 만들지 않으면 AI 정리 호출은 줄지만 확인된 발화·교정의 학습 결과를 잃는다. (3) 24시간 후 자동 종료·노트 생성은 다음에 새 대화를 시작하고 이전 기록을 남길 수 있으나 자동 종료/정리 작업과 실패 재시도·AI 비용이 추가된다. 사용자는 명시 종료를 기본으로 유지하고 외부 환경 중단에만 (3)을 채택했다.
- 결정: 네트워크·브라우저 등 외부 환경으로 세션이 중단된 뒤 24시간 동안 재개되지 않으면 앱이 자동 종료하고 저장된 실제 대화로 노트를 생성한다. 기한 전에 재개하면 자동 종료 예약을 취소한다. 다시 외부 환경으로 중단되면 새로운 중단 시각부터 계산한다. 정상 연결 중 침묵이나 응답 대기는 자동 종료하지 않는다. 사용자의 명시 종료는 계속 기본 경로다. 확정된 사용자 발화가 없으면 빈 노트를 만들지 않고 세션을 정리한다. 자동 종료 후에는 그 세션을 재개할 수 없고 다음 학습은 새 세션으로 시작한다. 현재 제품 동작은 [PRD 3·6·8절](../../PRD.md#6-대화-상태와-예외)을 따른다.
- 이유: 종료 버튼을 누르지 못한 중단에서도 학습 결과를 남기고, 오래 뒤 돌아온 사용자는 기억하기 어려운 중단 대화를 강제로 이어가지 않도록 한다. 사용자가 원해서 계속 대화 중인 경우의 종료 권한은 유지한다.
- 비용·일정·사용자 경험·데이터·운영 영향: 중단 기산 시각·자동 종료 작업·24시간 경계 경쟁·중복 실행·늦은 응답 차단을 구현해야 한다. 자동 종료된 미완성 대화에도 AI 요약 호출이 발생할 수 있어 운영비는 중단 빈도와 실제 단가 측정 후 추정한다. 최초 로컬 후보 비교 3만 원은 자동 운영 호출 예산이 아니다. 중단 중 원문·진행 상태는 재개용으로 유지하며, 자동 종료 후에는 DEC-012의 별도 최대 24시간 원문 정리 기한이 시작된다. 따라서 실패 재시도 시 중단부터 최장 약 48시간 원문이 남을 수 있다. 성공하면 즉시 삭제한다. 자동 생성 노트에도 DEC-017의 체험 기록 학습 종료 후 30일·유료 보존을 적용하며 자동 종료 시각을 종료 시점으로 사용한다.
- 검증: 중단 직전 저장 성공 턴과 대응 상태만 복원/요약에 사용하고 미저장 턴·미확인 응답·미재생 AI 발화를 제외한다. 경계 직전 재개가 자동 종료를 취소하는지, 경계의 재개와 종료 중 하나만 확정되는지, 자동 종료 후 늦은 응답이 기록을 되살리지 않는지 확인한다. 정상 연결 중 침묵, 명시적 종료, 중단 후 재개, 다시 중단한 경우를 분리한다. 확인된 사용자 발화가 없으면 노트 호출 없이 정리하고, 노트 추출·저장 실패에는 DEC-012의 재시도·24시간 기한·삭제를 적용한다. 앱 상태·중복/작업 실행은 자동 테스트로, 자동 노트의 근거·품질은 사례 평가로 검증한다.
- 미정 상세와 한계: 중단 감지·기산점의 기술, 자동 종료 작업 실행 주기·실패 재시도/알림, 경계 시각의 처리 방식, 체험 사용량 집계, 자동 노트 생성 비용과 데이터량, 백업/공급자 보관 조건은 구현/호출 전 확정한다. 묶음 저장 특성상 마지막 미저장 발화가 노트에 빠질 수 있다. 사용자 의도와 브라우저 이탈의 차이를 항상 식별할 수 있는 것은 아니므로 확인된 연결 중단을 예외 판단의 입력으로 삼는다. 구현·실측·AI 호출은 아직 없다.
- 재검토 조건: 예기치 않은 자동 종료, 노트 생성 실패/비용, 저장 손실, 재개 실패가 실제 평가에서 확인되면 시간·예외 범위·정리 방식을 재검토한다.
- 대체 관계: DEC-003의 “사용자가 명시적으로 종료할 때까지 임의 종료하지 않는다”는 절대 규칙에 외부 환경 중단 후 24시간 예외를 추가해 해당 부분을 대체한다. 대화/교정의 다른 규칙은 유지한다. DEC-010의 앱 실행 상태·명시적 종료 책임에는 자동 종료 예외를 구체화한다. DEC-012/013의 저장·삭제 원칙은 유지한다.
