# ADR-028 · DEC-028 · 지속 작업 목록과 정시 실행

- 결정일: 2026-10-21
- 상태: Accepted
- 동의 근거: 저장된 작업 목록과 정시 실행(A), 별도 큐·워커(B), 웹 프로세스 타이머(C)를 비교한 뒤 사용자가 `3-a`를 선택했다.
- 배경: DEC-024의 외부 중단 24시간 자동 종료, DEC-012의 노트 재시도·임시 원문 삭제, DEC-021의 탈퇴 24시간 삭제는 재시작 후에도 기한을 지켜야 한다.
- 대안: A는 구성 요소를 줄이면서 작업을 지속할 수 있지만 정시 실행·중복 방지·재시도·기한 감시가 필요하다. B는 작업 부하 분리에 유리하나 별도 서비스와 운영비가 든다. C는 구현이 간단하지만 프로세스 재시작·배포·절전으로 작업이 사라질 수 있다.
- 결정과 이유: A를 채택한다. 작업의 대상·기한·상태를 지속 저장하고 예약 실행에서 기한이 된 작업을 처리한다. 기한 준수가 필요한 작업을 웹 프로세스 수명과 분리하기 위해서다. 특정 DB·스케줄러·호스팅은 선택하지 않았다.
- 영향: 작업 상태와 중복 실행 방지, 실패 재시도, 늦은 저장 차단, 실행 누락 관측 및 복구 절차가 필요하다. 저장·예약 실행 비용과 운영 부담이 생긴다. 앱 재시작만으로 기한을 놓치지 않아야 하지만 실제 준수는 검증 전이다.
- 검증: 중복 실행·배포 중단·실패·기한 직전/직후 재개·탈퇴·노트 완료 경쟁을 테스트한다. 자동 종료와 원문 삭제는 각각의 24시간 기준을 지키고 탈퇴 삭제·백업은 DEC-021의 기한을 지켜야 한다. 구체 실행 시각·주기·재시도/알림은 D-02에서 정한다.
- 재검토 조건: 예약 실행의 기한·처리량·비용 검증이 실패하면 B와 다시 비교한다.
- 연결: [DEC-012](012-TEMPORARY-TRANSCRIPTS-AND-LEARNING-EVIDENCE.md), [DEC-021](021-SCHEDULED-ACCOUNT-DELETION-AND-BACKUP-DEADLINES.md), [DEC-024](024-AUTO-CLOSE-INTERRUPTED-SESSION-AFTER-ONE-DAY.md), PRD 8.2절, D-02/B-05.
