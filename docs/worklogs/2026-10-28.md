## PROGRESS·제안서 분류·TASKS 중복 정리

- 사용자 요청 “이어서 진행해”에 따라 남은 문서 책임 정리를 수행했다. PROGRESS는 현재 구현·남은 일·검증 근거로 재구성하고 과거 합의/구현 설명은 기존 날짜별 worklog와 Git 이력으로 연결했다. 기존 절 앵커와 작업 상태를 보존했으며 과거 worklog 본문은 다시 쓰지 않았다.
- [제안서 색인](../proposals/INDEX.md)을 추가해 기존 11개 파일을 남은 제안/논의 자료·채택/적용 전 검토 기록·가정에 따른 추정으로 구분했다. 일부 채택 범위와 현행 기준 문서·남은 제안을 연결했다. 기존 파일 위치/본문은 유지하고 작성 당시 미정·가격/약관 관찰을 최신 상태로 취급하지 않는다는 탐색 기준을 명시했다. 외부 자료의 재조회·최신 적합성 판정은 하지 않았다.
- TASKS의 D-02~04·B-00~07·B-09에서 정책 수치·기술 구성·날짜별 실행 결과의 반복을 기준 문서/근거 링크로 줄였다. 링크된 정책·기한·수치·계약도 수용 범위에 포함한다고 명시했으며 완료 판정의 범위를 줄이지 않았다. V/C 작업과 선행 관계는 유지했다.

- 점검: 문서 67개 로컬 링크·절 앵커 525개, TASK 27개의 ID/우선순위/상태·R-01~03 취소 상태·선행 관계 보존, PROGRESS의 기존 절 앵커/작업 상태를 확인했다. 제안서 11개와 PRD·DESIGN·상세 설계의 본문이 HEAD와 동일함을 확인하고 git diff --check를 통과했다. 이번 축약 전후의 검증 경계를 위 표로 대조했으며 이번 변경 범위의 남은 링크/상태 불일치는 없다.
- CHANGELOG와 PROGRESS를 맞췄다. 기능의 미완료 범위(실제 음성/학습 통합·Google 인증 상세·운영/백업 복원·유료 기록·장기 장애 등)는 그대로다. 코드·의존성·DB 변경이 없어 실행 테스트·공급자 호출은 하지 않았고 커밋/push도 수행하지 않았다. 앞선 절의 문서 정리 잔여 목록은 당시 상태이며 이번 작업으로 해당 정리를 마쳤다.

## 문서 머리말의 공통 안내 중복 축약

- 사용자가 검토한 중복 안내를 “그렇게 수정해줘”라고 요청해 README·PRD·DESIGN·DECISIONS·PROGRESS·TASKS·CHANGELOG·제안서 INDEX와 상세 설계 7개의 머리말/탐색 안내를 정리했다. 문서별 역할 전체 나열과 AGENTS 준수 안내를 반복하지 않고 각 문서의 목적·적용 범위만 남겼다. README의 공통 문서 탐색은 AGENTS로 연결한다.
- 상세 설계의 일반적인 전체 구조 링크·문서 역할 재설명을 줄이고 구체적인 정책 절·ADR·데이터 모델·소스 코드·검증 링크는 보존했다. LOCAL-OPERATIONS의 설치/보관 기한 등 주제에 직접 연결된 안내는 유지했다. 제안서 INDEX의 부분 채택·과거 제안 구분과 표는 보존하고 일반 문서 역할/갱신 절차 반복만 제거했다.
- TASKS는 상태 표기·요구사항 ID 연결·연결된 계약도 수용 범위에 포함한다는 해석을 유지했다. DECISIONS의 기록·변경 규칙, TROUBLESHOOTING의 기록 기준·양식, ADR의 승인 근거·상태·대체 관계와 과거 worklog/CHANGELOG 항목은 변경하지 않았다.
- 점검: 머리말/안내 수정 15개 문서의 절 제목 전체와 TASKS·PROGRESS의 작업 행이 작업 직전과 동일함을 확인했다. PRD·DESIGN·DECISIONS·TASKS·상세 설계·README는 첫 본문 절 이후가 동일하다. INDEX의 분류 표도 동일하며 기존 ADR·worklog·트러블슈팅은 보존했다. 문서 67개의 로컬 링크·절 앵커 491개와 git diff --check를 통과했다.
- PROGRESS의 문서 정리 현황과 CHANGELOG를 맞췄다. 요구사항·수용 기준·작업 상태·구현 계약의 변경과 이번 범위의 남은 링크/상태 불일치는 없다. 코드·DB·의존성 변경이 없어 실행 테스트·외부 호출은 하지 않았고 커밋/push도 수행하지 않았다.
