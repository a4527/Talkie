# 2026-10-24 작업 기록

## DB 개편안 재개 메모

- 사용자 요청에 따라 [DB 스키마 개편 재개 메모](../proposals/DATABASE-SCHEMA-REFACTOR.md)를 작성했다. 현재 코드에서 확인한 사실과 미승인 제안을 구분하고 다음 합의·구현·마이그레이션·검증 순서를 남겼다.
- PROGRESS에서 연결하고 오늘 worklog 링크를 바로잡았으며 CHANGELOG에 문서 추가를 기록했다. PRD/DECISIONS/design의 채택 정책·현재 스키마와 TASK 상태는 변경하지 않았다.
- 관련 문서의 링크·작업 ID·미승인 상태와 기존 DEC-028/034/035/048 경계를 대조했다. 변경 문서 4개의 로컬 링크 검사와 `git diff --check`를 통과했다. 실행 코드·DB는 수정하지 않았고 테스트를 재실행하지 않았다. 이번 문서 범위의 남은 불일치는 없으며 개편안 합의·구현·검증은 후속이다.

## 원문 생성·삭제 이력 확인

- 사용자 요청: `erase_at`이 삭제 완료 시각으로 읽혀 삭제 기한 표현을 바꾸고, 실제 생성 여부·삭제 완료 시각·사유를 원문 DB에서 확인하도록 했다(DEC-048).
- 지속/임시 DB의 기한 열을 `transcript_delete_deadline_at`으로 이름 변경했다. 기존 값을 보존하는 Drizzle SQL을 검토하고 현재 로컬 DB 두 개에 `npm run db:migrate`를 적용했다. 앱 요청 시 자동 마이그레이션은 추가하지 않았다.
- 원문 DB에 내용 없는 `transcript_lifecycle`을 추가했다. 저장소 생성과 첫 비어 있지 않은 발화 묶음 저장을 구분하고, 원문/버전 삭제와 완료 시각·사유 기록을 한 트랜잭션으로 처리한다. 기록 실패 시 삭제도 취소하고 재시도에서 기존 시각을 보존한다. 노트 저장 후 삭제·사용자 발화 없음·기한 만료 사유를 구분한다.
- 이력에는 원문·교정·digest·비밀값을 복사하지 않는다. 탈퇴/고아 정리에서 이력도 삭제하며 원문 DB의 백업 제외 경계를 유지한다. 과거에 이미 삭제된 원문의 이력은 복원하지 않고, 기존 원문의 미확인 생성/첫 저장 시각은 NULL로 유지한다. 완료 시각은 논리 삭제 기록이며 물리 소거 증거가 아니다.

## 검증과 적용

- 실행 중인 Docker Compose의 두 PostgreSQL/Mailpit이 healthy임을 확인했다. 민감한 환경 변수 값이나 실제 대화 내용을 출력하지 않았다.
- 현재 앱 DB와 다른 고유 이름의 `talkie_test_lifecycle_*` DB 두 개를 만들어 서버 시험을 실행하고 시험 종료 후 제거했다. 17개 중 16개 통과, `PG_BIN_DIR` 미지정으로 실제 백업/복원 시험 1개 제외. 마이그레이션의 기존 값 보존·과거 시각 미추정, 생성/첫 저장 구분, 중복 불변, 삭제 이력 기록 실패 시 원문 보존/재시도, 빈 대화·기한 만료 사유, 탈퇴 후 이력 제거를 확인했다. 시험용 트리거 장애이며 실제 운영 장애가 아니다.
- 기존 단위 테스트 13개·타입 검사 통과. 실제 AI·브라우저 시험·물리 소거·대규모 장애/기한 준수·운영 백업 복원 검증으로 확대 해석하지 않는다.
- 개발 서버가 실행 중이면 코드 반영 후 재시작하고, DBeaver 연결/테이블을 새로고침하면 새 스키마를 확인할 수 있다. 실제 사용자 대화를 시험 목적으로 생성·삭제하지 않았다.

## 문서 정합성 점검

- design의 현재 스키마/수명 계약을 기준으로 DEC-048, B-05 수용 기준, README 조회법, PROGRESS 현재 상태, CHANGELOG를 대조했다. DEC-012/027/034의 원문 성공 즉시 삭제·종료 후 최대 24시간·백업 제외와 충돌하지 않는다. PRD의 제품 보관 정책은 바꾸지 않았다.
- D-02/B-01/B-05/B-06의 IN PROGRESS를 유지했다. 이번 작업은 생성·삭제 확인 가능성 개선이며 전체 기능 완료가 아니다. 로컬 링크·작업/결정 ID와 상태 및 `git diff --check`를 점검한다.
- 시작 전부터 변경돼 있던 `app/next-env.d.ts`는 수정하지 않았다. 커밋/push는 수행하지 않았다.
- 남은 한계: 이전 삭제 이력은 알 수 없음, 임시 DB 볼륨 손실 시 이력도 손실, timer/실제 운영 삭제·물리 잔존·백업 복구 검증은 후속이다.

## 트러블슈팅 문서화·에이전트 안내 정리

- [트러블슈팅 문서](../TROUBLESHOOTING.md)에 선별 기준·최소 양식과 [원문 생성/삭제 구분 사례](../TROUBLESHOOTING.md#2026-10-24--원문-미저장과-자동-삭제를-구분할-수-없음)를 작성했다. 이후 사례 본문은 별도 문서에 두고 worklog에는 링크와 당일 결과만 남긴다. 위 구현/검증 기록은 해당 날짜의 결과로 유지한다.
- AGENTS의 결정 문서 안내를 표의 한 항목으로 모으고, ADR 분리·짧은 결정 형식·대체 절차의 반복 설명은 기존 결정 문서의 기록·변경 규칙으로 연결했다. 영향 큰 결정의 사전 논의·명시적 동의, 마감 점검·보안 검사와 Next.js 안내는 유지했다.
- 문서만 변경했으며 제품 정책·구현·TASK 상태는 바꾸지 않았다. 변경 문서의 링크·사례와 실제 검증 근거, `git diff --check`를 확인했다. 실행 코드 테스트는 다시 수행하지 않았다.
