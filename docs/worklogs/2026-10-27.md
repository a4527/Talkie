# 2026-10-27 작업 기록

## 합의 · Gemini Live 우선 통합과 음성 경계

- 사용자는 무료 Gemini Live로 E2E를 먼저 완성한 뒤 모델을 비교하고, 한 앱의 포트·어댑터로 구현하며 필요 시 음성 구현을 별도 서버로 옮기는 방향에 동의했다(DEC-055). MSA·별도 서버·최종 모델·공개 배포 채택이 아니다.
- 사용자가 테스트 중 공급자 학습 사용을 허용한다고 명시했다. 개인정보·민감/기밀정보 없는 합성 대화·개발자 본인 음성의 비공개 로컬 시험에만 적용한다(DEC-056, ADR-056). 실제 사용자 연결의 학습 금지·최대 30일과 앱의 원본 음성 미저장은 유지한다.
- PRD 8·9.2·11, DECISIONS와 ADR-025/056을 먼저 갱신하고 TASKS의 로컬 D-03 선행 관계와 B-02/B-09 진행 상태를 연결했다. 기존 후보 비교의 상세 계획은 후속으로 남기며 완료 처리하지 않았다.

## 구현 · 비공개 음성 연결의 첫 단계

- `app/src/voice/port.ts`: 공급자 독립 연결/PCM 입력·전사·PCM 출력·생성 완료·중단·오류·종료 계약. `adapters/gemini-live.ts`가 공급자 WebSocket 메시지를 변환하고 `browser-audio.ts`가 마이크·출력 장치를 담당한다. UI가 어댑터를 조립하며 공통 기록 코드는 공급자 원본 메시지를 다루지 않는다.
- `/voice`: 본인 시험 조건 확인→마이크 권한→인증된 단기 토큰→직접 Live 연결→음성/화면 전사문→종료. `/learn`에서 연결했다. 기존 가짜 AI·지속 DB 저장 흐름과 별개이며 실제 음성 저장·교정 상태·재개·노트 통합은 미완료다.
- `POST /api/voice/token`: 기존 동일 출처·JSON 본문·로컬 로그인 검사 후 시험 설정·무료 프로젝트 확인 플래그와 서버 키를 확인한다. 고정 모델/설정에 잠긴 1회 토큰, 새 연결 1분·만료 4분, 계정당 4분 발급 간격. 원문 공급자 오류·토큰·장기 키를 로그에 출력하지 않는다. 화면은 3분에서 종료하며 자동 재시도하지 않는다. 발급 제한은 프로세스 메모리라 재시작 후 유지되지 않는다.
- 입력 PCM은 작업 버퍼만 사용하고 Web Audio로 출력한다. 중단 시 출력 큐 폐기, 종료/오류/화면 이탈/연결 중 마이크 권한 응답의 지연에서도 장치·연결을 정리한다. 생성된 전사문을 자동으로 전달/학습 성공 처리하지 않는다. 재생 완료는 기기의 출력 큐 완료이며 실제 청취를 증명하지 않는다. 정확한 단어별 재생 경계를 아직 모르므로 중단 응답 전체를 근거에서 제외한다.
- 단기 키 직접 연결의 탈퇴 직후 강제 해지, 계정당 진행 대화 제약과 저장 통합, 운영 비용 차단, 미재생 맥락 동기화, 실제 장치·AI 판단 품질은 남는다. 기능/공개 운영 수용 기준 완료를 선언하지 않는다.

## 검증 · 가짜 연결과 실제 공급자 스모크 구분

- `cd app && npm test`: 기존 학습 13개 + 음성 포트/단기 토큰 9개 + 라우트 경계 4개 = **26개 통과**. setup 확인 전 입력 차단, 여러 음성 파트, 생성/재생 구분, 중단 후 늦은 완료, 종료 후 이벤트 무시, 입력 역압·연결 시간 제한, 무료 시험 설정, 토큰 제약/발급 간격, 같은 출처/인증/시험 확인·캐시 금지를 확인했다. 공급자·DB 인증 자체는 가짜이므로 실제 계정 보안 전체 검증이 아니다.
- `npm run typecheck`, `npm run build`: 통과. `/voice`와 `/api/voice/token` 포함 빌드 성공. 새로운 Next.js 코드 전 설치본 route handler 가이드를 읽었다.
- PC/모바일 Chromium 가짜 마이크·토큰·WebSocket 브라우저 시험 **4개 통과**. 시작 확인, 전사/실제 출력 큐 완료 표시, 종료 시 마이크 해제, 권한 거부 시 토큰 미발급, 화면 가로 넘침 없음을 확인했다. 실제 마이크/스피커·모바일 기기·청취 시험이 아니다.
- 환경 한계와 해소: Playwright Chromium이 없어 `/tmp/talkie-playwright`에 headless shell을 받았다. 이후 `libasound.so.2`가 없어 시스템 의존성 설치를 승인받았으나 sudo 암호가 필요해 설치하지 못했다. Ubuntu `libasound2t64` 패키지만 `/tmp`에 다운로드/추출하고 `LD_LIBRARY_PATH`로 시험 프로세스에 제공했다. 시스템 패키지 변경은 없다. 재현 명령: `PLAYWRIGHT_BROWSERS_PATH=/tmp/talkie-playwright LD_LIBRARY_PATH=/tmp/talkie-browser-libs/usr/lib/x86_64-linux-gnu npm run test:e2e -- voice.spec.ts`. 일반 설치 환경에서는 README 명령을 따른다.
- 실제 공급자: 사용자가 `app/.env`의 키가 **talkie 무료 프로젝트** 키라고 확인한 뒤 로컬 비공개 시험 플래그를 활성화했다. 키 값은 출력하지 않고 `.env` 추적 제외를 확인했다. 결제/등급/클라우드 설정을 변경하지 않았다.
- 단기 토큰 HTTP 200·제약된 WebSocket setup 성공을 확인했다. 임시 진단 클라이언트의 첫 수신은 Node의 Blob을 문자열로 파싱해 실패했으며 공급자 장애가 아니다. 디코더를 수정한 합성 문장 1회 요청에서 음성 13개 청크와 전사 수신을 확인했다. 이어 재현 가능한 `npm run voice:smoke`를 추가해 **실제 제품 Gemini 어댑터**로 고정 합성 문장 1회·음성 **13청크, 124,322 bytes**·전사 수신 성공을 확인했다. 원본 음성과 전사 내용은 저장/출력하지 않고 수신 여부·청크/바이트 수만 출력했다. 공급자 청구 콘솔의 실제 금액은 별도 조회하지 않았다. 이 결과는 지연/품질 기준선이나 전체 앱 E2E 완료가 아니다.
- 근거: [단기 토큰 공식 안내](https://ai.google.dev/gemini-api/docs/live-api/ephemeral-tokens), [Live API 규약](https://ai.google.dev/api/live), [오디오 가이드](https://ai.google.dev/gemini-api/docs/live-api/capabilities), [공식 SDK live.py](https://github.com/googleapis/python-genai/blob/main/google/genai/live.py), [tokens.py](https://github.com/googleapis/python-genai/blob/main/google/genai/tokens.py). REST 예시와 설치 SDK의 필드 변환 차이를 확인해 `bidiGenerateContentSetup`·제약된 연결 엔드포인트를 사용했고 실제 요청으로 확인했다. 미리보기 API라 향후 규약 변경 가능성이 있다.

### 시험 환경과 한계

- 현재 WSL에서 Docker 명령을 사용할 수 없고 기존 5433/5434·SMTP 포트도 열려 있지 않았다. `/tmp/talkie-naming-validation`에 Ubuntu PostgreSQL 16.15 서버/클라이언트·libpq 패키지만 다운로드/추출해 시스템 설치 없이 별도 15433/15434 인스턴스를 실행했다. DB 이름은 `talkie_test_naming_records`·`talkie_test_naming_transcripts`, 루프백 trust는 이 합성 시험 프로세스에만 적용했다.
- Mailpit 바이너리를 같은 임시 폴더에 받아 메모리 메일함·루프백 SMTP 11025/HTTP 18025로 실행했다. Chromium과 오디오 라이브러리는 앞서 받은 `/tmp/talkie-playwright`·`/tmp/talkie-browser-libs`를 사용했다. 장기 서버로 설치하지 않았고 검증 종료 후 두 DB와 Mailpit 프로세스를 종료했다.
- 첫 환경 준비에서 libpq 누락, 도구 호출이 끝난 뒤 백그라운드 DB 종료, DB 시작 직후 접속 준비 전 오류가 있었다. 제품 장애가 아니다. 필요한 라이브러리 추출과 한 검증 프로세스에서 DB 수명 관리·`pg_isready` 대기로 해소한 뒤 위 시험을 통과했다. 재현용 실행기·합성 DB 사본은 `/tmp`에만 있으며 프로젝트 환경/키를 변경하지 않았다.
- 이번 작업에서는 실제 사용자 데이터·실제 공급자 요청·유료 호출·운영 성능·실제 마이크/스피커를 사용하지 않았다. 명명 정리의 검증이며 B-01/B-02/B-05/B-06/B-09/D-03의 남은 제품 수용 기준 완료를 선언하지 않는다.

- design의 현행 API/코드 이름·저장 호환성 계약을 갱신하고 README·하니스 실행 안내·제안서 적용 상태/파일 목록·PROGRESS·CHANGELOG를 연결했다. 이동한 스키마/수명 파일에 직접 연결된 기존 제안서 두 개는 링크 대상만 보정했다. 과거 worklog/CHANGELOG 날짜의 이름과 SQL migration은 보존했다.
