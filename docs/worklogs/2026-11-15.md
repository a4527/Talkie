# 2026-11-15 작업 기록

## 첫 카페 미션 최소 계약 검토안 작성

- 사용자 “이어서 진행하자” 요청으로 PROGRESS 재개 지점 2를 진행했다. [미션 설계](../design/MISSIONS.md)·[API](../design/API.md)·[DB](../design/DATABASE.md)·PRD 4~6·8절과 현재 코드(`app/src/server/learning.ts`·`records-schema.ts`·`transcripts-schema.ts`·`voice/learning.ts`·`note-extraction.ts`)를 대조했다.
- 코드 확인 사항: 서버 `readConfirmed`가 확정 순번까지의 저장을 턴 ID로 병합하므로 클라이언트 128 KiB 창과 별개로 전체 대화 재구성이 가능하다. 실시간 구조화 도구는 교정/재시도용 하나이며 미션 진행 도구는 없다. 노트 추출 상한은 6청크×30,000자다.
- [검토안](../proposals/FIRST-MISSION-MINIMUM-CONTRACT.md)에 C1~C6 추천과 대안, 시작 API 형태, 승인 질문 Q1~Q4, 승인 후 검증 계획을 적었다. 미승인 제안이며 설계 문서·코드·DB는 바꾸지 않았다. 횟수·일수·무진전 임계값은 범위 밖으로 유지했다.
- 문서 대조: 제안서 색인과 PROGRESS 재개 지점 2를 갱신했다. TASK 상태·DEC·CHANGELOG는 바꾸지 않았다(사용자 동작 변경 없음).

## 최소 연결 계약 결정(DEC-086~089)

- 검토안의 Q1~Q4를 질문했다. 사용자 답: Q1 “코드 레지스트리”(추천), Q2 “평가가 끝나면 학습 노트 작성 혹은 학습 노트 작성 후 평가 이런식으로”(분리 순차, 순서는 추천대로 평가→노트로 기록), Q3 “점수 집계만 장기 보관”(추천 아님), Q4 “평가 재시도”(추천).
- Q3은 사용자 데이터 보관 약속의 변경이므로 ADR-088로 남겼다. 해석: 기준별 판정·사유는 DEC-017/018 기간(무료 30일·유료 무기한), 원문 없는 집계는 요금제와 관계없이 탈퇴 전까지 보관한다. 일수 날짜/소급은 여전히 B-12 미정이다. 나머지는 짧은 결정 DEC-086·087·089로 기록했다.
- 반영 순서: PRD 4.5(근거 불일치 재시도·기한 내 미확정 시 점수/일수 없음)·8절(호출 구성·원문 삭제 조건·집계 보관)·11절 색인 → DECISIONS/ADR-088 → [미션 설계 최소 연결 계약](../design/MISSIONS.md#최소-연결-계약)(정의·시작 API·세션 고정·진행 상태·실시간 도구·종료 처리·결과 저장) → DB/API/학습 노트 설계의 연결 문장 → TASKS B-06·B-12 수용 기준 → 검토안 결과·색인·PROGRESS·CHANGELOG.
- 확인 사항: 기존 만료 작업은 `learning_session_notes`만 지우고 `learning_sessions` 행은 남기므로 집계를 학습 세션에 FK로 연결해도 30일 만료로 사라지지 않는다(`app/src/server/maintenance.ts`). 테이블·도구 이름은 가칭이며 코드·DB·TASK 상태는 바꾸지 않았다.

## DEC-087 호출 방식 변경: 동시 호출

- 사용자가 순차 호출에서 첫 호출 성공 시에만 두 번째를 호출하고 실패한 쪽만 재시도하는 방식을 설명하며 순서 추천을 요청했다. 둘 다 성공하면 비용은 같고, 차이는 한쪽이 끝내 실패할 때뿐이라고 비교했다. 노트는 이미 구현됐고 부분 저장을 허용하며 11월 2일 합성 시험 8회에서 구간 실패가 0건이었다. 평가는 기준 누락·근거 불일치 시 전체 재시도라 실패 가능성이 더 클 것으로 추정했다(실측 없음). 이 비교로 노트→평가를 추천했다.
- 사용자가 “그냥 동시에 호출하는게 좋겠다. 그것도 실패한것만 호출하는거잖아. 이게 기존내용이지?”라고 답했다. 기존 기록은 평가→노트 순차이고 동시 호출은 새 내용이라고 정정한 뒤, 사용자 선택에 따라 DEC-087을 동시 요청·실패한 쪽만 재시도로 고쳤다. 원문은 둘 다 확정된 뒤 삭제한다. 절충은 사용자 지적(“하나가 실패한다고 다른 하나를 다시 시도하는게 아니잖아”)에 따라 정정했다. 한쪽 실패로 다른 쪽을 재호출하지 않아 둘 다 성공하면 비용이 같다. 순차보다 비싼 경우는 순차였다면 뒤 호출을 생략했을 때뿐이다. 이어 사용자가 실패 확률이 같으면 각 2회 실패 후 성공해도 두 방식의 호출 수가 같다고 지적해, 기한 안에 결국 성공하면 비용이 같고 차이는 기한 내 한 번도 성공하지 못하는 경우뿐이라고 DEC-087 문장을 다시 정리했다.
- 반영: DECISIONS DEC-087, PRD 8절, 미션 설계(호출 구성·종료 처리, 동시 확정 시 원문 삭제 경쟁), 학습 노트 설계, TASKS B-06, CHANGELOG, 검토안 결과. 코드는 바꾸지 않았다.

## 미션 정의 레지스트리와 시작 고정 구현(B-03 일부)

- 사용자 “진행해” 요청으로 [최소 연결 계약](../design/MISSIONS.md#최소-연결-계약)의 정의·시작 API·세션 고정을 구현했다.
- `app/src/mission/definitions.ts`: 카페 미션 정의 v1(공개 상황·역할·화면 목표, 상대역의 처음 아는 사실/사용자에게 들어야 아는 사실/규칙, 재제조·환불 경로)과 평가표 v1(PRD 4.5.1 목표 6항목 60점, PRD 4.5.2 언어 12기준 4/3/3). 배점 합계·영역별 10점·ID 중복·경로 존재 검증, 버전 조회, 엄격한 시작 요청 파서, 비공개 정보를 뺀 공개 보기.
- 지속 DB `learning_session_missions`와 마이그레이션 `0005_mission_sessions.sql`(drizzle-kit 생성, 검토함). 학습 세션과 같은 트랜잭션에서 생성한다.
- `startLearning`: `mission` 요청은 음성 경로로만 시작하고 현재 유효한 버전을 고정한다. 진행 세션이 있으면 요청값 대신 저장값으로 재개하며, 미션/자유 대화가 서로 재개되지 않게 `LEARNING_MODE_CONFLICT`로 거부한다. `GET /api/learn` 세션 항목에 `mission`을 추가했다. 오류 문구 `INVALID_MISSION`·`MISSION_UNAVAILABLE`을 추가했다. 화면은 아직 미션을 시작하지 않는다.
- 환경 조치: `openid-client`가 lock 파일에는 있으나 `node_modules`에 없어 기존 타입 검사가 실패했다. `npm install`로 lock 기준 3개 패키지를 설치했다(package 파일 변경 없음). 옛 경로(`/learn`·`/api/learning`)를 가리키는 `.next` 캐시의 타입 오류 6건은 `npm run clean`으로 지웠다.
- 검증: `npm run typecheck` 통과, `npm test` 15개 파일·128개 통과(새 `tests/mission.test.ts` 7개: 배점·버전·검증 실패·파서·공개 보기 비공개 정보 제외·경로의 미션 전달/거부). `tests/server.test.ts`에 DB 시험 1개(잘못된 미션/시나리오 거부와 세션 미생성, 고정값 저장, 다른 값 재개 요청 무시, 미션↔자유 대화 상호 재개 거부, 목록의 mission, 소유자 FK·모드 CHECK)를 추가했지만 **실행하지 못했다**. Docker WSL 연동이 꺼져 5433/5434 PostgreSQL에 연결할 수 없었다.
- 남은 일: DB 시험 실행(마이그레이션 적용 포함), 진행 상태 스냅샷, 실시간 미션 도구, 종료 평가/노트 동시 호출, 결과 저장, 선택 화면. TASK 상태는 바꾸지 않았다.

## 미션 DB 시험 실행과 진행 상태 저장(B-03 일부)

- 사용자 “다음 진행해줘” 요청으로 PROGRESS 재개 지점 2를 이어 갔다. Docker 로컬 PostgreSQL 16.15 두 개가 실행 중이어서 `npm run db:migrate`로 개발 DB에 0005를 적용하고, 시험 전용 `talkie_test_mission_records`·`talkie_test_mission_transcripts`를 만들어 `tests/server.test.ts`를 실행한 뒤 삭제했다(합성 데이터만).
- 첫 실행: 27개 중 26개 통과·1개 skip(`PG_BIN_DIR` 없음, 실제 백업/복원). 앞서 작성한 미션 시작 고정 DB 시험은 통과했다. 실패 1개 “reads retained difficulty…”는 [11월 1일](2026-11-01.md)에 원인 미조사로 남긴 것과 같다. 원인: 이 시험만 음성 시험 환경 변수(`TALKIE_VOICE_TEST` 등)를 설정하지 않고 음성 세션을 시작해 `VOICE_TEST_DISABLED`가 났다. 다른 음성 시험과 같은 설정·복원을 넣어 시험 코드만 고쳤다(제품 코드 변경 없음).
- [진행 상태](../design/MISSIONS.md#최소-연결-계약) 구현: `app/src/mission/progress.ts`(경로 사건 4종·무진전 연속 수의 구조 검증, 수락=사용자 턴·직원 확정=상대역 턴, 빈 진행 생략, 재개 시 무진전 0). `server/learning.ts`에 저장 키 `mission`(비어 있으면 생략해 구형 바이트·해시 유지), 확정 순번까지의 사건 ID 누적 병합·무진전 최신값, 저장 시 미션 세션 여부·고정 정의 경로 확인을 넣었다.
- 시험이 찾은 결함: 저장 경로가 턴과 달리 이미 확정된 경로 사건의 변경을 확인하지 않아 충돌 저장이 받아들여지고 이후 복원만 실패할 수 있었다. 저장 시 이력과 대조해 `SAVE_SEQUENCE_CONFLICT`로 거부하도록 고쳤다.
- 검증: `npm run typecheck` 통과, `npm test` 15개 파일·132개 통과(진행 상태 검증·재개 3개, 저장 코덱 호환 1개 추가). 시험 DB에서 `test:server` 29개 중 28개 통과·1개 skip(실제 백업/복원). 새 DB 시험은 정의 밖 경로 거부, 사건 누적·무진전 최신값, 확정 사건 변경 거부, 저장 JSON 키, 재개 시 무진전 0, 자유 대화의 진행 상태 거부를 확인한다.
- 한계: 진행 상태를 만드는 실시간 미션 도구와 클라이언트(`voice/learning.ts`)의 128 KiB 창에서 사건을 함께 다루는 경계는 아직 없다. 경로 ID는 브라우저 스냅샷에 포함된다(상대역 비공개 정보 아님).
- 문서 대조: MISSIONS 최소 연결 계약 상태·진행 상태 구현 메모, API `save` 행, LEARNING-PERSISTENCE 미션 필드 문장, PROGRESS 재개 지점 2·B-03 행을 갱신했다. 사용자 동작 변경이 없어 CHANGELOG·TASK 상태·DEC는 바꾸지 않았다.
