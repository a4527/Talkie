# 2026-10-29 작업 기록

## 실제 장치 음성 시험 재개 준비

- 마지막 체크포인트에 따라 로컬 시험 환경을 다시 준비했다. WSL의 `docker` 명령은 통합 안내와 함께 실패했지만 Windows `docker.exe`로 엔진과 기존 records·transcripts PostgreSQL 및 Mailpit 컨테이너의 healthy 상태를 확인했다. 컨테이너·볼륨·스키마는 변경하지 않았다.
- Next.js 개발 서버를 실행하고 `/account`·`/voice`·Mailpit의 HTTP 200 응답을 확인했다. 서버 환경의 API 키 존재 여부와 비공개 무료 시험 설정만 확인했으며 비밀값은 출력하지 않았다. 설정 확인은 공급자 계정의 실제 무료 등급 검증이 아니다.
- 실제 마이크 입력·청취·끼어들기·종료 확인은 사용자 장치 시험으로 남는다. 이번 준비에서 공급자 호출·단기 토큰 발급은 수행하지 않았다. 실행/시험 절차는 [README](../../README.md#gemini-live-비공개-음성-시험)를 따른다.
- 문서 대조: [음성 설계](../design/VOICE.md)의 비공개 시험 범위와 [TASKS](../TASKS.md)의 B-02/B-09 미완료 상태, [PROGRESS](../PROGRESS.md)의 실제 장치/학습 통합 미완료 설명을 유지한다. HTTP 응답은 인증·DB 처리·음성 동작의 검증 근거가 아니다. 코드·요구사항·구현 계약 변경이 없어 해당 기준 문서와 CHANGELOG는 변경하지 않았다.

## 사용자 직접 음성 시험 결과

- 사용자가 여러 번 시험을 시도한 뒤 “음성 시험 문제 없어”라고 보고했다. 현재 `/voice` 비공개 시험에 대한 사용자 확인이며 에이전트가 직접 청취하거나 계측한 결과는 아니다. 장치·브라우저·개별 시나리오별 결과와 지연·품질 수치는 수집하지 않았다.
- 반복 시험 중 표시된 대기 안내는 앱의 계정별 토큰 재발급 4분 제한임을 코드로 확인해 설명했다. 로그인 만료나 Gemini 자체의 필수 재접속 대기 시간이 아니며 제한·토큰 설정·화면 문구는 변경하지 않았다.
- PROGRESS에 사용자 보고를 반영했다. 교정 상태·저장/재개·노트 통합과 개별 검증은 남아 B-02/B-09의 IN PROGRESS 상태를 유지한다. 제품 변경이 없어 CHANGELOG·PRD·설계는 유지한다.
- 문서 대조: TASKS의 완료 기준과 VOICE의 미통합 경계를 확인했다. 관련 링크 대상과 git diff --check를 확인했으며 이번 범위의 상태 불일치는 없다. 코드 변경이 없어 추가 자동 시험이나 공급자 호출은 수행하지 않았다.

## 비공개 음성 저장 학습 연결

- 사용자 요청 “진행해”에 따라 DEC-055의 기존 로컬 E2E 범위 안에서 `/voice`에 저장 학습 시작/재개·중단·종료를 추가했다. 기존 메모리 전용 시험을 유지하고, 저장 학습은 기존 계정별 연결 소유·진행 대화 유일성·두 DB 저장 순번·종료/원문 정리 계약을 재사용한다. 공개 사용자·유료 호출·운영 경로를 새로 채택하지 않았다.
- 음성 포트에 입력 완료·구조화 학습 결과/취소를 연결했다. Gemini 도구의 교정/재시도는 원문 일치·재생된 교정 표현을 검증한 뒤 기록한다. 중단된 출력·늦은 재생 확인·근거 불일치·도구 취소는 교정 근거에 반영하지 않는다. 앱이 언어 판단을 새로 만들지 않는다. 실제 도구 출력 순서/호출 여부와 전사/교정 품질은 공급자 연결로 추가 검증해야 한다.
- 확인된 최근 턴/상태를 저장·재개 맥락과 연결하고 저장 실패/응답 유실 시 같은 순번·본문부터 재전송한다. 미저장 버퍼 제거는 누락을 표시하고 이미 저장한 과거 기록은 서버에 유지한다. 종료는 잔여 저장 뒤 근거 노트를 정리하며 실패 시 화면 메모리를 유지해 자동 재시도한다. 3분 시험 제한과 발급 후 4분 재발급 제한은 유지하며 안내 문구만 앱 제한임을 명확히 했다.
- 음성 노트는 저장된 최근 사용자 근거·재생/근거 검증을 통과한 교정/재시도 일부를 모은 통합 시험 결과다. 전체 P0 형식·네 기준의 AI 선별/요약 품질·개인별 장기 상태·소재 선택/반복 회피·중단 중 공급자 내부 맥락의 정확한 동기화는 미완료다. 새 노트 공급자 호출이나 실제 사용자 데이터 시험은 하지 않았다.
- 기존 저장 구분 컬럼의 값 제약에 `voice`만 추가하는 마이그레이션을 생성·SQL 검토했다. 기존 값·JSON 키/해시·테이블/데이터를 바꾸지 않으며 일반 로컬 DB와 별도 합성 시험 DB에 적용했다. 진행 대화의 음성/텍스트 방식을 자동 전환하지 않고 원래 화면에서 재개하도록 한다.

### 자동 검증과 환경

- 앱 단위/라우트: `npm test` **35개 통과**. 입력 완료/재생 완료 구분·구조화 교정/재시도 복원·중단/취소/근거 불일치 제외·동일 저장 재전송·연결 소유 확인을 포함한다.
- PostgreSQL: 별도 `talkie_test_voice_records`·`talkie_test_voice_transcripts`에서 **24개 통과, 1개 skip**. 새 음성 저장/재개·다른 계정/잘못된 연결 거부·방식 충돌·노트 지속 저장 후 원문 삭제와 기존 저장/인증/경쟁 검증을 포함한다. `pg_dump`/`pg_restore` 실행 환경이 없어 실제 백업/복원 시험 한 개는 skip했으며 이번 변경의 백업 복원 검증 완료로 보지 않는다.
- PC/모바일 Playwright: `voice.spec.ts`·`learning.spec.ts` **16개 통과**. 음성 교정→중단→상태 재개→재시도→종료/노트 표시와 기존 텍스트 흐름을 가짜 WebSocket·합성 마이크/API로 확인했다. 실제 Gemini 도구·마이크·청취 품질 검증은 아니다.
- 브라우저 실행 파일과 `libasound.so.2` 부재로 첫 실행이 실패했다. 시스템 의존성 설치는 sudo 암호가 없어 실행하지 못했다. Chromium을 `/tmp/talkie-playwright`에 받고 Ubuntu `libasound2t64` 패키지를 `/tmp/talkie-browser-libs`에 추출해 시험 프로세스의 `LD_LIBRARY_PATH`로만 사용했다. 시스템 패키지는 변경하지 않았다.
- 타입 검사·프로덕션 빌드·`git diff --check`를 확인했다. 이번 구현 중 실제 공급자 호출·단기 토큰 발급·유료 호출은 수행하지 않았다. 앞선 사용자 직접 시험 결과는 새 저장/도구 통합 이전 범위다.

### 문서 대조와 한계

- 기준 설계 VOICE·LEARNING-PERSISTENCE·API·DATABASE와 DESIGN의 현재 경계, 실행 README를 맞췄다. PRD와 유효 DEC의 제품 약속·보관 기한·공급자 예외 범위는 유지한다. 새 중요 결정을 채택하거나 기존 ADR의 당시 판단을 다시 쓰지 않았다.
- TASKS의 B-04는 구조화 교정/재시도 기록 구현을 시작해 IN PROGRESS로 변경했다. B-02/B-05/B-06/B-09도 미완료 상태를 유지한다. 실제 공급자 품질·전체 AI 선별·운영 비용/동시성/직접 연결 강제 해지 등 기존 완료 기준을 줄이지 않았다. PROGRESS·CHANGELOG에는 현재 범위와 검증/미검증을 요약했다.
- 변경 문서 10개의 로컬 링크/절 앵커 186개와 작업 ID/상태·관련 정책/설계·검증 근거를 대조했다. 이번 범위의 남은 링크/상태 불일치는 없다. 비밀값·원본 음성의 파일/로그 저장을 추가하지 않았으며 사용자 전사/노트는 인증/소유자 검사를 거친 기존 저장 API로만 처리한다. 커밋/push는 수행하지 않았다.
- 외부 관찰: [Google Live API 도구 문서](https://ai.google.dev/gemini-api/docs/live-api/tools)는 설정의 함수 선언과 명시적 도구 응답을, [WebSocket 참조](https://ai.google.dev/api/live)는 `clientContent`·`toolResponse`와 메시지 계약을 설명한다(2026-10-29 조회). 이 공식 계약을 구현 참고로 사용했으며 해당 모델이 실제로 정확한 교정 도구를 호출한다는 실측 증거로 취급하지 않는다.

- 최종 로컬 준비: 추가 마이그레이션 적용과 최종 빌드 후 개발 서버를 다시 실행하고 `/voice` HTTP 200을 확인했다. 새 저장 학습은 브라우저에서 직접 시험할 수 있으며 실제 공급자 구조화 결과의 검증 완료로 확대하지 않는다.

## 영어 발화의 한글 음차 표시 제보와 전사 설정 보완

- 사용자가 영어 발화가 가끔 “도파이브 코딩 유즈 AI”처럼 한글로 표시된다고 제보했다. 원본 음성/정답 전사문은 확보하지 않았고 같은 발화를 재현하지 못했다. 앱은 `inputTranscription.text`를 그대로 표시하므로 앱의 한글 변환은 관찰되지 않았다. 언어 힌트 없는 자동 감지의 오인식 가능성이 있으나 이 사례의 원인으로 확정하지 않는다.
- [공식 WebSocket 참조](https://ai.google.dev/api/live#AudioTranscriptionConfig)(2026-10-29 조회)에서 `languageCodes`가 언어 힌트이며 비어 있으면 자동 감지, `VERBATIM`이 원문 전사 모드임을 확인했다. 영어/한국어 두 언어 힌트와 VERBATIM을 명시했다. 영어 원문·실제 한국어 보존과 불확실한 인식의 확인 요청을 튜터 프롬프트에 보완했으며 언어 강제 고정·문자열 역음차·공급자 교체는 하지 않았다.
- 한국어 도움·교정/재시도 책임·공급자 데이터 조건과 보관 정책은 유지한다. VOICE 기준 설계와 실행 설정을 맞췄으며 실제 발화의 인식 개선 효과는 직접 재시험이 필요하다.

- 검증: 앱 단위/라우트 35개와 타입 검사·git diff --check 통과. 변경 설정으로 `npm run voice:smoke`를 한 번 실행해 실제 공급자의 단기 토큰/연결·음성 13청크(126,722바이트)·출력 전사 수신을 확인했다. 고정 합성 텍스트 입력이므로 실제 마이크 입력의 언어 감지나 해당 제보의 개선 효과·구조화 교정 도구를 검증한 것은 아니다. 발화/음성 내용·키·토큰은 출력하지 않았다.
- 문서 대조: PRD의 한국어 도움과 불확실한 인식 처리·B-02/B-04/B-09의 미완료 기준을 유지했다. VOICE·PROGRESS·CHANGELOG와 이번 검증 근거를 연결했으며 관련 링크/상태의 추가 불일치는 없다. 이미 연결된 시험에는 설정을 소급 적용하지 않으며 새 연결로 재시험한다.

## 사용자 저장 학습 시험 완료 보고

- 사용자가 저장 방식·중단 재개 기한·`transcript_saves`와 노트 저장 후 임시 원문 삭제 흐름을 확인한 뒤 “그럼 테스트 완료했어”라고 보고했다. 이번 비공개 저장 학습 시험에 대한 사용자 완료 보고로 기록한다. 에이전트가 해당 사용자 세션의 DB 행이나 실제 음성을 직접 관찰한 결과는 아니며 개별 시나리오·장치·지연 수치는 수집하지 않았다.
- 실제 공급자의 구조화 교정/재시도 출력 정확도·전사 언어 힌트의 개선 효과·난이도/교육 규칙·전체 AI 노트 선별 품질을 모두 통과했다고 확대하지 않는다. B-02/B-04/B-05/B-06/B-09는 IN PROGRESS를 유지하고 PROGRESS의 사용자 시험 결과를 연결했다.
- 문서 대조: TASKS 수용 기준·VOICE의 미완성 경계와 일치하며 정책/설계/코드 변경은 없다. CHANGELOG는 기존 기능 변경 기록을 유지한다. 관련 worklog 링크와 git diff --check를 확인했다.

## 구조화 학습 합성 음성 스모크

- 사용자 “다음 진행해줘” 요청에 따라 B-04/B-09의 실제 공급자 구조화 결과 확인을 다음 단계로 진행했다. `app/scripts/smoke-voice-learning.ts`와 `npm run voice:smoke:learning`을 추가했다. 고정 가상 문장을 로컬 `espeak-ng`로 생성하고 PCM16 16kHz로 변환해 실제 어댑터에 보낸다. 첫 응답 뒤 재시도 문장을 보내며 근거 검증을 통과한 교정·성공 재시도가 기록돼야 통과한다. 실제 API의 판단을 가짜 결과로 대체하지 않는다.
- 시험당 무료 설정 확인·단기 토큰 하나·연결 하나·연결 시험 60초·자동 재시도 없음이다. 기존 토큰/도구 설정과 제품 동작은 변경하지 않았다. 출력은 연결 여부·전송/수신량·도구/턴/교정/재시도 개수·제한된 오류 코드뿐이며 원문·음성·키·토큰·공급자 오류 본문을 출력하지 않는다. 재생 완료 신호는 모의이며 DB 쓰기·실제 청취·마이크 검증은 하지 않는다.

### 적용과 검증

- 기준 VOICE의 답변 완료/근거 연결 계약을 먼저 보완했다. 앱 어댑터에 실제 출력 시작 여부를 추가해 도구만 완료된 단계에서 근거 연결을 지우지 않도록 고쳤다. 중단 시 대기 연결은 버린다. 새 기능·공급자 선택·보관 정책·학습 판단 규칙을 채택하지 않았다.
- 시험 스크립트에서만 토큰 제약과 초기 설정 양쪽에 자동 발화 감지 해제를 동일하게 적용하고 발화 시작/끝을 명시했다. 앱의 실제 마이크 설정·프롬프트는 유지한다. 음성이 있는 응답에만 모의 재생 완료를 보내고 출력 없는 단계와 실제 답변을 구분한다. 연결 단계·도구 원문/교정 표현 일치 여부와 재시도 판정 누락을 내용 없이 진단하도록 했다.
- 회귀 테스트에서 기존 구현의 조기 완료 실패를 먼저 확인한 뒤 수정했다. 정상 후속 출력의 교정 기록·출력 전 중단 시 근거 폐기 테스트를 추가했다. 앱 단위/라우트 **37개 통과**, 타입 검사·프로덕션 빌드 통과. 브라우저의 저장/재개 시험에도 도구만 완료된 이벤트를 넣어 **PC/모바일 음성 시험 6개 통과**했다. 모두 가짜 공급자와 별도로 구분한다.
- 기본 Playwright 명령은 같은 프로젝트의 기존 3000 개발 서버와 중복 실행돼 Next 개발 서버 잠금으로 실패했다. 기존 서버를 중단하지 않고 `/tmp/talkie-voice-playwright.mjs`의 임시 설정으로 3000 서버를 재사용했다. 브라우저 실행 파일과 ALSA 경로는 앞선 `/tmp` 환경을 재사용했다. DB/운영 환경/실제 사용자 기록은 검증하지 않았다.
- 실제 재검증은 위 표처럼 교정 기록까지 확인했지만 재시도 판정 도구가 누락돼 실패했다. 한 사례의 교정 기록은 전반적인 교정 품질·재시도 규칙 준수의 증거가 아니다. 도구 누락 원인의 모델 내부 판단은 미확인이고 앱이 결과를 추정하지 않는다. 추가 호출·프롬프트 실험은 이번 단계에서 수행하지 않았다.
- 외부 관찰: [Google Live API 안내](https://ai.google.dev/gemini-api/docs/live-api/capabilities)의 자동/수동 VAD와 [WebSocket 계약](https://ai.google.dev/api/live)의 `activityStart`/`activityEnd`, 전사/출력 메시지를 참고했다(2026-10-29 조회). 공급자 문서가 이번 실측 결과나 품질을 대신하지 않는다.
- 문서 대조: VOICE 기준 계약·README 실행 범위·PROGRESS 현재 결과·CHANGELOG 오류 수정을 맞췄다. PRD·유효 DEC·TASKS B-02/B-04/B-09의 기존 수용 기준과 IN PROGRESS 상태를 유지한다. 이전 worklog의 당시 실패 기록은 보존하고 이번 후속 근거를 연결했다. 관련 링크/앵커와 `git diff --check`를 확인했다. 커밋/push는 하지 않았다.

## 재시도 판정 프롬프트 보완

- 사용자가 “프롬프트로 지정을 해야하는거 아니야?”라고 지적했다. 기존 설정에는 매 발화마다 학습 도구를 호출하라는 일반 지시가 있었지만, 교정 후 대기 상태·실제 재시도 판정·성공/실패에 따른 다음 대화 지시가 부족했다. PRD 4.3/F-05와 DEC-010의 기존 AI 판단 책임 안에서 기준 VOICE와 프롬프트/도구 설명을 구체화했다. 새 제품 정책이나 앱의 강제 교육 진행 제어는 추가하지 않았다.
- 교정 시 정확한 표현을 발화하고 다시 말하기를 요청하며 `retry`를 기록한다. 기존 교정의 실제 재시도에는 새 교정을 복제하지 않고 성공/실패와 다음 상태를 전달하도록 했다. 불확실한 인식은 판정을 보류하고 주제 변경/거절은 실패로 단정하지 않는 기존 제약을 유지했다. 학습 도구/상세 지시는 저장 음성 학습 설정에만 적용하며 토큰 제약과 초기 설정은 기존 공통 생성 함수를 재사용한다.
- 실제 무료 합성 음성 시험 1회(`npm run voice:smoke:learning`) **통과**: 도구 호출 2개·사용자 턴 2개·실제 응답 2개·음성 32청크(400,802바이트), 교정 기록 1개·재시도 성공 1개를 확인했다. 첫 결과의 상태는 `retry`, 다음 결과는 `conversation`과 `retryOutcome: success`였으며 두 입력 원문과 교정의 출력 표현 일치 검사를 통과했다. 재시도는 새 교정으로 중복 생성되지 않았다.
- 환경은 바로 앞 조사의 같은 고정 `espeak-ng` 합성 발화·명시적 발화 시작/끝·단기 토큰 한 개/연결 한 개·무료 비공개 설정을 사용했다. 자동 재시도·유료 후보 호출·실제 사용자 데이터·DB 저장은 없었다. 재생 완료는 모의이며 원문/음성/비밀값은 출력하지 않았다. 프롬프트 변경 전 실패와 비교하되 각 시행의 공급자 비결정성과 표본 1개의 한계 때문에 모든 누락 원인의 확정이나 전반적인 교육 품질 보장으로 해석하지 않는다.
- 앱 단위/라우트 37개·타입 검사와 `git diff --check`를 확인했다. 프롬프트 문구만 변경해 이미 통과한 브라우저·빌드/DB 시험은 반복하지 않았다. 성공/실패 구별·불확실 인식·주제 변경·반복 재시도·재개 등 전체 실제 AI 시나리오 평가는 남는다.
- 문서 대조: VOICE의 프롬프트 계약, README의 최신 검증 안내, PROGRESS의 제한된 통과 범위·CHANGELOG·트러블슈팅 후속을 맞췄다. 이전 실패 기록은 보존하고 후속 검증을 연결했다. PRD 요구사항·유효 DEC와 TASKS B-04/B-09의 기존 수용 기준/IN PROGRESS 상태는 유지한다. 관련 로컬 링크·새 절 앵커를 확인했으며 커밋/push는 수행하지 않았다.

## 프롬프트 전체 검토 대기와 다음 재개 지점

- 사용자 요청에 따라 추가 E2E 검증을 후속으로 남기고, 프롬프트는 전체 초안을 먼저 제시한 뒤 사용자 수정·승인을 받기로 했다. 다음 대화에서는 프롬프트 전체를 다시 보여준다.
- 대화에 제시한 10개 절 초안의 내용을 [미승인 제안서](../proposals/VOICE-TUTOR-PROMPT.md)에 정리해 보존하고 PROGRESS에서 연결했다. 이 단계에서 앱 코드·현행 프롬프트는 수정하지 않았다. 앞서 적용한 재시도 지시와 새 전체 초안을 구분한다.
- 문서 대조: PROGRESS의 재개 지점과 제안서의 승인 대기/미반영 상태를 맞췄다. TASK 완료 기준·상태·현행 정책/설계는 바꾸지 않았다. 문서 기록만 변경해 추가 테스트나 공급자 호출은 수행하지 않았다. 링크 대상과 git diff --check를 확인했다.

### 이전 학습 맥락과 난이도 초안 보완

- 사용자 검토 의견에 따라 제안서에 현재 대화 재개와 이전 세션 학습 활용을 구분하고, 주제 중복 회피·새 상황에서의 표현 복습·기초/확장/심화별 질문 부담과 조절 근거를 추가했다. 질문 하나 제한은 난이도에 따른 관련 질문 구성으로 바꿨다.
- 컨텍스트 조회·선별·전달은 앱 책임이며, 제안서는 전달된 데이터의 활용 규칙만 다룬다. 구체적인 컨텍스트 필드·선별 범위·구현은 이번 변경으로 확정하지 않았다.
- 문서 대조: 제안서의 승인 대기/코드 미반영 상태와 PROGRESS의 기존 재개 지점을 유지한다. PRD·설계·TASK 상태나 수용 기준은 변경하지 않았다. 문구 검토와 `git diff --check`를 수행하며, 모델 동작 검증·공급자 호출은 수행하지 않았다.

- 후속 사용자 요청: 난이도 초안의 기초/확장/심화 구분을 없애고 어휘·문장 구조·질문 개방성·설명 부담 등을 현재 응답에 따라 연속적으로 조절하도록 수정했다. 나머지 문구는 유지하고 후속 테스트에서 조정한다. 제안서만 변경했으며 코드 반영·모델 시험은 하지 않았다. 해당 절의 단계 구분 제거와 `git diff --check`를 확인했다.


## 전체 튜터 프롬프트 로컬 MVP 반영

- 사용자 요청 “다음 진행하자”를 앞서 수정한 초안의 로컬 MVP 적용 지시로 받아 반영했다. 실행 원문을 `app/src/voice/tutor-prompt.ts`로 분리하고 기존 공통 setup에서 사용한다. 도구 선언·포트·데이터 저장 방식은 유지하며 기록 도구 지시는 저장 학습에만 붙인다. 서버와 브라우저가 함께 사용하는 모듈이므로 파일 읽기나 서버 전용 의존성을 넣지 않았다. 설치된 Next의 server/client boundary 가이드를 확인했다.
- 현재 응답에 따른 연속 난이도, 관련 질문 구성, 기본 영어/한국어 도움, 이전 학습 활용·주제 중복 회피 규칙을 적용했다. 기존 PRD/DEC-003의 질문 하나 제한과 충돌하는 부분은 사용자의 앞선 변경 지시와 적용 요청에 맞춰 PRD·해당 TASK·사용자 흐름·ADR 후속과 결정 목록 연결을 갱신했다. ADR의 최초 판단은 보존했다.
- 이전 세션의 학습 맥락 조회/선별/전달과 난이도 선택 입력은 미구현이다. 현재는 재개할 대화의 기록만 전달한다. 음성 종료 확인 뒤 앱 종료 연결·노트 AI 선별도 완료로 표시하지 않았다. 프롬프트 문구만으로 해당 앱 기능이 생긴 것으로 취급하지 않는다.
- 검증: 앱 단위/라우트 37개 및 타입 검사 통과. 공통 setup 경로를 사용하는 기존 연결/토큰 테스트를 포함한다. 후속 문구 점검에서 기존 PRD의 기본 영어 원칙을 실행 원문과 검토본에 명시했다. 실제 공급자 호출·추가 E2E·교육 품질 평가는 하지 않았고 이전 스모크 통과를 새 프롬프트의 품질 근거로 재사용하지 않는다.
- 문서 대조: 실행 원문과 적용 검토본, VOICE의 구현/미구현 경계, PRD·DEC-003 후속·TASKS B-03 수용 기준을 맞췄다. B-03은 IN PROGRESS로 바꾸고 PROGRESS와 CHANGELOG에 적용 범위를 요약했다. 관련 링크 대상과 `git diff --check`를 확인했다. 기존 다른 미커밋 변경은 보존했으며 커밋/push는 하지 않았다.


## 이전 학습 복습 표현 컨텍스트 연결

- 다음 단계 진행 요청에 따라 PRD 7/9.2·F-11, DEC-008/010/023의 기존 제한 맥락·앱 선별 책임 안에서 복습 표현 전달을 부분 구현했다. 스키마·보관/삭제 정책·공급자·사용자 범위는 변경하지 않았다. 현재 노트에는 주제/상황의 구조화된 이력이 없으므로 해당 기능을 구현했다고 표시하지 않는다.
- 기준 VOICE에 조회 경계·초기 선택 방식·상한과 미구현 범위를 구체화했다. 서버가 토큰 발급 전 로그인·본인 음성 연결을 확인하고 본인의 종료/노트 준비 완료·미만료 음성 노트를 모두 검토한다. 노트의 알려진 ‘다음 복습’ 형식에 있는 표현만 읽고 중복을 합쳐 마지막 노트 등장 날짜가 오래된 표현 최대 2개를 고른다. 표현 1,200 UTF-8 바이트·직렬화 결과 4 KiB의 로컬 초기 상한이며 초과 표현은 생략한다. 모르는 노트 형식·빈 기록은 내용을 추정하지 않는다.
- 토큰 응답→브라우저→음성 포트→공급자 연결까지 `priorLearningContext`를 전달한다. 이전 표현은 현재 대화의 재시도 대기·숙달 근거가 아닌 별도 데이터로 표시하고 현재 대화 snapshot과 구분한다. 노트 전문·계정 정보·과거 전체 원문을 공급자에 보내거나 로그에 남기지 않는다. 메모리 전용 시험의 응답은 유지한다. 실제 주제/상황 선택·이전 수행 근거에 따른 시작 난이도·AI 복습 품질은 남는다.
- 검증: 앱 단위/라우트 **40개**, 타입 검사 통과. 표현 중복/오래된 이력 포함/Markdown 인용 복원/상한·미지원 형식 제외/현재 맥락과 분리 전송을 확인했다. 별도로 생성한 `talkie_test_prior_*` DB 두 개에서 서버 **24개 통과·백업 시험 1개 생략**. 새 세션 상태 초기화·본인 복습 조회·다른 계정 격리·만료 제외를 추가 검증했다. 시험 DB는 종료 후 제거했고 기존 앱 DB는 초기화하지 않았다. 설치된 Next route handler 가이드를 확인했다.
- PC/모바일 가짜 공급자 브라우저 **6개 통과**. 기존 저장/재개/종료 시험에서 이전 표현이 별도 메시지로 두 연결에 전달되는지 확인했다. 첫 시도는 브라우저 경로 미지정, 다음 시도는 과거 임시 설정의 3000 서버 부재로 실행 전 실패했다. 기존 `/tmp` 브라우저·ALSA 경로를 지정하고 정식 Playwright 설정이 별도 3100 개발 서버를 실행하도록 해 통과했다. 실제 공급자 호출·사용자 음성·교육 품질·운영 부하는 검증하지 않았다.
- 문서 대조: VOICE 기준 계약, API 응답, README 실행 범위, PROGRESS/CHANGELOG와 TASKS B-07의 IN PROGRESS 상태를 맞췄다. B-03/B-09 및 B-07 전체 수용 기준은 미완료로 유지한다. PRD·기존 유효 DEC와 충돌하는 보관/데이터 정책 변경은 없으며 관련 링크 대상과 `git diff --check`를 확인했다. 기존 다른 변경은 보존했고 커밋/push는 하지 않았다.

## 노트 단일 저장 형식 생성·검증·읽기 구현

- 사용자 “진행해” 요청으로 새 [노트 형식](../design/LEARNING-NOTE.md)을 코드에 반영했다. note-context.ts에서 버전 표식·상단 세 구획·하단 앵커/짧은 근거를 렌더링하고 다시 읽는다. 별도 맥락 테이블·JSON 열·영속 사본·스키마 이관은 추가하지 않았다.
- buildVoiceNoteMarkdown은 확인된 원문·재생된 교정 표현·실제 존재하는 재시도만 새 형식으로 기록한다. 기존 최근 교정 최대 3개의 로컬 범위를 유지한다. 메모리 후보의 근거 검증/부분 제외를 지원하되 실제 AI 종료 추출 호출은 아직 연결하지 않았다. 주제·난이도 추출 결과가 없으면 확인된 정보 없음으로 표시한다. 현재 snapshot에 턴별 시각이 없어 자동 생성 연습일은 미확인이다. 과거 노트 등장일도 실제 연습일로 반환하지 않는다.

- 서버는 주제/복습의 기존 최근 6개월 조회와 별개로 보관 중인 본인 음성 노트에서 최신 유효 난이도를 조회한다. 최신 날짜의 상충 관찰을 함께 유지한다. 조회/전달은 합성 노트로 확인했으며 실제 AI 난이도 생성·주제 후보 선택·복습 교육 품질은 미완료다. 난이도 조회는 유효 노트 본문을 읽는 초기 구현으로 대규모 성능은 미측정이다. 기존 임시 개수/바이트 상한을 최종 정책으로 확정하지 않았다.

- 문서 대조: PRD·DEC-010/012/023의 기존 책임·노트 단일 저장·조회 범위를 유지한다. LEARNING-NOTE/VOICE/LEARNING-PERSISTENCE/API의 구현 경계와 README·PROGRESS·CHANGELOG를 맞췄다. B-03/B-05/B-06/B-07/B-09는 IN PROGRESS를 유지하며 실제 AI 추출과 전체 P0 노트 완료로 확대하지 않는다. 관련 링크와 git diff --check를 확인했다. 기존 미커밋 변경을 보존했으며 커밋/push는 없다.
