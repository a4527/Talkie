- 다음 논의를 위한 [첫 미션 상세 검토안](../proposals/FIRST-MISSION-DETAILS.md)을 작성했다. 다섯 항목과 비용/경험/평가 절충을 적었으며 모두 미승인이다. 카페의 구체 음료 조건·배점은 기존 사례 또는 새 제안이지 이번 승인 범위가 아니다.

- 남은 미정: 난이도 단계/평가표·카페 상세 계약·판정 불가/재시도 범위·무진전·평가/노트 호출 구성·횟수/일수와 API/DB 계약. 설계/검토안으로 연결했다.
- 코드 변경·외부 호출·사용자 데이터 접근/로그 변경은 없다. 앱 테스트는 실행하지 않는다. 문서 링크와 공백 검사는 아래 결과를 따른다. 커밋은 요청하지 않아 수행하지 않았다.

## 난이도 합의 재확인과 목표 배점 수정안

- 사용자가 초중고급과 다른 난이도 방식을 이미 결정했다고 지적했다. 전날 계획서·worklog·DEC-069·현행 설계를 다시 확인했다. 확인된 합의는 세 단계에 고정하지 않는 확장 가능한 데이터 정의·버전 고정이며, 구체 단계 수·명칭은 해당 기록에 확정돼 있지 않다. 앞선 초중고급 추천은 이 합의를 충분히 반영하지 못해 철회했다.
- 상세 검토안의 난이도를 기존 합의로 되돌리고 언어 평가 예시의 초중고급 전제를 제거했다. 승인된 PRD·DEC를 새 난이도안으로 변경하지 않았다.
- 목표 배점을 더 세세하게 하자는 요청에 따라 카페 목표를 여섯 항목·총 60점의 수정안으로 제시했다. 전달/요청과 최종 해결을 구분하고, 한 발화의 여러 조건 충족·제안만으로 합의 불인정·불필요한 재진술 방지·판정 불가 경계를 적었다. 이 배점은 미승인이며 기존 60/40과 최종 해결 우선 원칙 안의 제안이다.
- 문서 대조: 수정 대상은 미승인 검토안과 오늘 기록뿐이며 TASK 완료·제품 정책·CHANGELOG에 새 승인으로 반영하지 않았다. 코드·공급자 호출은 없다.

## 카페 목표 배점 승인 반영

- 사용자가 세부 배점안에 “일단 그렇게 진행해보자”로 동의했다. PRD 4.5.1절을 기준 위치로 갱신하고 DEC-071에 동의·이유를 기록했다. 독립 항목별 이진 채점·요청과 해결의 구분·한 발화의 여러 조건 충족을 함께 반영했다.
- 제안서의 상세 표와 판정 규칙은 PRD로 이관하고 채택 안내만 남겼다. 미션 설계의 기존 미승인 안내·B-12 검증 기준·PROGRESS·CHANGELOG·제안서 색인을 맞췄다.
- 이번 동의는 목표 배점에 적용한다. 초중고급 세 단계는 다시 도입하지 않았으며 난이도별 평가표·언어 항목 세분화·허용 대안·판정 불가 처리까지 승인으로 확대하지 않았다. 앱/DB 변경이나 실제 AI 평가 완료는 없다. TASK 상태는 유지했다.

## A1~C2 참고 기준 채택과 평가 단위 비교

- 사용자가 난이도안을 채택하고 설명 구체화를 요청했다. PRD 4.1절→미션 설계의 수준별 설명→DEC-073→B-03 수용 기준·PROGRESS·CHANGELOG·제안서 색인을 맞췄다. 데이터 기반 확장과 언어 수준/미션 복잡도 분리·공인 인증 미제공 경계를 유지했다.
- 공식 CEFR 척도를 참고한 수준 설명에 사용자 선택용 설명과 대화 사례를 보강했다. 사례는 자체 구체화이며 세부 채점표/오류 허용 기준이나 평가 품질을 확정한 것은 아니다.

- 미션 설계·B-12·PROGRESS·CHANGELOG·제안서/색인을 맞췄다. 제안서의 채택된 상세 규칙·산술 표는 PRD 링크로 이관했다. 기존 반점 부분점수·판정 불가 배점 제외·만점 0 처리·다른 인정 미션의 당일 달성 유지는 바꾸지 않았다.
- 설계에는 반올림 표시값과 집계 입력 분리·실제 비율 경계 오차 방지·고정 검증 사례를 연결했다. 구체 API/DB 표현·화면 구성·날짜 귀속·소급 집계·수준별 실행 사례는 후속이다.
- 코드·DB·외부 호출·사용자 데이터 접근/로그 변경은 없다. 승인·미구현과 TASK 상태를 유지했으며 앱 테스트는 실행하지 않았다. 실제 화면 사용성과 AI 판정 품질·연결은 미검증이다.
- 검증: 변경/신규 문서의 상대 링크 293개 경로 존재·DEC-080 앵커·`git diff --check` 통과. 표시 반올림과 실제 비율 비교 5개 사례(정확히 80%·미달·초과·부분점수·반올림 경계)를 Decimal/Fraction 산술로 확인했다(앱 테스트 아님). PRD·DEC-080·설계·B-12·진행/변경 요약·제안서의 채택 상태와 남은 미정/미구현 범위를 대조했다.

## 카페 해결 경로 확대 검토

- 사용자가 해결을 다양하게 하고 환불도 추가하자고 제안해 검토안의 재제조 단일 경로 추천을 수정했다. 재제조·주문 취소/전액 환불과 대기 안내 후 경로 전환, 상대역의 선택지 안내·반응 경계를 구체화했다.
- 환불을 기존 온도/카페인 조건의 허용 대안 해결로 인정하는 추천과 판정 불가 제외·경로별 평가표 대안을 비교했다. 실제로 설명하지 않은 카페인 불일치까지 전달 점수를 주지 않으며 제안/요청만으로 완료하지 않는 사례를 포함했다.
- 이번 수정은 제안서·색인·worklog에 한정한다. 재제조 대기·환불 상세 조건·기존 배점 적용은 미승인으로 두고 PRD·DEC·TASK·PROGRESS·CHANGELOG의 승인 정책/상태는 유지했다. 실제 결제·외부 호출·코드/DB·사용자 데이터 접근은 없고 앱 테스트는 실행하지 않았다.
- 검증: 이번 세 문서의 상대 링크 58개 경로 존재·`git diff --check` 통과. PRD 4.5.1절의 허용 대안 문구와 수정 제안의 점수 경계를 대조하고, 환불을 이미 승인된 처리로 표시한 문구가 없는지 확인했다. 실제 환불 역할극·AI 판정 품질은 미검증이다.

## 복수 해결 경로와 카페 환불 승인 반영

- 사용자가 “그렇게 해 다양한 해결 루트가 있고 그 중 하나가 성공하면 되는거지”라고 명시적으로 동의했다. PRD 4.2/4.2.1절에 경로 중 하나의 완료로 성공·경로 변경·카페 재제조/환불 조건을 반영하고 4.5.1절에 환불의 동등 배점 적용을 기록한 뒤 DEC-081을 연결했다.
- 정상 경로 선택 때문에 만점을 줄이지 않으며 성공과 점수/일수는 분리한다. 환불은 허용 대안 해결로 인정하되 실제로 설명하지 않은 문제의 전달 점수를 자동 부여하지 않는다. 최종 합의만 사용하고 이전/최종 경로를 중복 합산하지 않는다.
- 미션 설계에 경로별 완료·최종 선택 근거·직원 역할 정보와 추가 검증 사례를 연결했다. B-03/B-12·PROGRESS·CHANGELOG·제안서 색인의 미승인 표시를 맞췄다. 제안서의 채택된 상세 조건·배점 설명은 PRD/설계 링크로 이관하고 기존 합성 대화는 검토 자료로 유지했다.
- 코드·DB·외부 호출·실제 결제·사용자 데이터 접근/로그 변경은 없다. 승인·미구현과 TASK 상태를 유지하며 앱 테스트는 실행하지 않았다. 다른 음료 교환의 상세·수준별 평가 사례·무진전·API/DB·실제 AI 품질 검증은 후속이다.
- 검증: 변경/신규 문서 상대 링크 304개 경로 존재·DEC-081/PRD 4.2.1절 앵커·`git diff --check` 통과. 양 경로의 목표 만점 60점 유지·카페인 불일치 미전달 시 해당 5점 자동 인정 금지·최종 해결/합의 40점의 산술을 대조했다(앱 시험 아님). PRD·DEC·설계·B-03/B-12·진행/변경 요약과 제안서의 채택 상태를 확인했으며 미구현·수준별 평가/무진전 등 후속 범위를 유지한다.

## 당일 마감 및 main 반영 준비

- 사용자 요청으로 당일 문서 전체 변경을 커밋 대상으로 검토했다. PROGRESS의 긴 결정 나열을 현행 상태·기준 문서·재개 지점으로 줄이고 검토안의 초기 난이도/조사 안내를 후속 채택 상태와 맞췄다.
