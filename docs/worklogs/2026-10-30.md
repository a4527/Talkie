## 분리형 음성 main 통합

- 별도 `voice-cascade` worktree의 비공개 분리형 구현을 `main`에 가져왔다. 사용자 보고에 따르면 분리형 짧은 대화 약 3회에서 전사·응답·재생이 작동했다. Soniox STT 사용액 $0.002298은 전체 세션 비용이 아니며 Gemini 청구액·지연·교육 품질은 미확인이다.
- 사용자가 Google 프로젝트의 무료 등급을 확인했다. 현재 로컬 `app/.env`는 Gemini Live와 분리형 시험을 모두 활성화했고, Soniox 키는 값 출력 없이 독립 worktree의 로컬 설정에서 옮겼다. `.env`는 Git 제외이며 키·음성·전사 원문을 기록하지 않았다. 실제 공급자 호출과 새 지출은 이번 통합에서 수행하지 않았다.
- 코드 검토에서 분리형 요청 토큰으로 임의 문구를 TTS에 보낼 수 있던 경로를 막았다. TTS는 같은 연결에서 서버가 생성한 답변 문구에 한 번만 허용하고 토큰을 학습 세션에 묶었다. 텍스트 요청은 마지막 확인 턴이 사용자 발화인 제한 맥락만 받는다. 화면 기본 경로는 Gemini Live로 정했다.
- `app`에서 타입 검사와 82개 단위/라우트 테스트가 통과했다. 실제 브라우저·마이크·끼어들기·저장 학습·장시간 연결을 이번 main 통합에서 재시험하지 않았다. 현재 단일 프로세스 시험 한도는 공개 배포의 비용 원장이나 클라이언트 맥락의 독립 검증이 아니다. PRD의 실제 사용자 데이터 조건과 B-09·D-03·V-05·C-02 완료는 그대로 남는다.
- 문서 대조: PRD/DEC-055·056의 로컬 예외와 음성 설계의 현재 구현·TASK의 미완료 상태를 확인했다. PROGRESS에는 현재 범위, CHANGELOG에는 사용자에게 보이는 선택 기능, README에는 로컬 실행 절차를 반영했다. 기존 비용·시간 제안은 미승인으로 유지한다.

## Orca WSL Git 확인과 분리형 worktree 생성

- 사용자의 작업 공간 분리 요청과 후속 WSL Git 지원 확인 요청을 처리했다. Orca의 Talkie 등록은 `kind: folder`였고 최초 voice-cascade 생성은 원본 폴더를 공유하는 가상 작업 공간이었다. 실제 Git worktree 생성으로 잘못 보고하지 않고 Git 목록과 대조했다.
- Windows Git의 `dubious ownership` 오류를 Orca 문제의 원인으로 단정한 설명을 정정했다. 설치된 Orca 1.4.243의 `app.asar.unpacked/out/main/chunks/runner-C8F4JwPf.js`를 읽어 WSL 경로를 배포판/Linux 경로로 해석하고 `wsl.exe`로 Git을 실행하는 분기를 확인했다(일반 파일 읽기의 정적 관찰). `host list`에 Windows만 나오는 것은 이 WSL 실행 기능의 부재를 의미하지 않는다. REA 전체 패키지 분석은 완료 결과를 얻지 못해 판정 근거에서 제외했다.
- `project setup-update --kind git` 지원을 확인했다. 전환을 막는 추가 폴더 작업 공간에 빈 셸만 있음을 확인한 뒤, 앞서 만든 중복 voice-cascade만 제거했다. 원본 경로/파일을 유지하고 Git 등록으로 전환했다. 전환 후 Orca가 main/origin/main·56b936b를 정상 조회했다. Windows Git의 전역 신뢰 설정은 변경하지 않았다.
- Orca의 worktree 생성 경로를 WSL의 `/home/taemin/Talkie-worktrees`로 지정하고 main(56b936b)에서 실제 `/home/taemin/Talkie-worktrees/Talkie/voice-cascade`와 `a4527/voice-cascade` 브랜치를 만들었다. 원본의 자식 관계로 등록했다. 별도 에이전트·설정 훅·앱/DB·공급자 호출은 실행하지 않았다. 기존 미커밋 검토 문서는 원본에 보존하며 새 worktree에 자동 복사하지 않았다.
- 제품 정책/설계·TASK 상태 변경은 없으며 기록은 이 worklog에 한정한다. 새 worktree는 구현 전 준비 상태다. Git worktree 목록·새 브랜치/기준 커밋·깨끗한 새 작업 공간·원본 변경 보존과 git diff --check를 확인한다.
