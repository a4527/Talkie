# 2026-11-02 작업 기록

## 분리형 TTS 후보 공식 자료 조사

- 사용자 보고의 Gemini TTS 무료 RPM/RPD 한도에 따른 후속으로 [비용 절감 검토안](../proposals/VOICE-COST-REDUCTION.md#2026-11-02--분리형-tts-후속-후보-조사-미승인)에 Soniox TTS, Google Cloud TTS, Cartesia, 브라우저 음성, OpenAI Speech API의 공개 가격·처리량·제약을 비교했다. 각 수치의 공식 출처는 검토안 표에 연결했다. OpenAI 항목은 OpenAI Docs의 공식 모델·Speech API 문서로 확인했다.
- Soniox TTS REST는 기본 100 RPM·동시 3요청, Google Cloud TTS는 음성 종류별 200~1,000 RPM, Cartesia는 요금제별 동시 2~15요청으로 확인했다. 서로 다른 계량 방식이므로 RPM과 동시성을 같은 처리량으로 환산하지 않았다. 기존 15분 세션·AI 음성 6분 가정으로 Soniox 약 $0.0705, Google Cloud Standard/WaveNet 약 $0.0216의 TTS 부분 비용만 계산했다. 실제 청구액·Talkie 계정 할당량은 확인하지 않았다.
- Soniox를 기존 STT와 결합하는 첫 청취 후보, Google Cloud Standard/WaveNet을 저가 비교 기준으로 제안했다. 공급자 선택·요금제 변경·API 호출·코드 변경은 수행하지 않았다. 실제 한영 발음·지연·끼어들기·데이터 보관/학습 조건은 미확인이다. DEC-054의 요소별 비교와 PRD 공급자 정책에 맞춘 후속 확인이 필요하다.
- 문서 대조: 제안서는 미승인 후보로 기록하고 [PROGRESS](../PROGRESS.md#다음-재개-지점)의 다음 지점을 갱신했다. 채택 결정·제품 약속·구현 변경이 없어 DECISIONS·PRD·DESIGN·TASKS·CHANGELOG의 현행 계약과 상태는 바꾸지 않았다. 링크와 상태를 대조했고 발견된 불일치는 없다.

## Soniox·Google Cloud TTS 비교 준비와 Soniox 호출

- 사용자 요청에 따라 고정된 가상 영어·한국어 문장 각 1개를 두 공급자에 보내는 `app/scripts/compare-tts.ts`와 `npm run tts:compare`를 추가했다. 저장 위치는 Git 제외 `app/.local/tts-compare/`이며 사용자 기록·키·공급자 오류 본문을 파일이나 로그에 남기지 않는다. Google Cloud 경로는 Gemini API 키를 재사용하지 않고 별도 OAuth 액세스 토큰을 요구한다. `/voice`의 TTS 공급자는 바꾸지 않았다.
- Soniox 실제 호출: `npm run tts:compare -- soniox` 1회, `tts-rt-v2`·Daniel 음성·WAV 24 kHz. 영어 50자 188,494바이트/3,162ms, 한국어 24자 168,014바이트/2,723ms. 두 파일은 RIFF/WAVE, 16비트 mono PCM 24 kHz로 확인했다. 이 수치는 네트워크 포함 전체 요청 시간으로 첫 음성 지연이나 청취 품질 판정이 아니다. Soniox 청구액은 미확인이다.
- Google Cloud 실제 호출은 하지 못했다. 현재 환경에 Cloud TTS 프로젝트 자격 정보와 `gcloud`가 없다. 사용자에게 Cloud TTS와 Gemini Developer API가 별도이며 프로젝트·API 활성화·결제·ADC가 필요함을 안내했다. 별도 인증 라이브러리 설치 요청은 중단됐고 설치/의존성 변경은 없다. 비교 스크립트는 짧은 OAuth 액세스 토큰을 받아 Cloud REST API를 호출하도록 준비했다.
- 검증: `npm run typecheck` 통과, `git diff --check` 통과. WAV 형식은 `file`로 확인. 실제 재생 청취, Google Cloud 호출, 같은 조건의 비용/지연 비교는 남는다. TASK 상태 변경 없음.
- 문서 대조: 실행법은 [README](../../README.md#tts-후보만-비교하기), 시험 상태는 PROGRESS에 기록했다. 공급자 채택·제품 정책·음성 경로 설계의 변경은 없어 PRD·DECISIONS·DESIGN·TASKS·CHANGELOG는 변경하지 않았다. 링크·상태 불일치는 발견하지 못했다.
- Cloud TTS 인증 절차를 다시 확인해 REST 요청에 사용자 인증의 과금 프로젝트용 `x-goog-user-project` 헤더를 추가했다. 스크립트는 `GOOGLE_CLOUD_PROJECT`를 요구한다. Google Cloud 호출은 여전히 미실행이며 수정 뒤 `npm run typecheck`·`git diff --check`가 통과했다.

## 두 TTS 후보의 동일 문장 생성 결과

- 사용자가 Cloud TTS 프로젝트 인증을 설정한 뒤 `npm run tts:compare -- google-cloud` 실행 결과를 공유했다. 영어 50자 171,514바이트/898ms, 한국어 24자 162,152바이트/347ms. 결과 파일을 직접 확인해 둘 다 24 kHz·16비트·mono WAV이며 재생 길이는 3.572초/3.377초로 읽혔다. Soniox의 앞선 동일 문장 결과는 188,494바이트/3,162ms와 168,014바이트/2,723ms다. 각각 단 1회·순차 호출이고 네트워크/초기 연결 조건이 달라 안정적인 지연 비교나 첫 음성 지연으로 해석하지 않는다.
- Soniox가 스트리밍 WAV의 RIFF·`data` 길이를 `0xffffffff`로 남긴 것을 파일 검사에서 발견했다. 기존 로컬 WAV 두 개의 헤더 길이만 실제 파일 길이로 보정했고, 비교 스크립트에도 보정을 추가했다. 보정 후 Soniox 영어/한국어 재생 길이는 3.925초/3.499초다. 음성 샘플 데이터는 수정하지 않았다. 네 파일 모두 WAV 파서로 다시 열렸다.
- 비교 결과는 가상 문장 두 개의 생성 성공·파일 형식·전체 요청 시간까지만 보여준다. 사용자의 영어 교정 발음·한국어 도움·한영 혼용·끼어들기 청취 판정과 실제 공급자 청구액·계정 한도는 남는다. `/voice`의 Gemini TTS는 변경하지 않았고 공급자 선택은 미승인이다.
- 검증: 수정 후 `npm run typecheck`와 `git diff --check` 통과. 문서 대조: PROGRESS의 Cloud 미실행 표기를 실제 확인 범위로 갱신하고, TASKS·PRD·DECISIONS·DESIGN의 상태·계약 변경은 없음을 확인했다. 링크·상태 불일치는 발견하지 못했다.

## 분리형 공급자 선택 시험 연결

- 사용자 범위 확정: 이번 비공개 앱 시험은 기존 STT Soniox·LLM Gemini를 유지하고 TTS에만 Google Cloud Standard를 추가한다. `/voice`는 STT·LLM·TTS 선택을 각각 표시하며 현재 앞의 두 단계는 한 후보만 있다. Soniox TTS는 앞선 WAV 비교에만 남긴다. 제품의 최종 공급자 채택이나 공개 배포 결정은 아니다.
- 코드: 선택을 연결 발급 요청에서 검증하고 서버 연결 토큰에 저장한다. 이후 음성 요청에서 브라우저가 보내는 공급자 값을 신뢰하지 않고 연결 토큰의 TTS로 호출한다. Google Cloud는 별도 프로젝트·OAuth 토큰·과금 프로젝트 헤더로 요청하고 WAV에서 24 kHz·16비트·mono PCM만 추출해 기존 재생·중단·근거 흐름에 전달한다. 한글 포함 여부로 한국어/영어 Standard 음성을 고르는 초기 시험 규칙을 적용했다. 5,000바이트 입력 한도 초과·오디오 형식 오류는 실패로 처리한다. 실제 사용자 음성 저장이나 공개 연결은 하지 않았다.
- 검증: `npm test` 117개 통과(선택 검증·연결 토큰 고정·Cloud 요청/PCM 검증 추가), `npm run typecheck` 통과. `npm run test:e2e -- voice.spec.ts`는 첫 실행에서 Chromium의 `libasound.so.2` 부재로 6개 모두 시작 실패했다. 시스템 설치는 sudo 비밀번호가 없어 실패했으며 `/tmp`에 Ubuntu `libasound2t64` 패키지를 추출해 `LD_LIBRARY_PATH`로만 제공한 재실행에서 기존 PC/모바일 6개 통과했다. 선택 UI의 PC/모바일 표시·화면 폭 2개와 선택값 발급 요청 전달 2개를 추가한 뒤 전체 10개 통과했다. 시스템 패키지·프로젝트 의존성은 변경하지 않았다.
- 한계: 새 Cloud TTS의 실제 `/voice` 연결·전체 학습/재생 청취·한영 혼용 발음·토큰 만료·실제 청구액은 미검증이다. 3분 단일 프로세스 비공개 시험의 기존 시간/횟수 제한을 유지하며 B-10의 공개 비용 집행과 다르다. TASK 상태 변경 없음.
- 문서 대조: 구현 계약은 [음성 설계](../design/VOICE.md#분리형-비공개-시험-경로), 실행 조건은 [README](../../README.md#gemini-live-비공개-음성-시험), 현황은 PROGRESS, 사용자 의미 변경은 CHANGELOG에 연결했다. PRD의 제품 약속·DEC-055/056의 로컬 시험 범위·B-09 수용 기준과 대조했고 새 결정은 기록하지 않았다. 발견된 링크·상태 불일치는 없다.

## Cloud TTS 토큰 자동 발급

- 사용자가 매번 `export`해야 하는 불편을 지적했다. 로컬 비공개 시험 경로에서 `gcloud auth application-default login`으로 만든 ADC를 읽어 `gcloud auth application-default print-access-token`을 앱 서버에서 자동 실행하게 했다. CLI가 PATH에 없으면 홈의 `google-cloud-sdk/bin/gcloud`를 찾는다. 단기 토큰은 서버 메모리에 45분까지만 재사용하고 파일·응답·로그에 저장하지 않는다. 만료된 수동 환경 변수 토큰이 우선되지 않도록 앱 시험 경로에서는 이를 읽지 않는다. 프로젝트 ID는 `app/.env`의 `GOOGLE_CLOUD_PROJECT`로 지정한다.
- 검증: 가짜 CLI 시험을 포함한 `npm test` 118개, `npm run typecheck`, `npm run build`, `git diff --check` 통과. 실제 로컬 ADC로 토큰 발급 성공(값 출력 없음), 같은 경로로 Cloud TTS의 고정 합성 영어 문장에서 PCM 105,626바이트 수신. 수동 토큰 환경 변수 없이 `npm run tts:compare -- google-cloud` 실행도 성공해 영어/한국어 WAV를 다시 생성했다. 이는 별도 합성 요청 확인이며 실제 `/voice`의 마이크·학습 E2E는 아니다. 공급자 청구액은 확인하지 않았다.
- 문서 대조: 기준 설계의 Cloud 인증 흐름, README·`.env.example`의 실행법, PROGRESS의 시험 범위, CHANGELOG의 사용자 의미 변경을 갱신했다. 제품 정책·공급자 선택·TASK 상태는 바꾸지 않았으며 링크·상태 불일치는 발견하지 못했다.

## Cloud TTS 앱 청취와 Amazon Polly 후보 보완

- 로컬 앱 서버와 두 DB를 가동하고 마이그레이션을 완료했다. 사용자는 `/voice`의 분리형 Google Cloud Standard 경로를 직접 시험한 뒤 "문제 없어"라고 보고했다. 시험 발화 수·재생 지연·청구액·계정 한도는 측정하지 않았으므로 품질과 비용의 일반화 근거로 쓰지 않는다.
- 누락된 AWS TTS 후보를 공식 [Polly 가격](https://aws.amazon.com/polly/pricing/), [할당량](https://docs.aws.amazon.com/polly/latest/dg/limits.html), [음성 목록](https://docs.aws.amazon.com/polly/latest/dg/available-voices.html)으로 조사해 [비용 절감 검토안](../proposals/VOICE-COST-REDUCTION.md#2026-11-02--분리형-tts-후속-후보-조사-미승인)에 추가했다. Standard $4/100만 문자·80 TPS 기본 한도, Neural $16/100만 문자·8 TPS 기본 한도는 공식 공개값이며 Talkie 계정 실측값이 아니다. 동일 5,400문자 가정의 Standard 비용은 $0.0216으로 Cloud Standard와 같다. Polly 실제 호출·청취·청구·데이터 조건 확인은 하지 않았다.
- DEC-053의 AWS 분리형 경로 제외와 Polly 단독 TTS 요소 후보 조사는 범위가 다르다. 공급자 채택·코드·제품 약속·TASK 상태는 바꾸지 않았다. PROGRESS의 현재 확인 범위와 다음 지점을 갱신했고 PRD·DECISIONS·DESIGN·TASKS·CHANGELOG와 대조해 링크·상태 불일치는 발견하지 못했다.

## TTS 공급자 데이터 조건 후속 조사

- 공식 Cloud TTS 문서는 고객 TTS 텍스트·음성을 로깅하지 않는다고 명시한다. 지역 엔드포인트는 Neural2만 제공하므로 현재 Standard의 전역 호출에 지역 제한을 가정하지 않는다. 공식 Polly 문서는 제출 텍스트 미보관과 입력·출력의 Polly 모델 학습 미사용을 각각 명시한다. 출처와 해석 범위는 [비용 절감 검토안](../proposals/VOICE-COST-REDUCTION.md#2026-11-02--분리형-tts-후속-후보-조사-미승인)에 기록했다.
- 문서상 일반 조건만 확인했다. 현재 계정의 계약·설정, 예외와 메타데이터 처리, 삭제 요청 방법은 확인하지 않았으며 실제 사용자 연결의 DEC-025 충족 판정은 하지 않았다. 공급자 호출·계정 설정·코드는 변경하지 않았다.
- 문서 대조: PRD 8절의 공급자 학습 금지·30일 보관과 제안서의 미승인 상태를 대조했다. TASKS의 B-09/D-03 완료 기준과 PROGRESS의 다음 지점은 유지하며, CHANGELOG에 적을 제품 변경은 없다. 링크·상태 불일치는 발견하지 못했다.

## 기존 Soniox·Cloud TTS 출력 재검증

- 사용자가 기존 두 공급자의 비교를 선택했다. 저장된 동일 문장 WAV 네 개를 재생 가능한 24 kHz·16비트·단일 채널로 읽고, 10ms 창의 진폭 500 초과 구간과 PCM 피크를 확인했다. Cloud 영어 3.572초·유음 약 0.01~3.22초·피크 20,660, 한국어 3.377초·약 0.04~3.03초·22,058. Soniox 영어 3.925초·약 0.05~3.80초·23,193, 한국어 3.499초·약 0.05~3.38초·19,621이다. 네 파일 모두 32,760 이상 샘플이 없어 클리핑은 발견하지 못했다. 유음 구간은 단순 진폭 기준의 근삿값이다.
- 새 공급자 호출 없이 앞선 출력 파일만 검사했다. 길이·진폭은 발음 정확성·자연스러움·첫 음성 지연·반복 호출 성능·실제 청구액을 판정하지 못한다. 청취용 파일을 사용자에게 제공했고 네 샘플 모두 괜찮다는 직접 청취 결과를 받았다. 후보 간 선호·한영 혼용 품질은 판정하지 않았다.
- 문서 대조: 이 검증은 기존 후보 산출물의 형식 재확인으로 TASKS 상태·PRD 제품 약속·공급자 선택을 바꾸지 않는다. PROGRESS의 실제 청구와 품질 평가 미완료 표기는 유지한다. 링크·상태 불일치는 발견하지 못했다.

## Soniox·Cloud TTS 비용만 비교

- 사용자 요청에 따라 같은 영어·한국어 두 문장, 총 74자의 기존 출력을 공개 단가로 비교했다. Soniox의 실제 출력 7.424초와 공식 문자당 약 0.3 입력 토큰·시간당 약 30,000 출력 토큰 가정에서 약 $0.00142, Cloud Standard의 74자×$0.000004는 $0.000296이다. 무료 할당량 제외 시 Cloud가 약 4.8배 저렴하다. 기존 6분 음성·5,400자 시나리오는 Soniox 약 $0.0705, Cloud $0.0216으로 약 3.3배 차이다. 공식 출처·산식·범위는 [비용 절감 검토안](../proposals/VOICE-COST-REDUCTION.md#2026-11-02--분리형-tts-후속-후보-조사-미승인)에 남겼다.
- Cloud Standard/WaveNet의 월 400만 무료 문자 범위에서는 실제 청구액이 $0일 수 있다. Soniox 실제 입력·출력 토큰과 양쪽 실제 청구서는 확인하지 않았다. 이번 요청에서 추가 API 호출은 없고 기존 출력의 추정 TTS 비용만 비교했다. STT·LLM·운영 비용은 포함하지 않았다.
- 문서 대조: 제안서에 비교 산술을 두고 오늘의 조건/결과를 이 기록에 남겼다. PROGRESS의 최종 공급자 미승인·실제 청구 미확인과 TASKS의 D-03/B-09 미완료를 유지한다. PRD·DECISIONS·설계·CHANGELOG의 계약/제품 변경은 없으며 링크·상태 불일치는 발견하지 못했다.

## 사용자 보고 사용액과 후보 비교 중단 요청

- 사용자가 오늘 Soniox 사용액을 STT **$0.002798**, TTS **$0.0014945**로 보고했다. 두 항목의 합은 **$0.0042925**다. 공급자 콘솔·청구서를 직접 조회하지 않았고, 이전에 보고한 STT $0.002298과 오늘 값의 집계 기간 관계도 확인하지 않았다. Google Cloud TTS 청구액은 사용자가 확인할 수 없다고 보고했다. 앞선 동일 문장 단가 산술은 이 실사용 보고를 대체하지 않는다.
- 사용자는 추가 AI 모델 비교를 이 정도에서 넘기고 실제 운영에서 조정하자고 요청했다. 이는 DEC-054의 모든 후보 시험 후 최종 선택 및 D-03의 완료 기준과 충돌할 수 있다. 오늘은 비교 중단 의사와 관찰 사용액만 기록하고, 공개 운영의 공급자 선정·데이터/비용 검증 조건을 바꾸는 결정은 아직 기록하지 않았다. [후속 비교 범위 검토안](../proposals/AI-CANDIDATE-EVALUATION-PLAN.md#2026-11-02-후속-비교-범위-검토-채택)에 절충과 남는 출시 전 조건을 정리했다.
- 문서 대조: 비용 보고와 중단 요청은 이 기록·PROGRESS·검토안에 연결한다. PRD의 실제 사용자 공급자 조건과 DEC-054/055, D-03/B-09 상태는 후속 합의 전 유지한다. 링크·작업 ID·상태 불일치는 발견하지 못했다.

## DEC-066 · 후보 확장 비교 후순위 승인

- 사용자는 [검토안의 B안](../proposals/AI-CANDIDATE-EVALUATION-PLAN.md#2026-11-02-후속-비교-범위-검토-채택)에 “그러자”라고 동의했다. 전 후보 시험을 공개 경로 선택의 선행 조건에서 해제하고 현재 로컬 경로로 기능 개발을 이어간다. 실제 사용자 연결 전에 선택 경로의 데이터 조건·실제 비용/계정 한도·지출 통제·핵심 학습 품질과 저장/접근/삭제를 확인하고 명시적으로 경로를 선택한다. 운영 중 주간 실제 비용·품질·오류에 따라 재평가한다. 현재 경로나 공개 배포를 승인한 것은 아니다.
- [DEC-066/ADR-066](../adr/066-DEFER-EXPANDED-AI-CANDIDATE-COMPARISON.md)에 배경·대안·절충·재검토 조건을 기록했다. 기준 문서인 PRD의 공개 경로 조건, TASKS의 D-03 수용 기준/선행 관계, 음성 설계의 경계, PROGRESS 현황, CHANGELOG의 사용자 의미 변경을 맞췄다. D-03/B-09는 IN PROGRESS이며 Cloud 청구액과 실제 사용자 공급자 조건은 미확인이다.
- 문서 대조: DEC-053/054의 전 후보 시험 범위와 DEC-055의 후속 비교 예정만 DEC-066이 대체하며 로컬 통합·음성 포트·실험 예산·데이터/비용 정책은 유지한다. 영향받은 PRD·TASKS·DESIGN·PROGRESS·CHANGELOG 및 링크·ID·상태를 대조했고 남은 불일치는 발견하지 못했다.

## 종료 노트 병합의 표기 중복 축소

- 분할 구간의 노트 후보를 합칠 때 같은 종류·문구의 연속 공백·줄바꿈·대소문자 차이를 정규화해 하나로 묶고 근거를 합친다. 다른 문구와 종류는 분리한다. 의미가 비슷하지만 문구가 다른 중복이나 AI가 기록된 재시도 결과를 빠뜨리는 문제는 해결 범위에 포함하지 않았다.
- 검증: `npm test -- --run tests/note-extraction.test.ts` 실행에서 전체 119개 통과, `npm run typecheck`·`git diff --check` 통과. 실제 공급자 호출·추가 E2E는 하지 않았다. B-06은 IN PROGRESS로 유지한다.
- 문서 대조: 현재 상태를 PROGRESS에 반영했다. PRD·TASKS·DECISIONS의 계약·완료 기준은 바뀌지 않았고 사용자에게 의미 있는 새 기능도 아니므로 CHANGELOG는 갱신하지 않았다. 직접 연결된 문서의 링크·작업 ID·상태 불일치는 발견하지 못했다.

## B-06 종료 노트 안전성·품질 보완

- 음성 종료 추출에서 모델이 유효 항목을 하나도 내지 못하면 노트를 `ready`로 확정하지 않고 기존 기한 안에서 재시도하도록 바꿨다. 추출 중 새 저장 순번이 확정되면 이전 snapshot의 결과를 버려 최신 저장분을 빠뜨리지 않게 했다. 검증에서 제외한 후보가 있으면 부분 누락을 표시한다. 사용자 발화 없이 AI의 질문만 인용한 주제 후보는 실제 다룬 주제로 저장하지 않는다. 짧은 인사·단답·거절에서 섹션을 억지로 채우지 말고 기록된 재시도 성공·실패를 구분하도록 종료 프롬프트를 보완했다. 확인된 교정의 실패·성공은 모델이 생략해도 앱의 확정 기록에서 렌더링한다.
- 무료 로컬 Gemini 합성 평가를 `retry-mixed`·`short-ack`에 1회씩 예비 실행하고 같은 두 사례를 각 3회 반복했다. 총 8회 호출, 구간 실패 0건, 자동 필수 위반 0건이다. 반복 평가에서는 근거가 사용자 발화 없이 AI 질문뿐인 주제 후보 2건을 제외했다. 짧은 대화 3개 결과는 실제 인사·거절만 요약했고 가짜 교정·복습을 채우지 않았다. 재시도 사례에서는 AI가 성공/실패 관찰을 누락하거나 잘못 귀속하기도 해 검증기가 관찰 표시를 제거했다. 앱의 확정 기록으로 작성한 노트에는 실패 `t4`와 성공 `t6`이 모두 남고 거절 `t8`을 실패로 만들지 않는 자동 시험을 추가했다. 모델의 시제 설명 일부는 문맥보다 강하게 단정해 교육적 정확성은 통과 판정하지 않는다. 원본 출력은 Git 제외 `app/.local/note-eval/`에만 저장했다.
- 검증: `npm test` 121개 통과, `npm run typecheck`·`git diff --check` 통과. 일반 DB를 향한 첫 `test:server` 실행은 시험 DB 이름 검사에서 작업 전에 거부됐다. 별도 `talkie_test_b06_*` DB 둘을 생성해 다시 실행한 결과 25개 통과·실제 백업 복원 1개 skip이며, 빈 결과/추출 중 저장 경합을 포함한다. 추가 브라우저 E2E는 사용자 보류에 따라 실행하지 않았다.
- B-06은 아직 `IN PROGRESS`다. [수용 기준](../TASKS.md#첫-학습-흐름과-기능-구현)의 전체 형식·근거/교육 품질, 실제 음성 종료/시간 경계, 저장 실패·부분 결과 경계와 사용자 직접 품질 판정이 완료되지 않았다. DEC-062의 시간 경계 상세와 B-10의 노트 호출 제한·공개 비용 집행도 미완료다. 이번 보완은 기존 DEC-058/064/065 범위이며 새 제품 결정을 채택하지 않았다.
- 문서 대조: 구현 계약은 [학습 노트 설계](../design/LEARNING-NOTE.md#생성검증저장-순서), 상태는 [PROGRESS](../PROGRESS.md#현재-작업-상태), 사용자 의미 변경은 CHANGELOG에 맞췄다. PRD 요구사항·TASKS 완료 기준·DEC 상태는 변경하지 않았고 링크·작업 ID·상태의 새 불일치는 발견하지 못했다.

## 배포 전 로컬 E2E 실행

- `app/scripts/predeploy-e2e.ts`를 추가했다. 일반·원격 DB를 거부하고 로컬 PostgreSQL 두 인스턴스에 임시 `talkie_test_predeploy_*` DB를 만들어 마이그레이션, 서버 시험, 프로덕션 빌드, PC/모바일 Playwright, 실제 Gemini 고정 합성 입력 스모크를 순서대로 실행한다. 종료 시 시험 DB를 삭제한다. 저장 브라우저 시험에도 시험 DB 이름 검사를 추가했다.
- 브라우저에 실제 HTTP·Mailpit·DB를 연결해 로그인 링크 미리보기·확정, 저장/새로고침·노트, 다른 계정의 기록 비노출, 탈퇴 재확인 후 접근 차단과 옛 쿠키 재사용 거부를 확인했다. 탈퇴 메일은 기존 30초 재요청 제한 뒤 발급되도록 시험을 맞췄다. 음성 브라우저 시험은 가짜 WebSocket·마이크를 사용한다.
- 환경: 2026-11-02 로컬 Docker Compose PostgreSQL 16 두 개·Mailpit, Node 24.22, Next 16.4.2 프로덕션 빌드, Chromium PC/Pixel 7 크기. 시스템에 `libasound.so.2`와 PostgreSQL 클라이언트가 없어 Ubuntu 패키지를 `/tmp`에 풀고 `LD_LIBRARY_PATH`·`PG_BIN_DIR`로 지정했다. `npm run typecheck` 통과. 최종 `npm run test:predeploy:e2e`: 실제 백업/복원 포함 서버 26개와 브라우저 24개 통과, Gemini 음성 9청크·94,560 bytes와 전사 수신, `PREDEPLOY_E2E_PASSED`. 첫 서버 실행에서는 저장/삭제 시각 단언이 1회 실패했으며 이후 여러 재실행에서 통과했다. 원인은 확정하지 못했다.
- 한계: 실제 Gemini 스모크는 합성 텍스트의 단일 연결이며 전체 브라우저 저장 학습과 공급자 응답을 잇지 않는다. 분리형 Soniox/Google Cloud의 이번 실제 E2E, 실제 마이크·청취·기기, 운영 환경의 메일/백업/복원·배포/롤백·데이터 조건·비용 집행은 확인하지 않았다. 품질 판정은 요청 범위에서 제외했다. V-01~03·C-03 등 TASK 상태는 변경하지 않는다.
- 문서 대조: 실행 방법은 README, 현재 검증 범위는 PROGRESS, 변경 요약은 CHANGELOG에 연결했다. PRD·DEC의 승인 범위와 TASK 수용 기준은 바꾸지 않았고 이번 시험으로 완료 판정하지 않았다. 링크·ID·상태의 새 불일치는 발견하지 못했다.

- 결정: 사용자가 배포 전 품질 평가를 제외한 앱 데모 완성을 요청했다. 계획 제시 후 로컬 시연·Mailpit 합성 메일 유지·Google 로그인 포함·음성 경로 선택 유지·현재 디자인 톤에 동의했다(DEC-068). Google 미확정 항목은 명시적 연결만·Google 재인증 탈퇴 확인·`openid-client` 사용으로 정했다([ADR-067](../adr/067-GOOGLE-ACCOUNT-LINKING-AND-REAUTH.md)). 화면 흐름은 [사용자 흐름의 앱 화면 지도](../design/USER-FLOWS.md#앱-화면-지도)에 기록했다.
- 구현: `/`·`/try`·`/login`·`/home`·`/talk`·`/notes`·`/notes/[날짜]`·`/account`와 공통 헤더·노트 렌더러를 추가하고 `/learn`·`/voice` 페이지를 `/talk` 리디렉션으로 대체했다. 음성 로직은 `use-voice-learning` 훅으로 옮겼고 앱의 음성 대화는 저장 학습만 제공한다. `google_identities` 테이블(마이그레이션 0004)과 Google 시작/콜백 라우트, 계정 API의 연결 상태·해제, 학습 조회 응답의 세션 방식·시작 시각·노트 세션 ID를 추가했다. 의존성 `openid-client@6.8.8`(2026-09-05 배포)을 추가했다.
- 검증 조건: 2026-11-02 로컬 Docker PostgreSQL 16 두 개·Mailpit, Node 24.22, Next 16.4.2. 브라우저는 이전과 같이 `/tmp`에 풀어 둔 `libasound.so.2`를 `LD_LIBRARY_PATH`로 지정했다. 실제 DB 시험은 `predeploy-e2e.ts`와 같은 방식으로 만든 임시 `talkie_test_predeploy_*` DB에서 실제 Gemini 스모크만 빼고 실행했다(임시 스크립트, 커밋 안 함).
