# 2026-10-25 작업 기록

## DB 스키마 검토

- 사용자 요청에 따라 [개편 재개 메모](../proposals/database-schema-refactor.md)와 현재 미커밋 구현의 두 스키마·인증/저장/정리 경로·마이그레이션·서버 시험을 읽고 [검토 제안](../proposals/database-schema-review-2026-10-25.md)을 작성했다. 기존 변경을 보존하고 실행 코드·DB·마이그레이션은 수정하지 않았다.
- 현재 11개 테이블의 수명 경계를 유지하며 소유자/작업 대상 제약·실제 조회 인덱스·예약 실행 계약·최근 창 중복 저장/과거 묶음 재검사를 평가했다. PostgreSQL 16 공식 자료의 사실과 적용 제안·미측정 비용을 구분했다.
- DB 카탈로그·사용자 원문·비밀값은 조회하지 않았다. 테스트·EXPLAIN·벤치마크를 실행하지 않았고 코드와 실제 DB의 일치는 미확인이다. 개편안은 미승인이며 D-02/B-01/B-05/B-06은 IN PROGRESS를 유지한다.

## 클로드와 양방향 검토

- `orchestration`·`orca-cli` 스킬로 Orca Claude 검토자를 실행했다. Run `run_f8ae371f53b5` / Task `task_828182c52dd8` / Dispatch `ctx_840337f4a3fe`. 독립 발견을 받고 Codex가 코드 근거로 반론한 뒤 최종 회신을 받았다. 상호 합의는 정책 채택이 아니며 Claude도 파일을 수정하지 않았다.
- 일반 재시도의 내용 변경 충돌은 브라우저 pending 고정으로 범위를 좁혔고, 새로고침 후 메모리 소실 재개의 미확정 번호 충돌은 별도 검증 공백으로 남겼다. 노트 작업의 실제 사용을 확인해 모든 예약 행이 미사용이라는 표현을 정정하고, 인증 잠금 완화·미확정 upsert 제안은 채택하지 않았다. 최종 회신에서 잔여 이견은 없고 성능은 미측정임을 확인했다.

## 검토 당시 문서 정합성 점검

- 후속 질문에 따라 검토서에 계정 생성 시각의 비필수성, 기존 탈퇴 재확인 근거, 최종 권한의 로그인 행 통합 대안, 세 가지 순번의 구분과 임시 상태/이력 통합 대안을 추가했다. 전체 컬럼의 명명 대응표와 11→9개 테이블 대안을 미승인으로 기록했다. 정책 제거·통합에 대한 사용자 동의는 아직 없으며 코드/DB/승인 문서는 변경하지 않았다.

- 제안서를 먼저 작성하고 재개 메모·PROGRESS·CHANGELOG에서 연결했다. PRD/DECISIONS/design의 승인 정책과 TASK 수용 기준/상태를 바꾸지 않았다. 원문 백업 제외·인증 저장 경계·수명 이력·지속 작업 방향과 충돌하지 않으며 새 선택은 미승인으로 남겼다.
- 이번 변경 문서 5개의 로컬 링크 누락이 없고 `git diff --check`를 통과했다. 이전 미커밋 파일을 보존했으며 커밋/push는 하지 않았다. 남은 검증은 복구 공백 재현, 실제 DB 일치·데이터 위반 사전 확인, 인덱스/저장 비용 계측과 변경안 승인이다.

## 승인한 DB 개편 구현·적용

- 사용자가 통합·명명 추천에 동의하고 `batch` 대신 저장 순번 용어를 선택한 뒤 적용을 요청했다. [DEC-049](../../DECISIONS.md#dec-049)와 [ADR-049](../adr/049-clear-database-names-and-merged-session-state.md)를 기록하고 design의 계약을 먼저 갱신했다. 앞 절의 미승인 표시는 승인 전 검토 당시 상태다.
- 지속 7개·임시 2개 테이블로 통합했다. 로그인 행의 탈퇴 권한은 만료/사용 후 독립적으로 정리하며 유효 로그인을 유지한다. 임시 상태는 원문 삭제 후 남기고 저장·삭제가 같은 행을 잠가 삭제 후 재저장을 거절한다. 기존 사용자 동작·보관/백업 경계는 유지했다. 소유자 복합 FK·상태/목적/순번 CHECK·NULL 대상 작업 중복 방지와 사용자 조회 인덱스를 보강했다. 성능 이득은 측정하지 않았다.
- `0002_clear_session_state.sql`을 두 DB에 추가하고 Drizzle 스키마/메타데이터·인증/학습/정리 코드·화면/API를 맞췄다. 기존 마이그레이션은 수정하지 않고 계정 생성 시각·노트·탈퇴 권한·원문 순번/해시/snapshot·확정 위치와 과거 NULL 시각을 보존했다. 원문 상태 충돌·미보존 초기 원문·소유자/제약 위반은 이관을 중단하고 트랜잭션을 되돌린다.

## 구현 검증과 기존 DB 적용

- 환경: WSL Ubuntu, Node/설치된 Next.js·Drizzle 버전은 app/package.json 기준. 처음에는 Docker 연결과 기존 DB가 꺼져 있어 PostgreSQL 16.15 패키지를 /tmp에 풀고 독립 인스턴스 두 개(25433/25434)와 `talkie_test_schema_*` DB로 시험했다. 시스템 PostgreSQL 설치나 기존 app/.env 변경은 하지 않았다.
- 서버 시험 23개 모두 통과(제외 없음). 이관의 시각·권한·노트·저장 내용/해시/순번 보존, 잘못된 이전 데이터의 이관 실패/롤백, 같은 순번 재전송·다른 내용 거부, 임시 DB만 커밋된 같은 내용 재시도, 원문 삭제/기록 원자성·중복 불변·삭제/저장 경쟁, 탈퇴 권한 만료/사용·원래 브라우저·독립 정리·백업 복원 후 무효화를 확인했다. 장애는 합성 시험용 트리거/데이터이며 운영 장애가 아니다.
- 기존 단위 테스트 13개, 타입 검사·최적화 빌드를 통과했다. `npm run db:generate`는 두 스키마 모두 추가 변경 없음을 확인했다. 초기 이관 시험은 복수 이력 행 중 첫 행을 가정해 실패했으므로 대상 세션 조건을 명시하고 전체 시험을 재통과했다.
- PC/모바일 크기 Chromium 브라우저 시험 12개를 통과했다. 독립 시험 DB와 로컬 Mailpit을 사용해 이메일 확인·로그인 유지·새 API의 저장/새로고침 재개·노트 다운로드·로그아웃을 검증했다. 실제 모바일 기기·실제 메일/AI 시험이 아니다. Chromium은 /tmp에 설치했고 Next의 생성 파일은 검사 과정에서 갱신될 수 있다.
- 사용자가 기존 컨테이너를 실행한 뒤 두 PostgreSQL과 Mailpit이 healthy임을 확인했다. 앱 수신 포트가 비어 있는 상태에서 기존 DB별로 전체 새 SQL을 트랜잭션 안에서 시험하고 원래/새 컬럼을 동일한 의미로 맞춘 행 전체의 집계 fingerprint를 비교한 뒤 롤백했다. 두 DB 모두 통과 후 실제 마이그레이션을 적용하고 다시 내용 보존을 확인했다. fingerprint와 사용자 원문·이메일·토큰은 출력/파일 저장하지 않았다. 원문 DB 덤프/백업은 만들지 않았다.
- 두 DB별 이관은 각각 원자적이며 두 인스턴스 전체의 동시 커밋은 아니다. 실제 적용은 둘 다 성공했다. 기존 로컬 DB에 시험 계정/대화를 만들거나 정리 실행기로 사용자 자료를 삭제하지 않았다.
