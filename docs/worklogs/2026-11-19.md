# 2026-11-19 작업 기록

## 달성 일수 결정과 구현(B-12)

- PRD 4.5절의 미정 항목(날짜 귀속·누적/연속 표시·소급)은 구현 전에 확정해야 했다. 사용자에게 대안별 영향을 제시했고, 사용자는 추천안 네 가지를 모두 선택했다. 결정은 종료 시각 귀속, 시작 시 기기 시간대 고정, 누적 일수만 표시, 확정 판정 고정이다. [DEC-095](../DECISIONS.md#dec-095)로 기록하고 [PRD 4.5절](../PRD.md#45-평가와-달성-일수)과 11절 미정 색인을 갱신했다.
- 구현: 미션 시작 요청에 브라우저 IANA 시간대를 받아 `learning_session_missions.mission_time_zone`에 고정한다. 값이 없으면 `Asia/Seoul`, 형식이 틀리면 거절하며 재개 요청의 값은 무시한다. 평가 확정 트랜잭션은 80% 이상이고 재개 만료가 아닐 때 종료 시각의 현지 날짜를 `learning_mission_results.achievement_date`에 1회 기록한다. 조회 응답에는 `achievementDayCount`와 세션별 `achievementDate`를 더했다. 홈 요약에 달성 일수를, 결과 화면에 인정 날짜 또는 재개 만료 제외 안내를 표시한다. 좁은 화면의 요약은 2열로 바꿨다. 마이그레이션은 `0007_mission_achievement_days.sql`이다. [일수 인정 설계](../design/MISSIONS.md#일수-인정)
- 기존 결과 화면의 “달성 일수 집계는 아직 준비 중” 문구를 지웠다. 노트의 한국 날짜(`learning_end_date_kst`)는 별도 기준이며 이번에 바꾸지 않았다.

### 검증

- `npm run typecheck`, `npm test`(20개 파일, 187개 시험), `git diff --check` 통과. 새 단위 시험은 시간대 검증(알 수 없는 이름·경로 문자·길이·비문자열 거절), 서울 자정 경계 직전/직후, 로스앤젤레스 전날 귀속, 80% 미만·판정 불가(null)·재개 만료 제외와 실전 무진전 실패의 인정, 시작 API의 시간대 전달·기본값·거절을 확인한다.
- DB 시험(`npm run test:server`)에 새 사례를 추가했다. 로스앤젤레스에서 시작한 미션을 서울 시간대로 재개해도 시간대는 유지되는지, 같은 날 두 인정은 한 번만 세는지, 80% 미만과 재개 만료는 날짜가 없는지, 80% 미만 행에 날짜를 쓰면 CHECK가 거절하는지 검증한다. 기존 평가 사례에는 기본 시간대 날짜와 누적 1일을 더했다. 처음에는 이 WSL 배포판에서 Docker를 찾지 못했다. 사용자가 Docker Desktop 연동을 켠 뒤 시험 전용 `talkie_test_days_*` 두 DB(합성 데이터, 실행 후 삭제)에서 35개 중 34개 통과·1개 skip(`PG_BIN_DIR` 없음, 실제 백업/복원)이었다. 개발 DB에는 `npm run db:migrate`로 0007을 적용했다.
- 브라우저 시험(`mission.spec.ts`)에 저장된 인정 날짜 표시, 재개 만료 안내, 홈 누적 일수, 가로 넘침 없음 사례를 추가했다. 처음에는 Playwright Chromium이 `libasound.so.2`를 찾지 못해 실행되지 않았고, 사용자가 `libasound2t64`를 설치한 뒤 실행했다. 이 파일은 브라우저 시간대를 `America/Los_Angeles`로 고정해 시작 요청이 기기 시간대를 보내는지, 화면이 저장된 날짜(11월 18일)를 다시 계산하지 않는지 확인한다. 기존 두 사례는 시작 요청 본문을 정확히 비교하므로 `timeZone`을 기대값에 더했다. `mission.spec.ts`는 8/8 통과했다.
- 전체 브라우저 시험은 28개 통과·4개 skip·2개 실패였다. 실패한 `learning.spec.ts`의 “keyboard learning flow”(데스크톱·모바일)는 `locator('pre')`가 Next 개발 오버레이(“Security Insight”)의 `pre`까지 잡는 strict mode 위반이다. 변경을 치운 HEAD에서도 같은 위반이 재현돼 이번 변경과 무관한 기존 문제로 남겼다. 코드가 바뀐 직후 첫 실행에서는 dev 서버 첫 컴파일 중 대부분의 사례가 약 1초 만에 실패했고, 다시 실행하면 통과했다. 이 첫 실행 불안정은 고치지 않았다.

## 미션 횟수 예약과 정산(B-10)

- 남은 P0 중 미착수인 B-10의 미정 항목을 논의했다. Live는 브라우저가 공급자에 직접 연결해 서버가 연결 성공을 볼 수 없다는 제약을 설명했다. 사용자는 시작 때 예약하고 끝날 때 확정하는 방식을 제안했고, 확정 조건은 추천안인 학습자 발화 확정 저장 여부로 정했다. 장애는 재개로 해결하고 환급하지 않으며, 새 시작마다 1회를 쓰고 장기 보호는 보류하며, 포함량은 환경 변수 시험값으로 두는 추천안도 선택했다. [DEC-096](../DECISIONS.md#dec-096)으로 기록하고 [PRD 6절](../PRD.md#6-대화-상태와-예외)·9.2절·11절 색인을 갱신했다.
- 구현: `mission_usage_holds` 원장(마이그레이션 `0008_mission_usage_holds.sql`)에 새 미션 시작 트랜잭션에서 예약한다. 종료 사유 기록 때 같은 트랜잭션에서 확정 또는 해제한다. 계정당 미정산 예약 하나를 부분 유일 색인으로 막고, 잔여 0이면 세션 생성 전에 `MISSION_ALLOWANCE_EXHAUSTED`로 거절한다. 조회 응답에 `missionAllowance`를 더했고, 대화 화면은 새 미션의 남은 횟수와 0회 안내를 보여 주며 재개는 막지 않는다. 한도는 `TALKIE_MISSION_ALLOWANCE`(기본 10)이다. [횟수 예약과 정산](../design/MISSIONS.md#연결과-횟수)
- 검증: `npm run typecheck`, `npm test`(187개), `git diff --check` 통과. 시험 전용 `talkie_test_cnt_*` DB(합성, 실행 후 삭제)에서 `test:server` 36개 중 35개 통과·1개 skip(실제 백업/복원)이었다. 새 DB 사례는 시작 예약과 재개 무예약, 발화 있는 종료의 확정, 인사만 저장된 종료의 해제와 복구, 0회 거절과 세션 미생성, 자유 대화 미차감, 재개 만료 확정, 잔여 1회에서 동시 시작 두 개 중 세션 하나·예약 하나, 미정산 예약 중복 삽입 거절, 잘못된 한도 설정 거절을 확인한다. 브라우저 시험은 `mission.spec.ts` 10개와 전체 32개 통과·4개 skip이었다. 기존 미션 시험의 가짜 응답에 남은 횟수를 넣었고, 남은 횟수 표시·0회 시작 차단·0회 재개 허용 사례를 추가했다. 개발 DB에 0008을 적용했다.

## 날짜별 노트·표현 탐색(B-08)

- 범위: F-12의 “날짜별 노트와 주요 표현을 찾는다”를 구현했다. 기존 날짜별 목록·상세·개별 다운로드(DEC-022)는 유지했다. 새 결정이나 저장 형식 변경은 없고, 표현은 서버에 따로 저장하지 않고 조회 응답의 노트 Markdown에서 화면이 읽는다. 따라서 만료·삭제된 노트의 표현은 노트와 함께 사라진다.
- 구현: `app/src/learning/note-expressions.ts`가 `talkie-learning-note-v1` 노트의 복습 표현(학습 맥락)과 상세 항목 중 직접 질문한 표현·교정·핵심 표현·다음 복습을 읽는다. 생성한 응용 예문(`복습용 응용`)·요약·칭찬은 제외한다. 형식 표시가 없는 이전 데모·음성 노트는 `## 핵심 표현 · 다음 복습`/`## 다음 복습` 아래 인용만 읽는다. 같은 표현은 NFKC·공백·대소문자·끝 문장부호를 정규화해 한 줄로 모으고, 최신 날짜의 문장을 보여 준다. `/notes`에 날짜별 노트/표현 보기 전환과 검색창을 더했다. 노트 검색은 날짜 문자열과 보이는 노트 내용만 대상으로 하고 발화 ID·앵커·형식 표시는 제외한다. 보기를 바꾸면 검색어를 비운다. 인용 해제를 재사용하려고 `note-context.ts`의 `readLiteral`을 내보냈다.
- 검증: `npm run typecheck`, `npm test`(21개 파일, 191개 시험), `npm run build`, `git diff --check` 통과. 새 단위 시험(`tests/note-expressions.test.ts`)은 응용 예문·요약·칭찬 제외, 특수 문자 원문 보존, 이전 두 형식 읽기와 근거 인용 미포함, 날짜를 넘는 병합·최신순, 대소문자/문장부호 무관 검색, 발화 ID 비검색을 확인한다. 새 브라우저 시험(`tests/browser/notes.spec.ts`, 가짜 조회 응답·합성 노트)은 날짜·내용 검색, 결과 없음 안내, 표현 보기 전환 시 검색어 초기화, 병합된 표현의 두 날짜 링크로 해당 노트 이동, 표현이 없는 노트의 안내, 가로 넘침 없음을 데스크톱·모바일에서 확인했다. 전체 브라우저 시험은 36개 통과·4개 skip이었다. 실제 DB 경로의 `/notes` 진입은 기존 `storage.spec.ts`가 계속 통과한다.
- 한계: 표현의 품질과 양은 B-06 노트 생성(AI 상세 추출 여부)에 따른다. 현재 개발 DB의 노트 4개는 형식 표시 이전 노트였다. 검색은 브라우저에서 조회 응답 전체를 대상으로 하며, 노트가 많아질 때의 응답 크기·검색 비용은 측정하지 않았다.
