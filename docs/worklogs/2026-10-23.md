# 2026-10-23 작업 기록

## 구현 전 체크포인트 커밋 준비

- 사용자가 현재까지 내용을 먼저 push한 뒤 구현하도록 요청했다. 기존 B-00 소스와 문서/결정 정리를 함께 검토했다. 앱 단위 테스트 13개·저장소 보안 검사 테스트 2개·Markdown 로컬 파일 링크와 공백 검사를 다시 확인했다. 앱의 원문/비밀값 외부 전송·로그/브라우저 저장소 사용과 입력 렌더링을 검토했으며 체크포인트의 B-00 메모리 범위를 유지한다. 커밋/전송은 스테이징 diff와 민감 파일명/Gitleaks 검사 후 수행한다.

## 인증·저장 후속 다섯 정책 채택

- 사용자가 전부 A에 동의하되 메일 발송 실패의 별도 재요청은 불필요하고 사용자가 알아서 다시 요청할 것이라고 명시했다. 2번은 자동 재발송/실패 전용 재요청 안내·버튼을 추가하지 않고 기존 요청 화면을 유지하는 것으로 반영했다. 기존 만료·무효 링크의 새 요청 경로, 30초 발급 간격·최신 링크만 유효·메일 미도착을 도착 성공으로 표시하지 않는 경계는 유지했다.
- PRD 8/8.1절을 먼저 갱신했다. 로그인할 브라우저·인증용 행 수명·백업 복원 후 재로그인은 인증 데이터/사용자 약속의 중요한 절충으로 ADR-046, 버퍼 상한에서 최근 완결 단위 유지와 오래된 미저장 기록 유실은 데이터 보관의 중요한 절충으로 ADR-047에 대안·선택 이유·비용/일정/사용자/운영 영향·미검증을 기록했다. 기존 결정의 미정 범위를 구체화하며 보관/삭제·일반 재시작의 인증 유지 정책은 보존했다.
- design·DECISIONS·D-02/B-01/B-05/B-06 수용 기준·두 점검/논의 문서·PROGRESS·CHANGELOG와 ADR-020/031 후속을 연결했다. D-02 IN PROGRESS와 기능 작업 상태는 유지한다. 구체 버퍼 수치/큰 단위·쿠키/링크 운반·이메일 식별·기한/복원·두 DB 경쟁 상세와 실제 검증은 남는다. 설치·코드/DB 실행·메일 전달·유료 호출·배포·커밋은 수행하지 않았다.
- 마감 대조: 변경 연결 문서의 로컬 파일 링크·DEC-046/047 목록 유일성·D-02 IN PROGRESS/B-00 DONE/B-01·05·06 TODO 유지·PRD의 메일 재요청 수정과 `git diff --check`를 확인했다. PRD와 해당 TASK 수용 기준·ADR 상태/링크·design·PROGRESS·CHANGELOG를 대조했다. 기능 검증은 수행하지 않았고 위 구현 상세/실행 검증은 후속으로 남는다.

## 인증 구현 상세와 다음 정책 묶음

- 사용자의 “이어서 진행”에 따라 design에 기존 결정 안의 32바이트 난수/base64url·SHA-256 검증값·목적 분리·UTC 만료 경계·잠금 대기 후 재검증·동시 발급/소비/갱신 계약을 정리했다. DB/메일 간 원자성이나 로그인 링크 브라우저 정책을 확정한 것으로 확대하지 않았다.
- 제안서에 지속/임시 테이블 후보, 두 저장소 부분 커밋·응답 유실·연결 손실/삭제 경쟁·원문 없는 복원의 실패표를 추가했다. 두 DB의 별도 트랜잭션과 연결 손실 뒤 잠금 해제 문제를 명시하고 미검증 프로토콜을 구현 완료로 취급하지 않았다.
- 로그인할 브라우저·메일 실패 재요청·인증용 행 정리·복원 후 인증·버퍼 초과 유지/포기 다섯 정책의 대안·추천·사용자/데이터/일정/운영 영향을 미채택 제안으로 작성했다. 기한/수치는 초기 제안이고 실제 사용자 보관·외부 공급자 전송 승인으로 확대하지 않는다. PRD·DECISIONS의 정책 채택은 없다.
- D-02는 실제 상세 설계 착수에 맞춰 TASKS/PROGRESS에서 IN PROGRESS로 갱신하고 도구 선택과 남은 구체 스키마/검증을 구분했다. B 기능 상태는 유지한다. PostgreSQL·OWASP·Node.js 공식 자료를 확인했으며 설치·코드 구현·메일 전달·DB/복원·유료 호출·배포·커밋은 수행하지 않았다.
- 마감 대조: 변경 연결 문서의 로컬 파일 링크·다음 묶음 1~5 번호 유일성·TASKS/PROGRESS의 D-02 IN PROGRESS 일치·B-00 DONE 유지와 `git diff --check`를 확인했다. 기존 PRD/TASK 수용 기준·DEC-020/026/031/032/035/036/040~045와 변경 범위를 대조했으며 새 정책은 미채택으로 구분했다. 사용자 선택 다섯 건과 이메일 식별/쿠키/링크 운반·기한/재시도 수치·두 DB 경쟁 프로토콜 및 실행 검증은 남는다.

## Drizzle ORM 채택

- 사용자가 “그래 drizzle orm으로 해보자”라고 명시해 2B를 Drizzle ORM·Drizzle Kit으로 채택했다. design을 먼저 갱신하고 작은 결정 DEC-045·설계 논의표·최소 점검표·PROGRESS·CHANGELOG를 연결했다. 이전 A 추천에서 사용자 경험 수준과 타입/마이그레이션 도구 지원을 고려해 B로 추천을 바꾼 이유·의존성/학습 부담·미측정 한계를 제안서에 기록했다.
- PostgreSQL 드라이버는 공식 지원 pg 어댑터로 구체화하고 TypeScript 스키마→생성 SQL 검토/버전 관리→명시 적용, 두 DB의 연결·스키마·마이그레이션 분리를 정리했다. 공식 Drizzle 연결·마이그레이션·SQL 문서를 확인했으며 RC 설치 예시를 버전 채택으로 확대하지 않았다. 매개변수화 SQL·런타임 검증·인증/소유자 확인과 두 DB 정합성 검증 책임은 유지한다.
- 다섯 기술 선택은 모두 확정됐으나 인증/저장 상세 계약과 실제 검증은 남는다. PRD·TASK 수용 기준·D-02/B 기능 상태는 유지하며 설치·SQL 실행·DB/메일/서비스 등록·유료 호출·배포·커밋은 수행하지 않았다.
- 마감 대조: 변경 연결 문서의 로컬 파일 링크·DEC-045 단일 항목/앵커·D-02 TODO/B-00 DONE 유지와 `git diff --check`를 통과했다. 미정이던 도구 선택의 현재 표현을 갱신하고 과거 제안은 시점별 설명으로 유지했다. 기존 인증/삭제 경계·TASK 수용 기준·PROGRESS/CHANGELOG를 대조했으며 구체 스키마·실행/장애/복원 검증은 남는다.

- 사용자가 인증·저장 설계부터 이어가도록 지정했다. PRD 8절·D-02/B-01/B-05·DEC-020/026/028/033~040과 현재 설계·점검표를 대조하고 `authentication-storage-design.md`에 미채택 초안을 작성했다. 현재 구조·Accepted 결정·제품 정책은 바꾸지 않았다.
- 토큰/세션/탈퇴 확인 권한 모델, 메일/DB의 비원자성, 동시 발급·소비·세션 갱신 경쟁, 두 DB 저장 성공 확인·늦은 쓰기와 원문 부활 방어의 미해결 지점을 명시했다. 로컬 DB 실행·DB 접근·메일 시험·기한 작업·백업 검증 범위 다섯 선택에 대안·추천·비용/일정/사용자/데이터/운영 영향을 제시했다.
- 공식 PostgreSQL·OWASP·node-postgres·Docker·Mailpit·systemd 문서를 확인하고 관찰과 Talkie 적용 판단·미검증을 구분했다. PATH에서 docker/psql 미발견·systemctl 발견만 확인했으며 설치·데몬/사용자 서비스 가용성은 미확인이다. 실제 계정·메일 전달·비밀값 저장·SQL 실행·복원/보안 시험은 수행하지 않았다.
- 점검표·PROGRESS·CHANGELOG에서 초안과 현재 논의를 연결했다. D-02는 채택/검증 전 TODO, B-00은 DONE, 실제 기능은 TODO 상태를 유지한다. 미정 버퍼 정책·메일 실패/브라우저 연결·삭제 경쟁 상세·실제 사용자 백업/복원과 공급자 검증은 남는다. 유료 호출·설치·배포·커밋은 없다.
- 마감 대조: 이번 연결 문서 다섯 개의 로컬 파일 링크 34개·제안 선택 번호 1~5의 유일성·D-02/B-00 상태 유지와 `git diff --check`를 확인했다. PRD 요구·연결 TASK 수용 기준·기존 DECISION과 초안의 미채택 표시를 대조했으며 새로 채택된 결정이나 완료 표시는 없다. 앞서 명시한 설계 미정·실행 검증 한계는 후속 작업으로 남는다.

- 사용자의 누락 없는 정리 요청에 따라 PRD F-01~12/O-01~08·11절, TASKS D/B/V/C와 선행 관계, design, 첫 흐름, 검증 설계, 기존 논의표와 DEC-031을 대조했다.

## 제품 정책·영향 큰 기술의 첫 묶음 제안

## B-00 파일·생성 산출물 정리

- 많은 TS/JSON의 주원인은 의존성 `node_modules` 11,790개와 Next.js 생성 산출물이었다. 앱 소스 7개·필수 패키지/타입 설정은 유지하고, 단일 대상 Vitest 설정 파일은 npm 명령으로 합쳤다. Playwright 설정은 `tests/browser/`로 옮기고 실행 기준 경로·결과 경로를 유지했다.
- `npm run clean`을 추가하고 개발 서버를 종료한 뒤 빌드·테스트 생성 파일 302개(64.3 MiB)를 제거했다. 처음 브라우저 재검증은 기존 개발 서버의 Next.js 잠금 때문에 시작하지 못했으며 기존 서버 종료 후 10개가 통과했다. 단위 테스트 13개와 정리 후 캐시 없는 타입 검사도 통과했다. 의존성은 재설치 부담을 피하기 위해 유지하며 산출물은 다음 실행 시 재생성된다.
- 마감 대조: 현재 구조·README 실행/정리 안내·PROGRESS·CHANGELOG를 맞추고 `git diff --check`와 이전 설정 경로 참조 제거를 확인했다. PRD·기존 결정·B-00 완료 상태·제품 동작은 유지하며 남은 문서 불일치는 없다. 커밋하지 않았다.


## 구현 파일을 app/로 통합

- 사용자 요청에 따라 소스·앱 테스트·package/잠금 파일·TypeScript/Next.js 설정·타입 선언·node_modules를 `app/`로 옮겼다. 빌드/테스트 산출물도 같은 디렉터리 안에서 생성된다. 루트의 Markdown·환경 파일·Git 설정·기존 공통 보안 검사와 그 테스트는 유지했다.
