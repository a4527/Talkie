# Talkie 변경 이력

사용자에게 의미 있는 제품 요구사항과 프로젝트 문서·구조의 변경을 날짜별로 기록한다.

## 2026-10-31

- 종료 노트 선별의 초기 수치(구간 30,000자·구간당 2회 요청·시도 45초/전체 120초 등)를 승인했다(DEC-065). 실측 전 값이며 실제 평가 후 조정한다. 코드는 상수와 가짜 생성기 시험까지만 반영했고 모델 호출은 하지 않았다.
- 종료 노트 선별의 모델(분리형 Gemini 텍스트 모델 재사용)·평가 기준·원문 크기 기준 분할을 승인하고 연결당 별도 시간 상한은 두지 않기로 했다(DEC-064). 수치는 미정이며 구현은 하지 않았다.

## 2026-10-30

- 연결 사용 시간은 브라우저 관찰값을 서버 신호와 대조해 차감하고, 종료 보고가 없을 때 짧은 유예만 계산한다. 계정당 음성 연결 하나와 별도 계정 이용권 테이블을 채택했다(DEC-063). 시간 경계의 대화 마무리 A안은 잠정 선택이며 수치·구현은 후속이다.
- 토큰별 지속 집계·예약 방식(DEC-060/061)을 연결 허용 시간 이용권, 별도 노트 호출 제한, 경로별 주간 실제 과금 대조로 변경했다(DEC-062). 구체 시간·기간·지출 한도와 구현은 후속이다.
- 같은 날 앞서 15분 강제 종료를 토큰 사용량 한도와 별도 노트 예산으로 바꾸고(DEC-060), 경로별 집계·예약/안내를 합의했다(DEC-061). 두 결정의 토큰 집행은 이후 DEC-062로 대체됐다.
- 앞서 공급자 과금량·단가로 차감하고 자체 환산식을 조정하기로 했으나, 이 차감 방식도 DEC-062로 대체됐다.
- 비공개 `/voice` 시험에 Gemini Live와 분리형 음성 경로 선택을 추가했다. 분리형은 Soniox 전사·Gemini 텍스트·TTS와 공통 학습 기록을 사용한다. 공급자별 공개 배포 조건과 품질 검증은 후속이다.

## 2026-10-29

- 짧게 자주 연습하는 제품 방향과 한 대화 최대 15분·종료 후 새 대화 시작을 승인했다(DEC-059). 시간 제한 구현·검증은 후속이다.

- 회화 세션 평균 10분을 초기 설계/비용 산정 가정으로 두고, 구간별 중간 요약 없이 종료 후 한 번에 노트를 선별하기로 했다. 세션 최대 시간은 미정이다.

- 종료 노트 선별은 별도 요청으로 연결하고, 오류별 제한적 재시도와 유효 부분 결과 완성 방향을 합의했다(DEC-058). 시험용 노트로 자동 대체하지 않으며 구현·모델/한도 확정·품질 검증은 후속이다.

- 음성 노트의 상단 세 맥락·하단 근거 형식 생성과 검증/읽기를 구현했다. 구형 노트 호환을 유지하며 실제 연습일이 없는 표현에는 날짜를 만들지 않는다. 주제·난이도 읽기/전달을 연결했고 실제 AI 종료 추출은 남는다.

- 노트 상단 세 맥락과 하단 근거의 형식·생성 검증·다음 학습 읽기 계약을 [학습 노트 설계](design/LEARNING-NOTE.md)에 구체화했다. 코드 반영은 후속이다.

- 기존 합의인 노트 상단의 주제·난이도·복습 표현, 하단의 세부 내용 구성을 명시하고 별도 학습 맥락 저장 제안을 철회했다. 구현은 후속이다.

- 이전 학습의 주제·복습 표현 조회 범위를 최근 6개월로 변경했다. 난이도는 최신 유효 값을 참고하며 노트의 보관·삭제 기간은 유지한다. 현재 복습 조회에 한국 날짜 기준의 달력 6개월 필터를 적용했고 주제/난이도 구조화와 실제 재연습일 갱신은 후속이다.

- 저장 음성 학습에서 이전 세션의 유효한 근거 노트를 확인해 복습 표현 최대 2개를 현재 대화와 구분해 전달한다. 다른 계정·만료 노트·현재 세션은 제외하며 주제/상황 이력 기반 소재 선택과 실제 AI 복습 품질은 후속이다.

- 사용자 검토한 전체 튜터 프롬프트를 로컬 음성 MVP에 반영했다. 난이도를 연속적으로 조절하고 응답 부담에 따라 관련 질문을 묶도록 변경했다. 이전 학습 활용 규칙을 포함하지만 이전 세션 기록의 선별·전달과 실제 교육 품질 검증은 남는다.

- PRD 4절을 제품 약속 중심으로 줄이고 단계별 사용자 흐름을 [USER-FLOWS](design/USER-FLOWS.md)로 분리했다. 정책·요구사항은 바꾸지 않았고 PRD 4.1~4.4 앵커는 유지했다. 순서도는 흐름 확정 후 추가한다.

- 저장 음성 학습 프롬프트에 교정 후 다시 말하기 대기, 재시도 성공/실패 판정과 다음 대화 전환을 구체화했다. 고정 합성 실제 연결 1회에서 교정·재시도 성공 기록을 확인했다. [조건과 한계](worklogs/2026-10-29.md#재시도-판정-프롬프트-보완)를 따른다.

- 실제 공급자 교정/재시도를 확인하는 고정 합성 음성 진단 명령을 추가했다. 원인 조사 후 합성 발화 구간을 시험에서 명시하도록 고쳤고, 앱 어댑터가 도구만 완료된 단계를 답변 완료로 처리해 교정 근거를 잃는 오류를 수정했다. 이후 프롬프트 보완으로 고정 재시도 사례는 통과했으며 전체 통합/품질 검증은 남는다. [조건과 한계](worklogs/2026-10-29.md#합성-음성-실패-원인-조사와-수정)를 따른다.

- 영어 발화가 한글 음차로 표시된다는 제보에 따라 입력 전사에 영어/한국어 힌트·원문 모드를 명시하고 불확실한 인식은 확인하도록 프롬프트를 보완했다. 해당 발화의 개선 효과는 재시험이 필요하다.

- `/voice`에 비공개 저장 학습을 추가했다. 확인 전사문·재생 완료된 AI 교정/재시도를 계정별 저장·중단/재개·종료 후 근거 노트/다운로드에 연결한다. 기존 메모리 전용 시험은 유지하며 실제 Gemini의 새 구조화 결과·교육 품질과 전체 AI 노트 선별은 후속 검증이다. 조건·결과는 [worklog](worklogs/2026-10-29.md)를 따른다.
- 시험 재연결 안내를 앱의 4분 제한임이 드러나도록 바꿨다. 제한 시간·공급자 토큰 설정은 유지한다.

## 2026-10-28

- 문서 머리말의 공통 역할·탐색 안내 중복을 줄였다. 각 문서의 적용 범위·미구현 경계·고유 규칙과 구체적인 정책/결정/구현/검증 링크는 유지했다.

- PROGRESS를 현재 구현·남은 일과 검증 근거 중심으로 정리하고 과거 합의는 기존 worklog로 연결했다. 제안서 색인을 추가해 채택 범위·남은 제안·과거 검토/추정을 구분하고 TASKS의 정책 반복을 기준 문서 링크와 검증 경계로 축약했다. 작업 ID·우선순위·상태와 승인된 정책은 유지한다.

- DEC-055의 Gemini Live 우선 통합·음성 포트 선택 근거를 ADR-055로 분리하고 결정 목록과 기존 앵커를 연결했다. 승인 범위·작업 상태는 유지한다.

- 최초 로그인뿐 아니라 세션 만료·백업 복원 후 재로그인도 이메일 링크 또는 Google을 지원하도록 명확히 했다(DEC-057 후속). 계정 연결·Google 전용 가입자의 탈퇴 재확인 상세는 미정이며 구현은 후속이다.
- PRD의 시험 예외·로컬 MVP/실제 운영 범위를 나누고 저장·노트·보관 정책을 주제별로 정리했다. 구현/실험 절차는 설계로 연결하고 첫 학습 흐름·ADR의 반복 상세와 설계의 작업 이력을 축약했다.

- DESIGN을 전체 구조의 진입점으로 정리하고 API·DB·인증·학습 저장·음성·로컬 운영의 상세 계약을 [상세 설계 6개](DESIGN.md#상세-설계)로 분리했다. 관련 링크·기존 절 앵커를 연결하고 음성 토큰 응답 필드를 현재 구현과 맞췄다. 제품 정책·코드는 변경하지 않았다.

- 문서별 기준 위치를 구체화했다. PRD는 제품 약속, DESIGN과 상세 설계는 구현 계약, ADR은 선택 이유·절충, DECISIONS는 결정 상태·연결을 관리하며 짧은 요약과 링크로 중복을 줄인다. 기록 기준은 [AGENTS](../AGENTS.md#document-ownership)를 따른다.

- `AGENTS.md`·`README.md`·`CLAUDE.md`를 제외한 Markdown 문서를 `docs/`로 모으고 파일명을 대문자로 통일했다. 기존 하위 분류와 `.md` 확장자는 유지하고 문서 링크·하니스의 문서 참조를 갱신했다.

- 이메일 링크 로그인을 유지하면서 Google OAuth/OIDC 로그인을 함께 제공하도록 요구사항·설계·작업 기준을 갱신했다(DEC-057). 계정 연결 등 상세는 미정이며 구현은 하지 않았다.

## 2026-10-27

- 명명 점검 N01~N19를 적용해 학습 API를 `/api/learn`으로 맞추고 세션·자격 증명·상태·노트·DB/음성 타입·파일·함수/단위를 구분했다. 기존 저장 JSON·해시와 비용 장부 누적값/시각의 호환성을 유지한다. 변경 전 브라우저 탭은 새로고침한다.

- Gemini Live로 로컬 음성 E2E를 먼저 연결하고 모델 비교는 뒤로 옮겼다. 음성 처리는 한 앱의 포트·어댑터로 분리하고 필요가 확인될 때 별도 서버를 검토한다(DEC-055). 비공개 합성·본인 음성 시험에 한해 공급자 학습·표준 보관을 허용하며 실제 사용자 정책은 유지한다(DEC-056).
- `/voice`에 비공개 음성 시험 화면, 로그인·동일 출처 확인을 거친 단기 토큰 발급, Gemini Live 어댑터, 마이크/재생/중단·자원 정리를 추가했다. 생성 전사문과 재생 완료를 구분한다. 무료 프로젝트에서 합성 입력의 실제 음성·전사 수신을 확인했다. 실제 마이크·청취와 기존 저장/재개·교정 상태·노트 연결은 후속이다.

## 2026-10-26

- AI 후보 시험 하니스 뼈대를 `harness/voice-eval/`에 추가하고 공급자 6곳의 키 발급·결제·환경변수 안내(PROVIDERS.md)를 작성했다. 구성 요소를 설정으로 교체하며 시험하고, 호출 전 최대 비용 예약·학습 정책 확인 게이트·발화 내용 비저장 기록을 갖췄다. 제품 코드는 바꾸지 않았고 공급자 호출은 수행하지 않았다.
- 저가형 분리형을 음성 인식·텍스트 모델·음성 합성 각 2~3개 후보로 한 요소씩 바꿔 시험하고, 성능 기준은 직접 말하고 들으며 정하며, Gemini Live·OpenAI Realtime도 시험한 뒤 최종 결정하기로 했다(DEC-054). 후보 모델 확정과 예산 배분은 미승인이다.
- AWS 분리형을 후보에서 제외하고 저가형 분리형(음성 인식·텍스트 모델·음성 합성의 저비용 조합)을 추가했다(DEC-053). 스모크는 저가형 분리형 → Gemini Live → OpenAI Realtime 순서로 하며 구성 모델과 성능 기준은 미정이다.
- 스모크에서 세 후보를 모두 시험하기로 했다(DEC-052). 보관 일수 미확인 후보는 합성·본인 음성에 한해 학습 금지를 확인하면 시험하고, 보관 상한 완화는 비용 측정 후 논의하며 아직 채택하지 않았다.
- 서비스 대상을 만 18세 이상으로 한정했다(DEC-051). 청소년은 받지 않으며 가입 시 연령 확인 방식은 구현 전에 정한다.
- 실시간 음성 후보를 OpenAI Realtime·Gemini Live·AWS 분리형으로 갱신했다(DEC-050). Bedrock Nova 2 Sonic과 사용자 구독 연결은 제외했고 DEC-025 미충족 후보에는 음성을 보내지 않는다. 후보 평가 계획 초안과 공식 문서 기반 가격·정책 조사를 추가했으며 호출·구현은 수행하지 않았다.
- 인증 메일 30초 제한의 별도 테이블/요청 인덱스 방식을 비교하는 합성 DB 실험 스크립트와 측정 근거를 추가했다. 제품 스키마·인증 정책 변경은 없으며 조건과 한계는 [실험 기록](worklogs/2026-10-26.md)을 따른다.

## 2026-10-25

- 승인한 DB 개편을 적용했다(DEC-049). 탈퇴 권한을 로그인 세션에 통합하고 원문 제어/이력을 합쳐 9개 테이블로 정리했다. 저장 순번·snapshot과 명확한 대상/시각 이름을 코드·API·조회 안내에 반영하고 기존 로컬 DB의 데이터 보존 이관을 확인했다.

- 종료 후 학습 항목 선별 기준으로 질문한 표현·반복 오류/재시도 어려움·재사용할 핵심 표현·대화 중 AI 추천 표현을 채택했다. 실제 전달된 내용을 대상으로 하며 AI 추천을 학습 성공으로 취급하지 않는다.

- 종료 후 AI가 저장된 대화·교정·재시도 기록을 한 번에 검토해 학습 항목과 원문 근거를 선별하는 방식에 합의했다 (DEC-012 후속). 앱은 근거가 실제 기록에 있는지 확인하며 선별 기준·분량·모델은 미정이다.

- 대화와 학습 진행 상태를 메모리에 모아 주기적으로 묶어 저장하고 정상 종료 시 남은 기록을 저장하는 방향을 채택했다 (`DEC-013`). 간격은 검증 후 조정한다. 메모리 손실 시 마지막 저장 이후 기록은 손실될 수 있다.

- 전체 대화 글은 임시 보관하고 요약·중요 학습 항목·필요한 짧은 원문 근거와 교정문을 지속 기록으로 남기는 방향을 채택했다 (`DEC-012`). 세션 종료 후 요약·항목·근거 저장 성공 확인 뒤 임시 전체 원문을 삭제하고 실패하면 재시도용으로 유지한다. 실패 시 보관 상한은 후속 합의로 종료 후 24시간으로 정했다. 저장 간격·지속 기록 보관 기간은 미정이다.

- AI가 교정·재시도·대화 진행을 판단하고 앱이 상태를 기록·복원하는 방향을 채택했다 (`DEC-010`). AI 판단은 시나리오 평가로, 앱의 기록·중복 방지·복원은 자동 테스트로 구분해 검증하며 조정한다. 저장은 DEC-013을 따른다.
- MVP는 대화 중 AI가 필요하다고 판단할 때 교정하는 단일 모드로 확정했다 (`DEC-011`). 교정 끄기·종료 후 일괄 교정 모드 선택은 이후 범위로 남겼다.
