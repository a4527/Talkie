## 짧은 결정

<a id="dec-085"></a>

- DEC-085(2026-11-14, Accepted): 사용자가 언어 세부 기준을 각자의 정의에 따라 독립 판정하는 방식에 “기준마다 따로 판정하는 방식으로 반영해”로 동의했다. 같은 반복 오류가 문장 구조와 안정성처럼 여러 기준의 정의에 해당하면 각각 반영해 영역별 약점을 드러내고 판정 규칙을 단순하게 유지하기 위한 선택이며, 한 오류를 한 기준에만 반영하자는 2026-11-14 추천은 채택하지 않았다. 점수가 더 내려갈 수 있어 기준별 근거 설명이 필요하다. 전체 대화의 세 단계 판정(DEC-074/079)과 단발 오류 자동 미충족 금지는 유지하며 현행 정책은 [PRD 4.5.2절](PRD.md#452-언어-세부-기준과-부분점수)을 따른다.

<a id="dec-084"></a>

- DEC-084(2026-11-14, Accepted): 사용자가 C1·C2를 C(고급)로 통합하고 고급 사례를 상황에 맞게 간결하게 고치는 안에 “변경하자”로 동의했다. 불필요한 장문을 유도하는 단계 차별화를 줄이고 선택·평가 검증을 단순화하기 위한 선택이며, DEC-073의 여섯 단계 구분만 대체한다. 현행 수준·기대 범위는 [PRD 4.1절](PRD.md#41-시작)을 따르고 고급 내부의 세부 구분은 제공하지 않는다.

<a id="dec-083"></a>

- DEC-083(2026-11-09, Accepted): 사용자가 수준별 관찰 범위·안정성 설명에 “괜찮네”로 동의했다. 불필요한 장문을 유도하거나 관찰 항목을 일괄 제외해 점수를 왜곡하지 않도록 이번 상황의 필요한 수행과 실제 구조의 일관성을 평가하며, 현행 정책은 [PRD 4.5.2절](PRD.md#452-언어-세부-기준과-부분점수)을 따른다(DEC-074/079 구체화).

<a id="dec-082"></a>

- DEC-082(2026-11-05, Accepted): 사용자가 실전 무진전의 다섯 판정 경계와 사례 검증 준비에 “그러자”로 동의했다. 정상적인 확인·경로 변경과 기술 문제를 실패로 오판하지 않도록 기존 미션 방향을 구체화하며 현행 정책은 [PRD 4.2.2절](PRD.md#422-실전-무진전-종료), 검증 구성은 [미션 설계](design/MISSIONS.md#무진전-판정과-사례-검증)를 따른다. 연속 3회는 검증 후보로만 채택하고 운영 임계값 확정은 검증 후 논의한다(DEC-069 구체화).

<a id="dec-081"></a>

- DEC-081(2026-11-04, Accepted): 사용자가 다양한 해결 경로 중 하나가 성공하면 된다고 명시하고 카페의 재제조·환불 및 동등한 목표 점수 적용안에 “그렇게 해”로 동의했다. 사용자가 해결을 선택·변경할 수 있게 하고 정상 대안 선택에 따른 불이익을 없애기 위한 선택이다. 현행 경로·완료 조건과 배점 적용은 [PRD 4.2.1절](PRD.md#421-첫-카페-미션의-해결-경로)·[4.5.1절](PRD.md#451-첫-카페-미션의-목표-배점)을 따른다. 재제조만 허용하거나 환불 시 만점을 줄이는 대안은 채택하지 않았으며 실제 역할 수행·AI 평가 연결은 미구현이다.

<a id="dec-080"></a>

- DEC-080(2026-11-04, Accepted): 사용자가 획득 점수/남은 만점·소수 첫째 자리 달성률 표시와 반올림 전 비율에 따른 달성 인정 추천에 “그러자”로 동의했다. 정수 반올림에 따른 기준 오해를 줄이면서 결과를 간결하게 보여주기 위한 선택이며 현행 표시·계산 경계는 [PRD 4.5절](PRD.md#45-평가와-달성-일수)을 따른다. 실제 화면·채점 연결은 미구현이다.

<a id="dec-079"></a>

- DEC-079(2026-11-04, Accepted): 사용자가 언어 네 영역의 각 세 기준과 4/3/3 배점·충족/부분 충족/미충족의 전부/절반/0점 방식에 “그러자”로 동의했다. 핵심 기능에 조금 더 비중을 두고 이진 방식보다 부분 수행을 반영하면서 다단계 채점의 구별 부담을 줄이기 위한 선택이다. 현행 기준·계산은 [PRD 4.5.2절](PRD.md#452-언어-세부-기준과-부분점수)을 따르며 수준별 세부 사례·실제 AI 판정 품질은 후속이며, 당시 미정이던 최종 표시·반올림은 후속 DEC-080으로 확정했다.

<a id="dec-078"></a>

- DEC-078(2026-11-04, Accepted): 사용자가 판정 불가 항목의 배점을 평가 만점에서 제외하는 방식을 제안하고 100점 중 10점 제외 시 90점 만점의 예로 확정했다. 확인 가능한 수행으로 점수를 산출하기 위한 선택으로 앞선 총점·인정 보류 추천을 채택하지 않았으며, 일부 항목 제외로 실제 평가 비중이 달라질 수 있다. 현행 계산·표시는 [PRD 4.5절](PRD.md#45-평가와-달성-일수), 정합성 검증은 [미션 설계](design/MISSIONS.md#기록평가결과)를 따른다.

<a id="dec-077"></a>

- DEC-077(2026-11-04, Accepted): 사용자가 연습의 수정 과정과 이후 수행을 전체 대화에서 함께 평가하는 추천에 “그러자”로 동의했다. 첫/마지막/최고 시도만 평가할 때 생기는 개선 누락·반복 오류 은폐를 줄이고 기존 전체 대화 평가·도움 무감점 정책을 일관되게 적용하기 위한 선택이다. 현행 정책은 [PRD 4.5절](PRD.md#45-평가와-달성-일수), 근거 연결은 [미션 설계](design/MISSIONS.md#기록평가결과)를 따른다. 실제 판정 일관성·비용·지연은 미검증이며 내부 배점·부분점수·판정 불가 처리는 이번 동의에 포함하지 않는다.

<a id="dec-076"></a>

- DEC-076(2026-11-04, Accepted): 사용자가 전체 대화의 앞선 근거를 함께 평가하고, AI가 쉽게 끝내지 않도록 상황·상대역 조건을 구체화하는 수정에 “그래 그렇게진행해”로 동의했다. 수락 한 번으로 끝나는 부실한 상황을 줄이고 실제 수행을 평가하기 위한 선택이다. 현행 경계는 [PRD 4.2절](PRD.md#42-일반-대화)·[4.5절](PRD.md#45-평가와-달성-일수), 구성·검증은 [미션 설계](design/MISSIONS.md#상대역의-정보와-반응-조건)를 따른다. 억지 오해·최소 턴 강제 대신 고정 조건 안의 자연스러운 반응을 사용한다. 카페의 추가 운영 수치·허용 대안과 내부 세부 배점/부분점수는 이번 동의로 확정하지 않는다.

<a id="dec-075"></a>

- DEC-075(2026-11-04, Accepted): 사용자가 언어 네 영역의 균등 배점 추천에 “그러자”로 동의했다. 정확성과 대화 구성·조율을 같은 비중으로 다루고 결과를 쉽게 설명하기 위한 선택이다. DEC-072의 영역별 배점 미정을 구체화하며 현행 배점과 수준별 적용은 [PRD 4.5절](PRD.md#45-평가와-달성-일수)을 따른다. 문법·어휘 비중을 높이는 대안과 구현 비용·일정 차이는 작으며 평가 품질은 미검증이다. 세부 부분점수·재시도 반영·근거 부족 처리는 후속이다.

- [DEC-065](#dec-065)(2026-10-31, Accepted): 종료 선별의 실측 전 초기값 채택. 승인 당시 수치·평가 범위 원본은 본문에 보존하며 현행 구현은 학습 노트 설계/코드로 연결.

2026-10-21 · Accepted — OpenAI Realtime과 Gemini Live를 동일한 핵심 사례로 소규모 비교한다. 한 후보만으로 확정하기 전 비교 근거를 얻으며 최종 공급자·모델 채택은 아니다(DEC-016 구체화). 후보 구성은 DEC-050이 갱신했다.

<a id="dec-030"></a>

### DEC-030 · 직접 음성 경로 우선 검증

2026-10-21 · Accepted — 서버가 단기 연결 자격을 발급하는 브라우저 직접 경로부터 검증하고 비용 차단·취소·재생 범위·기록 동기화가 충족되지 않으면 중계를 비교한다. 영구 키는 브라우저에 전달하지 않으며 최종 경로는 실험 후 별도 합의한다.

<a id="dec-035"></a>

### DEC-035 · 인증 상태도 지속 PostgreSQL에서 관리

2026-10-23 · Accepted — 로그인 토큰 검증값·세션 상태는 사용자·노트와 같은 지속 PostgreSQL의 별도 테이블에서 관리하고 비밀 토큰 원문은 저장·로그하지 않는다. 운영 대상을 줄이되 인증과 DB 장애·부하를 공유하며 실제 경합·운영 필요 시 분리를 재논의한다(DEC-026 구체화).

<a id="dec-036"></a>

### DEC-036 · 탈퇴 재확인 시간·메일 재발송 정책

2026-10-23 · Accepted — 탈퇴 링크와 재확인 후 해당 브라우저의 최종 확정 허용 시간은 각각 10분, 같은 이메일의 인증 메일 재발송 간격은 30초다. 사용자 선택에 따라 현재 이메일·IP별 횟수 상한은 두지 않으며 실제 비용·남용 시 재검토한다(DEC-020/026 구체화).

현행 인증 조건은 [PRD 8.1절](PRD.md#81-가입로그인과-로그인-유지)을 따른다.

<a id="dec-037"></a>

### DEC-037 · 로컬 진단 로그 7일 자동 삭제

2026-10-23 · Accepted — 로컬 개발·AI 실험 로그는 기록 시각부터 7일 후 자동 삭제하며 사본·내보내기도 원래 기한을 따른다. 잔존을 제한하되 기기가 꺼진 동안 삭제를 보장하지 않으며 운영 저장소·수명은 미정이다.

현행 수명/접근은 [PRD 9.1절](PRD.md#91-엔지니어링-품질과-운영-검증)을 따른다.

<a id="dec-038"></a>

### DEC-038 · 로컬 진단 로그 JSONL 저장

2026-10-23 · Accepted — 로컬 로그는 Git 제외한 `.local/logs/`의 날짜별 JSONL 파일에 저장한다. DB 장애 진단을 DB와 분리하며 기록별 7일 기한·시작 시 만료 정리를 적용하고 파일 회전으로 기한을 늘리지 않는다.

저장/정리 구현은 [로컬 운영 설계](design/LOCAL-OPERATIONS.md#로컬-진단-로그)를 따른다.

<a id="dec-039"></a>

### DEC-039 · 로컬 진단 로그 항목·제외 대상

2026-10-23 · Accepted — PRD 9.1절의 허용 진단 메타데이터만 기록하고 원문·본문·IP·이메일·음성·비밀값을 제외한다. 문제 분석과 수집 제한을 함께 충족하며 인증 추적 ID에 비밀 세션 토큰을 쓰지 않는다.

수집 범위의 기준은 [PRD 9.1절](PRD.md#91-엔지니어링-품질과-운영-검증)을 따른다.

<a id="dec-040"></a>

### DEC-040 · 로컬 MVP 자료 접근·대화 지속·종료 기준

후속: DEC-069가 관련 대화·교정·이용량 범위를 부분 대체한다. 당시 판단은 아래에 보존한다.

2026-10-23 · Partially Superseded — 로컬 로그는 본인만 접근하고 앱 조회·외부 자동 전송을 제외하며, 노트는 한국 시간 실제 종료일에 귀속하고 버튼은 즉시 종료·음성 의사는 한 번 확인한다. 평가 사본 미생성의 근거는 ADR-012, 장기 저장 실패에도 대화 지속·유실 위험 수용의 근거는 ADR-031에 보존한다.

<a id="dec-041"></a>

### DEC-041 · 로컬 PostgreSQL 두 인스턴스의 Compose 실행

2026-10-23 · Accepted — 사용자가 1A에 동의해 지속·임시 PostgreSQL을 Docker Compose의 별도 인스턴스·볼륨으로 실행한다. 재현 가능한 로컬 설정을 위해 선택했으며 Docker 관리가 추가되고 백업 제외는 별도 검증한다(DEC-033/034 구체화).

<a id="dec-042"></a>

### DEC-042 · 인증 메일은 로컬 합성 시험부터

2026-10-23 · Accepted — 사용자가 3A에 동의해 로컬 Mailpit·합성 주소로 링크 흐름부터 시험한다. 외부 계정·수신자 없이 검증하기 위한 선택이며 메일함은 메모리 기반·로컬 한정·종료 시 폐기하고 실제 전달 서비스/적합성은 별도 결정한다.

<a id="dec-043"></a>

### DEC-043 · 로컬 기한 작업의 사용자 systemd timer

2026-10-23 · Accepted — 사용자가 4A에 동의해 웹 서버와 분리한 작업 명령을 Linux 사용자 systemd timer로 정시 실행한다. 실행 상태·실패 관리가 이유이며 사용자 서비스 수명·절전/재부팅·누락 보완은 검증하고 운영 플랫폼은 별도 선정한다(DEC-028 구체화).

<a id="dec-044"></a>

### DEC-044 · 합성 데이터 백업·복원 시험부터 구현

2026-10-23 · Accepted — 사용자가 5A에 동의해 합성 데이터로 원문 백업 제외·복원·삭제 상태 재적용부터 시험하고 사본은 종료 시 폐기한다. 초기 검증 범위를 줄이는 선택이며 실제 사용자 데이터 보관 전 백업 보호·생성/폐기·복구 목표 확정은 유지한다.

<a id="dec-045"></a>

### DEC-045 · Drizzle ORM과 Drizzle Kit

2026-10-23 · Accepted — 사용자가 Drizzle ORM 채택에 동의했다. 타입·스키마/마이그레이션 도구의 도움과 SQL 직접 제어를 함께 얻기 위한 선택이며, Drizzle Kit 생성 SQL을 검토·버전 관리하고 필요한 매개변수화 SQL을 허용한다. 구체 버전·인증/동시성·실패/복원 검증은 남는다.

<a id="dec-048"></a>

### DEC-048 · 원문 삭제 기한 명명과 생성·삭제 이력

2026-10-24 · Accepted — 사용자가 삭제 기한 표현 변경과 원문 DB의 실제 생성·삭제 시각/사유 확인을 요청했다. 기한을 `transcript_delete_deadline_at`으로 명명하고 내용 없는 이력을 원문 DB에 남겨 저장·삭제를 구분한다. 기존 원문 보관 상한·백업 제외·탈퇴 삭제는 유지하며 상세 필드와 과거 시각의 미확인 처리는 design을 따른다.

<a id="dec-050"></a>

### DEC-050 · 실시간 음성 후보 구성 갱신

2026-10-26 · Accepted — 사용자가 [후보 평가 계획 초안](proposals/AI-CANDIDATE-EVALUATION-PLAN.md)의 후보 변경을 승인했다. 실시간 음성 후보를 OpenAI Realtime·Gemini Live·AWS 분리형(Transcribe·Bedrock 텍스트 모델·Polly) 세 구성으로 비교한다. Bedrock Nova 2 Sonic은 공식 언어 표에 한국어가 없어 제외하고 사용자 구독 연결은 PRD 10절대로 범위 밖이다. DEC-025를 충족하지 못한 후보에는 음성을 보내지 않으며 Gemini Developer API는 공식 정책의 로그 55일로 현재 미충족이다. 예산 배분·표본 수·월 한도·구독료는 확정하지 않았고 구독료 1만~2만 원은 사용자 가정이다(DEC-029 후보 구성 갱신). 후보 구성은 DEC-053이 다시 갱신했다.

<a id="dec-051"></a>

### DEC-051 · 서비스 대상 연령 만 18세 이상

2026-10-26 · Accepted — 사용자가 대상 연령 A안에 동의해 서비스를 만 18세 이상으로 한정한다. Gemini 약관의 18세 미만 접근 가능 서비스 금지와 OpenAI의 아동 개인정보·연령 확인 요구를 피하고 법적·구현 부담을 줄이는 선택이며 청소년 사용자는 받지 않는다. 가입 시 연령 확인 방식·법률 검토·AWS 서비스 약관과 OpenAI Business Terms 원문 확인은 남는다(DEC-014 공개 가입 범위 구체화, 근거는 [후보 평가 계획 초안](proposals/AI-CANDIDATE-EVALUATION-PLAN.md)).

<a id="dec-052"></a>

### DEC-052 · 후보 음성 시험 범위와 보관 상한 완화 조건

후속: 로컬 시험의 학습 금지 전제는 DEC-056이 대체하며 실제 사용자 조건은 유지한다.

2026-10-26 · Partially Superseded — 사용자가 스모크에서 OpenAI Realtime·Gemini Live·AWS 분리형을 모두 시험하기로 했다. 이 전 후보 시험 범위는 DEC-053/066이 후속 변경했다. 보관 일수를 아직 확인하지 못한 후보는 합성 대화·개발자 본인 음성(DEC-016)에 한해 학습 금지(유료 티어·옵트아웃·데이터 공유 미사용)를 확인한 경우에만 시험하도록 DEC-025의 음성 전달 금지를 유예한다. 실제 사용자 음성에는 DEC-025를 그대로 적용한다. OpenAI 비용이 과도하면 보관 상한 완화를 논의하기로 했으나 완화 한도·비용 기준·사용자 고지는 미정이며 상한 변경은 채택하지 않았다(DEC-025 구체화, DEC-050 후속).

<a id="dec-053"></a>

### DEC-053 · 저가형 분리형 추가와 저렴한 순 시험

후속: 시험 선행 순서는 DEC-055, 로컬 시험 학습 조건은 DEC-056, 전 후보 시험 선행 조건은 DEC-066이 대체한다.

2026-10-26 · Partially Superseded — 사용자가 AWS 분리형을 후보에서 제외하고 저가형 분리형(음성 인식·텍스트 모델·음성 합성을 저비용 서비스로 조합)을 추가했다. 스모크는 비용이 낮은 순서(저가형 분리형 → Gemini Live → OpenAI Realtime)로 진행하며 저렴한 후보가 성능 기준을 충족하면 더 비싼 후보를 쓸 이유가 없다는 판단이다. 구성 모델·성능 기준·예산 배분은 미정이다. DEC-052의 학습 금지 확인 전제와 합성·본인 음성 한정은 유지한다(DEC-050 구체화, 근거는 [후보 평가 계획 초안](proposals/AI-CANDIDATE-EVALUATION-PLAN.md)). 시험 범위는 DEC-054가 구체화했다.

<a id="dec-054"></a>

### DEC-054 · 구성 요소별 교체 시험과 직접 청취 평가

후속: 비교를 제품 통합보다 먼저 수행하는 순서는 DEC-055, 전 후보 시험 후 공개 경로 선택 조건은 DEC-066으로 대체한다.

2026-10-26 · Partially Superseded — 사용자가 저가형 분리형을 음성 인식·텍스트 모델·음성 합성 각 2~3개 후보로 두고 한 요소씩 바꿔 시험하기로 했다. 성능 기준은 사전에 수치로 정하지 않고 사용자가 직접 말하고 들으며 정한다. Gemini Live와 OpenAI Realtime도 각각 한 번 이상 시험하고 모든 시험 뒤 최종 결정한다. 저렴한 후보가 충족하면 상위 후보 시험을 생략할 수 있다는 DEC-053의 전제는 이 결정으로 대체하고, 시험 순서는 비용이 낮은 순서를 유지한다. 후보 모델 확정과 예산 배분은 계획 초안의 제안이며 미승인이다. DEC-052의 학습 금지 확인 전제와 합성·본인 음성 한정은 유지한다(DEC-053 구체화).

<a id="dec-055"></a>

### DEC-055 · Gemini Live 우선 E2E와 음성 포트·어댑터

결정일·동의 근거·이유와 적용 범위는 [ADR-055](adr/055-GEMINI-LIVE-FIRST-E2E-AND-VOICE-PORT.md)에 이관했다. 기존 앵커는 유지한다.

<a id="dec-058"></a>

### DEC-058 · 별도 종료 선별 요청과 제한적 재시도

2026-10-29 · Accepted — 사용자가 노트 선별을 실시간 연결과 분리된 종료 요청으로 처리하고, 오류별 제한적 재시도·검증된 부분 결과 완성·시험용 근거 노트로 자동 대체하지 않는 방향에 동의했다. 연결 단절 후에도 저장 확정 기록으로 처리하고 조기 원문 삭제를 피하기 위한 선택이며, 후속으로 사용자가 짧은 회화를 목표로 평균 10분 산정 가정·구간별 중간 요약 없는 종료 일괄 선별을 선택했다. 모델/호출 수치·평가/검증은 남는다. 현행 이용량은 DEC-069이고 구현 계약은 [학습 노트 설계](design/LEARNING-NOTE.md#생성검증저장-순서)를 따른다.

<a id="dec-059"></a>

### DEC-059 · 짧은 회화 중심과 한 대화 시간 상한

현재 상태·당시 이유·대체 관계는 위 목록과 [ADR-059](adr/059-SHORT-CONVERSATIONS-AND-SESSION-LIMIT.md)를 따른다. 기존 본문 앵커는 유지한다.

<a id="dec-064"></a>

### DEC-064 · 종료 노트 선별의 모델·평가 기준·실패 처리

후속: DEC-069가 관련 대화·교정·이용량 범위를 부분 대체한다. 당시 판단은 아래에 보존한다.

2026-10-31 · Partially Superseded — 종료 노트 선별 모델은 분리형 경로의 Gemini 텍스트 모델을 재사용하고 새 모델·공급자를 도입하지 않는다(기존 키·사용량 관찰 재사용, 텍스트 호출이라 음성보다 저비용). 평가는 [검토안](proposals/LEARNING-NOTE-EXTRACTION.md#검증할-사례)의 합성 사례를 반복 호출하며 근거 인용 일치·지시문 비실행·연습일 비추정·숙달 비단정은 필수 통과, 교육 품질은 직접 읽고 사례별 판정한다. 실패 시 DEC-058대로 시험용 근거 노트로 자동 대체하지 않는다. 추가로 연결당 별도 시간 상한은 두지 않고 계정/기간 허용 시간만 유지한다(DEC-062/063의 해당 부분 변경, 연결당 수치는 미정이었음). 노트 입력은 저장 확정 원문 크기로 판단해 한도 이하면 종료 후 한 번에 선별하고, 넘을 때만 턴 경계에서 나눠 구간별 선별 후 앱 규칙으로 병합한다(대화 중 중간 요약은 두지 않음, DEC-058 유지). 크기 한도·분할 크기·호출/재시도 횟수·시간 제한·평가 호출 수는 미정이며 품질 부족 시 상위 모델은 재합의한다. 수치는 [DEC-065](#dec-065)로 후속 승인했다.

### DEC-065 · 종료 노트 선별의 초기 수치

아래는 승인 당시 수치·평가 범위의 원본이다. 현행 이용량은 DEC-069, 구현/조정 대상은 [학습 노트 설계](design/LEARNING-NOTE.md#생성검증저장-순서)와 연결된 코드이며 이 기록을 최신 측정값으로 해석하지 않는다.

2026-10-31 · Accepted — 사용자가 추천안에 동의했다. 구간당 턴 본문 30,000자(평균 10분 가정의 약 3배), 구간당 출력 4,096토큰, 구간당 요청 2회(재시도 1회·간격 2초, 시간 초과·429·5xx·JSON 실패만, 인증·결제 등 4xx 제외), 시도당 45초·선별 전체 120초, 동시 3구간, 세션당 구간 6개·호출 12회, 분할 불가 블록은 한도 2배 이하만 단독 전송하고 초과는 제외·누락 표시(조용히 자르지 않음)다. 기한 내 자동 재시도는 구간당 누적 3회를 상한으로 하며 코드 상수로 둔다. 모두 실측 전 초기값이고 사용자가 실제 평가를 하며 조정하기로 했다. 평가는 합성 8개 사례×3회+분할 2회(약 26회, 무료 로컬 프로젝트), 통과 기준은 DEC-064의 필수 4개 위반 0건·전체 호출이 2회 안에 유효 JSON·교육 품질 직접 판정이다. 비용은 미측정이며 DEC-062의 시간 이용권과 별도 상한이다. 수치 근거는 문서·기존 코드에 실측이 없다.

## 기록·변경 규칙

- 사용자와의 핵심 약속, 되돌리기 큰 비용이 드는 선택, 보안·데이터 경계, 결론만으로는 오해하기 쉬운 중요한 절충은 ADR로 남긴다. 여러 구성 요소에 영향을 주거나 논의가 길었다는 사실만으로 ADR을 만들지 않는다.
- 기존 방향 안의 세부 방식이며 변경 시 데이터 이전·사용자 약속 변경이 필요 없고 결정과 이유를 두 문장으로 설명할 수 있으면 이 파일에 짧게 남긴다. 현행 제품 정책의 상세는 PRD, 구현 계약의 상세는 DESIGN 또는 관련 상세 설계로 연결한다.
- 짧은 결정은 ID·결정일·상태와 결정·핵심 이유를 1~2줄로 기록한다. 승인 대화 전문·대안별 분석·영향·검증 현황을 항목마다 반복하지 않는다. 영향이 커지면 ADR로 옮겨 링크를 남긴다.
- ADR이 있는 결정은 목록에 ID·제목·상태·ADR 링크·대체 관계만 관리하고 결론 식별에 필요한 요약만 허용한다. 같은 결정을 별도 본문에 장문으로 다시 기록하지 않는다. ADR로 이관한 기존 본문 앵커는 짧은 링크로 보존한다.
- ADR에는 결정 당시 배경·선택·이유·대안·절충과 승인 범위를 식별하는 핵심 조건을 남긴다. 전체 제품 정책·API/DB 명세·작업 수용 기준을 복사하거나 최신 검증 결과를 계속 누적하지 않는다. 검증 항목·재검토 조건은 결정의 위험을 설명하는 범위에 두고 실제 결과는 worklog로 연결한다.
- 승인 후 구현 진척만으로 과거 ADR의 판단·대안·당시 미확인 사실을 다시 쓰지 않는다. 후속 결정과 대체 범위를 연결하고 상태를 갱신한다. 오탈자·잘못된 링크 수정과 의미를 보존하는 문서 이관은 정책 변경과 구분한다.
- 중요한 새 결정·기존 결정 변경은 대안과 영향을 논의하고 명시적 동의 후 Accepted로 기록한다. 미확정안은 `docs/proposals/`에 둔다. 정책 변경 시 이전/후속 결정과 상태를 연결하고 영향받는 기준 문서를 갱신한다.
- 문서 축약·이관은 정책 대체와 구분한다. ID·상태·대체 관계와 중요한 위험 수용 근거를 보존하고 기존 링크를 새 위치로 연결한다. 2026-10-23 정리에서 ADR-040의 중요 근거는 ADR-012·031로 이관했다.

새 ADR은 결정일·상태·동의 근거, 배경, 결정과 이유, 핵심 대안·단점, 미검증 가정·재검토 조건, 대체 관계를 필요한 만큼 작성한다. 비용·일정·사용자 경험·데이터·운영 영향은 실제로 관련 있는 내용만 적는다.
