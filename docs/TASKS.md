## 선행 관계

첫 구현: `D-01 + D-04 → B-00`. 학습 상태 책임은 `DEC-010`의 B안을 따르며, B-00 임시 기록은 DEC-015로 실행 중 세션 메모리 범위에 합의했다. [남은 쟁점](proposals/LEARNING-STATE-ISSUES.md)의 실제 저장·복원 상세는 해당 기능 구현 전에 합의한다. MVP는 `DEC-011`의 대화 중 AI 판단 교정 단일 모드로 진행한다. B-00의 가짜 응답·임시 기록은 `B-03/B-04/B-05/B-06`의 실제 기능 완료를 대체하지 않는다.

D-03은 현재 로컬 Gemini Live·분리형 경로를 바탕으로 공개 전 선택 경로의 필수 조건을 검증한다(DEC-066). DEC-053/054의 요소별 2~3개 및 전 후보 시험은 선행 조건에서 해제됐다. 새 후보 비교가 필요하면 직접 말하고 들으며 품질을 확인하고 비용·오류·사용자 경험에 따라 재평가한다.

D-03 후보 테스트는 B-00·B-09의 제품 통합과 구분하며, 예산·테스트 데이터 범위를 합의한 뒤 수행한다. 최초 후보 비교는 DEC-016의 합성 대화·개발자 본인 테스트 음성 범위로 제한하고 공급자 조건은 [PRD 적용 범위](PRD.md#provider-data-policy)를 따른다. 실제 사용자 기록으로 실험 범위를 넓히려면 별도 합의와 D-02 정책·접근 통제 검증이 필요하다.

실제 기능: DEC-055/066의 로컬 경로는 `B-00 → B-09/B-02(Gemini Live·분리형 비공개 시험) → E2E 통합`으로 진행하고, `D-03 선택 경로 검증/명시적 선택 → B-09 공개 연결`은 공개 전 조건이다. 로컬 기능 구현에 D-03 완료를 요구하지 않는다. 다른 의존 관계는 `B-00 + D-02 → B-01/B-05`, `B-05 → B-06/B-07/B-08`이다. 실제 사용자 기록의 영구 저장과 외부 제공 전에는 D-02의 정책과 B-01의 접근 제어를 검증한다. B-01의 기기 간 기록 조회와 B-03의 이력 기반 소재 선택은 B-05의 실제 기록 저장을 연결한 뒤 통합 검증한다.

검증: `V-01/V-02/V-05/V-06`은 관련 기능마다 추가한다. `V-03`은 음성·접근 제어·삭제 구현 후, `V-04`는 안전하게 사용할 수 있는 서비스가 준비된 후 수행한다.

운영: `B-09 + V-05 → D-05 → C-01/C-02 → C-03/C-04 → C-05 → C-06`. C-03의 초기 배포 이후에도 기능과 검증을 작은 단위로 반복한다.
